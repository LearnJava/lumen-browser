## Engine — source pipeline

### lumen-dom (`crates/engine/dom`)
- ✅ Arena DOM: `Vec<Node>` + `NodeId(u32)`, no `Rc/RefCell`, no cycles (deny-linted).
- ✅ Node model: Document / Doctype / Element / Text / Comment / ShadowRoot; `QualName`, 6 namespaces, attributes.
- ✅ Core API: create/append/detach/get, `base_href()`, `find_first_element(predicate)`, tree-print.
- ✅ `InputType` (22 HTML5 input types), `DocumentMode` (NoQuirks/Quirks/LimitedQuirks, set by parser).
- ✅ Shadow DOM: `attach_shadow`, `FlatTree` + `build_flat_tree` with `<slot name>` assignment.
- ✅ Hibernation snapshot: `Document::to_bytes()/from_bytes()` (bincode); JS-wrapper refcounting for GC (`acquire/release_js_ref`, `dead_node_ids()`).
- ✅ Drag-and-drop draggability; contenteditable editing layer (`Range`, `Selection`, `CommandHistory` undo/redo, paste/drag transfer).
- ⬜ Arena compaction / free-list; auto-set `:target` from URL fragment is shell-side.
- ~232 tests.

- ✅ ~250 named entities + numeric refs; DOCTYPE public/system id; quirks-mode detection (detection only).

### lumen-css-parser (`crates/engine/css-parser`)
- Parses selectors + **untyped string declarations**; typed values + cascade live in `lumen-layout/style.rs` (~139 properties wired end-to-end — see CSS-SPECS.md).
- ✅ Selectors L3 full set + L4: attribute operators (`= ~= |= ^= $= *=`, case flag), structural pseudo, form/UI-state pseudo (DOM-attr-based), `:nth-*(of …)`, `:not/:is/:where`, `:has` (in layout).
- ✅ `:lang/:dir/:link/:visited(always false)/:scope/:target/:state()` (custom-state, matches `data-lumen-state-<name>` sentinel attr reflected by `ElementInternals.states`); interactive pseudo (`:hover/:focus`) parsed as always-false (runtime state applied in layout).
- ✅ `!important` extraction; at-rules parsed+stored: `@media` (cascade-integrated), `@font-face`, `@import`, `@property`, `@layer`, `@supports` (typed `evaluate()` — incl. `selector()`, `font-tech()`/`font-format()` matched against lumen-font capabilities), `@keyframes`, `@scope`, `@container`, `@color-profile` (`ColorProfileRule`), `@function` (`FunctionRule`, call-site evaluation wired in layout — see CSS-SPECS.md).
- ✅ `@import` **file loading** (shell `inline_css_imports`, 2026-07-18): parsed `@import` URLs are fetched (local file / http via the prefetch cache) and their rules inlined **before** the importing sheet's own rules (Cascade L4 §6.5); media-query gate skips non-matching imports, cycle + depth (16) guards, nested imports resolve against the importing sheet's own URL.
- ✅ **Dynamically inserted `<style>` reaches the cascade** (shell `Lumen::refresh_dynamic_css`, [BUG-743](bugs/BUG-743-FIXED.md), 2026-08-10): the page stylesheet is no longer frozen at load time — every relayout compares a hash of the inline `<style>` blocks and, on a change, rebuilds the sheet from memory (stored external `<link>` bodies + resolved `@import` text + the current blocks) without a single network request. Previously anything that inserted a `<style>` after the document was parsed (`load`, `setTimeout`, rAF, a promise — i.e. any CSS-in-JS) never applied at all. Not covered: `@import`/`@font-face` **inside the new** sheet are not fetched, and a `<style>` created by parsing `innerHTML` still does not work ([BUG-744](bugs/BUG-744-OPEN.md)).
- ✅ **Динамически вставленный `<style>` попадает в каскад** (shell `Lumen::refresh_dynamic_css`, [BUG-743](bugs/BUG-743-FIXED.md), 2026-08-10): таблица стилей больше не фиксируется на момент загрузки — на каждом релейауте сверяется хэш инлайновых блоков, и при изменении лист пересобирается из памяти (сохранённые тела внешних `<link>` + текст `@import`-ов + текущие `<style>`), без сетевых запросов. Раньше всё, что вставляло `<style>` после разбора документа (`load`, `setTimeout`, rAF, промис — то есть любой CSS-in-JS), не применялось никогда. Не покрыто: `@import`/`@font-face` **внутри нового** листа не подгружаются, и `<style>`, созданный парсингом `innerHTML`, по-прежнему не работает ([BUG-744](bugs/BUG-744-OPEN.md)).
- ✅ **Динамически вставленный `<style>` попадает в каскад** (shell `Lumen::refresh_dynamic_css`, [BUG-743](bugs/BUG-743-FIXED.md), 2026-08-10): таблица стилей больше не фиксируется на момент загрузки — на каждом релейауте сверяется хэш инлайновых блоков, и при изменении лист пересобирается из памяти (сохранённые тела внешних `<link>` + текст `@import`-ов + текущие `<style>`), без сетевых запросов. Раньше всё, что вставляло `<style>` после разбора документа (`load`, `setTimeout`, rAF, промис — то есть любой CSS-in-JS), не применялось никогда. Не покрыто: `@import`/`@font-face` **внутри нового** листа не подгружаются, и `<style>`, созданный парсингом `innerHTML`, по-прежнему не работает ([BUG-744](bugs/BUG-744-OPEN.md)).
- ✅ Cascade wiring for `@layer` (layer priority in `layer_pri`)/`@scope` (`node_in_scope`: root + donut `to (<limit>)` resolved in one ancestor walk, nearest boundary wins)/`@container` (`apply_container_rules`) — all applied in `compute_style`/`box_tree.rs`. Nested `@media`/`@supports`/`@layer`/`@container`/`@scope` inside another conditional-group at-rule body now parse too (bubble to stylesheet-level, flat model, done 2026-07-15).
- ⬜ Namespace prefixes.
- ~304 tests.

## Engine — layout & rendering

### lumen-layout (`crates/engine/layout`)
- ✅ Block + inline flow (line wrap, margin collapsing, `margin: 0 auto`, `line-height-step` vertical rhythm). A descendant of an inline element that cannot be flattened into text keeps its own box since [BUG-728](bugs/BUG-728-FIXED.md) (fixed 2026-08-09): a block-level child splits the inline box around it (CSS 2.1 §9.2.1.1), and a replaced child (`<img>`, form control) keeps its own height instead of collapsing to the line height — previously `<a><div class="card"><img>` (the shape of almost every link card on the web) lost the card's geometry entirely and painted the image at line height. `display: contents` stays transparent. ⬜ residual: the inline element itself still has no box of its own in the tree, so `getComputedStyle`/`getBoundingClientRect` on a `<span>`/`<a>` remain empty ([BUG-488](bugs/BUG-488-OPEN.md)); `<img>` is still block-level in Phase 0, so an image never shares a line with the text around it.
- ✅ `white-space` (normal/nowrap/pre/pre-wrap/pre-line/break-spaces) + CSS Text L4 longhands `white-space-collapse` (collapse/preserve/preserve-breaks/preserve-spaces/break-spaces) and `text-wrap-mode` — the legacy value is the L4 shorthand, layout reads an effective `WhiteSpace` recomputed via `WhiteSpace::combine`; `pre-line`/`preserve-breaks` keep source `\n` as forced breaks while collapsing surrounding spaces (`preserve-spaces` ≈ `preserve`, Phase 0).
- ✅ **CJK line wrapping (`line-break`, CSS Text L3 §5.5, p4-line-break-cjk 2026-07-29)** — text with no spaces (Japanese/Chinese/Korean) now wraps inside the container instead of overflowing it: `lumen_layout::line_break` derives UAX #14 break opportunities from a character-class table and `wrap_inline_run` cuts the run greedily at the last opportunity that fits. All five values are honoured — `strict` (nothing but ideograph boundaries), `normal`/`auto` (also before iteration marks `々ゝヽ`, `〜`, `゠`), `loose` (also before small kana, `ー`, `・`, `：`, `；`, `‐`, and around `￥`/`％`), `anywhere` (every typographic character unit, in any script, combining marks and ZWJ sequences kept intact). Opening brackets never end a line and closing brackets / `、` / `。` / `！` / `？` never start one. `word-break: keep-all` suppresses CJK breaking (previously a no-op, since CJK never broke at all); `line-break: anywhere` overrides it.
- ✅ Flexbox (direction, grow/shrink/basis, justify/align, gap, wrap). ✅ **Three §8.1/§9.7 holes closed 2026-08-17**, all three visible on one page (`tbank.ru/login/`, whose card sat in the top-left corner instead of the centre): (1) `margin: auto` on a flex item now absorbs free space on **both** axes and outranks `justify-content`/`align-self` — it used to resolve to 0, so such an item stuck to the line start; (2) a growing item is now frozen at its `max-width`/`max-height` (§9.7 step 4 "fix min/max violations" — the freeze loop existed only for shrinking), so it no longer books the whole line and leaves nothing for alignment while still being *drawn* at its max size; (3) the **cross axis of a column container** (i.e. horizontal placement) is implemented at all — items were unconditionally stretched to the container width, so `align-items: center`/`start`/`end` and horizontal auto margins did nothing there; a non-stretch item now takes its fit-content width and is placed by the same rules as in a row. ⬜ column-direction wrapping.
- ✅ CSS Grid (px/fr/auto/repeat/minmax, explicit+auto placement, dense, subgrid, `order`, per-cell `align-items`/`justify-items`/`*-self`, and — since p4-place-shorthands 2026-07-29 — container-level `align-content`/`justify-content`/`place-content`: `start`/`center`/`end`/`space-between`/`space-around`/`space-evenly` distribute the leftover track space, and the initial `normal` grows `auto` rows into a definite container height, CSS Box Alignment L3 §5 / CSS Grid L1 §12.3). An overflowing grid follows §5.3 — `space-between`→`start`, `space-around`/`space-evenly`→`center`, resolved unsafely — matching Edge. ⬜ grid-template-areas, named lines; the `safe`/`unsafe` keywords themselves (unsafe is unconditional, `safe` cannot be opted into). `grid-template-*: masonry` / `display: masonry` fall back to a regular grid / multicol (matches Edge, which ships no CSS masonry).
- ✅ Multi-column (`column-count`/`column-width`/`column-gap`/`column-rule`/`column-span`, `column-fill: balance|auto` — balanced atomic-box distribution via binary-searched column height).
- ✅ Table layout (colspan/rowspan, column widths) — live path `box_tree.rs` (note: `table.rs` is dead code).
- ✅ `border-radius` elliptical corners (`10px / 20px` syntax, CSS Backgrounds L3 §5.5): separate x/y radius fields per corner (`ComputedStyle::border_top_left_radius_y` etc.), threaded through `CornerRadii::from_style_and_box` into the femtovg, CPU raster and wgpu paths. All three apply the §5.5 overlap reduction through one shared `CornerRadii::clamped_to_box` (a single factor across the four corners, not a per-axis cap — BUG-277 slice 4); the wgpu path evaluates the shape as an SDF in `RRECT_SHADER_SRC`. `overflow: hidden` on a rounded box clips its children to the rounded contour in all three backends (wgpu: offscreen level composited through the shared `SDF_RRECT_WGSL` — BUG-277 slice 5; falls back to the bbox clip under a rotating/skewing transform).
- ✅ Positioned: relative, absolute/fixed (out-of-flow + containing-block threading); `position: sticky` (page-level and nested inside `overflow:auto`/`scroll` ancestors — wgpu default backend, `renderer.rs::sticky_bound()`, BUG-336; femtovg fallback backend still page-level-only, BUG-337).
- ✅ SVG layout pass (viewBox, rect/circle/ellipse/line/path, `<use>` with cycle detection); `<text>` with `text-anchor`/`dominant-baseline` (presentation attribute **and** CSS property — CSS overrides the attribute and inherits from `<g>`); vertical writing modes (`vertical-rl/lr`).
- ✅ Replaced: `<img>` (picture/srcset picker), `<iframe>` placeholder.
- ✅ Cascade: specificity + `!important`, RTL selector matching, all CSS3 structural + L4 form/UI pseudo, `:has()`, `:state()` (custom-state, matches `data-lumen-state-<name>` sentinel attr), `::before/::after` (string / `attr()` / `counter()` / quote content, plus `url()` inline-replaced images), `::first-line/::first-letter` (drop-cap float), `initial-letter` (size/sink drop cap, Phase 0).
- ✅ Values: `calc/min/max/clamp` + math fns, `var()` (including inside `font-size` and the `font` shorthand — BUG-731), `@property` registration, viewport units, intrinsic sizing (`min/max/fit-content`); `@function` custom-function calls (`--name(<args>)`, positional args + defaults, local decls, `result:` — direct calls and calls reached through a custom-property chain both resolve; `returns` typing deferred).
- ✅ Forced Colors Mode (CSS Color Adjust L1 §3): a11y-panel preference forces the system palette element-aware (LinkText/ButtonText/GrayText/Field), clears shadows, drops non-`url()` background images, honours `forced-color-adjust: auto|none|preserve-parent-color`; drives `@media (forced-colors: active)`; forces `scrollbar-color` → `auto` and `font-variant-emoji` `normal`/`unicode` → `text` (BUG-388, 2026-08-10). JS `matchMedia` shim not yet wired.
- ✅ Animations/transitions scheduling (`@keyframes` interpolation, timing functions, transform/gradient/filter interpolation; `background:<color>` shorthand in keyframes); `content-visibility: auto` skip; Shadow DOM flat-tree integration. 🟡 A running CSS animation/transition is invisible to JS, measured 2026-08-21: none of the eight `animation*`/`transition*` events is ever dispatched (no dispatch site exists — `grep -rn animationstart crates/` finds only the interface and the `on*` attribute name), and neither `getComputedStyle` nor `getBoundingClientRect` moves while one runs — [BUG-503](bugs/BUG-503-OPEN.md)/[BUG-536](bugs/BUG-536-OPEN.md). ⬜ Declarative SVG animation (SMIL `<animate>`/`<animateTransform>`/`<animateMotion>`/`<set>`) is absent entirely: no timing model, no attribute animation, no `beginEvent`/`endEvent`/`repeatEvent` — [BUG-806](bugs/BUG-806-OPEN.md).
- ✅ Scroll-Driven Animations L1: `animation-timeline: scroll()|view()|<named>` drives animation progress from scroll/viewport position (not the clock) — opacity/transform/animated `background-color`/`color` all composite in the live window (BUG-231, 2026-06-23). Remaining deviation vs Edge is font-parity/sub-pixel only (BUG-127, KNOWN_DEBTOR).
- ✅ `font-variant-caps` (CSS Fonts L4 §6.2, 2026-07-29): весь набор значений — `normal | small-caps | all-small-caps | petite-caps | all-petite-caps | unicase | titling-caps`, наследуемое; longhand + caps-компонента shorthand-ов `font-variant` и `font`. Пять значений синтезируются в layout-е (`caps_synthesis` в box_tree.rs режет inline-сегмент на прогоны и рисует капитель заглавными размера 0.8× с компенсацией базовой линии), потому что ни bundled-Inter, ни большинство системных шрифтов не содержат `smcp`/`c2sc`/`pcap`/`c2pc`; синтез работает одинаково на всех трёх текстовых путях (femtovg / wgpu / CPU), т.к. находится до них. `titling-caps` синтезу не поддаётся — уходит в шейпер фичей `titl` (на шрифте без этой фичи — no-op). Остальные longhand-ы `font-variant` (`-ligatures`/`-numeric`/`-east-asian`/`-position`/`-alternates`) не реализованы: shorthand их только сбрасывает в initial.
- 🟡 `font-variant-emoji` (CSS Fonts L4 §6.6, 2026-08-10): парсится, наследуется, входит в shorthand-ы `font-variant`/`font`, публикуется в `getComputedStyle` и форсируется в forced-colors mode (BUG-388). На выбор глифа пока НЕ влияет — presentation selection (variation selectors VS15/VS16, curated emoji-fallback) свойство не читает, так что `font-variant-emoji: text` не сделает цветной эмодзи монохромным.
- ✅ `font-stretch` (CSS Fonts L4 §2.5/§5.2, 2026-07-29): keyword-набор (`ultra-condensed`…`ultra-expanded`) + `<percentage>` (клампится в 50–200%), наследуемое; longhand + компонента shorthand-а `font` (там только keyword-ы). До рендера доезжает **двумя независимыми путями**, которые складываются: variable-шрифт получает ось `wdth` в `DrawText::font_variation_axes`, а статическое семейство с отдельными condensed/expanded-файлами подбирается matcher-ом по `usWidthClass` из OS/2 (`DrawText::font_stretch` → `FontProvider::pick_face`). Явный `font-variation-settings: "wdth" N` подавляет инъекцию оси, но не подбор face-а — по спеке низкоуровневая ось применяется уже после выбора шрифта. Дескриптор `font-stretch` у `@font-face` участвует в резолве `local()`-источника. Видимый эффект требует шрифта с осью `wdth` либо семейства с отдельными узкими/широкими начертаниями: bundled-Inter не имеет ни того, ни другого, поэтому на странице без `font-family` изменений не будет. CPU-путь (`cpu_raster`, детерминированные снапшоты) рисует только bundled-Inter без `FontProvider` и свойство игнорирует по построению.
- ✅ `font-palette` + `@font-palette-values` (CSS Fonts L4 §11.3/§13, 2026-07-29): `normal|light|dark|<dashed-ident>` parsed (inherited); custom idents resolved against `@font-palette-values` (name + family match, `base-palette`, `override-colors`) at the end of `compute_style`; carried as `DrawText.font_palette` and consumed by the wgpu renderer — a COLR v0 color glyph paints one atlas quad per layer, each in its CPAL palette color (`0xFFFF` = text color, palette alpha scaled by the text alpha). `light`/`dark` pick the first palette with the matching `paletteType` flag and fall back to palette 0 when the font has none. COLR v1 (paint graph: gradients, transforms) is deferred — a v1-only glyph falls back to its monochrome outline; the deterministic CPU path and femtovg render the bundled Inter face only, which has no COLR.
- 🟡 `ruby-position` / `ruby-align` / `ruby-merge` (CSS Ruby L1 §4, 2026-07-04): parsed as inherited `ComputedStyle` fields (`over|under`, `start|center|space-between|space-around`, `separate|merge|auto`); `RubyBox::from_style` drives `lay_out_ruby` (align distribution + separate/merge per-base pairing). No visual effect yet — `<ruby>` elements are not built into the box tree (module has no pipeline callers; P1 inline-flow integration deferred).
- 🟡 `math-style` / `math-depth` (MathML Core §2.1, 2026-07-04): parsed as inherited `ComputedStyle` fields (`normal|compact`; `auto-add | add(<integer>) | <integer>` resolved to a computed integer against the inherited depth); `collect_mathml_structure` carries `math-style` into `MathmlBox`, `lay_out_mathml` scales compact mfrac children and derives script scale from `math-depth` deltas (`MATH_SCRIPT_SCALE^Δ`, 0.71/level). No visual effect yet — `<math>` elements are not built into the box tree (module has no pipeline callers; P1 integration deferred); `font-size: math` not implemented.
- ✅ `backface-visibility` (CSS Transforms L2 §5.1, 2026-07-04 parse + 2026-07-05 culling): `visible|hidden` parsed into a non-inherited `ComputedStyle::backface_visibility` field; `is_backface_hidden()` (paint/display_list.rs) culls the box (and subtree) once its own 3D transform's `forward_box_transform().0[10]` goes negative (face normal `(0,0,1)` rotated past 90° from the viewer) — same matrix already used by depth-sort, no GPU dependency; `perspective`/`perspective-origin` projection wiring still ⬜ (P4).
- ✅ CSS Anchor Positioning L1 (`anchor-name`/`position-anchor`/`inset-area`/`anchor()`/`anchor-size()`): post-layout pass (`apply_anchor_positions`) repositions anchored elements; `anchor()` in `top`/`right`/`bottom`/`left` and `anchor-size()` in `width`/`height` resolved through the same two-phase local+global registry (`resolve_inset`/`resolve_inset_scoped`, `resolve_anchor_size`, 2026-07-15). CSS Grid subgrid (`SubgridContext`): child track sizes/gaps/offsets inherited from the parent grid via thread-local propagation in `box_tree.rs`. Both fully wired, not stubs.
- ✅ `%` lengths in block flow (RP-1): `width`/`margin-*`/`padding-*` resolve against the containing block's **width** (vertical margin/padding included, per CSS 2.1 §8); percentage `height` resolves against the CB **height** when definite, else computes to `auto`.
- ✅ `float: left/right` + `clear` (RP-4, CSS 2.1 §9.5): placement, shrink-to-fit auto width, wrap to next line (rule 8), float context establishes a BFC, container height encloses floats, inline text wraps around floats, `clear` clearance (margin-absorbing), `shape-outside` (circle/ellipse/inset/polygon/path). A non-BFC block beside a float keeps its full containing-block width — only its (and its descendants') line boxes are shortened, propagated into nested in-flow blocks; BFC blocks shift past floats; `clear` and nested floats work at depth. Remaining edge: per-line widening of an inline run *below* a shorter float (single-width approximation).
- ✅ `ch`/`ex` units (CSS Values L4 §5.1.1): resolve against the box's real font metrics — `ch` = advance of the "0" glyph, `ex` = x-height at the used font-size — published per box by `lay_out_inner` via the `FONT_CH_EX` thread-local; the spec `0.5em` assumption is the fallback when no measurer is available. `cap`/`lh` remain em-approximated.
- ✅ `direction` + `unicode-bidi` (CSS Writing Modes L4 §2.1/§2.2 over UAX #9, `layout/src/bidi.rs`): the inline formatting context is resolved as one bidi paragraph — `direction` supplies the base embedding level, `unicode-bidi` (`normal`/`embed`/`isolate`/`bidi-override`/`isolate-override`/`plaintext`) is applied exactly as the spec defines it, by injecting the matching explicit bidi controls before the run. Segments are split at level boundaries, rule L2 reorders each line box's fragments geometrically (positions mirror, the slice keeps logical order so find-in-page and Selection still read in reading order), and rule L4 + the character half of L2 turn every RTL run into visual order at display-list emission. ⬜ residual: `unicode-bidi` grouping is per *segment run*, not per inline element (flat segment list); vertical writing modes are not reordered; `plaintext` on a block does not re-resolve that block's `text-align: start/end`.
- ⬜ CSS4 color spaces (lab/lch/oklab/oklch), `attr()`/`counter()` content. Many L3/L4 properties are **parse+store only** (text-emphasis, container queries, touch-action, appearance).
- 🟡 `zoom` (CSS Viewport L1 §5, 2026-08-10): `<number>` / `<percentage>` / `normal` / `reset`, compounding down the tree (`ComputedStyle::effective_zoom` = the ancestors' factor × the element's own). Unlike `transform: scale()` it changes *layout*: the factor is folded into the computed values, so the box really occupies less space. Scaled: `font-size` and the absolute (`px`) lengths of the non-inherited box-model properties — width/height + min/max, margin, padding, inset, border-width, row/column-gap. This is what lets a fixed-width desktop container (tbank.ru: `min-width: max-width: 1104px` plus `zoom: .8` in a media query) fit a narrower viewport instead of overflowing it. Relative units need no handling — they resolve against bases that are themselves already zoomed; `font-size` follows the same rule and takes the compounded factor only when it resolved from a zoom-independent basis (`px`, `rem`, viewport units). Exported **`Memory.buffer` aliases live** (U-4b): it is one stable JS `ArrayBuffer` synced with Rust-owned linear memory at call boundaries, so the emscripten `HEAP32 = new Int32Array(memory.buffer)` pattern is coherent in both directions (and a captured view survives across calls; growth detaches and replaces it). Boundaries: a host import can't observe writes made earlier in the same in-flight call; an *imported* `Memory` is not aliased to the instance; `Memory.buffer` is not backed by a `SharedArrayBuffer`; no multi-memory. Measured 2026-08-09 on the vendored WPT `wasm` category (405 ids, `--processes=4`): 342/373 harness OK, but only 11314/179992 subtests (~6.3%) — the official spec-test corpus mostly fails to `compile()` at all, dominated by two confirmed defects rather than proposal absence: the element-segment decoder only implements flags 0/1/2, rejecting the expr-encoded-elements encoding the spec-test generator emits by default even for plain MVP control-flow tests ([BUG-700](bugs/BUG-700-OPEN.md)), and `WebAssembly.Table`'s constructor throws on a `BigInt` `initial`/`maximum` (`address:"i64"` 64-bit-addressed tables), which crashes the shared per-file WPT harness setup and cascades failures through the rest of each file ([BUG-699](bugs/BUG-699-OPEN.md)) — so the SIMD/relaxed-SIMD claims above are not yet re-verified against the spec corpus; re-measure after both land. ⬜ Privacy-Sandbox (Topics/Attribution/Background Fetch/Push — in-memory stubs), heap-snapshot serialization (shell re-runs scripts on restore).

> Boundary note: "functional" APIs (Canvas2D, WebGL, WebGPU, getUserMedia, WebSocket, XHR, IndexedDB, Web Animations, WebAssembly MVP) actually do work; many depend on the shell installing a provider — without it they degrade to rejection. The long stub list (WebCodecs/WebHID/…) resolves/rejects without doing work; WebCodecs `configure()` reports unsupported codecs via the async error callback (not a synchronous throw).
