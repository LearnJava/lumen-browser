# E2E-3 — hit-test инлайн-переключателя «показать пароль»

Стенд отвечает на вопрос карточки E2E-3: почему `type` по CSS-селектору поля
пароля на живом стенде отвечал `Element is not a mutable text field`, а клик в
верхнюю кромку поля при этом работал. Наблюдение 2026-09-09 называло две
гипотезы — переключатель получает бокс шириной во всю обёртку (420px) и
физически накрывает `<input>`, либо бокс правильный, а промахивается порядок
hit-test.

Обёртка `.password-wrapper` во всех вариантах — `position: relative; width: 420px`,
поле — `width: 100%`, то есть ровно та геометрия, что наблюдалась в поле.

## Как гонять

Нужно живое окно и http одного origin (hit-test проверяется на реальном layout,
headless-дамп сюда не годится):

```bash
python -m http.server 8764 --bind 127.0.0.1 --directory samples/e2e3-password-toggle &
python samples/e2e3-password-toggle/drive.py
```

`drive.py` поднимает `target/dev-release/lumen.exe --mcp-live-port 8904 --maximized`,
ждёт `document_ready` и по каждому варианту печатает бокс поля, бокс
переключателя, их пересечение, `document.elementFromPoint` в центре поля (точка,
куда целится автоматизация), computed `position`/`left`/`right`/`top` и ответ
канала на `type`.

## Варианты

| | Переключатель | Проверяет |
|---|---|---|
| A | `<button>`, `position:absolute; right/top` | канонический виджет |
| B | `<button>` в потоке, без `position` | контроль: поток работает |
| C | `<span>`, `position:absolute; right/top` | зависит ли дефект от `<button>` |
| D | переключателя нет | контроль: голое поле |
| E | `<span>` `right/top`, в обёртке без `<input>` | зависит ли от `<input>` |
| F | `<span>` `left/top`, в обёртке с `<input>` | зависит ли от `right` |
| G | `<span>` `left/top`, без `<input>` | то же без поля |
| H | `<div>` (блочный), `left/top` | абсолют вообще |
| I | `<span>` c `display:block`, `left/top` | блокификация вручную |
| J | `<button>` `right/top` + `width:100%` | откуда берётся 420px |

## Замер 2026-09-11 (P6, окно `--maximized`)

Computed style у всех абсолютных вариантов — `position: absolute` с заданными
`left`/`right`/`top`: декларация доезжает, её не применяет раскладка.

| Вариант | Уровень элемента | Ожидаемый бокс | Фактический | |
|---|---|---|---|---|
| A | inline (`<button>`) | (390, 35.4) | (8, 67) 30×26 | ✗ |
| B | inline, без `position` | в потоке | (8, 150) | ✓ контроль |
| C | inline (`<span>`) | (408.5, 199) | (429, 203) | ✗ |
| E | inline (`<span>`) | (409.3, 315) | (28.6, 307) | ✗ |
| F | inline (`<span>`) | (108, 346.9) | (429, 354.9) | ✗ |
| G | inline (`<span>`) | (108, 404.9) | (30.3, 400.9) | ✗ |
| H | **блочный** (`<div>`) | (108, 440.75) | (108, 440.75) | ✓ |
| I | **`display:block`** | (108, 476.6) | (108, 476.6) | ✓ |
| J | inline + `width:100%` | ширина 420 | (8, 477) **420**×21 | ✗ позиция |

Граница ровно по уровню элемента: блочный абсолютный ребёнок (H) и инлайн,
которому `display:block` выставлен явно (I), встают точно по `left`/`top`;
любой инлайн-уровневый — `<button>`, `<span>`, с `right` и с `left`, с полем в
обёртке и без — остаётся на статической позиции, а смещения игнорируются.

Это **[BUG-928](../../bugs/BUG-928-OPEN.md)** (OPEN, найден P3 2026-08-29), а не
новый дефект: инлайн-уровневые дети собраны в `InlineBlockRow`/`InlineRun` до
блочного цикла, который единственный отбирает абсолютных детей в `abs_deferred`.

### Чего проба НЕ воспроизвела

- **`type` не отказывает.** Во всех вариантах с полем (A, B, C, D, F, J) канал
  ответил `{"success": true}`, `value` стало `"secret"`, а `__HITS` содержит
  ровно `click=pw-*` — фокус ни разу не ушёл на переключатель.
- **Переключатель не накрывает поле.** `elementFromPoint` в центре каждого поля
  вернул само поле, ни разу переключатель. Выброшенный из потока бокс встаёт
  ПОД полем (A, J) или сбоку от него (C, F), а не поверх.
- **Ширина 420px — не отдельный дефект shrink-to-fit.** У переключателя без
  явной ширины бокс получается по содержимому (30px в A, 12px в B). 420px
  появляются только при `width: 100%` (J) — это 100 % обёртки, и такое же число
  вышло бы у корректно вынесенного из потока бокса.

Значит канальный отказ `Element is not a mutable text field` каноническим
виджетом не объясняется: он требует разметки, в которой смещённый BUG-928
переключатель попадает именно в центр поля. Такой разметки в поле не снято —
её и просила карточка E2E-3.
