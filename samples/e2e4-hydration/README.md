# E2E-4 — стенд гидрации React 18 / Next.js

Локальный стенд для дорожки **E2E** (`ROADMAP.md`, задача E2E-4). Отвечает на один
вопрос: доходит ли гидрация React 18 до конца в Lumen и на чём именно она встаёт.
Внешний стенд (Keycloak + Next.js 14) для этого поднимать не нужно — здесь
воспроизводится ровно та форма, на которой он падал.

Две ступени, отличаются **корнем гидрации**:

| Файл | Корень | Что проверяет |
|---|---|---|
| `index.html` + `client.js` | `hydrateRoot(<div id=root>, …)` | обычное React-приложение в контейнере |
| `doc.html` + `client2.js` | `hydrateRoot(document, …)` | форма Next.js 14 App Router |

Разметку SSR генерируют `gen.js` / `gen2.js` настоящим `react-dom/server`, поэтому в
ней есть маркеры Suspense `<!--$-->` / `<!--/$-->` — те самые, на которых стояла
живая проба. Клиентское дерево обязано совпадать с серверным байт в байт, включая
`<script>`-теги: у `doc.html` они часть дерева React, как их отдаёт Next.js.

`docapi.html` — отдельная минимальная страница: печатает, какие члены `Node` есть у
глобального `document`, а каких нет.

## Чего здесь нет

Бандлы `react.js` / `react-dom.js` (UMD, 18.3.1) и `ssr-body.html` **не
закоммичены** (`.gitignore`) — это чужой код, и вендорить его ради стенда не
нужно. Их кладёт рядом `gen.js`, копируя из `node_modules` любого проекта с
React 18. Внешний стенд для этого поднимать не обязательно: 18.3.1 ставится
локально во временный каталог за пять секунд (проверено 2026-09-10, итерация 3):

```bash
mkdir -p .tmp/react18 && cd .tmp/react18
npm install --no-save react@18.3.1 react-dom@18.3.1

NODE_PATH="$PWD/node_modules" node <lumen>/samples/e2e4-hydration/gen.js <lumen>/samples/e2e4-hydration
NODE_PATH="$PWD/node_modules" node <lumen>/samples/e2e4-hydration/gen2.js <lumen>/samples/e2e4-hydration
```

`gen.js` пишет `ssr-body.html` (тело для `index.html`) и копирует оба бандла;
`gen2.js` пишет `doc.html` целиком. Оба генератора детерминированы: на
неизменённых `gen*.js` перегон даёт байт-в-байт тот же `doc.html`, что лежит в
репозитории, — это и есть проверка, что бандлы взяты правильной версии.

Локальный React 19 не годится: у него нет UMD-сборок вовсе, а `hydrateRoot`
19-й ветки — другой алгоритм. Стенд про React 18 / Next.js 14.

## Как гонять

Гидрация React 18 планируется через Scheduler, а headless-дамп видит только
синхронный скрипт ([`docs/engine-gaps.md`](../../docs/engine-gaps.md)) — значит нужно
живое окно и http одного origin:

```bash
python -m http.server 8762 --bind 127.0.0.1 --directory samples/e2e4-hydration &
python samples/e2e4-hydration/drive.py http://127.0.0.1:8762/index.html 15
python samples/e2e4-hydration/drive.py http://127.0.0.1:8762/doc.html 15
```

`drive.py` поднимает `target/dev-release/lumen.exe --mcp-live-port`, ждёт
`document_ready`, вычитывает журнал страницы (`window.__PROBE`) и печатает
`resource://console` и отфильтрованный stderr. Дальше три фазы интерактивности:

1. MCP-`click` по `#btn` — путь настоящего ввода, через hit-test шелла;
2. `btn.dispatchEvent(new MouseEvent('click', {bubbles: true}))` — тот же клик
   **мимо** hit-test. Разделяет «клик не попал по кнопке» (геометрия) и
   «событие не дошло до корня React» (событийный путь);
3. `onClick` висит и на самом контейнере `#app` — если MCP-клик промахнулся по
   кнопке и попал в родителя, видно, дошёл ли он хотя бы до делегирования React.

На странице без `#btn` (`doc.html`) фазы 1–3 пропускаются, а не роняют прогон.

`?lookahead=1` подставляет `document.removeChild`/`insertBefore`/`replaceChild`
заглушками, `?lookahead=2` добавляет геттеры `firstChild`/`lastChild`. Они
остались от итерации 1, когда этих членов у `document` не было вовсе
([BUG-557](../../bugs/BUG-557-FIXED.md), починен 2026-09-09): семантика заглушек
**заведомо неверная**, и с починенным движком они уже не помогают, а мешают —
гоняй стенд без параметра.

## Замер 2026-09-09 (P6, E2E-4 итерация 1)

* Корень-контейнер — гидрация проходит целиком: фиберы на месте
  (`__reactFiber$…` на кнопке), маркеры Suspense съедены штатно.
* Корень `document` — страница **виснет**: 130 тыс. повторов
  `TypeError: t.removeChild is not a function`, `wait{document_ready}` истекает
  за 30 с (воспроизведено трижды). Причина — [BUG-557](../../bugs/BUG-557-FIXED.md).
* Интерактивность упирается в [BUG-926](../../bugs/BUG-926-FIXED.md) (нулевая ширина
  `<button>`) и [BUG-1044](../../bugs/BUG-1044-OPEN.md) (MCP-клик попадает в родителя).

## Итерация 2 (2026-09-09): BUG-557 починен, стенд НЕ перегнан

Механизм зависания снят — у `document` теперь полный интерфейс `Node`, и обход
`firstChild` → `nextSibling` доходит до конца (разбор и проба — в карточке
[BUG-557](../../bugs/BUG-557-FIXED.md)). Но **прогон этого стенда не повторён**:
бандлы React 18 UMD не вендорятся (см. «Чего здесь нет»), а единственный
доступный локально React — 19.2.7, у которого UMD-сборки нет вовсе. Значит,
«гидрация в корень `document` проходит» здесь **не измерено** — это первое, что
нужно сделать в итерации 3, положив рядом настоящий React 18.

## Замер 2026-09-10 (P6, E2E-4 итерация 3): гидрация закрыта, встало на вводе

Настоящий React 18.3.1 UMD поставлен локально (`npm install` во временный
каталог, см. «Чего здесь нет»), перегон `gen.js`/`gen2.js` дал байт-в-байт тот
же `doc.html` — версия правильная. Обе ступени прогнаны **без** `?lookahead`,
`dev-release`, живое окно `--maximized`.

**Гидрация проходит на обоих корнях.**

| Корень | Результат |
|---|---|
| `hydrateRoot(<div id=root>, …)` | `__reactContainer$…` на контейнере, `__reactFiber$…`/`__reactProps$…` на кнопке, `DONE` |
| `hydrateRoot(document, …)` | `__reactContainer$…` на `document`, `__reactFiber$…` на `h1`, `DONE`, **ни одного** `onRecoverableError` |

Форма Next.js 14 App Router (`hydrateRoot(document, …)`) больше не виснет и
доходит до конца — [BUG-557](../../bugs/BUG-557-FIXED.md) закрыл её целиком.
Разведка итерации 1 обещала здесь recoverable-ошибки #418/#423 — **это была
догадка поверх заведомо неверных заглушек `?lookahead`, замер её не подтвердил**:
recoverable-ошибок нет вовсе.

**Встало на вводе, и ровно в трёх уже заведённых дефектах.**

* Событийная система React **работоспособна**: настоящий MCP-клик поднимается
  до корня гидрации, React строит синтетическое событие и зовёт обработчик
  (`REACT synthetic onClick on #app`).
* `dispatchEvent` до корня **не поднимается** — [BUG-873](../../bugs/BUG-873-OPEN.md).
  Вызывается только слушатель самой кнопки, `onClick` React не срабатывает,
  счётчик остаётся `clicked 0`. React 18 слушает на корне, поэтому дефект
  отрезает от React-приложения весь программный ввод.
* Кнопка недостижима кликом: `btn.getBoundingClientRect()` → `w=0`
  ([BUG-926](../../bugs/BUG-926-FIXED.md)), из-за чего MCP-клик уходит в родителя
  ([BUG-1044](../../bugs/BUG-1044-OPEN.md)) — `target=app/DIV`, а не кнопка.

Новых номеров итерация не завела: все три дефекта уже были в `BUGS.md`.
Итерация 4 — снять геометрию (BUG-926), после неё повторить фазу 1 и проверить,
что React-счётчик наконец растёт.

## Замер 2026-09-10 (P6, E2E-4 итерация 4): реальный ввод дошёл до React

[BUG-926](../../bugs/BUG-926-FIXED.md) починен, стенд перегнан без изменений в
самом стенде (`dev-release`, живое окно `--maximized`, без `?lookahead`).

**Счётчик растёт — фаза 1 закрыта.**

```
[probe] btn rect x=8 y=100.96 w=70.53 h=23        ← было w=0
[probe] native click on #btn target=btn/BUTTON     ← было target=app/DIV
[probe] native click bubbled to #app target=btn/BUTTON
[probe] REACT synthetic onClick on #app
btn.textContent → "clicked 1"                      ← было "clicked 0"
```

Клик всплывает штатно по всей цепочке `#btn → #app → #root → document`, React
строит синтетическое событие и зовёт обработчик, состояние компонента
обновляется и перерисовывается. Настоящий пользовательский ввод в React-
приложении работает end-to-end.

Ступень `doc.html` (`hydrateRoot(document, …)`) перегнана тем же прогоном —
регрессии нет: `__reactContainer$…` на `document`, `__reactFiber$…` на `h1`,
`DONE`, `onRecoverableError` не вызван ни разу.

**Что осталось.** Фаза 2 по-прежнему не проходит:
`btn.dispatchEvent(new MouseEvent('click', {bubbles: true}))` вызывает только
слушателя самой кнопки, до `#app` не всплывает, счётчик остаётся `clicked 1`.
Это [BUG-873](../../bugs/BUG-873-OPEN.md) — он не зависел от геометрии и не
снялся. Практическое следствие ровно одно: программный (не через hit-test)
ввод в React-приложение по-прежнему не доходит.

[BUG-1044](../../bugs/BUG-1044-OPEN.md) на этом стенде больше не наблюдается —
клик попадает в кнопку. Его собственный репро тоже перестал воспроизводиться
(измерено отдельно, дописано в карточку); остаток бага — «честный отказ вместо
`success` при промахе» — с формами больше нечем запустить.
