# BUG-1854 — `watcher_window_receives_settingchange` гонит между процессами: `FindWindowW` ищет окно класса по всему десктопу

**Статус:** OPEN
**Заведён:** 2026-11-26 (P6, попутно гейту MCP-TOTAL-S7a)
**Область:** shell (`crates/shell/src/platform/os_params/windows.rs:186` — `FindWindowW`, `:195` — `SendMessageW`; сам watcher — прод-код, не трогается)

## Симптом

В полном прогоне замыкания (`cargo test` по крейтам гейта MCP-TOTAL-S7a) тест
упал: `assert_eq!(HANDLED, before + 1)` — `left: 0, right: 1`
(`windows.rs:196`). Одиночный повторный прогон на фоне параллельного чужого
прогона того же тест-бинаря (второй слот пула worktrees, свой `target/`) не
завершился за 5 минут (убит по таймауту) — см. «Причина».

## Причина

Кросс-процессная гонка тестовой изоляции, прод не страдает:

1. Класс окна `LumenOsParamsWatcher` регистрируется каждым процессом
   lumen-shell; `FindWindowW` ищет среди **всех** top-level окон десктопа без
   фильтра по pid. Два параллельных прогона тест-бинаря lumen-shell (две
   сессии-слота) дают два окна одного класса, и тест может найти чужое окно —
   тогда сообщение уходит туда, свой счётчик не растёт, ассерт падает.
2. `SendMessageW` синхронен: в чужое окно, чья нить перестала качать сообщения
   (чужой тест-бинарь уже завершает прогон), он блокируется навсегда — отсюда
   зависший одиночный прогон.

Контроль (2026-11-26, тот же вечер): `cargo clean -p lumen-shell`,
`CARGO_INCREMENTAL=0`, соло и без чужого прогона — тест зелёный.
Промежуточный повторный прогон перед этим падал на линковке (`rust-lld:
undefined symbol: anon…` в тест-бинаре) — инкрементальная сборка на машине
под параллельной чужой сборкой, к тесту отношения не имеет. Красным тест
остаётся только при параллельном чужом прогоне lumen-shell — что и
наблюдалось на гейте (два слота пула).

## Что делать

1. Находить своё окно: после `FindWindowW` — `GetWindowThreadProcessId` и
   отброс чужих pid (или перебор `FindWindowExW`), либо уникальный на процесс
   класс (суффикс pid).
2. `SendMessageTimeoutW` с `SMTO_ABORTIFHUNG` вместо `SendMessageW` — чужое
   зависшее окно не должно вешать тест.

## Как проверить

Два параллельных `cargo test -p lumen-shell --bin lumen
watcher_window_receives_settingchange -- --exact` в двух worktrees — оба
зелёные и оба завершаются; полный прогон замыкания с параллельным чужим — без
падения и без зависаний.
