# BUG-703: `tbank.ru` не завершает гидратацию React — главная страница остаётся пустой (белой), DOM застревает на SSR-скелетоне

**Статус:** OPEN
**Компонент:** js (V8-движок; конкретная точка отказа не локализована — гидратация не бросает исключений, значит не диагностируется по `resource://console`)
**Найден:** живая проверка `https://www.tbank.ru/` (запрос пользователя — открыть браузер, зайти в личный кабинет), 2026-08-09

## Симптом

После полной загрузки (`document.readyState === 'complete'`, все 28 внешних +
15 инлайн-скриптов отчитались `Загружен скрипт`/выполнились без строки
`script error:`) DOM остаётся на 136 узлах — это только SSR-скелетон, 0 кастомных
элементов, 0 shadow root'ов. `resource://console` пуст — ни одной ошибки.
Скриншот: белая страница, виден только бордер одного чекбокса.

`document.body.innerHTML` показывает застрявший маркер React 18 Suspense:

```html
<div class="application"><div class="aA--yu9"><!--$!--><template></template><!--/$--><div></div></div></div>
```

`<!--$!-->` — маркер «Suspense-заглушка ещё показывается» (fallback showing,
не resolved); при здоровой гидратации он заменяется реальным содержимым.

## Что не является причиной

Не выброшенное исключение (консоль пуста), не сетевая ошибка (все скрипты
отчитались 200 OK), не сбой парсинга (216 DOM-узлов при `--dump-source`
до выполнения скриптов, разбор HTML прошёл нормально) — это тихий отказ именно
на этапе гидратации/маунта React-компонента.

## Возможный общий корень с BUG-702

Главная страница подключает свою пару react+platform-рантайма (другие файлы,
чем страница входа): `pfphomeMain.<hash>.chunk.js` / `react.<hash>.js` /
`platform.<hash>.js` из `cdn.tbank.ru/s3aas/apps/pwaplatform/prod/compiled/`
— тот же класс «react + platform-рантайм от того же вендора», что вызывает
бесконечный цикл в [BUG-702](BUG-702-OPEN.md), но здесь эффект другой (тихий
отказ, не зависание) и с другой конкретной парой файлов. Не доказано общей
причины — не проверено, зависает ли эта пара в изоляции тем же способом, что
BUG-702; стоит проверить в первую очередь при диагностике одного из двух багов.
