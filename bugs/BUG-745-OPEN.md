# BUG-745: абсолютно позиционированный бокс с `width: auto` не ужимается по содержимому

**Статус:** OPEN
**Компонент:** layout (`crates/engine/layout/src/box_tree.rs` — размещение
`position: absolute`/`fixed`)
**Найден:** P3 при разборе пункта 4 [BUG-733](BUG-733-OPEN.md), 2026-08-10

## Что происходит

По CSS 2.1 §10.3.7 у абсолютно позиционированного не-replaced элемента с
`width: auto` и хотя бы одной `auto`-инсетой ширина — shrink-to-fit. Lumen
вместо этого растягивает бокс на всю ширину содержащего блока, а потом от него
же отсчитывает `right` — бокс уезжает за левый край на величину инсеты.

Локальное репро `.tmp/b745_abs.html` (вьюпорт 1024, контейнер `.rel` — 400):

| Объявление | Lumen `x, w` | Ожидается |
|---|---|---|
| `fixed; right: 16px` | `-16, 1024` | `~948, ~60` (правый край 1008) |
| `fixed; left: 16px` | `16, 1024` | `16, ~60` (сейчас вылезает на 1040) |
| `absolute; right: 16px` в блоке 400 px | `-16, 400` | `~324, ~60` |
| `fixed; left: 10px; right: 10px` | `10, 1004` | то же ✔ |
| `fixed; right: 16px; width: 200px` | `808, 200` | то же ✔ |

То есть обе «якорные» ветки (обе инсеты заданы; ширина задана явно) считаются
верно — ломается ровно та, где ширину нужно вывести из содержимого.

## Почему это важно

Это остаток пункта 4 [BUG-733](BUG-733-OPEN.md). После
[BUG-743](BUG-743-FIXED.md) cookie-баннер `tbank.ru` наконец получает свои
`position: fixed; bottom: 16px; right: 16px; z-index: 200` и белый фон, но
рисуется полосой во всю ширину вьюпорта со сдвигом на 16 px влево
(`x = -16, w = 1024`) вместо карточки шириной по содержимому справа внизу.
Форма «всплывающая карточка/тултип/тост, приклеенная к углу» — одна из самых
частых на вебе, так что дефект не про одну страницу.

## Как воспроизводить

```
python .tmp/b745_abs.py
```
