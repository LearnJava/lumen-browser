# BUG-1077 — Плавающая chrome-панель `#demoBar` (CC-18, BUG-1059) видна в живом окне и ломает диф-гейт каждого real-JS графического теста

**Статус:** FIXED 2026-11-15
**Тип:** регрессия тестового окружения — не дефект движка/страницы, панель рисуется корректно по своему собственному дизайну.
**Заведён:** 2026-09-21 (P1, срез 6 P3-webgl2, `docs/tasks/ph3-webgl2.md`)
**Область:** тулинг графтестов / shell chrome — `assets/chrome/chrome.html` (`.demo-bar`, `position:fixed; left:18px; bottom:18px`) + `crates/shell/src/chrome_ui.rs`/`chrome_float.rs` (`take_floating_panel`/`chrome_floating_dl`, BUG-1059) + `graphic_tests/run.py`.
**Владелец:** P2 (тулинг графтестов) — решение «флаг для авто-прогонов» принято и реализовано рычагом окружения.

## Симптом

BUG-1059 (закрыт 2026-09-19) починил реальный рендер-баг: `#demoBar`/`#infoPanel` (CC-18, "ПАНЕЛЬ УПРАВЛЕНИЯ ДЕМО — не часть Lumen") были геометрически
корректны, но никогда не попадали на экран живого окна из-за клипа `build_chrome_overlay_strips`. Побочный эффект: эта панель **всегда** рисуется
поверх страницы в любом `lumen.exe`-окне (position:fixed, left:18px, bottom:18px, ~252×520px по умолчанию) — включая живое окно `graphic_tests/run.py`
(`--mcp-live-port`, SDC-3/SDC-4), которое **не** передаёт никакого флага, чтобы её скрыть.

`msedge.exe` (эталон) никогда её не рисует — это чисто Lumen-side dev-виджет ("не часть Lumen"). Поэтому любой real-JS графический тест (в котором живое
окно, а не CPU-снапшот, снимает пиксели — TEST-57, TEST-129..138 и новый TEST-157), у которого хоть какой-то контент/фон приходится на нижний левый угол
(примерно x:[18,270], y:[186,706] в 1024×720-вьюпорте после кропа магента-маркера), получает диф вместо чистого совпадения (TEST-57 8.59%,
TEST-157 5.06% — весь диф = контур панели, 0 расхождений в тестовом контенте).

Панель `position:fixed` относительно всего окна, а не часть контента страницы, поэтому сдвиг тестового контента помогает лишь частично: панель
перекрывает пустой фон страницы, где у Edge — пустой `#0f172a`.

## Фикс

Принят вариант 1 из «Ожидания»: рычаг окружения, а не `KNOWN_DEBTORS`-запись на каждый real-JS тест.

- `crates/shell/src/chrome_float.rs::demo_panel_hidden()` — `LUMEN_NO_DEMO_PANEL=1` (любое значение, кроме `0`) скрывает плавающие панели:
  `rebuild_chrome_floating_dl` пропускает их (кроме `#profileFrame`, это обводка окна, а не панель), `floating_panel_hit` отвечает `None`.
  Заведено в THREAD-13 срез 2 (`1a236426fa`), где живое окно графтестов перестало быть «особым случаем».
- `graphic_tests/run.py`: `LiveWindowClient` (живое окно, дефолтный захват с SDC-4) ставит `LUMEN_NO_DEMO_PANEL=1` в окружение процесса с
  самой первой версии рычага; в этой сессии то же добавлено в `capture_lumen` — per-test gdigrab-путь (`--gdigrab`/`--per-test-process`)
  раньше спавнил окно без рычага и ловил тот же диф.
- `KNOWN_DEBTORS['157']` (`('BUG-1077', 5.06)`) удалён: TEST-157 по TEST-9 снимается через IPC (не в `GPU_CAPTURE`), эта таблица для него не
  читается вовсе — запись была мёртвой и при этом маскировала бы регрессию, если тест когда-нибудь вернут на gdigrab.

## Гейты

- `python graphic_tests/run.py --only 157` — **PASS 0.00%** (IPC-снимок; страница рендерится без панели и без дефекта WebGL-пути).
- `python graphic_tests/run.py --self-test` — ok (25 id в `GPU_CAPTURE`, 173 теста).
- `python graphic_tests/dump_golden.py` (`LUMEN_PROFILE=dev-release`) — 12/12 дампов совпадают с эталоном (хром в дампы не попадает).
- Живой gdigrab-замер (TEST-00 магента-калибровка) в этой сессии недоступен: захват отдаёт экран блокировки Windows, «magenta marker not found» —
  тот же класс окружения, что записан в BUG-625-FIXED.md §Гейты. Поэтому пиксельное подтверждение «панели нет» получено косвенно
  (IPC-путь не рисует хром) + статически: оба пути отрисовки/хит-теста панели читают `demo_panel_hidden()` первым делом, а рычаг стоит в
  окружении обоих спавнов `run.py`.

## Не проверялось

- Полный `python graphic_tests/run.py --continue-on-fail` — невозможен на заблокированном рабочем столе (см. выше).
- Влияние позиции панели между запусками — снято вопросом: при `LUMEN_NO_DEMO_PANEL` панель не отцепляется в `chrome_floating_dl` вовсе.
