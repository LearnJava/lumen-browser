# BUG-1108 — кадр с сфокусированным полем ввода блокирующе ждёт мьютекс документа на всё время off-thread relayout

**Статус:** OPEN
**Заведён:** 2026-09-23 (P1, вынесено из [BUG-683](BUG-683-FIXED.md) срез 7-8).
**Область:** shell (`crates/shell/src/lumen/text_input.rs::typeable_field` —
`document.lock()`; вызывается из `focused_input_caret` в
`crates/shell/src/app/window_event/redraw_requested.rs` на каждом кадре).

## Симптом (по коду, живьём не воспроизведено)

[BUG-683](BUG-683-FIXED.md) срез 7 показал: off-thread relayout движкового
потока держит `Document` на всё время каскада (на github.com — 11-16 с), и
любой блокирующий `document.lock()` на пути кадра превращается в фриз окна
той же длительности. Срез 7 снял такой лок в сборе `<dialog>`
(`try_lock` + кэш прошлого кадра). Тот же шаблон остался в
`typeable_field`: `self.layout_source.as_ref()?.document.lock()` —
блокирующий. На пути кадра он вызывается только через
`focused_input_caret()` и только при сфокусированном `<input>`/`<textarea>`,
поэтому в замере среза 7 (фокуса не было) не проявился.

Ожидаемо: пользователь ставит курсор в поле поиска на тяжёлой странице во
время relayout — окно не перерисовывается до конца каскада.

## Что сделать

1. Воспроизвести: живой github.com, `--maximized`, `LUMEN_FRAME_LOG=1`, фокус
   в поле поиска во время relayout; найти статью кадра, куда уходит ожидание.
2. Кадровый путь (`focused_input_caret`) перевести на `try_lock` с кэшем
   прошлого кадра по образцу `Lumen::modal_dialog_cache` (ключ — адрес `Arc`
   документа). Путь ввода с клавиатуры (`typeable_field` из обработчиков
   клавиш) может остаться блокирующим — там ожидание оправдано: символ
   должен лечь в актуальный DOM.
