# BUG-753 — 725 внутренних имён движка по-прежнему **читаются** с глобала по известному имени (`typeof window._lumen_get_attr === 'function'`): одного `_lumen_query_selector_scoped` достаточно, чтобы опознать Lumen

**Статус:** OPEN — срезы 1–2 из 3 сделаны (2026-09-29/30), см. §Срезы; на глобале страницы осталось одно внутреннее имя
**Компонент:** js (`crates/js/src/dom.rs::WEB_API_SHIM` — 246 top-level `var`/`function _lumen_…`; регистрация нативов из Rust — `crates/js/src/v8_compat.rs::register_v8_native`/`register_v8_native_scoped`, 468 имён; плюс top-level объявления ~120 модульных шимов `crates/js/src/*.rs`)
**Найден:** P3, остаток при закрытии [BUG-378](BUG-378-FIXED.md) (2026-08-10)

## Симптом

После фикса BUG-378 внутренние имена невидимы для перечисления и неизменяемы, но
по-прежнему читаемы, если имя известно заранее. Проба
(`.tmp/probe378.html`, `--dump-layout`):

```
PROBE own=1518 internal_own=725      <-- own-свойств, подходящих под /lumen|^__/
PROBE enumerable=700 enumerable_internal=0
PROBE descriptor _lumen_get_attr = {"type":"function","writable":false,"enumerable":false,"configurable":false}
```

То есть `Object.getOwnPropertyNames(window)` и прямое обращение
`window._lumen_get_attr` выдают всю внутреннюю поверхность движка — 725 имён
против нуля в Chrome/Firefox.

## Причина

Шим обращается к нативам **поздно**: `_lumen_get_attr(nid, name)` — обычный
поиск по scope chain, который заканчивается глобальным объектом. Пока имя
резолвится так, оно обязано лежать на глобале, поэтому BUG-378 смог сделать его
только скрытым и неизменяемым, но не отсутствующим.

## Влияние

**Отпечаток.** Приватность — заявленная ценность проекта, а одного
`typeof window._lumen_query_selector_scoped === 'function'` достаточно для
стопроцентного опознания Lumen независимо от User-Agent и от защит
`surface_api.rs`. Это единственное оставшееся следствие BUG-378: подмена
(перезапись/удаление) и перечислимость закрыты, спека `for (k in window)`
соблюдена.

## Как чинить

Пункт 1 из «Как чинить» [BUG-378](BUG-378-FIXED.md): обернуть `WEB_API_SHIM` в
IIFE и экспортировать в глобал только web-видимые имена (~110 штук: `document`,
`location`, `fetch`, `Element`, `Event`, `Node`, `URL`, …; список получается
фильтром top-level объявлений шима по префиксу `_`). Нативы, регистрируемые из
Rust, передавать шиму аргументами IIFE (или одним неперечисляемым
объектом-контейнером, удаляемым с глобала после установки) — захват в замыкание
попутно снимает и позднее связывание.

Прецедент меньшего масштаба, который уже работает:
[`crate::file_input::seal_file_natives_v8`](../crates/js/src/file_input.rs)
(BUG-371) именно так и делает — оба file-API шима копируют нативы в замыкание на
установке, после чего `install_dom` **удаляет** имена с глобала. Задача — тот же
приём для всего движка.

## Заметки

- Главная трудность не в самом шиме, а в его потребителях: модульные шимы
  (`crates/js/src/*.rs`, ~120 файлов) обращаются к внутренним именам шима
  напрямую по имени (`_lumen_make_element`, `_lumen_element_wrappers`,
  `_lumen_headers_new`, `_lumen_body_source`, …). Под IIFE эти имена перестанут
  быть видимы, поэтому нужен явный внутренний контейнер, доступный шимам, но не
  странице, — то есть перестройка не одного файла, а всей границы
  «шим ↔ модульные шимы».
- **Не ломать инвариант BUG-378 при перестройке:** `WEB_API_SHIM` сейчас
  вычисляется через indirect eval именно для того, чтобы его top-level
  `var`/`function` попадали на глобал как `configurable` (у Script
  `GlobalDeclarationInstantiation` передаёт `D = false`, и снять `enumerable` с
  такого свойства нельзя вовсе). Под IIFE эти объявления вообще перестанут быть
  свойствами глобала, и indirect eval станет ненужен — но пока переход не
  сделан, отказ от него вернёт 247 перечисляемых имён. Страж —
  тест `internal_globals::tests::shim_has_no_top_level_lexical_declarations`.
- Смежное: [BUG-378](BUG-378-FIXED.md) (перечислимость и подмена — закрыты),
  [BUG-371](BUG-371-FIXED.md) (те же нативы для File System Access, закрыт
  удалением), [BUG-379](BUG-379-FIXED.md) (маркеры автоматизации
  `surface_api.rs` — 15 имён, создаваемых защитой от детекта).

## Срезы

**Срез 1 (2026-09-29): `WEB_API_SHIM` под IIFE.** `internal_globals::wrap_page_shim`
оборачивает собранный page-шим в функцию: ~1000 top-level `var`/`function`
становятся локалами, вызовы внутри шима связываются рано (по локалу, а не по
scope chain до глобала). Имена сканируются по колонке 0 (`function NAME` /
`var A, B = …`), пролог создаёт свойства на глобале до тела (шим сам делает
`defineProperty(globalThis, 'X', {enumerable:false})` и читает `window.X` при
загрузке), эпилог публикует финальные значения `var`. Публичные имена — обычные
data-свойства (как у eval-`var`); внутренние и любые `_x` — не перечислимые
аксессоры над локалом (запись из модульных шимов/Rust доходит до переменной шима;
seal-проход делает их непереконфигурируемыми, у функциональных снимает сеттер).
Побочный эффект: ~10 scratch-переменных циклов (`_dohi`, `_wohi`, …) больше не
торчат на глобале. Цена IIFE: шим читает переопределённое модулем имя по
локалу, а не по глобалу — найдены и исправлены `File` (structuredClone) и
`ValidityState`; **остаточный риск** — другие имена, которые модульные шимы
переопределяют (`Blob`, `ImageData`, `atob`/`btoa`, `Navigator`, `DOMRect`, …),
если шим читает их голыми после переопределения: правка — `globalThis.X` в месте
чтения.

**Срез 2 (2026-09-30): внутренний контейнер.** Вместо переписывания ~120 модульных
шимов границу «шим ↔ модульные шимы» держит один объект на контекст:
`internal_globals::install_container` (null-прототип, висит на глобале под
приватным символом V8 — из JS не достать, содержит ссылку на себя `__lumen_C`).
Что на нём лежит и как до него добираются:
- нативы из Rust (`register_v8_native*`) с внутренним именем (`__…`/`_lumen…`)
  регистрируются на контейнер, не на глобал;
- page-шим — функциональное выражение с параметром `__lumen_C`: свои
  `_`-имена экспортирует аксессорами на контейнер, уже лежащие нативы связывает с
  локалами заранее, а имена, на которые только ссылается (регистрирует позже
  какой-то `install_*`), получают локал + аксессор — позднее `container.x = fn`
  доходит до локала через сеттер;
- каждый **внутренний** `eval` (`JsRuntime::eval`, модульные шимы, Rust-сниппеты
  шелла, тесты) исполняется как `with (container) { … }`
  (`wrap_for_container`; контейнер передаётся одноразовым глобалом, который
  префикс читает и удаляет до тела скрипта). Граница страницы
  (`eval_and_report*`, модульные точки входа) не обёрнута — страница не видит ни
  `window._lumen_x`, ни голого `_lumen_x`;
- скрипт без единого имени-кандидата (`_`-префикс) не оборачивается вообще; со
  строгой директивой — тело уходит в строгую функцию под `with`; верхнеуровневые
  `class X` перепубликуются на глобал аксессором, верхнеуровневые `let`/`const` —
  скрипт запускается без обёртки;
- `window._lumen_x` / `globalThis._lumen_x` / `Object.defineProperty(globalThis,
  '_lumen_x', …)` в шимах, Rust-строках и тестах (~920 мест) переписаны на
  `__lumen_C._lumen_x` — sed по префиксу `_lumen|_LUMEN|__lumen`; scratch-имена
  тестов `window.__got` и т.п. не тронуты.
Результат замера по `Object.getOwnPropertyNames(globalThis)` после `install_dom`:
внутренних имён **725 → 1**; оставшееся — `_lumen_import_meta_resolve` (его зовёт
преамбула `import.meta` в модульном коде, куда `with` не доходит); тест
`only_known_internal_names_remain_on_the_global` фиксирует это. Цена: `with`-скоуп
у внутренних `eval`-ов, номер колонки первой строки сдвинут на длину префикса
(`capture_call_site_reports_source_char_position` учитывает).

**Срез 3 (не сделан):** `import.meta.resolve` через хост-колбэк
`HostInitializeImportMetaObject` вместо текстовой преамбулы (снимает последнее имя
и глобал-модульные `var __$lumen_meta__`); проверить, нужен ли ещё
`SEAL_INTERNAL_GLOBALS` (перепись даёт ровно одно имя, так что скорее всего он
мёртв); `with` оставить только тем шимам, которые реально читают внутренние имена.
