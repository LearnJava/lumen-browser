# BUG-879 — значения import map не резолвятся относительно базового URL карты: относительный таргет даёт «module not found»

**Статус:** OPEN
**Заведён:** 2026-08-23 (WPT-RUN-6, срез 27 — живой замер, варианты `importmap`/`importmap-absolute`)
**Область:** `crates/js/src/esm.rs:148-151` — ветка (4) `resolve_specifier_with` отдаёт `import_map.resolve(name, Some(base))` наружу как есть, тогда как ветки (3)/(3b) выше резолвят относительный и root-relative спецификатор против базы; значение карты через них не проходит
**Владелец:** P1/P3 (`lumen-js`). Заведён P2 в ходе WPT-задачи, здесь не чинится.

## Симптом

Карта импортов сама по себе применяется — спецификатор подменяется. Но если
значение в карте относительное (`"./x.js"`, ровно та форма, которой написана
почти вся папка `import-maps/` в WPT), подменённый спецификатор дальше не
резолвится против базового URL документа, и импорт падает с
`Error: module './x.js' not found`; запроса за файлом нет. Абсолютное
значение (`http://host/x.js`) работает. Прямой `import('./x.js')` из того же
скрипта — тоже работает, то есть резолвинг сломан именно на выходе карты.

Побочно замерено: `import()` несуществующего модуля отклоняется обычным
`Error`, а не `TypeError`, как требует HTML LS; `HTMLScriptElement.supports`
отсутствует.

## Прямое измерение

`tests/wpt/verify_callback_import_preload_gaps.py --variant importmap-absolute`
(2026-08-23, dev-release, Linux, `main` = `34cbefd25`). Карта содержит два
ключа на один и тот же файл — абсолютный и относительный:

```
ima-abs-resolved mapped-module                                  ← абсолютный
ima-rel-rejected Error: module './vcip-mapped.js' not found     ← относительный
ima-plain-resolved mapped-module                                ← import('./vcip-mapped.js')
[server saw: GET /vcip-mapped.js]                               ← ровно один раз
```

## Цена по WPT

`import-maps/dynamic-module-map-key.html` — файл строит карту из скрипта и
импортирует по ключу; оба ключа относительные. Оставшиеся два id остатка в
`import-maps/` (`no-referencing-script-integrity*.html`) упираются раньше в
[BUG-630](BUG-630-OPEN.md) — их импорт запускается из `onload`-атрибута
`<img>`, которого движок не диспатчит. Категория целиком не вендорена, так
что настоящая цена больше измеренной.

## Что дальше

HTML LS «resolve a module specifier»: значение из карты — это URL,
разрешаемый относительно базового URL карты (то есть документа, если карта
инлайновая), и результат подстановки уже абсолютен. Достаточно резолвить
значение при разборе карты, а не при использовании.
