# BUG-426 — шесть действий хрома разобраны в пустую ветку: профиль, режим Фокус, архив-карточка, DevTools-вкладки

**Статус:** FIXED 2026-08-01 (документирован, не перереализован — см. «Закрыт»)
**Компонент:** shell (`crates/shell/src/main.rs` — `dispatch_chrome_action`),
chrome (`assets/chrome/chrome.html`, `crates/chrome/src/model.rs`)
**Найден:** P1, 2026-07-28, при разборе того, какие «подвиды» дизайна доступны
пользователю

## Симптом

Клик проходит хит-тест, действие резолвится — и не делает ничего. Пять
вариантов `ChromeAction` сведены в одну пустую ветку `=> {}`:

`SetProfile` · `ArchiveCard` · `ToggleSwitch` · `ToggleFocusTimer` ·
`ToggleFocus` · `SetDevtoolsTab`

Пользовательские последствия:

| Ось дизайна | Состояние |
|---|---|
| Профиль (Личный/Рабочий/Аноним/Гость) | поповер аватара открывается, выбор ничего не меняет |
| Режим Фокус | не включается |
| Тема (светлая/тёмная) | берётся только из тёмной темы ОС (`self.dark_mode`), в UI не переключается |
| Вертикальные/горизонтальные вкладки | состояние живёт и сохраняется (`vertical_tabs.visible`, `draft.tab_layout`), но единственный путь к нему — тумблер настроек, а он `ToggleSwitch` → [BUG-421](BUG-421-OPEN.md) |

При этом привязка состояний в DOM полностью готова: `bind_model`
(`crates/chrome/src/model.rs:570`) выставляет `body[data-theme]`,
`body[data-layout]`, `body[data-profile]`, а флип темы отдельно отслеживается
для перерисовки (`bind_model_tracked`, `["data-theme"]`). То есть не хватает
только обработчиков, а не поддержки состояний.

## Причина, зафиксированная автором среза

Комментарий на месте пустой ветки: все шесть тумблеров дизайна несут один и тот
же `data-action` без различающего атрибута, поэтому по одному `data-action`
нельзя понять, какую настройку переключили; структурный резолвер (по образцу
`chrome_permission_kind_for_node`) был вынесен за DoD среза.

## Что нужно сделать

1. В `scripts/gen_chrome_assets.py` проставлять различающий атрибут при
   инжекте — файл наш, генерация детерминированная (тем же приёмом, каким
   CC-13 инжектит `role`/`aria-*`).
2. Реализовать `SetProfile` (уже есть `ProfileRegistry`, DS-14) и `ToggleFocus`.
3. Дать теме UI-переключатель: `self.dark_mode` сейчас не имеет ни одной точки
   присваивания из UI.
4. `ArchiveCard` и `SetDevtoolsTab` — доработать или явно закрыть с
   обоснованием, если функциональности за ними нет.

## Закрыт 2026-08-01 (P1)

Переразбор показал: заявка объединила шесть действий в одну заявку по форме
дефекта («сидят в пустой ветке»), но у каждого — своя, не похожая на соседей
причина. Ни одно не оказалось «маленькой дырой в резолвере» вроде
[BUG-419](BUG-419-FIXED.md)/[BUG-420](BUG-420-FIXED.md)/[BUG-421](BUG-421-FIXED.md).
Различающий атрибут (пункт 1 исходного плана) для `SetProfile` и
`SetDevtoolsTab` **уже существует** в замороженном эталоне
(`data-profile`/`data-dt-tab`) — придумывать резолвер по образцу
`chrome_permission_kind_for_node` не потребовалось бы, но реализовывать
оказалось нечего:

1. **`SetProfile`** — `#profileMenu`/`.pm-item` в движковом хроме не просто не
   подключены, они принципиально недостижимы: CC-15-1
   (`docs/tasks/p1-css-chrome.md`) осознанно оставил переключатель профиля
   легаси-оверлеем (`panels::profile_menu::build_panel`, свой хит-тест в
   `WindowEvent::MouseInput`, вне `chrome_doc`), а не перенёс его на
   `ChromeModel`/`bind_model`. `#profileMenu` никогда не получает класс
   `.open` ни от какого кода — значит, у него нет layout-бокса, и хит-тест
   по движковому дереву никогда не достанет до `.pm-item`. `data-profile`
   на `<body>` уже и так синхронизирован с легаси-путём переключения (через
   `ChromeModel::profile_slug`), ровно как описывает обоснование CC-15-1.
2. **`ArchiveCard`** — две демо-карточки `.bm-card.readlater` внутри
   `#view-bookmarks`'s `.bm-grid` вычищаются на **каждом** релейауте:
   `bind_bookmarks` (`crates/chrome/src/model.rs`) вызывает
   `remove_children_with_class(doc, grid, "bm-card")`, а это совпадение по
   классовому токену — `.bm-card.readlater` тоже несёт токен `bm-card` и
   попадает под удаление; список отстраивается заново из
   `ChromeBookmarksModel::cards`, где понятия «readlater»/«archive-card»
   вообще нет. Разметка с этим `data-action` не доживает до первой отрисовки
   — код в пустой ветке для неё не «недоделан», а провably недостижим.
3. **`ToggleSwitch`** — тот же корень, что уже закрыл
   [BUG-421](BUG-421-FIXED.md): у оставшихся четырёх `.toggle` («Принудительный
   HTTPS», два ряда Extensions, QA «Стабильные test-id») нет ни одного
   реального поля состояния в шелле.
4. **`ToggleFocusTimer`/`ToggleFocus`** — единственная пара из шести, где
   реальное состояние **есть** (`self.focus: FocusModePanel`) и уже полностью
   интерактивно — но через другой легаси-оверлей
   (`panels::focus_panel::build_panel`, свой `MouseInput`/`FocusHit`
   хит-тест, рисуется безусловно при `self.focus.active`), а не через
   `chrome_doc`. Движковая `.focus-timer`-плашка в эталоне — простая
   (иконка + `MM:SS` + две кнопки), легаси-виджет — карточка с
   триангулированным SVG-кольцом прогресса; `<body>` никогда не получает
   класс `focus-mode`, так что у плашки нет layout-бокса. Подключить эти два
   действия по-настоящему значит либо рисовать оба виджета одновременно
   (визуальный дубль), либо снести кольцо-анимацию и перейти на плашку
   эталона — тот же по типу выбор «оставить легаси-оверлеем», что CC-15-1
   уже сделал для профиля, только для Focus mode это отдельное решение, не
   принятое в этом заходе. Follow-up, не багфикс этого масштаба.
5. **`SetDevtoolsTab`** — четыре статических ряда `.dt-tab` (Elements /
   Console / Network / Sources) в эталоне изображают многопанельный DevTools,
   которого у движка нет: `self.devtools_console: ConsolePanel` — только
   JS-консоль без per-tab данных для остальных трёх вкладок. Переключать
   нечего.

Комментарий на месте пустой ветки (`dispatch_chrome_action`) переписан:
объясняет причину для каждого из шести действий по отдельности вместо общего
«демо без бэкенда». Верхний doc-comment функции также обновлён — он был
времён CC-5/CC-6 и называл `SetSettingsSection`/`ShowView` неподключёнными,
хотя CC-10b их давно реализовал.
