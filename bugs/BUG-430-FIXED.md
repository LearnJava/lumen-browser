# BUG-430 — детерминированный CPU-гейт рисует `<img>` серой заглушкой, а не пикселями

**Статус:** FIXED 2026-08-22
**Компонент:** driver (`crates/driver/src/session.rs::run_pipeline` / `screenshot_cpu_rgba`)
**Найден:** P3, 2026-07-29 — остаток [BUG-429](BUG-429-FIXED.md) после того, как половина про
скрипты и Canvas 2D была закрыта.

## Симптом

Эталоны `graphic_tests/snapshots/cpu/18-images.png` и `19-object-fit.png` фиксируют серые
прямоугольники-заглушки, а не декодированные картинки. Гейт `cases::snapshot_cpu` поэтому
проверяет на этих страницах только геометрию боксов: полный отвал декодирования, выбора
источника или ресэмплинга пройдёт зелёным.

## Причина

`InProcessSession::run_pipeline` не грузит подресурсы вообще — ни `<img src>`, ни
`<link rel=stylesheet>`. В набор картинок, который `screenshot_cpu_rgba` отдаёт
`render_to_image_cpu`, после фикса BUG-429 попадают только canvas-битмапы; для `DrawImage` с
незарегистрированным ключом растеризатор рисует ту же серую заглушку, что и GPU-рендерер в
своём fallback-е (это задокументировано в шапке `crates/driver/tests/cases/snapshot_cpu.rs`).

## Масштаб

Работа больше, чем «дочитать файл»: помимо загрузки байтов и `lumen_image::decode` нужен выбор
источника — `srcset` (дескрипторы `w`/`x`), `<picture>`/`<source media|type>` — который сейчас
живёт в шелле (`crates/shell/src/main.rs`), а не в общем крейте. Плюс решение по политике:
детерминированный офлайн-гейт не должен ходить в сеть, значит поддерживать имеет смысл только
локальные (`file://`-относительные) источники, а сетевые — пропускать явно и шумно, как это уже
сделано для внешних `<script src>` (BUG-429).

## Что оказалось на самом деле (2026-08-22)

Оценка масштаба устарела в одной части: **picker уже общий**. `<picture>`/`srcset`/`sizes`
разрешает `lumen_layout::collect_image_requests` (`box_tree.rs::resolve_image_source`) — тот же
код, которым layout строит `BoxKind::Image { src }`, так что ключ запроса совпадает с
`DrawImage.src` по построению; шелл его и вызывает, ничего своего не пикая. В шелле оставалась
только `apply_intrinsic_size` — доставка размеров декодированной картинки обратно в DOM.

## Фикс

Три части:

1. **`apply_intrinsic_size` → `lumen-layout`** (`box_tree.rs`, рядом с picker-ом, чей
   `ImageRequest` она обслуживает). Тело без изменений; шелл зовёт её из общего места. Иначе
   спец-правило BUG-269 (недостающая сторона считается по intrinsic aspect ratio) существовало
   бы в двух расходящихся копиях.
2. **`InProcessSession` грузит локальные подресурсы-картинки.** `<img>` — в `run_pipeline`
   **до** layout (intrinsic-размер это вход layout-а: без него бокс с `height: auto`
   схлопывается в ноль); `background-image` / `list-style-image` / `content: url()` — в
   `layout_and_commit` после layout, так как их URL известны только по готовому дереву
   (`collect_background_image_requests`, DPR 1.0 — как у `build_display_list_ordered`).
   Декодирует `lumen_image::decode` (PNG/JPEG/GIF-кадр-0/WebP/AVIF), повторный URL читается и
   декодируется один раз, intrinsic-размер применяется поэлементно. Карта чистится на навигации.
3. **Политика офлайн-пути.** Читаются только локальные источники. `http(s)`/`data:`/`blob:` и
   любой относительный URL на странице без локальной базы (`navigate_html`, http-страница)
   пропускаются со счётчиком в stderr — так же, как внешние `<script src>` (BUG-429); бокс при
   этом остаётся с серой заглушкой. `loading="lazy"` здесь не откладывается: в этом пайплайне
   нет ни скролла, ни второго прохода, отложить = не загрузить никогда.

Тот же набор картинок отдаётся и GPU-ветке `screenshot` (`--no-default-features`,
`register_image`), чтобы два headless-пути не расходились.

## Результат

Эталоны `graphic_tests/snapshots/cpu/` перегенерированы; изменились ровно пять страниц —
`18-images`, `19-object-fit`, `1000000-final` (`<img>`), `53-background-origin`,
`59-image-set-cross-fade` (background-image). Все пять теперь показывают реальные пиксели:
`18-images` — PNG/JPEG/WebP, `srcset`-кандидаты и `<picture>`; `19-object-fit` — реальные
кадрирования `contain`/`cover`/`fill`/`none`/`scale-down`; `53-background-origin` — разные
точки привязки фона для `border-box`/`padding-box`/`content-box` (страница впервые показывает
то, ради чего написана). Две ячейки `cross-fade() 30%`/`70%` на `59` остаются пустыми — это
корректно: беспрефиксная 3-аргументная форма невалидна по CSS Images L4 §4 и отбрасывается,
как в Edge (решение BUG-101, закреплено тестом
`collect_bg_image_unprefixed_legacy_cross_fade_collects_nothing`).

Гейт: `crates/driver/tests/cases/subresource_images.rs` — 6 тестов на свойства, которые были
сломаны (пиксели дошли до растера, intrinsic-размер дошёл до layout, фон дошёл до растера,
сетевой источник не качается, относительный URL без базы не резолвится, навигация сбрасывает
картинки прошлой страницы), а не на равенство снэпшоту.

## Остаётся за рамками

`<link rel=stylesheet>` этот путь по-прежнему не грузит (`extract_style_blocks` читает только
инлайновые `<style>`) — отдельный дефект того же класса, здесь не трогался.
