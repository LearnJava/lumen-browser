# BUG-1584 — Пока идёт CSS-анимация и работает цикл `requestAnimationFrame` либо вторая анимация, таймеры (`setTimeout`/`setInterval`/`MessageChannel`) не срабатывают до конца анимации

**Статус:** OPEN
**Заведён:** 2026-10-09 (P2, WPT-RUN-14 срез 26, `css/css-page` + `css-animations` + `css-transitions` + `css-shadow` + `css-borders` + `css-scroll-snap`)
**Область:** shell/js (цикл событий движка и тики анимаций; возможна связь с ADR-016 rAF-путём, [BUG-935](bugs/BUG-935-OPEN.md) — не проверена)

## Симптом

Таймеры JS и сообщения каналов откладываются до конца ближайшей CSS-анимации, если одновременно работает ещё один источник кадров. rAF при этом идёт (63 кадра за 1,2 с), то есть поток не завис, а очередь макрозадач не обслуживается.

## Проба

`run_smoke.py` + testharness, замер `performance.now()`; во всех строках запись о CSS-анимации — `<div style="animation:o 4s linear">`, `@keyframes o{from{opacity:0}to{opacity:1}}`:

| что работает | ожидание `setTimeout` 800–1000 мс закончилось на | `setInterval(200)` за ~2,9 с |
|---|---|---|
| CSS-анимация 4 с + `f.animate(…, {duration:4000})` (5 запусков, 2 страницы) | 4106 / 4057 / 4084 / 4127 / 4094 мс | — |
| CSS-анимация 3 с + цикл rAF 2,5 с | 2553 / 2614 мс | 4 тика: 272…1449, затем 2615, 2924 |
| CSS-анимация 6 с + `f.animate(…, {duration:6000})` | 6071–6080 мс | 1 тик (6078 мс) |
| только CSS-анимация 3 с, без rAF | 2403 мс при ожидаемых 2300 (1500 + 800): нет голодания | 505, 793, 1253, 1520 мс (запаздывают, но идут) |
| только `f.animate(…)` или только transition, без CSS-анимации (контроль) | 1001–1090 мс | 4 тика за 1 с |
| ни одной анимации, цикл rAF (контроль) | 1302 мс | 250, 502, 753, … 2766 мс |
| `setTimeout(0)`, `setTimeout(100)`, `MessageChannel` при CSS-анимации 4 с + `f.animate` | 4063 мс (все три) | — |
| `f.animate(…).pause()` или `new Animation(…)` без `play()` рядом с CSS-анимацией | 1155 / 1045 мс (нет голодания) | — |
| CSS-анимация 4 с + `f.animate(…, {duration:100})` | 1110 мс (нет голодания) | — |
| CSS-анимация 3 с + `f.animate(…, {duration:500})` + `setInterval(200)` | 2768 мс | — |

Воспроизводится повторами (три и более запуска каждой строки); граничное условие — именно **идущая** вторая анимация или цикл rAF вместе с CSS-анимацией.

## Как найдено

WPT-RUN-14 срез 26: при разборе 20 TIMEOUT в `css-transitions`/`css-animations` (`events-001…006`, `transitioncancel-002/003`, `non-rendered-element-*`, `transition-zero-duration-with-delay`) пробы с `setTimeout` показали задержку таймеров; связь с этими id не доказана.

## Что делать

Выяснить, кто держит поток в обработчике кадра (тик `AnimationScheduler`/WAAPI-шима, цикл `pump_raf_engine_thread`), и вернуть управление очереди таймеров между кадрами. Сначала проверить связь с BUG-935.

## Как проверить

Проба выше; затем `css/css-transitions/events-001.html` и `events-002.html`.
