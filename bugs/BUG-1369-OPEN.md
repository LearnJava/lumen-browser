# BUG-1369 — `line-height` меньше высоты глифов: отрицательное полу-ведущее отбрасывается, глиф не поднимается над строкой

**Статус:** OPEN
**Заведён:** 2026-10-07 (P2, WPT-RUN-14 срез 14, `css/CSS2` (text, linebox, fonts, generated-content, lists, bidi-text))
**Область:** layout (`crates/engine/layout/src/box_tree/` — выбор базовой линии/вертикального положения сегмента в строке при `line-height` < content-area шрифта)

## Симптом

`font: 20px/1 Ahem; margin:0`, три `div` с `X` (`#a` — `line-height:0` на `y=0`; `#b` — `1px`, `margin-top:60px`; `#c` — `2`, `margin-top:60px`); `--dump-display-list`:

| `line-height` | высота строки | `y` `DrawText` | ожидается |
|---|---|---|---|
| `0` | 0 | `0.00` | `-10.00` — полу-ведущее `(0 − 20) / 2` |
| `1px` | 1 | `60.00` (верх бокса) | `50.50` — `(1 − 20) / 2` над верхом |
| `2` | 40 | `+10.00` от верха бокса | `+10.00` — верно, `(40 − 20) / 2` |

CSS 2.1 §10.8.1: полу-ведущее = `(line-height − content area) / 2`; при `line-height` меньше content-area оно **отрицательное**, и глиф выступает за строку сверху и снизу. Lumen положительное считает верно, отрицательное зажимает в 0: глиф стоит у верха бокса и выпирает только вниз.

## Как найдено

WPT-RUN-14 срез 14: `linebox/line-height-*` (41 id): тест — квадрат Ahem при `line-height: 0|1px|-…`, эталон — абсолютно позиционированный `div` с высотой 1em/21px; у Lumen квадраты не встают рядом (`line-height-002.xht`: тестовый квадрат на 10 px ниже, чем должен). Пробы выше — отдельная страница.

## Что делать

Привести расчёт вертикального положения сегмента в строке к CSS 2.1 §10.8.1: `top = line_top + (line_height − (ascent + descent)) / 2` для каждого inline-бокса без зажима снизу нулём. Проверить `BoxKind::InlineRun` в `layout_dispatch.rs`/`inline_wrap.rs`, где считается `y` фрагмента.

## Как проверить

`css/CSS2/linebox/line-height-002.xht`, `line-height-003.xht`, `line-height-004.xht`.
