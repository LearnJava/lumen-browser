# BUG-1035: блокировщик рекламы (EasyList) блокирует 100% первосторонних JS-чанков duckduckgo.com — сайт нефункционален с рекламоблокировщиком по умолчанию

**Статус:** OPEN
**Компонент:** shields/adblock (правило-мэтчер EasyList, конкретный файл не
локализован — нужен разбор, какое именно правило матчит эти URL)
**Найден:** P1, THREAD-3 срез 1, 2026-09-08, живой `--bidi-port --maximized`
(блокировщик включён по умолчанию, как у обычного пользователя)

## Симптом

При открытии `https://duckduckgo.com/` в живом окне с настройками по
умолчанию (блокировщик рекламы включён — персистентная настройка «Блокировать
рекламу», как у настоящего пользователя) **абсолютно все** JS-чанки страницы
(её собственный Next.js/turbopack бандл, first-party
`duckduckgo.com/static-pages/home-desktop/_next/static/chunks/*.js`)
блокируются EasyList:

```
✗ https://duckduckgo.com/static-pages/home-desktop/_next/static/chunks/04t-5vp__6gfz.js (easylist)
Пропуск скрипта ...: network error: blocked: easylist
✗ https://duckduckgo.com/static-pages/home-desktop/_next/static/chunks/11g2fku5av7k~.js (easylist)
... (все ~25 чанков без исключения)
```

Без единого работающего чанка клиентское приложение duckduckgo.com не
гидрируется вообще — сайт остаётся на SSR-скелетоне (тот же класс UX-отказа,
что описан для `tbank.ru` в BUG-703, только полный, а не частичный).

## Почему это баг, а не ожидаемая блокировка

Это не сторонняя телеметрия/трекер — это **собственный** код приложения
(first-party origin, `_next/static/chunks/` — стандартный путь сборки
Next.js). Ложное срабатывание того же класса, что уже задокументировано в
BUG-800 (EasyList ложно матчит WPT-инфраструктурные URL) и в BUG-438
(тихий отказ навигации от блокировки маскируется под «страница не
работает») — обе записи FIXED для своих доменов (WPT test-runner), но общий
паттерн «EasyList слишком агрессивно матчит легитимные first-party пути по
имени файла» остаётся неисправленным как класс.

## Что уже исключено

- Не сетевая проблема — с `LUMEN_NO_ADBLOCK=1` те же URL успешно грузятся
  (`← 200 .../04t-5vp__6gfz.js`, `Загружен скрипт: ...`) на том же движке в
  той же сессии.
- Не путаница с БЛОКИРОВЩИКОМ основного зависания — see
  [BUG-1034](BUG-1034-OPEN.md): зависание (CPU-спин) на duckduckgo
  воспроизводится и без adblock (`LUMEN_NO_ADBLOCK=1`), то есть это два
  независимых дефекта на одном сайте, не один и тот же корень.

## Не сделано в этом срезе

Не локализовано, КАКОЕ именно правило EasyList матчит эти пути (список
110960 правил, конкретный паттерн не вычленён) — нужен трейс блокировщика
(судя по выводу движка `network error: blocked: easylist`, точка блокировки
известна архитектурно, но не показывает совпавшее правило; для локализации
нужен диагностический режим, печатающий id/паттерн сработавшего правила, или
бисекция списка правил на минимальный воспроизводящий поднабор).

## Как воспроизвести

```
target/dev-release/lumen.exe --bidi-port 9333 --maximized --health-log
# в другом терминале — BiDi-навигация на https://duckduckgo.com/, или просто
# открыть сайт в обычном окне с настройками по умолчанию
# → все ~25 чанков *_next/static/chunks/*.js помечены "(easylist)" в stderr
```
