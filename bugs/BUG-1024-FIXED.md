# BUG-1024 — `html/canvas`: два `--check` подряд на свежем baseline дают два РАЗНЫХ, растущих набора регрессий

**Статус:** FIXED 2026-09-08 (P3)
**Заведён:** 2026-09-07 (P2, WPT-RUN-7 срез 21 — `html/canvas`, продолжение среза 20)
**Область:** не локализован. Регрессии рассыпаны по несвязанным подкаталогам
(`element/manual`, `element/fill-and-stroke-styles`, `offscreen/fill-and-stroke-styles`,
`offscreen/path-objects`, `element/path-objects`, `offscreen/transformations`,
`offscreen/compositing`, `element/pixel-manipulation`, `element/drawing-rectangles-to-the-canvas`
и др.) — никакого одного общего файла-знаменателя, в отличие от BUG-1022
**Владелец:** P1/P3 (после локализации)

## Симптом

`--update-expected --all --root html/canvas --recursive --processes 6` прошёл штатно
(**4 мин 32 с**, 3216/3308 harness OK, 945/5433 сабтестов, 2592 новых `.ini`). Два
последовательных `--check` на том же бинаре и том же свежезаписанном baseline, без
изменений между прогонами (`--processes 6` в обоих):

- прогон 1 (**4 мин 32 с**): **124 регрессии**, 166 unexpected pass, 0 other deviations
  (`.tmp/wpt-canvas-check1.stdout.log`);
- прогон 2 (**4 мин 18 с**): **140 регрессий**, 215 unexpected pass, 0 other deviations
  (`.tmp/wpt-canvas-check2.stdout.log`).

Растущий, а не колеблющийся счётчик (124 → 140), как в BUG-1022 (6 → 19 → 27), но здесь на
крупнейшей категории, где эта находка воспроизведена (3308 id против 2223 у BUG-1022).
Наборы регрессий пересекаются лишь частично: из 124+140 записей только 78 общие, 46
встречаются только в прогоне 1 (в прогоне 2 та же пара subtest вернулась к expected PASS),
62 — только в прогоне 2 (новые, отсутствовавшие в прогоне 1). Общий класс с BUG-1003/1004/
1005/1011/1022 подтверждён и на этой категории отдельным симптомом: заметная доля
`unexpected pass` (65 из 166 в прогоне 1) — это `offscreen/*.html`-тесты, у которых baseline
записал FAIL с `ReferenceError: OffscreenCanvas is not defined` (см. хвост
`.tmp/wpt-canvas-update.stdout.log`), а на следующем прогоне тот же тест на том же бинаре
неожиданно PASS — то есть глобал `OffscreenCanvas` виден не на каждом прогоне одного и того
же теста. Это может быть частным случаем общего механизма (расширяет гипотезу BUG-1022 о
утечке ресурсов конкретным наблюдаемым симптомом — гонка при установке глобала), а может
быть отдельной причиной; не разделено. Обратной связи «только offscreen» нет: 81 из 124
регрессий прогона 1 — вне `offscreen/`, в равно раскиданных `element/*`-подкаталогах.

Baseline `html/canvas` не закоммичен — `.ini`-файлы, записанные `--update-expected`, откачены
`git clean -fd tests/wpt/metadata/html/canvas/` до исходного (отсутствующего) состояния этим
же срезом.

## Почему это важно

Тот же класс находки, что [BUG-1003](BUG-1003-OPEN.md)/[BUG-1004](BUG-1004-OPEN.md)/
[BUG-1005](BUG-1005-OPEN.md)/[BUG-1011](BUG-1011-OPEN.md)/[BUG-1022](BUG-1022-OPEN.md)
(«N `--check` подряд без изменений между ними дают N разных наборов регрессий»), теперь на
самой крупной из проверенных категорий (3308 id) — при этом отличается от BUG-1022 тем, что
у растущего счётчика нет ни одного стабильного общего знаменателя-файла: регрессии рассеяны
по десятку несвязанных подкаталогов сразу, что говорит скорее в пользу ресурсной/нагрузочной
гипотезы (утечка портов/хендлов/памяти внутри одного `run_report.py`-прогона, растущая с
числом обработанных тестов), чем в пользу конкретного сломанного теста или общего хелпера.
Частный симптом `OffscreenCanvas is not defined` то появляющийся, то нет, на одном и том же
тесте между прогонами — самая конкретная зацепка на сегодня для локализации: указывает на
гонку при экспонировании глобала в контексте offscreen/worker, а не на общий износ ресурса,
раз оба класса симптомов (offscreen-специфичный и general element/*) присутствуют
одновременно.

## Воспроизведение

```
tests/wpt/.venv/bin/python tests/wpt/run_report.py \
  --binary target/dev-release/lumen --all --root html/canvas --recursive \
  --processes 6 --update-expected
tests/wpt/.venv/bin/python tests/wpt/run_report.py \
  --binary target/dev-release/lumen --all --root html/canvas --recursive \
  --processes 6 --check
# повторить --check несколько раз подряд без изменений между прогонами — набор регрессий
# не совпадает и растёт от раза к разу (124 → 140 на первых двух)
```

## Что не проверялось

- Третий/четвёртый `--check` подряд — есть только две точки, тренд опирается на минимальную
  выборку (как и в BUG-1022 на трёх точках).
- Изоляция симптома `OffscreenCanvas is not defined` конкретно (какой из ~65 задетых файлов
  ловит его детерминировано в изоляции через `run_smoke.py` в цикле, как это сделано для
  BUG-1011) — не делалось.
- Не сравнивалось поведение при последовательном (без `--processes`) прогоне, как это сделано
  в BUG-1011 для `html/rendering`, и не проверялось, растёт ли счётчик быстрее/медленнее при
  другом числе `--processes`.

## Не проверялось (категория)

Осталось крупных под-путей `html/*` без baseline: `semantics` 2223 (заблокирован BUG-1022),
`browsers` 759 (самый грязный), `rendering` 150 (заблокирован BUG-1011). `html/canvas`
(3308 id, крупнейший из проверенных) остаётся без baseline из-за этой находки.

## Локализация и фикс (2026-09-08, P3)

**Причина не в WPT-харнессе и не в утечке ресурсов — она в движке, и математически
детерминирована; флак давал не сам рендер, а внешний, накладываемый на его результат
слой.** Изоляция `run_smoke.py` в цикле (без `--processes`, один процесс на запуск —
методика BUG-1011) воспроизвела дефект на ДВУХ независимых, ничем не связанных файлах вне
`offscreen/*` без единого общего подкаталога:
`element/transformations/2d.transformation.scale.basic.html` (fillRect + `scale()`, без
`fillStyle`-парсинга вовсе) — 7-8 из 8 повторов дают Wrong-channel `±1` (то R, то G, то B,
без видимой закономерности); `offscreen/fill-and-stroke-styles/2d.fillStyle.parse.hsla-clamp-4.html`
— 6 из 8. Оба теста заливают `fillRect` ЦЕЛИКОМ покрывающий канвас и читают пиксель глубоко
внутри (не на кромке) — при честном рендере результат обязан быть бит-в-бит одинаковым
каждый раз.

**Пруф, что сам рендер детерминирован:** временный `#[test]` в `crates/engine/canvas`,
5000 итераций `Context2D::fill_rect` в ОДНОМ процессе (`cargo test --release`) — 0
несовпадений. Ручной разбор `crates/engine/canvas/src/rasterize.rs` (покрытие AA,
`fill_shapes`/`coverage_row`/`add_span`) и `crates/engine/canvas/src/lib.rs::composite_pixel`
подтверждает: для заливки, покрывающей весь канвас, и пикселя вдалеке от кромки каждое
слагаемое — точная степень двойки (`AA_ROWS=4`, вес `0.25`), путь бит-точен по построению.

**Настоящий источник — анти-fingerprinting шум `getImageData` (ADR-007 layer 4,
`docs/plan/privacy.md` §9.5, введён [BUG-454](BUG-454-FIXED.md) 2026-08-31), включённый по
умолчанию даже в профиле Standard.** `crates/js/src/canvas2d.rs::session_seed()` сидирует
`CanvasNoiseGenerator` смесью `SystemTime::now()` и `std::process::id()` — значением, которое
меняется при КАЖДОМ запуске бинаря `lumen` (стабильно внутри одной сессии/процесса, что и
объясняет, почему `cargo test`-пруф внутри одного процесса ничего не показал). `_assertPixel`
у `canvas-tests.js` не допускает никакого допуска (`assert_equals`, не
`assert_approx_equals`) — спека требует бит-точного `getImageData()` для этого класса тестов,
а шум даёт `±1`/канал почти на каждый прочитанный пиксель. Растущий/несовпадающий набор
регрессий между `--check`-прогонами (124 → 140, затем 168 при повторной проверке этим
срезом) — не накопление ресурса, а просто новый случайный сид при каждом перезапуске
`lumen`-процесса воркером `wptrunner`. Частный симптом «`OffscreenCanvas is not defined»
то есть, то нет» из исходной находки — это НЕ часть этого механизма: worker-контекст
никогда не устанавливает `OffscreenCanvas` вовсе (`crates/js/src/worker.rs:1699-1707`,
задокументированный, стабильный, не флакующий гэп — уже заведён отдельно как
[BUG-937](BUG-937-OPEN.md)); `unexpected pass` на baseline-прогоне объясняется тем же
самым, чем и весь остальной флак — просто эти сабтесты угадали `±0` смещение на своём сиде.

**Фикс:** три места установки шума (`crates/js/src/canvas2d.rs` — element-canvas
`_lumen_canvas2d_create`; `crates/js/src/offscreen_canvas.rs` — `arm_noise()` +
`_lumen_offscreen_canvas_new`) теперь пропускают `set_noise_generator`, когда
`LUMEN_DISABLE_CANVAS_NOISE` установлена (новая функция `canvas2d::canvas_noise_enabled()`,
`OnceLock`-кэш одного чтения env). В обычном браузере переменная не установлена — поведение
не меняется, привацы-модель ADR-007 не тронута. `tests/wpt/run_smoke.py` теперь сам
проставляет `os.environ.setdefault("LUMEN_DISABLE_CANVAS_NOISE", "1")` при импорте, поэтому
и он, и `run_report.py` (который переиспользует его `run()`) включают это для КАЖДОГО
запущенного `lumen`-процесса без явного участия вызывающего.

**Верификация:** 16/16 изолированных повторов (`run_smoke.py` × 8 на каждый из двух файлов
выше) — 0 несовпадений при включённом фиксе (было 6-8/8 до него на тех же файлах). Полный
цикл на всей категории: `--update-expected` (`--processes 6`) дал 1664/5433 сабтестов PASS
(было 944/5433 без фикса на том же коде — шум портил и часть baseline, не только
воспроизводимость), ДВА последовательных `--check` дали **0 регрессий, 0 unexpected pass,
0 other deviations** каждый (было 124 → 140 → 168 без фикса). Baseline `html/canvas`
закоммичен этим фиксом (2585 `.ini`, `tests/wpt/metadata/html/canvas/`) — впервые для этой
категории. `cargo build -p lumen-shell --profile dev-release` чист; `cargo clippy` не
прогнан workspace-целиком на этой машине (`rustc` 1.98.1 системный вместо пина 1.97.0, нет
rustup — падает на несвязанных файлах `lumen-image`/`lumen-font`, известная ловушка
CLAUDE.md), крейты `lumen-canvas`/`lumen-js` без изменённого diff'а не показывают новых
предупреждений при точечном чтении.

**Остаток:** `unexpected pass` внутри самого baseline-прогона больше не наблюдался (0/0 на
двух `--check`), но абсолютное число PASS (1664/5433) далеко от 100% — подавляющее
большинство FAIL/TIMEOUT остатка — реальные, не связанные с этим багом гэпы движка
(canvas-фичи, которых ещё нет), не предмет этой находки.
