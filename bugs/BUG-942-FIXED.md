# BUG-942 — Mojibake baked into `crates/shell/` string literals and comments (CP1251-as-UTF-8 double encoding)

**Статус:** FIXED 2026-09-01
**Компонент:** shell (90 файлов под `crates/shell/`, включая рантайм-строки `println!`/`eprintln!`)
**Найден:** 2026-09-01, при разборе жалобы пользователя «почему лог не по-русски» (скриншот `lumen.exe https://otr.ru`)

## Симптом

Часть текста, который печатает браузер (и часть doc-комментариев в исходниках),
на самом деле не «русский текст, криво показанный консолью», а **испорченные
байты, закоммиченные в git**. Пример — `crates/shell/src/dump_mode.rs:596` и
`crates/shell/src/page_pipeline.rs:522`:

```rust
eprintln!("РљРѕРґРёСЂРѕРІРєР°: {}", encoding.name());
```

Байтово внутри строкового литерала лежала не «Кодировка», а другая
последовательность кодпоинтов — подтверждено на уровне git blob
(`git show <rev>:crates/shell/src/dump_mode.rs`, `xxd`), это был не артефакт
отображения инструментом чтения.

Механизм порчи: исходный корректный UTF-8 текст был **прочитан как CP1251 и
заново сохранён как UTF-8** — один или два раунда такого round-trip. Пример на
тире: `—` (U+2014, UTF-8 `E2 80 94`) → прочитан как CP1251 → `в` (U+0432) +
`Ђ` (U+0402) + `”` (U+201D) → сохранён как UTF-8 = `вЂ”`.

## Не является причиной

Консольная кодовая страница Windows (`chcp`) — отдельная, реальная проблема
(корректно закодированный UTF-8 тоже бьётся консолью с кодовой страницей не
65001), но она не объясняла этот симптом: строки вроде «Кодировка» были
испорчены на уровне закоммиченных байтов, никакой `SetConsoleOutputCP`/
`chcp 65001` их не восстановил бы. Фикс для консольной кодовой страницы внесён
отдельно (`crates/shell/src/main.rs::set_console_utf8`, коммит `1782bb596`,
до этого бага) — лечит только корректно закодированный, но неверно
отображаемый вывод, не пересекается с этим багом.

## Фикс

Механическое восстановление скриптом (не закоммичен, одноразовый инструмент):
для каждого максимального фрагмента не-ASCII символов пробовать
`run.encode('cp1251').decode('utf-8')` и заменять фрагмент результатом при
успехе, повторяя до фикспоинта (для дважды испорченных фрагментов). Метод
проверен как безопасный на реальных примерах ДО массового прогона: корректно
закодированная кириллица и настоящее тире (`распознан`, `Кодировка
определена`, `smart quote — fixed`) гарантированно проваливают round-trip
(`UnicodeDecodeError`), то есть остаются нетронутыми, а испорченные строки
успешно восстанавливаются.

Один нюанс, найденный в процессе: часть слов (пример — `ЖИВОГО` в
`main.rs`) была испорчена ДВАЖДЫ, и на одном из промежуточных раундов байт
попал в неопределённый диапазон CP1251 (0x80–0x9F), из-за чего строгий
Python-кодек `cp1251` отказывался кодировать этот символ обратно и фикспоинт
останавливался на полпути. Кодек расширен: неопределённые байты 0x80–0x9F
кодируются как есть (identity passthrough) — реальный текст практически
никогда не содержит буквальных C1-control-символов, так что риска спутать
корректный текст с мусором это расширение не добавляет. После этого
повторный прогон почистил все 25 оставшихся файлов, третий прогон дал 0
изменений (фикспоинт подтверждён).

Затронуто 90 файлов, только `crates/shell/` — весь остальной workspace
(`layout`, `paint`, `css-parser`, `js`, `network`, …) не задет. Изменения
только в комментариях и текстовых строковых литералах (`println!`/
`eprintln!`/doc-комментарии) — идентификаторы, код, структура файлов не
менялись (дифф — построчная замена содержимого, число строк не изменилось).

**Верификация:** `cargo check -p lumen-shell`, `cargo clippy -p lumen-shell
--all-targets -- -D warnings` чисто. Изменения не затрагивают paint/layout —
полный графический прогон не требуется.

## Не выяснено

Источник порчи (какой инструмент/сессия читал UTF-8 как CP1251 при
сохранении) не установлен — новые правки в этой же сессии (тот же файл
`main.rs`, добавленный doc-комментарий с `—`/`→`/`…`) были закодированы
корректно, то есть это исторический артефакт (самая старая проверенная
строка — из коммита `50efa9109d`, 2026-08-25), а не текущий, воспроизводимый
в этой среде риск.
