# BUG-103

**Статус:** OPEN (KNOWN_DEBTOR, класс «артефакт тайминга захвата Edge» — как BUG-199/BUG-126)
**Компонент:** js / shell
**Файл:** `crates/js/src/view_transitions.rs`, `crates/shell/src/main.rs` (view_transition cross-fade)

## Описание

View Transitions API L1 **реализован и рендерится** (ревизия F2-4, 2026-06-22):
`document.startViewTransition(callback)` возвращает корректный `ViewTransition`
(updateCallbackDone/ready/finished/skipTransition), шелл снимает `old_dl` на `Begin`
и кросс-фейдит его над новым display-list на `End` (300 ms). Проверено CPU-снимком
(`--screenshot`) и детерминированным `--ipc`-прогоном: страница рисуется правильно.

**Прошлый «99.53%» был артефактом** — пустой gdigrab-захват (белый кадр, регион во весь
экран = сигнатура blank-capture). Реальный детерминированный diff (`run.py --only 61 --ipc`)
= **10.71%**, и тот распадается на:

1. **Тайминг захвата Edge (доминирует, ~8.5% страницы).** По спеку update-callback
   `startViewTransition` асинхронный (выполняется на шаге «update the rendering»). Edge
   headless `--screenshot` снимает кадр ДО срабатывания callback → видна СТАРАЯ DOM
   (card1 «Before» active) + уже выполненный синхронный код (зелёный лог). Lumen рендерит
   **устоявшееся** состояние после callback (card2 «After» active) — спек-корректно и
   полезнее как инструмент рендера. Воспроизвести кадр Edge можно лишь намеренно
   ПРОПУСКАЯ view-transition callback в снимке (тогда ЛЮБАЯ страница с startViewTransition
   рисовала бы устаревшее состояние) — это хуже, чем один debtor. Тот же класс, что
   TEST-71 (BUG-199) и TEST-77 (BUG-126).
2. **Font-parity текста (rule 3).** Заголовок + строка лога рендерятся Inter vs Edge UI-шрифт.

**gdigrab для этой страницы flaky** (то ~11% хороший кадр, то ~100% пустой) — мерить надо
детерминированным `--ipc`. Baseline в `KNOWN_DEBTORS` оставлен 99.53 (gdigrab-blank-safe).

## Регрессия TEST-61, замерена 2026-08-04 (P3, попутно к BUG-128 ч.2)

Полный прогон 2026-07-31 (коммит `1bde65105`) писал TEST-61 = **5.1986%** при
записи `KNOWN_DEBTORS['61'] = ('BUG-103', 5.16)`. Сейчас тест даёт **11.2–11.4%**,
то есть ратчет («регрессия, если > baseline + 2 п.п.») красный и полный прогон
на этом тесте останавливается.

**Это не BUG-128.** A/B тремя сборками в одном worktree (`p3-work`, тот же
дисплей, те же эталоны), по три прогона на сборку — числа детерминированные,
не флейк:

| Сборка | TEST-61 |
|---|---|
| `c1ff90449` (main ДО влития BUG-128 ч.1) | 11.37% |
| `b869b2791` (main С BUG-128 ч.1) | 11.35% |
| ветка BUG-128 ч.2 (`serif` по умолчанию) | 11.21% |

Регрессия предсуществует обеим частям BUG-128 и приехала где-то между
2026-07-31 и 2026-08-04 — окно, в котором TEST-61 никто не гонял (`--only`-
прогоны не переписывают `results/latest.json`, а полный прогон в этом окне не
делался). Baseline **намеренно не поднят**: поднять его = спрятать регрессию.

Что делать дальше: бисект по мержам окна `1bde65105..c1ff90449` с
`run.py --only 61`. Страница анимационная (300 ms cross-fade), поэтому кандидат
номер один — что-то, сдвинувшее фазу кадра на захвате (планировщик анимаций,
поток движка, тайминг презента), а не рендер сам по себе.

**Опционально (XL, не валидируется TEST-61):** полный L1 — захват NEW-снимка + именованные
группы `view-transition-name` (морф) + проводка псевдо `::view-transition*` в paint с учётом
авторского `animation-duration`. Текущая реализация — упрощённый root cross-fade.

## Бисект регрессии завершён 2026-08-05 (P3) — не дефект, снятие маскировки

Виновный коммит найден бисектом по окну `1bde65105..c1ff90449` (сборки на
`d8f3cea94` и `0bbab3c35` в изолированном worktree, `run.py --only 61` на
каждой): **`0bbab3c35` (S12b-G5, «порт view_transitions/cookie_store на V8»,
2026-08-04)**. Родитель `d8f3cea94` даёт ровно 5.16% (совпадает с baseline),
сам `0bbab3c35` — 11.37%.

Причина — не регрессия рендера, а исчезновение случайной маскировки:

- **До `0bbab3c35`** (то есть на V8 уже как единственном движке, но до этого
  батча S12b-G) `install_view_transition_bindings` не была портирована на V8
  вовсе — `document.startViewTransition` был `undefined`. Живая проверка
  (скриншот страницы) это подтверждает буквально: лог-строка на странице
  показывает «`document.startViewTransition not available (Phase 0 stub
  missing)`», карточка «Before transition» (card1) остаётся активной — ровно
  то состояние, что и ловит headless-Edge по своей собственной, уже описанной
  выше причине (Edge снимает кадр ДО async update-callback). Два независимых
  бага («API не существует» + «Edge ловит кадр до callback») случайно давали
  почти совпадающие кадры → маленький diff (5.16%).
- **`0bbab3c35`** правильно портирует API на V8 (закрывает реальные регрессы
  BUG-545/BUG-546) — теперь `startViewTransition` работает, callback
  выполняется, кросс-фейд реально проигрывается, и Lumen корректно
  устаивается в card2-active («After transition»), как и было до V8-миграции
  под QuickJS. Это ровно спек-корректное поведение, уже описанное в разделе
  выше как основной остаток («тайминг захвата Edge»). Просто теперь оно не
  маскируется вторым, независимым дефектом — diff вырос до полного размера
  этого класса расхождения (~10.6%).

**Проверка, что сама кросс-фейд-анимация не глючит:** живой probe (debug-принты
в `render`/`Begin`/`End` временно добавлены и удалены, не закоммичены) на
тёплом wgpu-состоянии показывает монотонную сходимость `alpha: 0.995 → 0.152 →
0.113 → 0.090 → 0.049 → 0.020 → 0.000` за ~313 ms — в пределах заявленных 300 ms
и намного меньше `LIVE_SETTLE_SEC=1.5s`, которые `run.py` ждёт перед gdigrab.
К моменту снимка кросс-фейд давно закончился и `view_transition` очищен —
никакого «призрачного» полупрозрачного слоя в финальном кадре нет; итоговый
diff (см. `61-view-transitions-diff.png`) целиком лежит в областях карточек
(before/after highlight) + давно известный font-parity текста, без следов
блендинга.

**Вывод: не P3-регрессия, откатывать `0bbab3c35` нельзя** (это откатит
реальный фикс BUG-545/546, вернёт API в сломанное состояние). Правильное
действие — ратчет `KNOWN_DEBTORS['61']` 5.16% → **10.59%** (текущее измерение,
`graphic_tests/run.py`), с этим же обоснованием в комментарии рядом с
записью. Полный прогон разблокирован.

Побочная находка (не относится к BUG-103): текст лога на странице задаётся
через `innerHTML = '<span class="dot ...">...'`; на обеих сторонах бисекта
Lumen показывает буквальные `<span>`-теги как текст вместо цветной
точки-индикатора (Edge рендерит точку корректно) — тот же класс, что уже
заведён как [BUG-368](bugs/BUG-368-OPEN.md) (`innerHTML` — текстовая
заглушка без fragment-парсинга). Воспроизводится одинаково на обеих сторонах
бисекта → не источник регрессии, отдельный уже открытый баг.
