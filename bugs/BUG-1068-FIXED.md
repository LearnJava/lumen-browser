# BUG-1068 — восстановление после битой декларации съедает `}` блока и обесточивает остаток стилей

**Статус:** FIXED 2026-09-20 (P3)
**Заведён:** 2026-09-20 (по наблюдению пользователя «контент в максимизированном окне прижат к левому краю»)
**Область:** `crates/engine/css-parser/src/parser.rs::recover_to_block_end`
**Владелец:** P3

## Симптом

Реальные сайты рендерятся без своих стилей: ссылки столбиком, Times, всё от
`x=0`. В максимизированном окне это читается как «страница прижата к левому
краю» — на самом деле у страницы просто нет ни одного из её layout-классов.

Проверено на `rust-lang.org`: все 4 CSS-файла скачиваются (`← 200`), парсер
рапортует 914 правил, но ни `.mw8`, ни `.center`, ни `.tc` к документу не
применяются (`--dump-layout --viewport 1920x1080`: `display=list-item`,
`color=#0000ee`, никаких контейнеров).

Само центрирование при этом исправно и к дефекту отношения не имеет — проверено
отдельно: layout-viewport в максимизированном окне равен реальной ширине окна
(проба с `margin:0 auto` даёт блок ровно в центре 1920-окна; `example.com`
кладёт свой `width:60vw` контейнер в `rect=(384.00, …, 1152.00, …)`, центр 960).

## Воспроизведение

```css
.x{*zoom:1}
.y{text-align:center}   /* НЕ применяется */
```

```css
.x{*zoom:1;}            /* с `;` — всё в порядке */
.x{_zoom:1}             /* `_`-хак парсится нормально: `_` — ident-start */
```

Бисекция по `vendor_10880690442070639967.css` rust-lang.org (841 top-level
правило, 73 375 байт) указала точку обрыва — правило **`.cf{*zoom:1}`** на
смещении 7355. Всё, что объявлено после него (вся утилитарная часть Tachyons:
`.mw8`, `.center`, `.tc`, флексы — 650+ правил), до документа не доезжает.

## Root cause

`recover_to_block_end` искала `{` или `;` и **не останавливалась на `}`**:

```rust
'{' => { self.consume(); self.skip_block(); return; }
';' => { self.consume(); return; }
_   => { self.consume(); }      // '}' попадал сюда
```

Декларация, начинающаяся не с ident-символа (звёздочный IE7-хак `*zoom:1`, всё
ещё живущий в минифицированных вендорных бандлах), в
`parse_declaration_block_with_nesting` попадает в ветку CSS Nesting L1 §4 —
`*` законно начинает вложенное правило (`* { }`). Дальше `{` не находится,
вызывается восстановление, и оно проглатывает закрывающую `}` самого блока, а
следом — целиком следующее правило (ветка `'{' => skip_block`).

Разрушительная половина — не потеря одного правила, а десинхронизация: парсер
остаётся «внутри» `.cf`, и каждое последующее top-level правило `.foo{…}`
записывается как вложенное `.cf .foo`. Селекторы валидны, правил в таблице
много (те самые 914), но не матчат ничего — поэтому отказ полностью немой.

По CSS Syntax L3 §5.4.3 (consume a qualified rule) `}` закрывает *объемлющий*
блок и в отбрасываемую конструкцию не входит.

## Фикс

Одна ветка в `recover_to_block_end` — `'}' => return` (без `consume`), `}`
остаётся вызывающему циклу.

Все вызывающие (`parse_stylesheet`, `parse_bare_group_body`, тела `@media`/
`@supports`/`@layer`/`@scope`, `parse_declaration_block_with_nesting`,
`parse_mixin_result_body`) уже обрабатывают `Some('}') => consume + break` и
страхуют от зацикливания проверкой `self.pos == before`, так что остановка на
`}` безопасна во всех контекстах — и попутно чинит тот же класс десинхронизации
внутри `@media`-тела.

## Проверка

`crates/engine/css-parser/src/parser/tests/recovery.rs` — 8 тестов; 5 из них
красные на коде до фикса (проверено подстановкой старой ветки): хак последней
декларацией, хак после валидной декларации, отсутствие переподчинения
следующих правил в nested, граница `@media`-блока, форма вендорного бандла.
Остальные 3 пинят то, что ломать нельзя: `;`-форму, настоящее вложенное
правило после битой декларации и универсальный селектор `* { }` в позиции
декларации.

Живая сверка: `rust-lang.org` в максимизированном окне рендерится со своими
стилями (flex-хедер, `GET STARTED`, бирюзовая секция «Why Rust?»), `--dump-layout`
показывает `display=flex`, `p=(0.50rem, 2.00rem, …)`, `text-align=center`.
