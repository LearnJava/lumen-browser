# BUG-793 — `@media;` (at-правило без блока, закрытое `;`) съедает весь остаток таблицы стилей

**Статус:** OPEN
**Заведён:** 2026-08-20 (WPT-RUN-5, срез 13 — зонд механизма инертного CSS)
**Область:** `crates/engine/css-parser/src/parser.rs` — `parse_media_rule` (3282) и однотипные `parse_supports_rule` / `parse_keyframes_rule` / `parse_container_rule` / `parse_scope_rule`
**Владелец:** P4 (css-parser). Заведён P2 в ходе тулинговой задачи, здесь не чинится.

## Симптом

At-правило, которому по грамматике положен блок, но которое в исходнике
закрыто точкой с запятой (`@media;`), приводит к потере **всех правил после
него**, а не только самого битого правила.

Минимальное репро (`--dump-layout` по http, `.tmp/probe/at21.html`):

```html
<style>
#a{width:100px;height:100px}
@media;
#b{width:200px;height:60px}
#c{width:300px;height:40px}
</style>
<div id=a></div><div id=b></div><div id=c></div>
```

```
Block rect=(8.00, 8.00, 100.00, 100.00) w=100.00 h=100.00     ← #a применилось
Block rect=(8.00, 108.00, 1008.00, 0.00)                      ← #b потеряно
Block rect=(8.00, 108.00, 1008.00, 0.00)                      ← #c потеряно
```

Убрать строку `@media;` — оба правила применяются.

## Какие at-правила задеты (замерено, не предположение)

Одинаковое репро, меняется только строка посередине; «хвост OK» = `#b`
применилось:

| at-правило | хвост | почему |
|---|---|---|
| `@media;` | **потерян** | `parse_media_rule` |
| `@supports;` | **потерян** | `parse_supports_rule` |
| `@keyframes;` | **потерян** | `parse_keyframes_rule` |
| `@container;` | **потерян** | `parse_container_rule` |
| `@scope;` | **потерян** | `parse_scope_rule` |
| `@foo;` (неизвестное) | OK | `skip_at_rule` — он `;` обрабатывает правильно |
| `@charset;` | OK | |
| `@import "x.css";` | OK | `parse_import_body` |
| `@page;` | OK | `parse_page_rule` |
| `@font-face;` | OK | `parse_font_face_body` |
| `@layer;` | OK | `parse_layer_at_rule` — единственный, кто явно различает statement- и block-форму |

То есть **неизвестное** at-правило движок переживает, а известное — нет:
общий `skip_at_rule` (3780) останавливается на `;`, а специализированные
`parse_*_rule` — нет.

## Механизм

`parse_media_rule` (`parser.rs:3282`) собирает prelude сканированием **до
первого `{`**, ничем другим цикл не прерывается:

```rust
while let Some(c) = self.peek() {
    if c == '{' { break; }
    self.consume();
}
if self.peek() != Some('{') { return None; }
```

На входе `@media;\n#b{…}\n#c{…}` первым `{` оказывается блок `#b`, поэтому
prelude становится `; #b`, а тело `@media` — объявлениями `#b`. Медиа-запрос
`; #b` не разбирается, всё содержимое уходит в никуда, и позиция парсера уже
за телом `#b`; `#c` разбирается дальше как правило внутри того же
несуществующего медиа-блока. Наружу не попадает ничего из хвоста.

По [CSS Syntax Level 3 §5.4.2](https://www.w3.org/TR/css-syntax-3/#consume-at-rule)
`<semicolon-token>` на верхнем уровне **завершает** at-правило: оно
объявляется невалидным и отбрасывается, разбор продолжается со следующего
правила. Ровно это уже делает `skip_at_rule`.

**Оговорка к фиксу:** останавливаться на любом `;` нельзя — `;` внутри
скобок/строк точку с запятой верхнего уровня не образует
(`@supports (margin: 0; …)` встречается в WPT), поэтому правка должна
считать глубину `(`/`[`/строк, а не искать `;` подстрокой. Это же отличает
её от однострочного «добавить `|| c == ';'` в условие».

## Как найдено и насколько массово

Найдено при разборе `css/CSS2/cascade/at-import-009.xht` — теста, который
стоял `inert` (движок не применил ни одного авторского объявления) и при этом
шёл в зачёт как reftest-PASS. Его `<style>` — `@media; @page; @charset;
@import "support/import-green.css";`, и первая же строка убивает `@import`,
ради которого тест написан.

Масштаб по корпусу маленький и на цифру pass-rate почти не влияет: `grep` по
вендоренному WPT даёт 89 файлов с похожим паттерном, но подавляющее
большинство совпадений — строки в JS (`"@media into " + rule_name`) и проза,
а не CSS. Ценность бага не в WPT-очках, а в устойчивости на живых сайтах:
одна лишняя `;` после `@media screen` в рукописной таблице стилей молча
выключает всё, что ниже, и диагностируется это тяжело — ошибок движок не
печатает.

## Проверка фикса

1. Репро выше: `#b`/`#c` применяются, ширины 200/300.
2. Таблица at-правил выше: ни одно значение «OK» не должно стать «потерян».
3. `@supports (margin: 0; padding: 0) { … }` — `;` внутри скобок не должен
   обрывать prelude.
4. `css/CSS2/cascade/at-import-009.xht` перестаёт быть `inert`:
   `.venv-wpt/bin/python tests/wpt/inert_style_audit.py --explain <json>` даёт
   для него `sheet_live` вместо `tail_eaten`.
