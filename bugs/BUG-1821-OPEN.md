# BUG-1821 — CLI: `--dump-layout <url> --trace-nav <out.json>` молча читает out.json как источник страницы

**Статус:** OPEN
**Заведён:** 2026-11-17 (P3, попутно переписи BUG-1778)
**Область:** shell (`crates/shell/src/cli_args.rs` — разбор позиционных аргументов двух режимов)

## Симптом

Обе формы `--dump-layout` и `--trace-nav` требуют свой позиционный `<path-or-url>` (`lumen --help`). Форма с двумя позиционными рядом:

```
lumen --dump-layout https://example.com/ --trace-nav out.json
```

не даёт ошибки аргументов: `out.json` (или следующий позиционный) захватывается как источник `--trace-nav`, рендер идёт на путь out-файла как на страницу и падает с `Ошибка --trace-nav: … Не удаётся найти указанный файл. (os error 2)` (источник — несуществующий файл; если out.json уже существует от прошлого прогона — трассируется его содержимое как HTML, молча и без диагноза). Правильная форма — свой URL у каждого режима: `lumen --trace-nav out.json https://example.com/`.

## Воспроизведение

```
lumen --dump-layout <url> --trace-nav out.json     # → Предупреждение --trace-nav: рендер завершился с ошибкой: … os error 2
lumen --trace-nav out.json <url>                    # → штатно
```

На любом источнике (https и локальный файл), на любом бинарнике dev-release от HEAD `bdda6efb9` (слот p3-work и основное дерево). Найдено 2026-11-17 при переписи BUG-1778: ложный «сломанный --trace-nav» стоил ~30 мин диагностики (A/B против `--screenshot` на том же источнике показал, что конвейер целый).

## Что делать

В `cli_args.rs` — режимы с позиционным аргументом (`--dump-*`, `--screenshot`, `--print-to-pdf`, `--trace-nav`) должны отвергать комбинацию, где позиционного у режима нет, а занят чужим: ошибка аргументов с подсказкой использования, не тихий захват.

## Как проверить

Обе формы выше: первая — ошибка аргументов, вторая — «Трейс навигации сохранён». Регресс — ошибка на правильной форме недопустима.
