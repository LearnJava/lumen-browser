# BUG-364 — `new Worker("script.js")` с внешним URL молча подставляет комментарий вместо скрипта: ни загрузки по сети, ни события `error`

**Статус:** OPEN
**Компонент:** js (`crates/js/src/worker.rs:657-695` — конструктор `Worker` в воркер-шиме; тот же путь у `SharedWorker`, `crates/js/src/shared_worker.rs`)
**Найден:** P2, WPT-VENDOR-eventsource (2026-07-28), `run_report.py --all --root eventsource --recursive`

## Симптом

Страница делает `new Worker('eventsource-onmesage.js')` — обычная запись, скрипт
воркера лежит рядом с документом. Объект воркера успешно конструируется, у него
есть `postMessage`/`terminate`/`onmessage`, но:

- **скрипт никогда не запрашивается по сети** — в логе прогона всей категории
  `eventsource` нет ни одной строки загрузки для 14 файлов
  `dedicated-worker/*.js` и `shared-worker/*.js`, при том что сами документы
  `*.htm` загружены (`grep -oE 'http://127.0.0.1:8300/eventsource/(dedicated|shared)-worker/[^ ]*'`
  по логу даёт только `.htm`, ни одного `.js`);
- **события `error` на объекте воркера не возникает** — по спеке (HTML Living
  Standard §10.2.6) неудача выборки скрипта обязана поставить в очередь задачу,
  которая бросает событие `error` на объекте `Worker`;
- воркер живёт как ни в чём не бывало и просто никогда ничего не присылает.

Проба `--dump-layout` вне WPT подтверждает молчаливость:

```
typeof Worker                = function
typeof SharedWorker          = function
new Worker('wp_worker.js')   = constructed, typeof=object   ← исключения нет
worker.postMessage           = function
worker.terminate             = function
new SharedWorker('wp_worker.js') = constructed, port=object
```

## Причина

Ограничение прямо записано в коде — `crates/js/src/worker.rs:687-690`, ветка
`else` после разбора `blob:lumen/` и `data:`:

```js
} else {
  // External URL workers are not yet supported (requires async fetch).
  script = '/* Lumen: external URL worker not supported: ' + u.replace(/\*\//g,'*\\/') + ' */';
}

this._id = _lumen_create_worker(script);
```

То есть телом воркера становится **комментарий**. Воркер-поток стартует, скрипт
успешно (и вхолостую) исполняется, ошибок не возникает нигде: ни исключения в
конструкторе, ни `error`-события, ни записи в консоль. Поддержаны только
`data:` и `blob:lumen/` URL.

Сама нереализованная выборка — известное и осознанное ограничение (комментарий в
коде это фиксирует). Дефект, ради которого заведён баг, — **молчаливость**:
вызывающий код не может отличить «воркер работает и пока молчит» от «воркера нет
вовсе», и любой тест или страница на этом зависает вместо того, чтобы получить
ошибку.

Побочно: `var u = String(url || '')` (`worker.rs:659`) — тот же `|| ''`, что
ломает стрингификацию ложных значений в `EventSource` (BUG-362).

## Расхождение с документацией

`CAPABILITIES.md:141` заявляет «**Workers/Concurrency** — ✅ Web Workers (real
threads, importScripts), SharedWorker …» без оговорки про схемы URL. По факту
поддержаны только `data:`/`blob:`, то есть основной способ создания воркера —
отдельным `.js`-файлом — не работает. Строку следует уточнить при починке
(или раньше).

## Масштаб

В категории `eventsource` — **14 из 61 id** (все 7 тестов `dedicated-worker/` и
все 7 `shared-worker/`), каждый TIMEOUT по 10 с, то есть ~2:20 из 8:01 прогона.
Ни один из них не проверяет ничего специфичного для воркеров сверх того, что уже
проверяют корневые тесты — они просто повторяют тот же сценарий внутри
воркера, — поэтому починка BUG-362/BUG-363 их не сдвинет: они висят раньше, на
загрузке скрипта.

За пределами WPT масштаб больше, чем у категории: `new Worker('worker.js')` —
доминирующая форма записи в реальном коде (`data:`/`blob:` встречаются в
основном в бандлерах и тестах). Любая страница, выносящая работу в воркер таким
образом, в Lumen молча не получает от него ответа.

## Возможный фикс (не реализован в этой сессии)

- Минимально и в духе текущего дефекта: если URL не `data:`/`blob:lumen/` —
  ставить в очередь `error`-событие на объекте воркера (и писать в консоль),
  вместо подстановки комментария. Это не добавляет функциональности, но убирает
  молчаливый отказ и превращает 14 TIMEOUT в честные FAIL.
- Полноценно: реализовать выборку скрипта по сети. Синхронного фетча в
  воркер-потоке нет (о чём говорит комментарий в `worker.rs:523`), но
  асинхронный путь уже существует для `fetch()` — пять мостов
  `_lumen_fetch_async_start`/`_poll`/`_abort`/`_commit`/`_free`
  (`subsystems/js.md`, «Ph3 async fetch»); конструктор `Worker` по спеке и так
  асинхронен, так что модель подходит.
- URL воркера при этом нужно резолвить относительно базы документа — та же
  правка, что в BUG-362, иначе `new Worker('worker.js')` упрётся в
  `missing scheme` сразу после того, как выборка появится.
- Заодно `String(url)` вместо `String(url || '')` (`worker.rs:659`).

Не чинится в этой сессии — P2-wpt вендорит и обследует, фиксы кода — дорожка P3
(`CLAUDE.md`, назначения разработчиков).
