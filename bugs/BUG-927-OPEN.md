# BUG-927 — нативный клик по радиокнопке не снимает отметку с соседа по группе

**Статус:** OPEN
**Найден:** P3, попутно к BUG-480 срез 18, 2026-08-29
**Область:** shell (`crates/shell/src/forms.rs::classify_click` →
`crates/shell/src/lumen/click.rs`, ветка `FormClickAction::ToggleRadio`)

## Симптом

Клик мышью по `<input type=radio>` делает её отмеченной и оставляет
отмеченным того соседа по группе, который был отмечен до этого. В DOM
остаются два элемента с атрибутом `checked` в одной группе (`name="g"`,
одна форма) — состояние, которое HTML LS §4.10.5.1.14 «radio button state»
объявляет невозможным: постановка флажка обязана снять его со всех остальных
элементов группы («radio button group»).

Измерено `tests/wpt/verify_frame_forms.py` (2026-08-29) на СТРАНИЦЕ, а не во
фрейме: разметка `<input type=radio name=pg id=pr1 checked><input
type=radio name=pg id=pr2>`, один нативный клик по `pr2`, состояние читается
следующим кликом (шелл переключает атрибут после рассылки `click`):

```
parent-click pcb=true r1=true r2=false   ← до клика по радиокнопке
parent-click pcb=true r1=true r2=true    ← после: отмечены ОБЕ
```

## Механизм

`classify_click` честно распознаёт радиокнопку и даже кладёт имя группы в
`FormClickAction::ToggleRadio { clicked, _group_name }`, но обработчик этого
варианта в `handle_click_at` вызывает ровно то же, что и для флажка:

```rust
forms::FormClickAction::ToggleRadio { clicked, _group_name: _ } => {
    forms::toggle_checkbox(&mut src.document.lock().unwrap(), clicked);
    self.relayout_form();
}
```

`toggle_checkbox` переворачивает атрибут `checked` на ОДНОМ узле. Имя группы
подчёркнуто как неиспользуемое (`_group_name`) — то есть обход группы не
«сломался», его никогда не было.

Побочно: второй клик по уже отмеченной радиокнопке её РАЗотмечает (то же
`toggle`), чего спека тоже не допускает — снять отметку с радиокнопки может
только `form.reset()` или отметка другой кнопки группы.

## Что нужно

В ветке `ToggleRadio` вместо переворота — установка: снять `checked` со всех
элементов группы и поставить его на `clicked`. Группа по §4.10.5.1.14 — это
элементы `<input type=radio>` с тем же `name` (сравнение регистрозависимое,
пустое `name` группы не образует) внутри той же формы-владельца, а вне формы
— внутри того же дерева. `lumen_dom::find_ancestor_form` уже даёт
форму-владельца, `_group_name` уже посчитан.

Ветка одна, но читателей два: тот же путь исполняется теперь и для
под-документа фрейма (`crates/shell/src/lumen/frame_forms.rs`, BUG-480 срез
18), поэтому правку надо класть в общую функцию `forms`, а не в
`click.rs`, — иначе страница и фрейм разойдутся.

## Чего это НЕ касается

`:checked` в каскаде и `:indeterminate` для группы без единой отметки
реализованы верно (`crates/engine/layout/src/style.rs:10213` обходит группу
как надо) — дефект только в записи состояния по клику, не в его чтении.
Скриптовое `el.checked = true` идёт другим путём и здесь не измерялось.
