# BUG-900 — «muted errors»: исключение из cross-origin скрипта репортится без редакции

**Статус:** OPEN
**Область:** js (`crates/js/src/dom.rs` — `_lumen_report_exception`,
`_lumen_parse_error_location`; `crates/js/src/v8_runtime.rs` —
`eval_and_report`/`eval_module_and_report`)
**Заведён:** P1, 2026-08-23, при закрытии [BUG-591](BUG-591-FIXED.md)

## Симптом

HTML LS §8.1.3.6 «report the exception» требует: если скрипт, из которого
пришло исключение, не проходит проверку CORS относительно документа
(«muted errors» — классический `<script src>` с чужого origin без
`crossorigin`), страница обязана увидеть **обезличенный** отчёт —
`message = "Script error."`, `filename = ""`, `lineno = 0`, `colno = 0`,
`error = null`. Это единственный барьер, который мешает чужой странице
вычитывать текст ошибок стороннего скрипта.

Lumen редакции не делает вовсе: `_lumen_report_exception` строит `ErrorEvent`
из настоящего сообщения, а `filename`/`lineno`/`colno` либо приходят от
хоста (`v8::Message` в `eval_and_report`), либо разбираются из `err.stack` —
и в обоих случаях это подлинные значения независимо от origin скрипта. Флага
«muted» у скрипта нет ни в одной структуре: `grep -rn "muted" crates/js/src`
— ноль совпадений.

## Почему это отдельный баг, а не остаток BUG-591

BUG-591 закрывал вопрос «доходит ли исключение до страницы вообще» — там
ничего не доходило ни от одного источника. Здесь механизм доставки уже
работает, и речь о **содержимом** отчёта для одного узкого класса скриптов.
Требуется то, чего у движка сейчас нет ни для чего другого: отметка origin на
самом скрипте (и её проброс через `<script crossorigin>` + заголовки CORS
ответа), то есть работа в сетевом слое и в загрузчике скриптов, а не в
развилке отчётов.

## Как проверять

WPT: `html/webappapis/scripts/errors/muted-errors.sub.html` и соседние
`muted-errors-*` — они грузят скрипт с `www1.127.0.0.1` (алиас прогона) и
ассертят ровно пятёрку `"Script error."`/`""`/`0`/`0`/`null`. Учтите
ловушку WPT-RUN-10 (`CLAUDE.md`): cross-origin подресурсы прогона сейчас
блокируются как mixed content раньше, чем дойдёт до этого кода, — сначала
проба должна доказать, что скрипт вообще загрузился.

## Соседний, не покрытый этим багом остаток

`<body onerror>` для **чужого** документа: форвардинг требует вложенного
контекста просмотра, которого в движке нет ([BUG-480](BUG-480-OPEN.md)).
