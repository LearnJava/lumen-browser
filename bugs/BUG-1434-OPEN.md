# BUG-1434 — Цвета `lch()`/`oklch()`/`lab()` вне гаммы sRGB обрезаются покомпонентно вместо сопоставления гамм; `L = 100%`/`0%` не дают белый/чёрный

**Статус:** OPEN
**Заведён:** 2026-10-08 (P2, WPT-RUN-14 срез 19, `css/css-images` + `css/css-values` + `css/css-color`)
**Область:** layout (`crates/engine/layout/src/style/values/color.rs` — перевод `lab`/`lch`/`oklab`/`oklch` в sRGB)

## Симптом

`--screenshot`, `background-color:<значение>`, пиксель в x=5:

| значение | получено | ожидается |
|---|---|---|
| `lch(100% 110 60)` | `(255,208,50)` | `(255,255,255)` |
| `lch(0% 110 60)` | `(75,0,0)` | `(0,0,0)` |
| `oklch(100% 1.1 60)` | `(255,0,0)` | `(255,255,255)` |
| `oklch(0% 1.1 60)` | `(0,206,0)` | `(0,0,0)` |
| `lab(100% 50 50)` | `(255,214,160)` | `(255,255,255)` |
| `lab(0% 50 50)` | `(66,0,0)` | `(0,0,0)` |
| `lch(50% 200 60)` | `(255,0,0)` | цвет, найденный CSS Gamut Mapping (насыщенность урезана, светлота ≈ та же) |
| `lch(50% 50 90)` (внутри гаммы, контроль) | `(136,118,22)` | так же |

Покомпонентный `clamp(0, 255)` даёт «горячие» цвета вместо белого/чёрного и сдвигает тон.

## Как найдено

WPT-RUN-14 срез 19: `css-color/lch-009.html`, `lch-010.html`, `oklch-009.html`, `oklch-010.html` (4 `thick`); эталон `whitesquare-ref.html`/`blacksquare-ref.html`.

## Что делать

После перевода в OKLab/OKLCH, если результат вне `[0,1]` в линейном sRGB, применять алгоритм Gamut Mapping (CSS Color 4 §13, `oklch`: бинарный
поиск по `C` с проверкой по ΔEOK); для `L ≥ 100%` и `L ≤ 0%` возвращать белый и чёрный напрямую.

## Как проверить

Страница из таблицы; `css/css-color/lch-009.html`, `oklch-010.html`.
