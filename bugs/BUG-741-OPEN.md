# BUG-741: текст перед atomic inline-level боксом переносит его на новую строку

**Статус:** OPEN
**Компонент:** layout (`crates/engine/layout/src/box_tree.rs` — ветка
`BoxKind::InlineBlockRow` в `lay_out`)
**Найден:** P3 при разборе [BUG-739](BUG-739-FIXED.md), 2026-08-10

## Симптом

В строке «текст + atomic inline-level бокс» (`inline-block`, а после
[BUG-739](BUG-739-FIXED.md) также `inline-flex`/`inline-grid`) бокс всегда
уезжает на следующую строку, хотя места в строке сколько угодно.

```html
<div>before <span style="display:inline-block;background:#ccf">X</span> after</div>
```

`--dump-layout` (виджет 1024 px, бинарник **до** BUG-739 — дефект старый):

```
InlineBlockRow rect=(0.00, 0.00, 1024.00, 46.06)
  InlineRun  rect=(0.00,  0.00, 1024.00, 19.20)   seg[0] "before "
  Block      rect=(0.00, 23.00,   10.67, 19.20)   display=inline-block
  InlineRun  rect=(10.67, 23.00, 1013.33, 19.20)  seg[0] " after"
```

Edge на той же разметке держит всё в одной строке (`x` бокса = ширина слова
«before » + пробел). Высота блока у Lumen 46 вместо 19.

## Механизм

`lay_out`, ветка `BoxKind::InlineBlockRow`, раскладывает детей по X курсором
`cur_x`. Для ребёнка-`InlineRun` она передаёт в `lay_out` **остаток** строки как
доступную ширину, но сам `InlineRun` — блочный по ширине бокс: его
`rect.width` становится равен всей выданной доступной ширине, а не ширине
текста (`line[0]`/`frag[0]` при этом верные, они короткие). Дальше курсор
двигается на `rect.x + rect.width`, то есть сразу на правый край контейнера, и
следующий не-run ребёнок не проходит проверку
`child_right > content_x + content_width` → перенос строки.

Симметрично: `InlineRun` ПОСЛЕ бокса тоже занимает весь остаток (в дампе выше —
1013.33), просто там это уже ни на что не влияет.

## Влияние

Бьёт по самой частой форме inline-верстки — иконка/бейдж/кнопка внутри абзаца
текста. Дефект старый (существует, сколько существует `InlineBlockRow`), но
[BUG-739](BUG-739-FIXED.md) расширил его область: раньше `inline-flex` в такой
строке бокса не получал вовсе (и текст, схлопнутый в сегменты, случайно
выглядел правильно) — теперь бокс есть и переносится.

## Как воспроизводить

`.tmp/p3/ib.html` в ветке `p3-bug-739`; страница читается `--dump-layout`
напрямую, воспроизводится и на `inline-block` (то есть на любом бинарнике).

## Направление фикса

Курсор должен двигаться по **содержимому** прогона, а не по его боксу: либо
после `lay_out` ужимать `rect.width` анонимного `InlineRun` до максимальной
ширины его строк (`lines`), либо считать перенос по фактической ширине
последней строки. Ловушки: `frag.x` внутри прогона относительны `rect.x`
(ужатие ширины их не двигает), многострочный прогон должен продолжать переносить
текст по ВЫДАННОЙ ширине, а не по ужатой, а высота строки в `InlineBlockRow`
считается по `row_max_h` — её пересчёт трогать не нужно. Правка меняет геометрию
любой страницы с `inline-block` в тексте, поэтому гейт — полный визуальный
прогон, а не только `dump_golden`.
