# BUG-1634 — Google Fonts: качаются все поднаборы `unicode-range` и повторно, `FontLoaded` ×99

**Статус:** FIXED 2026-10-19
**Заведён:** 2026-10-18 (Chat, при разборе [BUG-1239](BUG-1239-OPEN.md))
**Область:** font / css-parser / shell (загрузка `@font-face`) — не локализовано

## Симптом

YouTube (`--proxy`, `LUMEN_NO_ADBLOCK=1`, release 2026-10-18 13:40), ~35 с после открытия главной.
Страница подключает `https://fonts.googleapis.com/css2?family=Roboto:wght@300;400;500;700&family=YouTube+Sans:wght@300..900&display=swap`.

- **271 запрос** к `fonts.gstatic.com`, из них **208 разных** `.woff2` (174 — YouTube Sans); отдельные файлы
  Roboto запрошены до 8 раз.
- В логе `FontLoaded: «YouTube Sans» weight=300` — **99 раз**, `«Roboto» weight=300/400/500/700` — по 9 раз.

Google Fonts отдаёт на каждое начертание десятки блоков `@font-face` с разными `unicode-range`
(cyrillic, latin, latin-ext, vietnamese…). По CSS Fonts 4 §4.5 браузер скачивает поднабор, только если
на странице есть символ из его диапазона. Chrome на такой странице грузит единицы файлов.

Похоже на два дефекта:
1. `unicode-range` не управляет ленивой загрузкой — качаются все поднаборы;
2. повторные запросы одного и того же URL и повторные `FontLoaded` — нет дедупликации загрузки
   по (URL) или цикл «загрузился шрифт → relayout → снова запрос».

## Почему важно

Сотни лишних запросов и перерисовок на каждой странице с Google Fonts (очень частый случай); возможная
причина того, что engine-поток YouTube занят и не отвечает.

## Что сделать

1. Минимальная фикстура: локальный CSS с 3–4 блоками `@font-face` одного семейства с разными
   `unicode-range` + текст только латиницей; посчитать запросы и `FontLoaded`.
2. Грузить поднабор только при наличии символа из диапазона (CSS Fonts 4 §4.5); одна загрузка на URL.
3. Тест на фикстуре: латиница → загружен только латинский поднабор, каждый URL ровно один раз.

**Готово, когда:** на YouTube запросов к `fonts.gstatic.com` — единицы, без повторов одного URL;
`FontLoaded` на начертание — один раз.

## Исправление (2026-10-19)

Причина — `spawn_web_font_fetches` (`crates/shell/src/page_load.rs`) качал каждый `url()`-источник каждого
блока `@font-face`, не глядя на `unicode-range`. Теперь `take_needed_web_fonts` сверяет диапазон блока с
кодпоинтами видимого текста документа (`crates/shell/src/web_font_usage.rs`: текстовые узлы, `value`/
`placeholder`, теневые деревья; без `<head>`/`<script>`/`<style>`); блоки без совпадения лежат в
`Lumen::deferred_web_fonts` и перепроверяются в начале `apply_relayout_result` — как только в тексте появляется
символ из диапазона, поднабор уходит в загрузку. Блоки без `unicode-range` грузятся сразу, как раньше.
Дедупликация по (семейство, вес, стиль, URL) прежняя (`requested_web_fonts`), плюс отсев уже отложенных.

Тесты: `web_font_usage::tests` (латинская страница → только latin-поднабор; кириллица в тексте → поднабор
освобождается; script/style/head не заказывают шрифты).

Не вошло: строки `content:` в CSS не учитываются как «видимый текст» (поднабор нужен только если символ
есть в DOM); фреймовый (`frames.rs`) и headless (`dump_mode.rs`) пути по-прежнему грузят все поднаборы;
повторные запросы одного URL (×8 на youtube) в рамках одной страницы не воспроизведены — дедупликация
уже была, наблюдавшиеся повторы, вероятно, из фреймов и `FontFace.load()` из скриптов.
