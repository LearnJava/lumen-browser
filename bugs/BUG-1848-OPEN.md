# BUG-1848 — portal.nextera.ru: флекс-скроллер `.messages-area` не сжат до вьюпорта, колесо уводит вверх весь основной столбец

**Статус:** OPEN
**Заведён:** 2026-11-26 (ZCode, живая сессия portal.nextera.ru, Lumen dev-release 9a22a771a4; симптом докладан пользователем)
**Область:** layout (флекс-размерирование — автоматический минимальный размер скролл-контейнера; не локализовано) + scroll-input (политика wheel на `overflow:hidden`, lumen-shell)

## Симптом

Доклад пользователя: при прокрутке «уезжает вся страница вверх», хотя левая колонка
(`.sidebar`, `position:fixed`) должна оставаться на месте, а прокручиваться должен только
список сообщений диалога.

## Замеры на живой странице (MCP eval, главная «/», вьюпорт 845 px)

| Объект | CSS сайта | Lumen 9a22a771a4 |
|---|---|---|
| `document.scrollingElement` | `html/body overflow:hidden` | `scrollHeight 845 == innerHeight`, `scrollTop 0` — документ не скроллится |
| `.sidebar` (левая колонка) | `position:fixed` | `y=0, h=845`, **не** потомок `.pp-chatflex`; при `scrollTop=300` на `.pp-chatflex` не сдвинулась |
| `.messages-area` | `overflow-y:auto` | **`clientHeight 12596`** = контенту (`scrollHeight 12620`) — запас скролла всего 24 px |
| `.pp-chatflex` (флекс-предок) | `overflow:hidden` | `clientHeight 845`, **`scrollHeight 54076`** — весь столбец торчит из-под клипа |

Симуляция: `pp-chatflex.scrollTop = 300` принимается, `.messages-area` уезжает `0 → −300`
(вся главная поверхность: шапка, сообщения, композер), при `scrollTop=0` возвращается.

Ожидаемое поведение выведено из CSS сайта (Chrome в этом прогоне не сравнивался, профиль
с сессией в Temp доступен): `.messages-area` должен быть сжат флекс-предком до ≈700–800 px
и прокручивать только сообщения; wheel на `overflow:hidden`-контейнере в Chrome не
прокручивает его.

## Механизм (две части)

1. **Layout (первопричина, триггер уточнён):** второй пасс контейнерных запросов
   (`apply_container_inner`, `container_anchor.rs`) перекладывает детей size-контейнера
   блочным стеком (`child_y += height`) независимо от того, что контейнер — `display:flex`:
   флекс-айтемы теряют сжатие по главной оси. Триггер на портале — связка
   `#screen-chat-dev .pp-chatflex .pp-chatflex { container: pp-chat / inline-size }` +
   наличие единственного правила `@container pp-chat (min-width: 1025px) { … }`; снятие
   `container` у родителя на живой странице схлопывает `.messages-area` до правильных
   634 px. Авто-мин-размер (`min-height:auto`→0) тут ни при чём — сайт задаёт
   `min-height: 0` явно; блочный стек игнорирует и его. Результат: скроллер равен
   контенту (12596–15286 px), композер вытеснен на y ≈ 13,7–15,4 тыс. px.
2. **Wheel (видимая часть, уточнено срезом 2):** колесо попадает в **корневой scroller
   документа** — несмотря на `overflow:hidden` html/body и нулевой диапазон
   (`scrollHeight == innerHeight`); в `mouse_wheel.rs` фолбэк «крутить страницу»
   безусловный, а диапазон (`max_scroll()`) раздут `content_height_of(display list)`
   через `.max()` поверх уже правильного ответа `page_scrollable_extent` (hidden→0 там
   реализован). `scrollTop` **не клэмпится** к диапазону (overscroll 689 px «в пустоту»),
   и **paint смещает всё окно на этот оффсет, включая `position:fixed` элементы**
   (layout при этом считает их на месте; `renderer.rs:937-941`). Результат на
   скриншоте пользователя: весь контент уехал вверх, под приложением — пустота, композер
   и верх сайдбара вне экрана. Внутренние контейнеры при этом не скроллятся вовсе.

### Срез 2 — реальный wheel пользователя (2026-11-26, портал, `?`-чат после переписки)

После прокрутки пользователем (скриншот: уехало всё окно, внизу пустота): `docST 689`
при `docSH 845 == iH 845`, `html/body overflow:hidden`; **ни один** внутренний элемент не
имеет `scrollTop>0`; `.sidebar` — `position:fixed`, `gBCR.y = 0` (layout), но на скриншоте
сдвинута вместе с контентом (paint применяет корневый оффсет ко всему); `#chatTextarea`
при `y = 15373`. `nx-pin-left = 1`.

## Что делать

- Flex: клэмпить авто-мин-размер флекс-элемента до 0 по главной оси, когда он —
  скролл-контейнер.
- Wheel/scroll-input: корневой scroller не должен принимать wheel, когда html/body имеют
  `overflow:hidden` и диапазон нулевой; `scrollTop` клэмпить к
  `scrollHeight − clientHeight`; paint/hit-test не должны применять корневый scroll-оффсет
  к `position:fixed` элементам (смежно с BUG-1166 — там gBCR).

## Как проверить

Портал (логин): колесо над чатом → движется только `.messages-area`
(`clientHeight` ≪ контента, ≈700–800 px), `pp-chatflex.scrollTop` остаётся 0, шапка и
композер на месте; панель неподвижна. Контрольный признак починки части 1 —
`messages-area.clientHeight` перестаёт равняться контенту.

Смежные: BUG-1166 (gBCR против скролла предка), BUG-1607 (сплющивание модалки
`max-height`), BUG-1846 (grid `auto` при `fr` — другое размерирование).
