# BUG-737: intrinsic-ширина row-flex контейнера считалась по блочному правилу

**Статус:** FIXED 2026-08-10
**Компонент:** layout (`crates/engine/layout/src/box_tree.rs` —
`max_content_outer_width`, `min_content_outer_width_of_contents`,
`preferred_inline_block_width`)
**Найден и исправлен:** P3 при разборе [BUG-733](BUG-733-FIXED.md), 2026-08-10

## Симптом

Все три расчёта intrinsic-ширины применяли к любому не-inline боксу правило
блочного контейнера — «дети складываются вертикально, берём самого широкого».
Для контейнера `display: flex`/`inline-flex` с `flex-direction: row` это неверно:
его элементы стоят **бок о бок**, ширина контейнера = их сумма + `column-gap`
(CSS Flexbox L1 §9.9).

Занижение до одного элемента било по трём путям сразу:

* вложенный row-flex как flex-элемент внешнего контейнера — его flex base size
  (`flex_auto_base_main_width` → `max_content_outer_width`) равнялся ширине
  самого широкого вложенного элемента;
* `inline-block` / `float` вокруг row-flex — shrink-to-fit
  (`preferred_inline_block_width`) обтягивал тот же максимум;
* пол сжатия (`flex_item_min_main_width` → `min_content_outer_width_of_contents`)
  разрешал сжать row-flex-элемент ниже суммы его элементов, хотя развести их по
  строкам при `flex-wrap: nowrap` нечем.

Сверка с headless Edge (два вложенных элемента по 35.19 px):

| Форма | Edge | Lumen до | Lumen после |
|---|---|---|---|
| вложенный row-flex как flex-элемент | 70.38 | 35.19 | 70.38 |
| он же с `gap: 10px` | 80.38 | 35.19 | 80.38 |
| он же с `flex-wrap: wrap` | 70.38 | 35.19 | 70.38 |
| `inline-block` вокруг row-flex | 70.38 | 35.19 | 70.38 |
| `float: left` вокруг row-flex | 70.38 | 35.19 | 70.38 |
| контейнер 60 px (min-content пол) | 70.38 | 35.19 | 70.38 |
| вложенный **column**-flex | 35.19 | 35.19 | 35.19 |

## Корень

`max_content_outer_width` / `min_content_outer_width_of_contents` /
`preferred_inline_block_width` различали ровно два формат-контекста:
`BoxKind::InlineRun` (сумма отрезков текста) и `BoxKind::InlineBlockRow` (сумма
детей). Всё остальное попадало в общую ветку «max по детям, плюс отдельная сумма
для флоатов». Flex-контейнер — это `BoxKind::Block` с `style.display == Flex`,
поэтому он попадал именно туда: горизонтальный формат-контекст мерился
вертикальным правилом.

Тот же класс дефекта, что [BUG-178](BUG-178-FIXED.md): флоаты тоже стоят бок о
бок, и до него их тоже мерили максимумом.

## Фикс

Общий хелпер `flex_row_intrinsic_sum(b, viewport, per_item)` — сумма
`per_item(ребёнок)` + горизонтальные margin-ы + `column-gap` между элементами;
предикат `is_row_flex_container` отделяет row от column (колоночный контейнер
складывает элементы вертикально, для него блочное правило верно и не тронуто).
Подключён в три точки:

* `max_content_outer_width` — сумма при любом `flex-wrap` (max-content подавляет
  перенос строк по определению, все элементы остаются на одной линии);
* `min_content_outer_width_of_contents` — сумма только при `flex-wrap: nowrap`;
  при `wrap` элементы можно развести по строкам, поэтому min-content = самый
  широкий элемент (прежняя ветка);
* `preferred_inline_block_width` — сумма (ребёнок без собственной
  предпочтительной ширины даёт 0, как и в соседней горизонтальной ветке).

Проценты `column-gap` резолвятся от content-box самого контейнера, которого на
этапе intrinsic-расчёта ещё нет, — дают 0, как и все остальные проценты в этих
функциях.
