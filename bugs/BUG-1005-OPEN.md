# BUG-1005 — `input-events`: перегенерация baseline даёт 159 регрессий на немедленном повторном `--check`

**Статус:** OPEN
**Заведён:** 2026-09-05 (P2, WPT-RUN-7 срез 6 — перегенерация expectations baseline после
фикса выборки среза 4)
**Область:** не локализован. Все регрессии сосредоточены в одном файле,
`input-events-get-target-ranges-deleting-in-list-items.tentative.html`, с десятками
`?Backspace,ol`/`?Delete,ul`-подобных query-вариантов; категория и раньше давала нестабильный
краш другого класса ([BUG-995](BUG-995-FIXED.md), [BUG-986](BUG-986-FIXED.md))
**Владелец:** P1/P3 (после локализации)

## Симптом

`--update-expected --all --root input-events --recursive` прошёл штатно (3 новых `.ini`,
0 удалённых), но немедленный `--check` на том же прогоне/бинаре дал **159 регрессий** —
почти все внутри `input-events-get-target-ranges-deleting-in-list-items.tentative.html`,
разные `<ol>`/`<li>`-вложенности одного и того же сценария (`Backspace at "<ol>..."`),
плюс минимум один `expected ERROR, got OK` (неожиданный PASS того же файла с другим query).
Свежесозданный baseline не совпал сам с собой в следующем прогоне.

## Почему это важно

Категория уже была источником двух подтверждённых крашей движка на смежном пути
(`Document::get` на чужом `NodeId` — BUG-986/995, оба чинились P3). Масштаб этой находки
(159 из ~1442 подтестов одного файла) заметно больше единичной флакующей проверки, как в
[BUG-1003](BUG-1003-OPEN.md)/[BUG-1004](BUG-1004-OPEN.md), и статистически похож не на
жёсткую гонку по таймингу, а на артефакт накопленного состояния (утечка/порча DOM между
последовательными `?query`-вариантами одного файла в одном процессе wptrunner, а не
чистый рестарт на каждый вариант). Baseline **не перегенерирован** этим срезом (изменения
к `tests/wpt/metadata/input-events/` откачены `git checkout --`) — категория остаётся в
состоянии среза 3 (последний известный зелёный `--check` после фикса BUG-995).

## Воспроизведение

```
LUMEN_PROFILE=dev-release python tests/wpt/run_report.py \
  --binary target/dev-release/lumen --all --root input-events --recursive --update-expected
LUMEN_PROFILE=dev-release python tests/wpt/run_report.py \
  --binary target/dev-release/lumen --all --root input-events --recursive --check
```

## Что не проверялось

Не подтверждено, что 159 регрессий воспроизводятся стабильно (наблюдение — один раз, не
серия); не проверялось, крашится ли `lumen`-процесс молча где-то в середине файла
(`--log-raw` не снимался); не изолирован конкретный query-вариант через `run_smoke.py` на
одном id. Первый шаг для локализации — прогнать один и тот же вариант
(`?Backspace,ol`) изолированно несколько раз подряд и сравнить с прогоном всего файла
целиком: если изолированный прогон стабильно зелёный, а прогон всего файла — нет, это
подтверждает гипотезу накопленного состояния, а не тайминг.
