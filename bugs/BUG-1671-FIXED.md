# BUG-1671 — `getBoundingClientRect` = 0,0,0,0 у пустого inline и у inline с блочным потомком

**Статус:** FIXED 2026-11-15 (P3) — закрыт фиксом [BUG-1558](BUG-1558-OPEN.md) срез 1
(2026-10-28, `89787e62ae`), заведён раньше, чем тот фикс попал в `main`;
отдельного кода не потребовалось, добавлен регресс-тест JS-пути.
**Заведён:** 2026-10-21 (P2, TEST-11 — [geom-diff-2026-10-21](../docs/quality/geom-diff-2026-10-21.md))
**Область:** js/layout (прямоугольник строчного элемента для JS: фрагменты inline-бокса)

## Симптом

```html
<!doctype html><p>aaa<span id=e></span>bbb</p>
<!doctype html><p>aaa <a id=b href=#><div>blk</div></a></p>
```

Chrome: `#e` = `29.3,16,0,17` (нулевая ширина, высота строки, на месте в строке), `#b` = `29.3,16,0,17`
(прямоугольник первого строчного фрагмента до блока). Lumen — `0,0,0,0` у обоих. Inline с текстом
(`<a>link</a>`) — верно.

На сайтах: HN `a×20` и `span×18` (пустые `<a id=up_…>`, `<span class=…>`), crates.io `a×30` —
ссылка-карточка вокруг `div`. Скрипты, которые берут позицию якоря/ссылки (`scrollIntoView`,
всплывающие подсказки, IntersectionObserver), получают начало координат.

## Причина и фикс

Оба случая — один дефект: элемент не имеет собственного текстового фрагмента, а сборщик
геометрии (`collect_layout_rects`) публиковал записи только по фрагментам текста, поэтому
ключа элемента в снимке не было вовсе и JS отвечал нулевым прямоугольником.

Фикс пришёл с BUG-1558 срез 1: `InlineSegment::is_empty_inline_marker` оставляет пустому
строчному элементу нулевой сегмент-маркер в строке, `for_each_empty_inline_element`
(`crates/engine/layout/src/lib.rs`) ставит по нему нулевой по ширине прямоугольник высотой
в строку — тем же путём получает геометрию и `<a>`, разрезанный блочным потомком
(ведущий пустой кусок слайса block-in-inline, BUG-1353/BUG-1530).

## Как проверить

`cargo test -p lumen-driver --test all bug1671` — новые
[`bug1671_inline_rects.rs`](../crates/driver/tests/cases/bug1671_inline_rects.rs):
оба репро идут через настоящую раскладку и снимок геометрии в V8, проверяются
`getBoundingClientRect` (нулевая ширина, высота строки, x после предыдущего текста) и
непустой `getClientRects()`. Репро из карточки числа Chrome (±1px по метрикам шрифта).

## Остаток (не этот баг)

Строгие WPT-формы того же класса — пустой inline один в блоке без строки (`height: 0`) и
`getClientRects-inline-with-block-child` (ждёт два нулевых по высоте фрагмента) — остаются
в [BUG-1558](BUG-1558-OPEN.md) §Остаток: там нужен ран без строк, а не геометрия маркера.
