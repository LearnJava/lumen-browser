# BUG-911 — тесты `lumen-network` берут эфемерный порт у ОС и падают, когда он попал в список «bad ports» Fetch §3.9

**Статус:** OPEN
**Заведён:** 2026-08-25 (P1, поймано гейтом `scoped-test.sh` при закрытии [BUG-832](BUG-832-FIXED.md))
**Область:** `crates/network/src/lib.rs:6186` (`mock_http_server`), `:8353`
(`mock_http_server_capturing`) — обе биндят `127.0.0.1:0`; `crates/network/src/lib.rs:302`
(`require_http_scheme` → `blocked port`), `crates/network/src/bad_port.rs`
**Владелец:** P3 (`lumen-network`)

## Симптом

Один прогон `cargo test -p lumen-network --lib` из ~30 падает на случайном
тесте, использующем мок-сервер, с сообщением вида

```
thread 'tests::global_offline_fails_before_touching_network' panicked at
crates\network\src\lib.rs:8921:39:
fetch after clearing offline must reach the real server: Network("blocked port: 6000")
```

Повторный запуск того же теста проходит с первой попытки — три подряд, без
единой правки. Тест здесь ни при чём: упасть может любой из 27 потребителей
`mock_http_server` (плюс потребители `mock_http_server_capturing`).

## Причина

`mock_http_server` биндит `TcpListener::bind("127.0.0.1:0")` и спрашивает у ОС
выданный порт, а `HttpClient::fetch` с 2026-08-24 ([BUG-772](BUG-772-FIXED.md))
проверяет порт по списку Fetch §3.9 «bad ports» **до** DNS и до любого
`connect`. Оба поведения правильны по отдельности; пересекаются они в том, что
эфемерный диапазон Windows на этой машине — 1024…15000 (`netsh int ipv4 show
dynamicport tcp`), а в него попадают **19** из 83 запрещённых портов: 1719,
1720, 1723, 2049, 3659, 4045, 4190, 5060, 5061, 6000, 6566, 6665…6669, 6679,
6697, 10080. Это 0.136 % на один бинд, то есть ~4 % на прогон крейта — редко
настолько, чтобы читаться как «гейт иногда мигает», и часто настолько, чтобы
мигать регулярно.

Диапазон машинозависим: на Linux по умолчанию 32768…60999, где запрещённых
портов нет вовсе, так что в CI на `ubuntu-latest` этого не увидят никогда —
дефект наблюдаем только на Windows-машине разработчика.

## Чего это НЕ

Не [BUG-805](BUG-805-OPEN.md): тот про зависание `scoped-test.sh` на
`h3::udp::tests::udp_round_trip`, здесь же тест падает мгновенно и на другом
механизме.

## Направление починки (не предписание)

Перебиндить в цикле, пока `bad_port::is_bad_port(port)` истинно, — правка на
две строки в `mock_http_server`/`mock_http_server_capturing`, и она держится
за уже существующий предикат, а не за копию списка. Прибивать порт константой
нельзя: тесты гоняются параллельно.

## Как проверить фикс

Прямого воспроизведения нет (ждать 0.136 % на бинд бессмысленно) — проверять
надо сам цикл: временно подменить предикат на «запрещён каждый порт, кроме
последнего выданного» либо утверждением на то, что возвращённый порт
`!is_bad_port(port)`, и прогнать `cargo test -p lumen-network --lib`.
