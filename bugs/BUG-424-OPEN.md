# BUG-424 — иконки хрома (`<use href="#i-…">` из инлайн-спрайта) рисуются мусором, правый кластер тулбара схлопывается у края окна

**Статус:** OPEN
**Компонент:** chrome (`assets/chrome/chrome.html` — инлайн SVG-спрайт ~35
`<symbol>`), paint (`<use>`-разворот, масштабирование к CSS-размеру),
shell (раскладка тулбара при большой ширине окна)
**Найден:** P1, 2026-07-28, при первом визуальном показе движкового хрома после
флипа CC-14

## Симптом

Живое окно, ширина 1920, любая страница:

* левый кластер (назад / вперёд / reload) — вместо трёх иконок несколько
  наложенных штрихов размером ~10 px;
* правый кластер (поиск / сайдбар / AI / загрузки / печать / DevTools /
  настройки — 7 кнопок) сжат в ~20 px у самого правого края и нечитаем;
* в макете это 7 отдельных иконок 16 px с шагом 8 px.

Тот же ассет, отрисованный движком **как обычная страница**
(`lumen --screenshot out.png assets/chrome/chrome.html`, ширина 1024):
иконки навигации не рисуются вовсе, а лупа внутри поля поиска — рисуется.
То есть часть `<use href="#…">` разрешается, часть нет.

## Воспроизведение

```bash
cargo build -p lumen-shell --profile dev-release
# 1) живое окно
./target/dev-release/lumen.exe --maximized about:blank
# 2) тот же ассет как страница (CPU-путь, без окна)
./target/dev-release/lumen.exe --screenshot .tmp/chrome-asset.png assets/chrome/chrome.html
```

## Направление разбора

1. Развести две разные жалобы: «символ спрайта не найден/не отрисован» и
   «кластер схлопнут по ширине». Вторая, вероятно, чистый layout (flex-раскладка
   тулбара при ширине >> 1024), первая — `<use>`/`<symbol>`.
2. Сравнить те `<symbol>`, что рисуются (лупа), с теми, что нет: отличие в
   `viewBox`, в `stroke` vs `fill`, в `stroke-width`, во вложенных группах.
3. CC-2 / [BUG-334](BUG-334-FIXED.md) уже правили масштабирование внешнего
   `<svg>` к CSS-размеру — проверить, не тот же ли это путь.
