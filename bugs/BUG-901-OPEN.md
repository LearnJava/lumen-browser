# BUG-901 — одиночный суррогат в строке, пересекающей границу JS↔натив, молча становится `U+FFFD`

**Статус:** OPEN
**Компонент:** js (`crates/js/src/v8_runtime.rs` — конвертация `v8::String` → Rust `String` в макросе регистрации нативов; проявляется на всех нативах, принимающих или возвращающих строку)
**Найден:** P1, 2026-08-24, при закрытии [BUG-773](BUG-773-FIXED.md) — `run_report.py --all --root webstorage --recursive`

## Симптом

JS-строка — последовательность UTF-16 code unit-ов, в которой одиночный
(непарный) суррогат `U+D800`…`U+DFFF` совершенно легален; WebIDL `DOMString`
это ровно такая последовательность. Rust `String` — UTF-8 и одиночный суррогат
представить не может, поэтому конвертация на границе заменяет его на
`U+FFFD` REPLACEMENT CHARACTER. Обратно правильная строка уже не
восстанавливается: порча необратима и происходит без единого предупреждения.

Измерено на Web Storage, где это видно чище всего — значение кладут и тут же
читают. Проба (юнит-тест на `V8JsRuntime`, `String.fromCharCode`, чтобы
исходник пробы сам не был источником суррогата):

```js
var C = String.fromCharCode;
localStorage.a = C(0xD800);              // одиночный старший суррогат
localStorage.b = 'a' + C(0xDF4D);        // одиночный младший, не в начале
localStorage.c = C(0xD83C) + C(0xDF4D);  // корректная пара (U+1F34D)
localStorage.d = C(0xD7FF);              // соседний код, вне диапазона
localStorage.setItem(C(0xD800), 'k');    // суррогат в КЛЮЧЕ
```

Результат — `fffd, fffd, 2/1f34d, d7ff, 0`, то есть:

| что записали | что прочли |
|---|---|
| `U+D800` | `U+FFFD` |
| `'a' + U+DF4D` | `'a' + U+FFFD` |
| пара `U+D83C U+DF4D` | ровно она же, `codePointAt(0) === 0x1F34D` |
| `U+D7FF` | `U+D7FF` |
| ключ `U+D800` | ключа с таким первым code unit-ом в `Object.keys` нет |

Портится только непарный суррогат, и **ключ страдает так же, как значение**.

`tests/wpt/webstorage/storage_setitem.window.js` перебирает `interesting_strs`
(`"퟿"`, `"\uD800"`, `"\uDBFF"`, `"\uDC00"`, `"\uDFFF"`, `"\uD83Ca"`,
`"a\uDF4D"`, …) — 12 сабтестов (6 значений × 2 хранилища) падают именно так:
`assert_equals: expected "U+d800" but got "�"`. Всё, что образует
корректную суррогатную пару, и весь BMP вне суррогатного диапазона проходят.

## Почему это не про Web Storage

Хранилище — только самая наблюдаемая точка: `setItem`/`getItem` — это
round-trip через натив за одну инструкцию. Тот же путь проходит **любой**
`_lumen_*` натив со строковым параметром или результатом (`setAttribute`,
`textContent`, `document.title`, URL-хелперы, `postMessage`, …), поэтому
чинить нужно границу, а не `Storage`.

## Куда смотреть

Конвертация делается в `v8_runtime.rs` при разборе аргументов и упаковке
результата натива (`to_rust_string_lossy` и его аналоги — уже по имени
«lossy»). Правильное представление `DOMString` в Rust — не `String`, а
что-то, способное нести непарный суррогат: `Vec<u16>`, WTF-8 или собственный
newtype поверх него. Это затрагивает `lumen_core::WebStorage` и всякое другое
хранилище, куда такая строка кладётся, поэтому цена фикса — не одна функция, и
браться за него имеет смысл отдельной задачей с решением про тип.

## Не расследовано

Насколько широко порча видна за пределами Web Storage — не измерялось: пробы
на `setAttribute`/`textContent`/`document.title` не ставились. Также не
проверено, что делает с одиночным суррогатом персистентный слой
(`crates/storage/`) — возможно, там стоит вторая, независимая потеря.
