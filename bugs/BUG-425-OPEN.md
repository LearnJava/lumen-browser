# BUG-425 — вертикальный сайдбар: вкладки нарисованы одна поверх другой, пропал заголовок группы, подписи переносятся

**Статус:** OPEN
**Компонент:** chrome (`assets/chrome/chrome.html` — `#sbTabs` / `.sb-tab` /
`.sb-section-title`), layout (вертикальная раскладка списка внутри сайдбара)
**Найден:** P1, 2026-07-28, при сверке движкового хрома с макетом
`docs/design/lumen-v3_3.html`

## Симптом

Ассет хрома, отрисованный движком как страница
(`lumen --screenshot .tmp/chrome-asset.png assets/chrome/chrome.html`,
ширина 1024):

1. **Все элементы списка вкладок нарисованы на одной строке, поверх друг
   друга** (визуально — нечитаемая каша примерно на y≈195). В макете это
   вертикальный список из 5 строк с отступом 4 px и вложенностью (дерево
   вкладок: «Re: правки по релизу» вложен в «Почта — Входящие», «Выписка за
   июль» — в «Т-Банк — Счета»).
2. **Заголовок группы `ВКЛАДКИ · ЛИЧНОЕ` не виден** — в макете он есть над
   списком.
3. Подписи, укладывающиеся в макете в одну строку, переносятся в две:
   «Новое пространство», «Восстановить закрытые».

Пункты 1 и 2, вероятно, одна причина (список не набирает высоту → всё
схлопывается в одну строку и вытесняет заголовок). Пункт 3 — отдельная, скорее
всего расхождение в ширине/паддингах контейнера или в метриках шрифта.

## Воспроизведение

```bash
cargo build -p lumen-shell --profile dev-release
./target/dev-release/lumen.exe --screenshot .tmp/chrome-asset.png assets/chrome/chrome.html
```

Сверять с `docs/design/lumen-v3_3.html`, открытым в стороннем браузере
(в макете сайдбар виден в режиме «Вертикальные»).

## Направление разбора

`--dump-layout` по тому же ассету даст геометрию `#sbTabs` и его детей: нулевая
или одинаковая `y` у всех `.sb-tab` подтвердит «список не раскладывается по
вертикали». Дальше — какое свойство контейнера теряется (`display:flex` +
`flex-direction:column`, `gap`, или высота элементов).
