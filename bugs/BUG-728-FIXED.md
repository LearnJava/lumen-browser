# BUG-728: элемент внутри inline-элемента теряет собственную геометрию — схлопывается в высоту строки

**Статус:** FIXED 2026-08-09
**Компонент:** layout (`crates/engine/layout/src/box_tree.rs` — `collect_inline_segments` / `InlineSegment`)
**Найден:** P3 при разборе [BUG-725](BUG-725-OPEN.md), 2026-08-09
**Исправлен:** P3, 2026-08-09

## Симптом

Всё, что вложено внутрь inline-элемента (`<a>`, `<span>`, …), рисуется на высоту
текстовой строки и теряет собственную раскладку. Минимальное репро (`img { width:
50px; height: 50px }`, `.b { display: block; height: 30px }`):

| разметка | было | стало |
|---|---|---|
| `<div>A: <img></div>` | `DrawImage (0, 16.8, 50, **50**)` — верно | без изменений |
| `<div><span><img></span></div>` | `DrawImage (…, 50, **16.8**)` | `DrawImage (…, 50, **50**)` |
| `<div><a href="#"><img></a></div>` | `DrawImage (…, 50, **16.8**)` | `DrawImage (…, 50, **50**)` |
| `<div><span><span><img></span></span></div>` | `DrawImage (…, 50, **16.8**)` | `DrawImage (…, 50, **50**)` |
| `<div><span><div class="b">…</div></span></div>` | `FillRect (0, 122, 82, **17**)` | `FillRect (0, 247.1, **1024, 30**)` |
| `<div><span><div style="display:flex">…</div></span></div>` | флекс-контейнера нет, остался текст | контейнер `1024×40` + два элемента `40×40` в ряд |
| `<div><span><input></span></div>` | ни одной команды | `FillRect (0, 333.9, 176, 23)` |

То есть ширина (`width: 50px`) сегмент переживал, **высота — нет**, а
блочно-уровневый или флекс/грид потомок внутри inline вообще переставал быть
контейнером: от него оставался текстовый прогон и фон в одну строку.

## Механизм

`collect_inline_segments` разворачивала поддерево inline-элемента в плоский список
`InlineSegment`. У сегмента есть `img_width`, `pre_space`, `post_space` — и **нет
высоты**: вертикальный размер строки считается по метрикам шрифта. Замещаемый
элемент (`<img>`) попадал в сегмент с `is_element_box: true`/`img_src`, поэтому
`DrawImage` эмитился, но с высотой строки. Блочный потомок (CSS 2.1 §9.2.1.1 требует
разрезать вокруг него inline-бокс) не разрезал ничего — рекурсия просто собирала из
него текст, и собственный бокс с его `display`/`height`/флекс-раскладкой не строился.

## Фикс

Узел, который не порождает сегментов, больше не уплощается:

* `produces_inline_segments_nested` — единственный признак «этот потомок можно
  уплотнить в текст». False для блочно-уровневого (`Block`, `Flex`, `Grid`,
  `InlineBlock`, `Table`, …) и для replaced (`<img>`, form control).
  `display: contents` — прозрачен: бокса он не порождает вовсе (CSS Display L3
  §3.1), уплощать надо СКВОЗЬ него, иначе `<span>cc<span
  style="display:contents">dd</span>ee</span>` разъезжается на три строки.
  На replaced-элементе `contents` вычисляется в `inline`, бокс остаётся.
* `InlineEscape { at, node, inherited }` — отложенный узел: позиция в потоке
  сегментов, сам узел и **стиль inline-родителя**. Последнее существенно: бокс
  строит блочный контейнер, далёкий от места находки, и его собственный стиль
  здесь не подходит — цвет/шрифт промежуточного `<span>` были бы потеряны.
* `split_inline_pieces` собирает поток обратно: сегменты между escape-ами →
  отдельные `InlineRun`, каждый узел → настоящий бокс через `build_box_or_reuse`
  ровно на своём месте. `::first-letter` применяется к каждому куску отдельно
  (маркер стоит на одном сегменте, для остальных кусков это no-op) — так вставка
  сегмента-остатка не сбивает индексы escape-ов.
* `breaks_inline_row` — блочно-уровневый всплывший бокс дополнительно **разрывает
  анонимную группу**: контент до него и после него попадают в разные анонимные
  контейнеры, а не в один `InlineBlockRow`. Отличить его от анонимного прогона по
  `display` нельзя (`anon_style` копирует `display` блока-родителя) — признак роль,
  `BoxRole::AnonymousInlineRun`. Inline-уровневый всплывший бокс (`inline-block`,
  form control) ряд не разрывает и течёт рядом с текстом.

### Что сознательно НЕ изменено

Инвариант «`<img>` в Phase 0 — block-level replaced» (UA-дефолт `default_display`,
задокументирован на `is_inline_content`) не тронут. Картинка внутри `<span>` ведёт
себя ровно как прямой ребёнок блока: своя строка и свои `50×50`. Настоящий
inline-replaced (картинка в строке текста) — отдельная задача; делать её здесь
значило бы двигать пиксели на каждой странице с картинками внутри текста.

По той же причине не тронут и уровень сиблингов блочного контейнера: там
`display: contents`, `<img>` и form controls и до этого получали отдельный бокс —
`is_inline_content` оставлена как была.

## Проверка

* 8 юнит-тестов `lumen-layout` на всю матрицу выше плюс граничные случаи:
  `img_inside_inline_element_keeps_its_own_box`,
  `block_child_of_inline_element_keeps_its_height`,
  `flex_child_of_inline_element_stays_a_flex_container`,
  `form_control_inside_inline_element_gets_a_box`,
  `escaped_child_inherits_from_the_inline_element_not_the_block`,
  `escape_preserves_document_order_around_the_split`,
  `display_contents_inside_inline_element_stays_flattened`,
  `inline_block_inside_inline_element_stays_in_the_row`.
* Полный `cargo test -p lumen-layout` — 3503 теста, 0 падений; `scoped-test.sh` —
  зелёный, кроме одного эталона (см. ниже).
* Эталон `lumen-paint` `img_inside_span` был запечён с `32.00, 19.20` — с высотой
  строки вместо `height="32"`, то есть **этот дефект сидел в эталоне**. Обновлён
  на `32.00, 32.00`.
* Пиксельный гейт. `dump_golden.py` — 12/12 дампов совпадают; детерминированные
  CPU-снимки (`cases::snapshot_cpu`, 81 страница, побайтовое сравнение) —
  зелёные. Сверх того прогнан прямой гейт нейтральности: `--dump-display-list`
  по **всем 158 страницам `graphic_tests/`** сборкой до и после — дампы
  побайтово идентичны, то есть полный визуальный прогон не может дать другого
  результата. Причина: ни одна тест-страница не кладёт не-inline элемент внутрь
  настоящего inline-элемента (`.box` в `111-appearance-none.html` — это
  `display: inline-block`, другой путь).

## Отношение к BUG-488

[BUG-488](BUG-488-OPEN.md) — про **интроспекцию**: у inline-элемента нет своего
`NodeId` в дереве боксов, поэтому `getComputedStyle`/`getBoundingClientRect` по нему
отдают пусто/ноль. Здесь дефект был в самом рендере: геометрия терялась в выводе, а не
только в отчёте о нём. **Фикс BUG-728 не закрывает BUG-488**: у самого `<span>`/`<a>`
своего бокса по-прежнему нет — он появился только у всплывших потомков. Симптомы
легко перепутать (на `tbank.ru` 896 из 2242 элементов отдают пустой `display` и
нулевой rect — это BUG-488, и по нему нельзя судить, есть у элемента бокс или нет).

## Как воспроизвести (историческое)

`.tmp/img-repro/inline.html` из разбора (матрица выше) + локальный HTTP-сервер;
`lumen --dump-display-list http://127.0.0.1:PORT/inline.html`. `file://` как стартовый
аргумент не работает ([BUG-651](BUG-651-OPEN.md)).
