# BUG-1225 — при полной навигации 0.27–0.5 с показывается страница без стилей (последний кадр стриминга), пока не завершится финальный pipeline

**Статус:** OPEN
**Компонент:** shell (`crates/shell/src/app/user_event.rs:215-…` — `LoadEvent::LoadDone`, «финальный pipeline (off-thread)»; кадр стриминга, `stream_builder`/`stream_sheet`)
**Найден:** 2026-09-29, покадровый разбор видео пользователя (`lumen_browser_0.mp4`, 8 fps) + живой замер, сборка `main` 22a782d55

## Симптом

После клика по ссылке (см. [BUG-1224](BUG-1224-OPEN.md): сейчас каждый переход — полная загрузка) окно на 3–4 кадра записи (0.375–0.5 с)
показывает сырой HTML без CSS: сайдбар — serif-текст с синими подчёркнутыми ссылками и иконками, основного содержимого нет,
заголовок окна уже новый. Затем страница разом становится стилизованной. Так же на первом открытии: страница входа один кадр без стилей.

Видео, покадрово (8 fps, 8 кадров/с ⇒ шаг 0.125 с):

| Эпизод | Кадров без стилей |
|---|---|
| 30.6 с: вход → дашборд | ≥ 2 |
| 55.9 с: `/calendar` → `/creditors` | 3 пустых серых + 4 без стилей |
| 69–74 с: серия переходов на «Документооборот» | 3–4 на каждый переход, повторяется |
| 91.5 с: `/about` → `/documents` | 4 |
| первое открытие, страница входа | 1 |

## Живой замер (без записи, без фоновой нагрузки; `LUMEN_FRAME_LOG=1`, время от `navigate`)

`/correspondence`: ответ документа 0.054 с → кадр 47 команд (только оболочка) 0.062 → **кадр 366 команд на 0.171 с
(relayout off-thread 23 мс, `styled=195`)** → тишина ~270 мс → `RenderDone` 0.421 → layout 17 мс на 0.441 → итоговые
**281 команда** и загрузка шрифтов 0.454. Кадр из 366 команд одинаков на разных страницах (`/documents`, `/profile`, `/correspondence`),
итоговое число команд — разное: 217 / 375 / 281. Вывод «это страница без стилей» косвенный (число команд отрисовки, совпадение с видео по длительности); прямого скриншота промежуточного кадра из живого окна нет — CPU-скриншот MCP идёт другим путём.
`/about`: кадр 56 → следующий значимый 334 команды только на 0.49–0.54 с.

CSS запрашивается на 0.04–0.06 с (`preload css [high]`), разбор 129 КБ — 3–5 мс ([BUG-1223](BUG-1223-OPEN.md)), то есть
стили доступны почти сразу, но на экран попадают только после `RenderDone`.

## Причина (по коду, не проверена правкой)

`user_event.rs`: пока тяжёлый финальный pipeline (загрузка скриптов → JS → CSS/шрифты/картинки → layout) идёт в фоне, «event loop остаётся
живым (перерисовка последнего streaming-кадра)». Кадр стриминга строится без применённых таблиц стилей, и он же остаётся на экране до `RenderDone`.

## Ожидание

Как в других браузерах: первая отрисовка ждёт render-blocking `<link rel=stylesheet>` из `<head>` (или показывает прежнюю страницу),
а не рисует нестилизованный DOM.

## Что делать

Не публиковать кадр стриминга, пока не применены таблицы из `<head>` (они уже запрошены в момент первого кадра); либо
блокировать первую отрисовку до готовности CSS. Метрика для теста: ни один показанный кадр не содержит нестилизованных
элементов (число команд первого показанного кадра = итоговому ± контент).
