# BUG-728: элемент внутри inline-элемента теряет собственную геометрию — схлопывается в высоту строки

**Статус:** OPEN
**Компонент:** layout (`crates/engine/layout/src/box_tree.rs` — `collect_inline_segments` / `InlineSegment`)
**Найден:** P3 при разборе [BUG-725](BUG-725-OPEN.md), 2026-08-09

## Симптом

Всё, что вложено внутрь inline-элемента (`<a>`, `<span>`, …), рисуется на высоту
текстовой строки и теряет собственную раскладку. Минимальное репро (`img { width:
50px; height: 50px }`, `.b { display: block; height: 30px }`):

| разметка | display list |
|---|---|
| `<div>A: <img></div>` | `DrawImage (0, 16.8, 50, **50**)` — верно |
| `<div><span><img></span></div>` | `DrawImage (0, 71.6, 50, **16.8**)` |
| `<div><a href="#"><img></a></div>` | `DrawImage (0, 88.4, 50, **16.8**)` |
| `<div><span><span><img></span></span></div>` | `DrawImage (0, 105.2, 50, **16.8**)` |
| `<div><span><div class="b">…</div></span></div>` | `FillRect (0, 122, 82, **17**)` вместо height 30 и полной ширины блока |
| `<div><span><div style="display:flex">…</div></span></div>` | флекс-контейнера нет, остался только текст |
| `<div><span><input></span></div>` | ни одной команды — поле исчезло |

То есть ширина (`width: 50px`) сегмент переживает, **высота — нет**, а
блочно-уровневый или флекс/грид потомок внутри inline вообще перестаёт быть
контейнером: от него остаётся текстовый прогон и фон в одну строку.

## Механизм

`collect_inline_segments` разворачивает поддерево inline-элемента в плоский список
`InlineSegment`. У сегмента есть `img_width`, `pre_space`, `post_space` — и **нет
высоты**: вертикальный размер строки считается по метрикам шрифта. Замещаемый
элемент (`<img>`) попадает в сегмент с `is_element_box: true`/`img_src`, поэтому
`DrawImage` эмитится, но с высотой строки. Блочный потомок (CSS 2.1 §9.2.1.1 требует
разрезать вокруг него inline-бокс) не разрезает ничего — рекурсия просто собирает из
него текст, и собственный бокс с его `display`/`height`/флекс-раскладкой не строится.

## Почему это важно

Так свёрстана почти любая карточка-ссылка: `<li><a><div class="card"><img>…`. На
`https://www.tbank.ru/` внутри `<a>` лежат все контентные картинки и вся сетка
карточек — это основная оставшаяся причина расхождения с эталоном
([BUG-725](BUG-725-OPEN.md)).

## Отношение к BUG-488

[BUG-488](BUG-488-OPEN.md) — про **интроспекцию**: у inline-элемента нет своего
`NodeId` в дереве боксов, поэтому `getComputedStyle`/`getBoundingClientRect` по нему
отдают пусто/ноль. Здесь дефект в самом рендере: геометрия теряется в выводе, а не
только в отчёте о нём. Симптомы легко перепутать (на `tbank.ru` 896 из 2242 элементов
отдают пустой `display` и нулевой rect — это BUG-488, и по нему нельзя судить, есть у
элемента бокс или нет). Чинить, вероятно, вместе: обе беды растут из того, что
inline-поддерево уплощается в один прогон.

## Как воспроизвести

`.tmp/img-repro/inline.html` из разбора (матрица выше) + локальный HTTP-сервер;
`lumen --dump-display-list http://127.0.0.1:PORT/inline.html`. `file://` как стартовый
аргумент не работает ([BUG-651](BUG-651-OPEN.md)).
