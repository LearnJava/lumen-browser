# BUG-1178 — у документа без `<script>` нет JS-рантайма: MCP `eval` всегда «JS context not available»

**Статус:** OPEN
**Заведён:** 2026-09-25 (P6, по ходу закрытия [BUG-493](BUG-493-FIXED.md)).
**Область:** shell (`crates/shell/src/scripts.rs:788-791` — `run_scripts_with_dom` возвращает
`(doc_arc, None, None)`, если скриптов нет и `always_runtime == false`;
`crates/shell/src/page_pipeline.rs:1260` передаёт `false` для страницы верхнего уровня).

## Симптом

Живое окно `--mcp-live-port`, `navigate` на страницу без единого `<script>` —
`http://127.0.0.1:8793/noscript.html` (`<title>noscript</title><p>hi</p>`) или
`https://example.com/`. `wait document_ready` проходит (3.9–5.8 с), затем `eval("document.title")`
→ `Eval error: JS context not available` — 2 из 2 и 2 из 2. Та же страница с одним
`<script>window.x=1</script>` отвечает сразу.

Chrome (CDP `Runtime.evaluate`) отвечает на любой странице: глобальный объект и `document`
существуют независимо от того, есть ли на странице скрипты.

## Почему это дефект, а не особенность автоматизации

Рантайм, которого нет, — это не только `eval`: расширения/инструменты автоматизации, `click`
с JS-обработчиками, вставленными позже через MCP, и всё, что читает DOM через JS, получают на
статической странице ответ «контекста нет». Ответ ещё и совпадает по тексту с таймаутом движкового
потока ([BUG-1145](BUG-1145-OPEN.md)) и с окном `about:blank`
([`docs/probe-method.md`](../docs/probe-method.md) §2), так что пробу на статической странице
легко принять за сломанное окружение.

## Что сделать

Создавать рантайм для документа верхнего уровня всегда (как уже делается для фреймов —
`always_runtime`, BUG-480 срез 8), либо лениво при первом запросе автоматизации. Оценить цену:
сколько стоит V8-контекст на статической странице (время и память) — если заметно, выбрать
ленивый вариант.

Критерий: `eval("document.title")` на `noscript.html` возвращает `"noscript"`.
