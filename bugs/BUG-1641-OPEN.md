# BUG-1641 — `mix-blend-mode` не применяется в живом wgpu-окне (TEST-56: 1.36% → 14.13%)

**Статус:** OPEN
**Заведён:** 2026-10-19 (P2, при TEST-9-S2: полный прогон графтестов после перехода на гибридный захват)
**Область:** paint (wgpu-исполнение плана рендера: группа `mix-blend-mode`; `crates/engine/paint/src/renderer.rs`)

## Симптом

В живом окне (gdigrab, GPU-путь) все панели `graphic_tests/tests/56-mix-blend-mode.html` рисуются как `mix-blend-mode: normal`:
синий квадрат поверх жёлтого фона остаётся `#39F` во всех 16 ячейках, а у Edge он смешан (multiply/screen/difference/… —
разные цвета). Последняя ячейка с красным/зелёным наложением тоже без смешивания.

| способ захвата | diff с Edge |
|---|---|
| gdigrab (живое окно, wgpu) — `python graphic_tests/run.py --gdigrab --only 56` | **14.13%** (регион x:60–821 y:50–646, то есть все ячейки) |
| gdigrab, прогон 2026-09-19 (`results/20260919-133745.json`) | 1.355% |
| IPC (CPU-растеризатор) — `python graphic_tests/run.py --ipc --only 56` | 0.85% (одна ячейка, x:60–149 y:434–503), 09-19: 2.17% |

CPU-растеризатор смешивание делает, wgpu-путь окна — нет. Результат стабилен (три прогона подряд 14.13%), не флак захвата и не
зависит от способа запуска окна. Между 09-19 и 10-19 тест красным не был по другой причине (FAIL 1.36% над порогом 0.5%), поэтому
регрессия 1.36→14.13 не была видна в списке красных.

## Как проверить

```
python graphic_tests/run.py --gdigrab --only 56      # 14.13%
python graphic_tests/run.py --ipc --only 56          # 0.85%
```

Картинки — `graphic_tests/screenshots/56-mix-blend-mode-{lumen-cropped,diff}.png` после прогона. Бисект по коммитам между
2026-09-19 и 2026-10-19 в paint (wgpu) не делался.
