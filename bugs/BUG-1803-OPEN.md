# BUG-1803 — Lumen не следует системному прокси Windows (WinINET): маршрут отличается от Chrome у пользователя с прокси

**Статус:** OPEN (ДОРАБОТКА → COMPAT-ROUTE)
**Открыт:** 2026-11-12 (P3, перф-аудит ebay; замечено пользователем с включённым системным прокси)
**Компонент:** network (стек не читает WinINET-настройки; единственный механизм прокси — `proxy = "…"` в `data/fingerprint.toml`, BUG-1210)

## Симптом

Машина пользователя: `ProxyEnable=1`, `ProxyServer=http://127.0.0.1:12334` (HKCU\...\Internet Settings). Chrome и другие браузеры идут через прокси; **Lumen всегда напрямую** — grep по `crates/` не находит чтения системных настроек прокси (WinHttpGetIEProxyConfigForCurrentUser/реестра нет), `--proxy`-флаг не действует (BUG-1210).

Последствия (наблюдение 2026-11-12, ebay): выход-нода пользовательского прокси была забанена DataDome — **Chrome (через прокси) получал 403, Lumen (напрямую) — 200**: у пользователя Lumen «работает там, где Chrome не может», но и обратное верно — сайт, доступный только через прокси, в Lumen открыть нельзя. Отчёт: [docs/perf/runs/2026-11-12-ebay-audit.md](../docs/perf/runs/2026-11-12-ebay-audit.md) §8.

## Что сделать

Минимум: при старте сетевого стека читать `ProxyEnable`/`ProxyServer` (и `AutoConfigURL` — PAC отдельным шагом) из HKCU Internet Settings и использовать как дефолт, если `fingerprint.toml` свой `proxy =` не задаёт (его приоритет выше). Затем — HTTP-прокси с CONNECT; PAC/автоопределение — отдельные срезы.

## Репро

Включить системный прокси, открыть в Lumen любой сайт, смотреть маршрут в сетевом логе — соединения идут мимо прокси.
