# BUG-1195 — Web Animations: `_wa_lerp_scalar` смешивает единицы и не экстраполирует

**Статус:** FIXED 2026-10-01 (P3)
**Заведён:** 2026-09-26 (P1, по ходу GAP-INTERESTINVOKER — вне выданного пункта).
**Область:** js — Web Animations в
[`web_api_shim_tail_b.js`](../crates/js/src/shim/web_api_shim_tail_b.js)
(`_wa_lerp_scalar`, `_wa_compute_at_p`).

## Симптом (по коду)

`_wa_interp_prop` для всех свойств, кроме цвета/`opacity`/`transform`/`dynamicRangeLimit`,
зовёт `_wa_lerp_scalar(a, b, t)`:

- обе стороны читаются `parseFloat` **без приведения единиц**, единица результата — единица
  `a` (или `b`). Ключевые кадры `1s → 2000ms` на полпути дают `1 + (2000 − 1)·0.5 = 1000.5` и
  единицу `s` — `1000.5s` вместо `1.5s`. То же для любой пары разных единиц одного типа
  (`1in → 96px`, `1turn → 90deg`);
- `_wa_compute_at_p` зажимает локальный прогресс сегмента в `[0, 1]` до `_wa_ease`, поэтому
  прогресс вне отрезка (`cubic-bezier` с выбросом, WPT `interpolation-testcommon.js`
  на `-1.5`/`1.5`) не экстраполируется: `-0.3` даёт начальное значение, а не `0.7s`.

## Что это ломает

WPT `html/semantics/interestfor/interestfor-css-properties.tentative.html`: все 12 подтестов
«Web Animations: property <interest-delay-start|end> from [1s] to [2000ms] at (…)» —
`expected "1.5s" but got "1000.5s"` и `expected "0.7s" but got "1s"`. Любая
`element.animate()`-анимация длины/угла/времени с разными единицами в кадрах даёт мусор.

## Направление

Разобрать значение на число+единицу, привести к канонической единице типа (`s`, `px`, `deg`)
до смешивания, а несовместимые пары оставить дискретными (`t < 0.5 ? a : b`). Зажимать
прогресс только там, где тип значения этого требует (неотрицательные `<time>`/`opacity`),
а не весь сегмент.

## Исправление

`_wa_lerp_scalar` приводит разные единицы одного измерения (время → `s`, длина → `px`,
угол → `deg`) к канонической до смешивания; несовместимые пары — дискретно. Одинаковые
единицы сохраняются. Зажим прогресса сегмента для `linear`/`cubic-bezier` к тому моменту уже
снят (`_wa_compute_at_p`), экстраполяция `-0.3 → 0.7s` работает. Тест —
`wa_lerp_scalar_converts_units_and_extrapolates`.
