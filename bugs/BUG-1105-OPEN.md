# BUG-1105 — `<audio>.duration` остаётся `Infinity` у полностью декодированного MP3

**Статус:** OPEN
**Заведён:** P3, 2026-09-23, попутно при закрытии [BUG-924](BUG-924-FIXED.md)
**Область:** shell (`crates/shell/src/platform/audio_player.rs:169-176` — `AudioCmd::Load`, `rodio::Decoder::total_duration()`)
**Владелец:** P3

## Симптом

`<audio src="…sine440.mp3">` доходит до `loadeddata`/`readyState=4` (сеть и
декодирование в порядке), но `audio.duration` остаётся `Infinity` вместо
реальной длительности. Замерено пробой
`tests/wpt/verify_bug924_audio_src_resolve.py` (2026-09-23, dev-release):

```
PROBE abs:loadeddata currentSrc=http://127.0.0.1:PORT/sine440.mp3 duration=Infinity
```

на всех трёх формах URL одинаково — от резолва пути дефект не зависит.

## Механизм

`total_duration()` из `rodio::Decoder` (backend `minimp3` для формата mp3,
`rodio = { features = ["mp3", …] }`) не считает длительность без полного
прохода по фреймам — для MP3 он всегда отдаёт `None`, откуда
`.unwrap_or(f64::NAN)` (`audio_player.rs:175`) кладёт `NaN` в `st.duration`,
а шим (`audio_element.rs:395-402`) превращает `NaN` в `Infinity` — это
осознанное поведение шима для случая «длительность не определена» (см.
[BUG-825](BUG-825-FIXED.md)), а не баг рефлексии; сам факт «не определена»
и есть дефект.

Починка требует одного из: (1) досчитать длительность отдельным проходом по
уже скачанным байтам (framecount × frame-duration для CBR, оценка по битрейту
для VBR — тот же трюк, которым MP3-плееры в браузерах закрывают этот же
пробел у `minimp3`), либо (2) сменить декодер/бэкенд на тот, что считает
длительность из заголовков (symphonia, уже вендорится где-то в дереве —
проверить прежде чем добавлять новую зависимость, ADR-027). Не блокирует
[BUG-924](BUG-924-FIXED.md) — тот про резолв URL, не про декодер; заведено
отдельно, потому что механизм и файл другие.

## Как проверить фикс

Тот же пробник, `duration=` в логе — конечное число, близкое к реальной
длительности `tests/wpt/media/sine440.mp3`.
