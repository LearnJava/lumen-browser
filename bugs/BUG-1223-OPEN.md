# BUG-1223 — Переходы между страницами bankruptcy-platform: 0.34–1.36 с, ~5 полных relayout на переход, каскад — 58 % каждого

**Статус:** OPEN (замер; механизм общий с [BUG-341](BUG-341-FIXED.md))
**Компонент:** layout (каскад `precompute_counters`), shell (relayout при мутации DOM), js (гидратация)
**Найден:** 2026-09-29. Методика и цифры — [docs/perf/bankruptcy-platform-2026-09-29.md](../docs/perf/bankruptcy-platform-2026-09-29.md)

**Поправка 2026-09-29 (позже):** замеры ниже названы «клиентскими переходами» ошибочно — это были **полные перезагрузки страницы** (маркер `window` терялся после каждого клика): Lumen игнорирует `preventDefault()` на клике по ссылке, см. [BUG-1224](BUG-1224-FIXED.md). Цифры остаются верными как стоимость полной загрузки; стоимость настоящего мягкого перехода не измерялась.

## Симптом (жалоба пользователя)

Переход между страницами то мгновенный, то заметно тормозит; на ходу видна страница без стилей.

## Замеры (dev-release `main` 22a782d55, окно `--maximized`, 1920×945)

- Клик по пункту сайдбара → смена URL и заголовка: **0.34, 0.36, 0.34, 0.52, 0.38, 0.75, 0.38, 1.36, 0.38 с**
  (медиана 0.38, хвост до 1.36 с).
- За 10 переходов движок сделал **56 полных `layout_measured_hyp`** (≈5 на переход): среднее 17.8 мс, максимум 52.8 мс.
  `precompute_counters` (по факту — **полный каскад `compute_style` по всем узлам**, не только счётчики) — 584 из 998 мс = **58 %**.
- `[engine] relayout` (off-thread) на 180–184 стилизуемых узла: p50 22.7 мс, p95 40.5 мс, max 65.9 мс.
- Разбор CSS **дешёвый**: 129 КБ (115 + 14) парсятся за 3–5 мс, `cssom-node-sheets` 3.5–6 мс. Кэш разобранных таблиц
  даст ≤ 8 мс на загрузку; основной выигрыш — не пересчитывать каскад узлов, чей стиль не менялся.
- Пока идёт гидратация (42 JS-чанка), XHR `/api/*` завершаются за ~260 мс; на простаивающей странице те же запросы —
  23–47 мс (backend напрямую 17–45 мс). Ответы ждут занятый JS-поток.

## Связь с открытыми багами

- Инкрементальный каскад (`RestyleDelta`, BUG-341 S3…) есть, но при клиентском переходе заменяется почти всё поддерево,
  и каждый из ~5 relayout идёт полным проходом.
- [BUG-1112](BUG-1112-WONTFIX.md) — связь снята 2026-10-01: `ShareCache` по построению берёт только SVG-presentational
  узлы (`is_svg_presentational_element`), обычные HTML-узлы Tailwind-вёрстки он не шарит ни при каком ключе, а на
  измеренных сайтах даёт `hit=0` даже с идеальным ключом (BUG-1112 срезы 13-14). Стоимость ≈50 мкс на узел из 1521
  правила здесь — вопрос самого каскада (кандидаты `RuleIndex`, матчинг), не разделения стилей.

## Повторный прогон без фоновой нагрузки

Переходы: 0.37–0.55 с (медиана 0.50), хвост 1.36 с был от чужих `rustc`. Relayout — 3 на переход (30 на 10 переходов), 493 мс всего,
каскад 286.5 мс = 58 % (доля прежняя), off-thread relayout p50 31.6 / p95 52.7 мс. Цифры — в отчёте, раздел «Повторный прогон».

## Ограничение замера

Часть прогонов шла, пока на машине работали два `rustc` (≈125 % и 115 % при 8 ядрах, чужие сборки), поэтому абсолютные
времена завышены; доли (58 % каскад, ~5 relayout на переход) от нагрузки не зависят.
