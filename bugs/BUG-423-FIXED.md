# BUG-423 — с реальных страниц пропадали буквы: bbox composite-глифа брался из заголовка, а он бывает битым

**Статус:** FIXED 2026-07-29
**Компонент:** font (`crates/engine/font/src/face.rs` — `glyph_resolved_inner`,
`crates/engine/font/src/rasterizer.rs` — `Rasterizer::rasterize`)
**Найден:** P1, 2026-07-28, при показе живого окна на https://yandex.ru
**Исправлен:** P1, 2026-07-29

## Симптом

Часть букв на реальных сайтах не рисуется, **на их месте остаётся пробел ровно
их ширины** — то есть метрики известны, а ink-а нет.

Воспроизведено на https://ya.ru (живое окно, wgpu/DX12):

| Должно быть | Было нарисовано |
|---|---|
| `Санкт-Петербург` | `нкт-П` |
| `Найдётся всё` | `йдёт я в ё` |
| `Финансы` | `Фин ы` |
| `Медицина` | `дицин` |
| `Алиса AI` | `ли AI` |

## Причина (установлена на байтах шрифта)

Пропадали ровно те кириллические буквы, которые «YS Text Home» собирает из
латинских **composite**-ссылкой: `а`←`a`, `с`←`c`, `о`←`o`, `е`←`e`, `р`←`p`.
Буквы с уникальной формой (`н`, `к`, `т`) — простые глифы — рисовались всегда.

Разбор `glyf` этого шрифта (gid 445 = `о`, компонент — gid 335 = `o`):

```
gid 335 (база 'o'):  n=2,  bbox = (35, -10, 537, 529)      ← корректный
gid 445 (комп. 'о'): n=-1, bbox = (746, 35, -10, 537)      ← x_max < x_min
```

Шрифт пишет в заголовок композита сдвинутую четвёрку — фактически
`(advance, xMin, yMin, xMax)`. По спеке поле обязано быть корректным, но
сабсеттеры/сборщики кладут туда что угодно, а движки на него и не полагаются:
истинные границы собранного глифа известны только после разворачивания
компонентов.

Дальше цепочка была такой:

1. `Font::glyph_resolved_inner` разворачивал композит в `Outline::Simple`
   корректно, но **bbox копировал из заголовка parent-а** (`bbox: glyph.bbox`).
2. `Rasterizer::rasterize` считал по этому bbox размер битмапа, получал
   `width_i32 <= 0` и возвращал `None` — эту ветку добавил
   [BUG-283](BUG-283-FIXED.md) как защиту от заворачивания `u32` и падения
   процесса на `vec![0u8; width*height]`.
3. `push_text_glyphs` на `None` просто двигал курсор на advance из `hmtx`
   (верный) — буква исчезала, ширина оставалась.

Дефект был **невидим для тестов**: bundled-шрифты (Golos Text, Inter,
JetBrains Mono) содержат 306/1881/589 композитов и **ни одного** с вывернутым
bbox, поэтому графические и снапшот-тесты его не задевали.

## Починка

* `face.rs::glyph_resolved_inner` — bbox развёрнутого композита считается по
  собранным точкам (`glyf::bbox_from_contours`), а не берётся из заголовка.
* `rasterizer.rs::rasterize` — при вывернутом заголовке
  (`BoundingBox::is_inverted`) бокс пересчитывается по точкам вместо отказа.
  Защита BUG-283 сохранена: пересчитанный бокс ограничен координатами точек, а
  `MAX_GLYPH_DIM` по-прежнему режет экстремальные случаи.

Для квадратичных Безье коробка по контрольным точкам — **надмножество**
истинной (кривая лежит в выпуклой оболочке своих контрольных точек), поэтому
глиф от такого бокса не обрезается; в худшем случае битмап получает лишний
прозрачный край.

## Проверка

* `crates/engine/font/tests/cases/composite_bbox.rs` — синтетический TTF, где
  composite ссылается на квадрат, а заголовок содержит вывернутую четвёрку из
  YS Text: bbox после resolve равен геометрии компонента, растеризация даёт
  непустой битмап (до правки — `None`). Контрольный тест с честным заголовком
  показывает, что для корректных шрифтов результат не изменился.
* `glyf.rs` — юнит-тесты `bbox_from_contours` / `is_inverted`.
* `rasterizer.rs` — два теста BUG-283 переведены с «вернуть `None`» на
  «пересчитать бокс по точкам» (размер битмапа совпал с честным bbox).
* Живой прогон https://ya.ru до/после: пропажи букв ушли (временная
  диагностика `[glyph] BLANK` осталась только на пробелах U+0020), текст на
  скриншоте полный.

## Что оказалось не так в исходной заявке

1. **Гипотеза про `unicode-range` опровергнута.** Заявка объясняла симптом тем,
   что сабсеты одной @font-face-семьи затирают друг друга в `FontRegistry`.
   Затирание реально (замерено: 9 `FontLoaded` → 8 замен на локальной странице
   с Google Fonts), но буквы от него **не пропадают** — у рендера есть
   codepoint-каскад (`renderer.rs::pick_face_for_codepoint`), берущий глиф из
   любого другого загруженного face-а; живой кадр такой страницы отрисован
   полностью. Затирание выделено в [BUG-434](BUG-434-FIXED.md). Симптом на ya.ru
   при этом воспроизводится вообще без единой замены в реестре.
2. **Часть про хром не воспроизведена** — см. [BUG-435](BUG-435-OPEN.md).
