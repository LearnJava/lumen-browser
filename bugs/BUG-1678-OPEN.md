# BUG-1678 — `decode_woff2` не реконструирует преобразованную таблицу `hmtx`

**Статус:** OPEN
**Заведён:** 2026-10-22 (P6, найдено при BUG-1404)
**Область:** font (`crates/engine/font/src/woff2.rs::decode_woff2`)

## Симптом

WOFF2 §5.4 (transform version 1 для `hmtx`): таблица хранится как байт флагов, массив `advanceWidth` и опциональные массивы
`lsb`/`leftSideBearing`, а `lsb` пропорциональных и моноширинных глифов можно опустить — декодер обязан взять их из `xMin`
глифов в реконструированной `glyf`. Сейчас `decode_woff2` лишь проверяет байт флагов (BUG-1404) и кладёт преобразованный поток в
sfnt как `hmtx` — размер и содержимое не соответствуют `hhea.numberOfHMetrics`/`maxp.numGlyphs`, метрики шрифта искажены.

Файлы: `tests/wpt/css/WOFF2/support/tabledata-transform-hmtx-001.woff2`, `-002.woff2` (валидные, декодируются без ошибки).

## Что делать

После реконструкции `glyf` собрать `hmtx` по §5.4: `numberOfHMetrics` из `hhea` (смещение 34), `numGlyphs` из `maxp` (смещение 4),
недостающие `lsb` = `xMin` глифа из реконструированных данных (0 для пустого глифа); тест — сверка с `hmtx` исходного шрифта.
