# BUG-702: `tbank.ru/auth/login/` вешает JS-движок бесконечным циклом (100% CPU, не завершается) — взаимодействие двух конкретных внешних бандлов

**Статус:** OPEN
**Компонент:** js (V8-движок, `run_scripts_with_dom` в `crates/shell/src/main.rs:6952` — синхронное исполнение classic-скриптов; конкретный код зависания не локализован глубже пары бандлов)
**Найден:** живая проверка `https://www.tbank.ru/auth/login/` (запрос пользователя — открыть браузер, зайти в личный кабинет, заполнить поля входа), 2026-08-09

## Симптом

`lumen --dump-layout https://www.tbank.ru/auth/login/` никогда не завершается —
`timeout 120` даёт exit 124. CPU процесса растёт монотонно (в одном замере: 29.75с
→ 36.39с → 42.98с накопленного CPU-времени за 10с реального времени между
замерами), память стабильна ~150-165МБ. Это настоящий бесконечный цикл, а не
ожидание сети: в headless dump-режиме таймеры не прокачиваются после начального
синхронного прохода по скриптам (см. `run_scripts_with_dom`, `for src in &scripts
{ rt.eval(src) }` без промежуточных `tick_timers`), значит зависание — синхронный
busy-loop внутри одного вызова `rt.eval(src)`.

То же самое воспроизводится в живом окне (`--mcp-live-port`): `navigate` на
`/auth/login/` возвращает `Ack`, но `wait{document_ready}` уходит в таймаут, и
после этого `eval` навсегда падает `JS context not available` — движковый поток
шелла застрял внутри зависшего `rt.eval`, поэтому automation-канал никогда не
получает обратно хэндл `js_ctx`. Это следствие зависания, не отдельный баг.

## Локализация (бисекция)

Страница входа подключает 4 внешних скрипта с `cdn.tbank.ru`:
- `unic/sso-newauth/react.<hash>.js` (140КБ)
- `unic/sso-newauth/platform.<hash>.js` (493КБ)
- `unic/sso-newauth/login.<hash>.chunk.js` (18КБ)
- `twa/platform/<hash>/client.js` (111КБ)

Скачаны через `curl`, собраны локальные тестовые HTML-страницы с разными
комбинациями `<script src="...">`, прогнаны `--dump-layout` с `timeout`:

- каждый скрипт **по отдельности** — завершается мгновенно, без ошибок;
- **любая пара, кроме react+platform** — завершается мгновенно;
- **`react.js` + `platform.js` вместе, в любом порядке тегов** — зависает
  (воспроизведено полностью офлайн, без сети, локальным HTML с двумя
  `<script src>` и без реального контента страницы) — значит дело в
  взаимодействии глобального состояния (повторная инициализация webpack-рантайма,
  полифилл конфликтует сам с собой и т.п.), а не в тайминге сети.

Дальше не бисектировано (нужен бинарный поиск усечением 493КБ минифицированного
`platform.js` через много итераций `--dump-layout`+`timeout` — не влезло в объём
предыдущей сессии).

## Возможный фикс

Не диагностирован — нужен пошаговый профайлер/дебаггер V8 (или продолжение
бисекции усечением файла) внутри `platform.js`, чтобы найти конкретную функцию
цикла. Один из кандидатов: тот же класс проблемы, что [BUG-703](BUG-703-OPEN.md)
(зависшая гидратация React на главной странице того же сайта) — тот же дуэт
react+platform-рантайм, другая пара конкретных бандлов; не доказано общей
причины, стоит проверить в первую очередь при диагностике.
