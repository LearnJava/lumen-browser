# BUG-782 — TEST-18 (картинки) ушёл с 2.31 % на 6.34 %: регрессия на main между 2026-08-12 и 2026-08-17

**Статус:** FIXED 2026-09-30 (P3) — виновник найден бисекцией, а не среди семи кандидатов ниже.

## Причина и исправление (2026-09-30)

Бисекция `run.py --ipc --only 18` (CPU-снимок воспроизводит регрессию: 2.12 % → 15.03 %)
по 2124 коммитам указала на `0924acc73` FONTLOAD-10: strut ряда `InlineBlockRow` стал брать
`descent_px_with_families` реального шрифта (Times, 3.46 px) вместо bundled Inter. Живые
прогоны в `graphic_tests/results/` показывают тот же скачок на 2026-09-05 (2.29 → 14.98 %);
6.34 % из заголовка — промежуточное состояние, к срезам 13–23 BUG-405 отношения не имело.
Кадр под картинкой в Edge высотой ровно 160 px (156 + 4), у Lumen 159.46.

Blink округляет ascent/descent/lineGap до целых и кладёт floor половины half-leading на верх
(`FontHeight::AddLeading`), так что нижняя часть strut = `round(d) + ceil(round(gap)/2)` =
3 + 1 = 4. Так теперь считает и `layout_dispatch.rs` (`InlineBlockRow`). CPU-снимок:
TEST-18 15.03 → 2.06 % (DEBTOR), TEST-02/04 0.68 → 0.00 %, TEST-21 3.24 → 1.54 %,
TEST-56 2.17 → 0.85 %; ни один тест не ухудшился. Живой (gdigrab) прогон из этой сессии
недоступен (захват экрана из фона не калибруется) — `KNOWN_DEBTORS` не трогались; TEST-47/55/57/157
в CPU-снимке ниже 0.5 %, снять их записи нужно по живому прогону.

Ниже — исходная запись, оставлена как история.
**Компонент:** paint/image (кандидаты — срезы 20–23 [BUG-405](BUG-405-FIXED.md) и
[BUG-771](BUG-771-FIXED.md); точный коммит не бисекчен)
**Найден:** 2026-08-17 (P3), полным прогоном графтестов при снятии гейта для правки флекса
(ветка `p3-esm-async`). Перенумерован дважды из-за гонки номеров между параллельными
сессиями: заведён как BUG-772 (номер занят WPT-VENDOR-websockets), переименован в BUG-775
(номер занят WPT-VENDOR-webvtt при `git pull` 2026-08-18), окончательный номер — **BUG-782**.
В коммите гейта и в его сообщении баг ещё называется BUG-772/BUG-775 — это тот же самый файл.

## Симптом

`graphic_tests/18-images.html`: было `DEBTOR 2.31 %` (эталон
`graphic_tests/results/latest.json`, снят 2026-08-12 на коммите `9588ae076`), стало
**`FAIL 6.34 %`** — порог теста 0.5 %, запись должника BUG-219 рассчитана на 2.11 %.

Число устойчивое: два прогона подряд дают ровно 6.34 %.

## Чего это НЕ

Не правка флекса из ветки, на которой найдено. Проверено прямым A/B на одном рабочем дереве:
с откаченным `crates/engine/layout/src/box_tree.rs` (`git checkout HEAD~1 -- …`, полная
пересборка `dev-release`) TEST-18 даёт **те же 6.34 %**. Страница вдобавок не содержит ни
одного `flex` (`grep -c flex graphic_tests/18-images.html` → 0), а все три ветки правки
включаются только при auto-полях, `flex-grow` или `max-width`.

## Где искать

Эталон снят на `9588ae076` (BUG-405 срез 16). После него в main влиты, в порядке:

* `83ce75b4d` — BUG-405 срез 13 (укладка текстового run-а считается один раз);
* `96f6b3724` — срез 14 (выбор бэкенда wgpu, кэш пробы);
* `e6a240843` / `945e7bff7` — срез 20 (прогрев полосы скролл-композитора);
* `744c3f907` — срез 21 (bind group блита полосы);
* `2207cdb38` — срез 22 (полоса ужимается под лимит текстуры);
* `1177bc1b1` — срез 23 (сторона текстуры по тиру адаптера);
* `a8b45059e` — BUG-771 (пре-резолв face-ов `DrawText`).

Срезы 22/23 меняют размер текстур и путь композитора, срез 14 — сам бэкенд wgpu; и то и
другое способно сдвинуть пересэмплирование картинок, а именно им TEST-18 и мерится
(остаток BUG-219 — «image downscale resampling parity vs Edge»). Первый шаг — бисекция по
этим семи коммитам с `run.py --only 18`; каждый шаг ≈ 3 мин сборки + 10 с прогона.

**Гоча при бисекции:** число зависит от бэкенда wgpu (BUG-405 срез 14 — Vulkan против DX12
меняет и картинку, и время). Перед сравнением пинуй `WGPU_BACKEND=vulkan` и проверяй строку
`[wgpu] adapter: …` в stderr, иначе смена бэкенда между шагами выглядит как «нашёлся
виновный коммит».

## Как воспроизвести

```bash
LUMEN_PROFILE=dev-release python graphic_tests/run.py --only 18
```
