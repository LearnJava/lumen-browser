# BUG-1077 — Плавающая chrome-панель `#demoBar` (CC-18, BUG-1059) теперь всегда видна в живом окне и ломает диф-гейт каждого real-JS графического теста

**Статус:** OPEN (DEBTOR)
**Тип:** регрессия тестового окружения — не дефект движка/страницы, панель рисуется корректно по своему собственному дизайну.
**Заведён:** 2026-09-21 (P1, срез 6 P3-webgl2, `docs/tasks/ph3-webgl2.md`)
**Область:** тулинг графтестов / shell chrome — `assets/chrome/chrome.html` (`.demo-bar`, `position:fixed; left:18px; bottom:18px`) + `crates/shell/src/chrome_ui.rs`/`chrome_float.rs` (`take_floating_panel`/`chrome_floating_dl`, BUG-1059).
**Владелец:** P2 (владелец тулинга графтестов) — сама панель не баг, решение (флаг для авто-прогонов vs. добавление в KNOWN_DEBTORS каждого real-JS теста) нужно принять на уровне run.py/CLI.

## Симптом

BUG-1059 (закрыт 2026-09-19) починил реальный рендер-баг: `#demoBar`/`#infoPanel` (CC-18, "ПАНЕЛЬ УПРАВЛЕНИЯ ДЕМО — не часть Lumen") были геометрически
корректны, но никогда не попадали на экран живого окна из-за клипа `build_chrome_overlay_strips`. Побочный эффект: теперь эта панель **всегда** рисуется
поверх страницы в любом `lumen.exe`-окне (position:fixed, left:18px, bottom:18px, ~252×520px по умолчанию) — включая живое окно `graphic_tests/run.py`
(`--mcp-live-port`, SDC-3/SDC-4), которое **не** передаёт никакого флага, чтобы её скрыть.

`msedge.exe` (эталон) никогда её не рисует — это чисто Lumen-side dev-виджет ("не часть Lumen"). Поэтому любой real-JS графический тест (в котором живое
окно, а не CPU-снапшот, снимает пиксели — TEST-57, TEST-129..138 и новый TEST-157), у которого хоть какой-то контент/фон приходится на нижний левый угол
(примерно x:[18,270], y:[186,706] в 1024×720-вьюпорте после кропа магента-маркера), теперь получает диф вместо чистого совпадения:

```
TEST-57:  FAIL (8.59%)   ← был известный дебтор BUG-099, baseline 0.88%+2% допуск, теперь превышен
TEST-157: FAIL (5.06%)   ← новый тест (P3-webgl2 срез 6), весь диф = ровно контур панели, 0 расхождений в самом WebGL-контенте
```

`157-webgl2-diff.png` подтверждает: единственные ненулевые пиксели в diff — сама панель (заголовок «Lumen — ДЕМО-ПАНЕЛЬ · ПЕРЕТАЩИ МЕНЯ», кнопки формы,
профиль, тема, Command Palette hint); все 5 WebGL-канвасов дают идеально чёрный (нулевой) диф.

Так как панель `position:fixed` относительно всего окна, а не часть контента страницы, **сдвинуть тестовый контент, чтобы её избежать, работает только
частично** — TEST-157 уже переверстан в один ряд полностью выше панели (используя тот же приём, что и ряд 1 TEST-57), но диф всё равно 5.06%, потому что
сама панель перекрывает пустой фон страницы, а не только тестовый контент: там, где у Lumen рисуется панель, у Edge — пустой фон `#0f172a`, и это
расхождение не зависит от того, что находится в этой области у тестовой страницы.

## Ожидание

Один из вариантов (решение — за владельцем тулинга, P2):
1. Флаг `--mcp-live-port`/новый `--no-demo-bar` для `lumen.exe`, который `graphic_tests/run.py` передаёт в живое окно (аналог уже существующего
   `--no-scrollbar`, `crates/shell/src/cli_args.rs::extract_no_scrollbar`).
2. Или: `run.py` добавляет `KNOWN_DEBTORS` запись для каждого real-JS теста, у которого контент/фон попадает под панель, с обоснованием "BUG-1077" —
   тот же паттерн, что уже покрывает TEST-57 (BUG-099).

## Не проверялось

- Влияет ли позиция панели (перетаскиваемая, "Перетащите за шапку в любое место") на воспроизводимость между запусками — по коду позиция не
  персистится на диск, так что каждый свежий процесс должен давать одинаковый CSS-дефолт (`left:18px; bottom:18px`), но не подтверждено много прогонов.
- Полный список всех real-JS тестов (57, 129-138), которые теперь ловят регрессию — прогнан только TEST-57 точечно.
- Формы панели (`data-demo="compact"/"bar"/"dock"/...`) — возможно, какая-то занимает меньше места и меньше пересекается с типичным контентом тестов.
