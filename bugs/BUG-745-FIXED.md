# BUG-745: абсолютно позиционированный бокс с `width: auto` не ужимается по содержимому

**Статус:** FIXED 2026-08-10
**Компонент:** layout (`crates/engine/layout/src/box_tree.rs` — размещение
`position: absolute`/`fixed`)
**Найден:** P3 при разборе пункта 4 [BUG-733](BUG-733-FIXED.md), 2026-08-10

## Что происходит

По CSS 2.1 §10.3.7 у абсолютно позиционированного не-replaced элемента с
`width: auto` и хотя бы одной `auto`-инсетой ширина — shrink-to-fit. Lumen
вместо этого растягивает бокс на всю ширину содержащего блока, а потом от него
же отсчитывает `right` — бокс уезжает за левый край на величину инсеты.

Локальное репро `.tmp/b745_abs.html` (вьюпорт 1024, контейнер `.rel` — 400):

| Объявление | Lumen `x, w` | Ожидается |
|---|---|---|
| `fixed; right: 16px` | `-16, 1024` | `~948, ~60` (правый край 1008) |
| `fixed; left: 16px` | `16, 1024` | `16, ~60` (сейчас вылезает на 1040) |
| `absolute; right: 16px` в блоке 400 px | `-16, 400` | `~324, ~60` |
| `fixed; left: 10px; right: 10px` | `10, 1004` | то же ✔ |
| `fixed; right: 16px; width: 200px` | `808, 200` | то же ✔ |

То есть обе «якорные» ветки (обе инсеты заданы; ширина задана явно) считаются
верно — ломается ровно та, где ширину нужно вывести из содержимого.

## Почему это важно

Это остаток пункта 4 [BUG-733](BUG-733-FIXED.md). После
[BUG-743](BUG-743-FIXED.md) cookie-баннер `tbank.ru` наконец получает свои
`position: fixed; bottom: 16px; right: 16px; z-index: 200` и белый фон, но
рисуется полосой во всю ширину вьюпорта со сдвигом на 16 px влево
(`x = -16, w = 1024`) вместо карточки шириной по содержимому справа внизу.
Форма «всплывающая карточка/тултип/тост, приклеенная к углу» — одна из самых
частых на вебе, так что дефект не про одну страницу.

## Как воспроизводить

```
python .tmp/b745_abs.py
```

## Исправление 2026-08-10 (P3)

`lay_out_abs_children` (`box_tree.rs`) считает ширину такого бокса по формуле
CSS 2.1 §10.3.7 `min(max(min-content, available), max-content)`, где
`available` — ширина содержащего блока за вычетом заданных инсет и
горизонтальных margin'ов, а min/max-content берутся уже существующими
`min_content_outer_width`/`max_content_outer_width` (они возвращают
border-box, поэтому margin'ы возвращаются обратно — `lay_out` трактует свой
`available_width` как margin-box). Обе «якорные» ветки не тронуты: ветка
«обе инсеты заданы» проверяется первой, ветка «ширина задана явно» отсекается
условием `cs.width.is_none()`.

Формула применяется не ко всем боксам — предикат `abs_box_shrinks_to_fit`
исключает три класса:

* **replaced** (`Image`/`Video`/`Canvas`/`Iframe`/`FormControl`) — §10.3.8
  сайзит их из intrinsic-размеров, а intrinsic-машинерия их содержимого не
  видит (ширина картинки лежит в `BoxKind::Image`, а не в детях), так что
  измерение схлопнуло бы их в padding+border;
* **`BoxKind::Table`** — уже ужимается сам, в `lay_out_inner`, по
  `table_intrinsic_content_width` (ширины колонок + border-spacing); блочное
  правило «максимум по детям» этого не воспроизводит;
* **`display: grid`/`inline-grid`** — max-content грида по строчной оси = сумма
  max-content колонок + gap'ы (аналог `flex_row_intrinsic_sum` для грида),
  такого правила ещё нет, и блочное занизило бы многоколоночный грид до одной
  колонки. Растягивание — менее разрушительный режим отказа, пока правило не
  появится.

Проверка: 5 строк таблицы выше сходятся (`--dump-layout .tmp/b745_abs.html`),
4 юнит-теста `bug745_*` в `box_tree.rs`, живой `tbank.ru` три прогона подряд
даёт баннеру `x = 796, y = 572, w = 212, h = 132` — правый край 1008, нижний
704, то есть ровно `bottom: 16px; right: 16px` при вьюпорте 1024×720.

Свип дампов display list по 158 страницам `graphic_tests/`: изменились две
страницы (`65-flex-align-content`, `78-scroll-driven-animations`), в обеих —
только ширина рамки `DrawText` у абсолютных подписей с `left: 0`; x/y и глифы
на месте. Эталоны `graphic_tests/dump-golden/` обновлены.
