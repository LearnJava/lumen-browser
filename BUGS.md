# BUGS.md — Баг-трекер Lumen Browser

Живой список известных багов движка. История прогонов — в `graphic_tests/results/*.json` (коммитируются).

**Как добавить баг:**
1. Создай файл `bugs/BUG-NNN-OPEN.md` (следующий номер по счёту, сейчас BUG-985)
2. Добавь строку в таблицу ниже со ссылкой на файл

**При изменении статуса:** переименуй файл (`BUG-NNN-OPEN.md` → `BUG-NNN-FIXED.md`) и обнови ссылку в таблице.

**Уточнение статуса `OPEN (ДОРАБОТКА → <task>)`** (введено 2026-08-28 по решению пользователя): запись описывает не дефект реализованного кода, а никогда не реализованную функциональность, и ведётся как задача `<task>` в [ROADMAP.md](ROADMAP.md) — P3 её как баг НЕ берёт. Разделяет две записи не «не работает» против «работает неверно», а объём: доработка — это когда функциональности нет вовсе **И** она размером с семейство API или модель состояния, а не с один член: `document.forms` отсутствует целиком, но чинится строкой на коллекцию — это баг; `document.styleSheets` отсутствует так же, но за ним нет ни одного класса CSSOM — это доработка. Развилка с примерами — [docs/probe-method.md §8](docs/probe-method.md). Файл `bugs/BUG-NNN-OPEN.md` остаётся на месте (переименование порвало бы ссылки из CLAUDE.md, STATUS-файлов и питон-тулинга) и служит детальной записью наблюдений; его «срезы» при этом — прогоны, упиравшиеся в ту же дыру, а не куски выполненной работы. Префикс `OPEN` сохранён, чтобы `parse_status` и `awk`-выборки продолжали работать.

**Статусы:** `OPEN` · `IN PROGRESS` · `FIXED <date>` · `WONTFIX (Phase N+)` · `DUPLICATE → BUG-NNN` (тот же дефект уже заведён; файл переименовывается в `BUG-NNN-DUPLICATE.md`, уникальные измерения переносятся в выживший баг — выживает **первый по дате**)
