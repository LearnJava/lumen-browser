# Старт задачи — протокол координации Lumen

$ARGUMENTS — id задачи (`BUG-1240`, `1240`, `perf-10`, `wpt-run14-s15`).
Если аргумент не передан — спроси у пользователя.

## Шаг 1 — Синхронизируй main

**Резервация задачи — это ветка `p<N>-…` на origin**, ничего больше
(`docs/dev-roles.md` §«Reserving a task»). Никакого реестра «в работе» в
`lumen-plan.md` нет и быть не должно: этот файл — оглавление на 21 строку, и
`docs/doc-sync.md` §«What NOT to update» прямо запрещает держать в нём статус.

!`git pull origin main 2>&1 | tail -2`

`git pull origin main` обновляет только main. Чужие ветки он **не** подтягивает:
`git branch -a` после него показывает origin на момент последнего полного
`git fetch`, и бронь с другой машины в нём не видна (так BUG-1240 2026-10-07
взяли на двух машинах). Занятость проверяет только шаг 3.

## Шаг 2 — Определи программиста и доменную зону

Роли, их домены и крейты — [docs/dev-roles.md](../../../docs/dev-roles.md)
(единственный источник; таблица в CLAUDE.md была удалена 2026-09-03 вместе с
дублирующим списком, который расходился с ней по крейтам).

Если пользователь указал «ты программист N» — проверь, что задача помечена
`[PN]` в `ROADMAP.md`. Если нет — уточни.

## Шаг 3 — Проверь занятость, займи слот, опубликуй ветку (одна команда)

```bash
cd "$(bash scripts/task-claim.sh <N> $ARGUMENTS | tail -1)"
```

Скрипт делает:
1. `git fetch origin --prune` — свежий список чужих веток;
2. ищет **любую** невлитую ветку (локальную или на origin), в имени которой есть
   id задачи — не только точное `p<N>-<задача>`: другая машина могла назвать её
   `p1-bug1240-relative`;
3. занимает постоянный слот пула `p<N>-work` (`scripts/worktree-pool.sh`;
   `target/` остаётся тёплым, экономия 9–15 мин холодной сборки);
4. `git push origin <ветка>` — до первой правки кода: локальная ветка другие
   машины ни от чего не удерживает;
5. снова fetch и повтор п. 2 — ловит гонку, если чужая бронь появилась между
   проверкой и пушем.

Коды возврата: `0` — задача твоя; `1` — занята или ошибка — **сообщи
пользователю и остановись**, не дублируй работу; `2` — гонка: на origin есть ещё
ветка с тем же id — код не трогай, спроси пользователя через `ask-user`.

Имя ветки по умолчанию — `p<N>-bug-<номер>` для бага, `p<N>-<id>` иначе; своё
имя — третьим аргументом (префикс `p<N>-` обязателен). Если ветка твоя и
незакончена — скрипт не считает её занятой и просто переключит слот на неё.
Если `worktree-pool.sh` отказал (в слоте незакоммиченная или невлитая работа) —
не форсируй: разберись с тем, что там лежит, это чья-то незавершённая задача.

После этого работа ведётся **только** в слоте: `.claude/worktrees/p<N>-work/`.
Собирать в слоте только профиль `dev-release`. Подробности — `docs/git-workflow.md`.

Строку-указатель в `STATUS-PN.md` **не трогай** — она остаётся на месте до
завершения задачи и удаляется только при закрытии.

## Шаг 4 — Сообщи пользователю

Выведи итог:
- Имя ветки (опубликована — задача зарезервирована) и путь слота
- Строка-указатель, с которой взята задача, и её источник
- Следующий шаг: какой файл открывать первым для реализации

Теперь можно начинать работу. Все дальнейшие коммиты — в этом worktree.
