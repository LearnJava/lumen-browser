# Lumen Perf Audit — аудит на реальных сайтах

Цикл: **вопросы → подготовка → прогон → сравнение → журнал → баги → очередь**.
Прогон, который нельзя сравнить с прошлым, бесполезен — большинство правил ниже
про сравнимость.

**Перед любым cargo** (Windows + Git Bash): `export PATH="$HOME/.cargo/bin:$PATH"`.

## Шаг 0. Спросить пользователя до запуска (не угадывать)

Одной формой, до сборки:

1. **Маршрут сети.** Проверь VPN: `ipconfig` → адаптер `tun0` (Hiddify). Через
   туннель TLS-рукопожатие 0.4-1 с с выбросами до 15 с у любого клиента, напрямую
   ~50 мс; медиана Lumen 37.6 с через туннель против 14.0 с напрямую (журнал,
   2026-09-23). Прогоны разных маршрутов несравнимы. Варианты: выключить VPN;
   split-прокси (Шаг 2); идти через туннель и сравнивать только с «туннельной»
   частью прошлого прогона. Маршрут прошлого прогона — в его секции журнала.
2. **Экран на несколько часов.** Окна `--maximized` на переднем плане; запуск из
   фона или работа поверх окна ломает замеры. top100 в compat — около 1.5 ч.
3. **Перемерять ли Chrome.** По умолчанию нет — база `docs/perf/runs/*-chrome.json`.
   Скрипта замера Chrome в репозитории нет: если перемерять — сначала написать и
   закоммитить скрипт, потом мерить.

Ответа нет (автономный режим) — выбрать вариант, сохраняющий сравнимость с прошлым
прогоном, и записать выбор первой строкой секции журнала.

## Шаг 1. Ветка, сборка, холодный старт

```bash
git pull origin main
cd "$(bash scripts/worktree-pool.sh p2-work p2-perf-audit-<YYYYMMDD> | tail -1)"
cargo build -p lumen-shell --profile dev-release     # НЕ --release (в 2-3 раза дольше)
```

- Движок НЕ трогать — аудит только наблюдает. Правки: `docs/perf/*`, `scripts/perf_*`,
  `scripts/split_proxy.py`, `BUGS.md`, `bugs/*`, `STATUS-P3.md`.
- **Версия Chrome в UA:** `chrome_major!()` в `crates/network/src/http/mod.rs` против
  мажора Chrome на машине (`chrome://version`; Chrome for Testing —
  `%LOCALAPPDATA%/ms-playwright/chromium-*/chrome-win64/<версия>.manifest`).
  Отстаёт больше чем на 2 мажора — поднять отдельным коммитом до прогона: устаревший
  UA сам даёт 403/«unsupported browser» (BUG-1113).
- **Холодный `data/`:** удалить `target/dev-release/data/` целиком (HTTP-кэш, память
  ресурсов PERF-15, профиль). `perf_audit.py` его не чистит, тёплый кэш подменяет
  сеть. Если прокси задан через `fingerprint.toml` (Шаг 2) — удалить всё, кроме него.
- **Блокировщик выключен:** скрипт ставит `LUMEN_NO_ADBLOCK=1`; после прогона ни в
  одном логе не должно быть `blocked: easylist` (`perf_compare.py` проверяет). Строка
  `adblock: filter installed` о включённом блокировщике не говорит.

## Шаг 2. Split-прокси (если выбран этот маршрут)

```bash
python scripts/split_proxy.py --bind <IP Wi-Fi> --probe hosts.txt     # что недоступно напрямую
python scripts/split_proxy.py --bind <IP Wi-Fi> --port 8900 \
    --tunnel-hosts docs/perf/split-tunnel-hosts.txt --log .tmp/split.log --log-conns
```

- Трафик идёт мимо TUN; домены из `split-tunnel-hosts.txt` и хосты, у которых прямое
  соединение не прошло, — в туннель (`AUTO-TUNNEL` в логе). Стало больше NET_FAIL —
  обновить список `--probe` по хостам прошлого прогона.
- **Lumen берёт прокси только из `data/fingerprint.toml`** (`proxy = "http://127.0.0.1:8900"`):
  флаг `--proxy` не действует ([BUG-1210](../../../bugs/BUG-1210-OPEN.md)).
  `perf_audit.py --proxy <url>` проверяет, что строка на месте, и пишет URL в results.json.
- Пока открыт [BUG-1209](../../../bugs/BUG-1209-OPEN.md), за прокси нет мультиплексирования
  HTTP/2 и бывают ответы `421`: скорость и соединения — «Lumen за прокси», так и писать.
- Прямой путь может рвать TLS (`peer closed connection without sending TLS close_notify`).
  NET_FAIL на первом документе → A/B `--dump-source` прокси против туннеля на этих
  сайтах, прежде чем записывать что-то на Lumen (2026-09-28: 5 обрывов из 16 против 0).
- После прогона: остановить прокси **по PID** и удалить `proxy =` из `fingerprint.toml`,
  иначе обычный запуск из слота пойдёт в мёртвый прокси.

## Шаг 3. Прогон

Три режима (AUDIT-1), не смешивать в одном отчёте (BUG-992: прогон читался как
«сайты», а мерил усталость процесса):

- **`--mode compat`** (A) — свежий процесс на сайт, числа сопоставимы между сайтами.
  Для сравнения с прошлым прогоном и с Chrome — только он.
- **`--mode stability`** (B, default) — одно окно, новая вкладка на сайт, вкладки не
  закрываются: накопление, утечки, деградация. Партиями по 15–20 сайтов (`--only`).
- **`--mode session`** (C) — одна сессия: `--session-tabs` вкладок, затем
  скролл/назад-вперёд/попап/фрейм/приближённое закрытие (MCP не даёт
  `switch_tab`/`close_tab`). «Назад-вперёд»/«фрейм» стабильно `DEGRADED` —
  [BUG-998](../../../bugs/BUG-998-OPEN.md), не тулинг.

```bash
python scripts/perf_audit.py --mode compat --corpus docs/perf/corpus-top100-foreign.txt \
    --timeout 240 --compare docs/perf/runs/<прошлый>.json [--proxy http://127.0.0.1:8900] \
    > .tmp/run.out 2>&1          # в фоне; прогресс — строки `[N] slug -> STATUS`
```

- Процессы lumen снимать **только по PID**, никогда `taskkill /IM lumen.exe` — у
  пользователя и параллельных сессий свои окна.
- Сравнивать только прогоны одного режима, машины, маршрута и таймаута.
- `--phases --only <slug>` — headless-разложение одного медленного сайта
  (source/layout/screenshot), не замена режимам.
- Результаты: `.tmp/perf-audit/<stamp>/` (results.json, summary.md, stderr-логи,
  скриншоты). Быстрая проверка перед полным прогоном: `--only google`.

## Шаг 4. Сравнение

```bash
python scripts/perf_compare.py .tmp/perf-audit/<stamp> --base docs/perf/runs/<прошлый>.json \
    --chrome docs/perf/runs/<chrome>.json --tunnel-hosts docs/perf/split-tunnel-hosts.txt \
    --expect .tmp/expect.json
```

Даёт статусы и переход каждого сайта, скорость (ready_s против `load` Chrome,
напрямую/туннель), память, «Не отвечает» ≥ 2 с (и в обоих прогонах), сигнатуры
stderr (BUG-1205 H2-таймаут, BUG-1206 EvalError, easylist, `421`), белые кадры среди
OK, HUNG с повтором. **Числа в журнал и баги — только из вывода скрипта**, не ручным
grep: ручной подсчёт `421` 2026-09-28 дал 40 на 8 сайтах вместо 24 на 5.

**`--expect`** — JSON `{slug: [BUG-NNN]}`: сайты, которые должны были починиться багами,
закрытыми после прошлого прогона (пройти `bugs/*-FIXED.md`, найти slug'и корпуса).
Не подтвердилось — сначала исключить маршрут и антибот (curl с UA Chrome тем же
маршрутом); затем: та же ошибка вернулась → баг со ссылкой на закрытый; ошибка ушла,
а сайт сломан другим → находка, не регрессия.

Разбор по сайту:

1. **Статус** (`classify_status`): OK (готовность + кадр + ноль JS-ошибок) / DEGRADED
   (кадр не подтверждён или JS-ошибки) / BROKEN_RENDER (подозрение «ничего не
   нарисовано», точность ограничена [BUG-993](../../../bugs/BUG-993-FIXED.md)) /
   TIMEOUT / HUNG / DEAD; внешние SITE_REFUSED (401/403) и NET_FAIL. Внешнее — не
   дефект Lumen, если тем же маршрутом не открывается и у Chrome/curl (ebay 403 по
   IP, reuters 401 — DataDome по IP).
2. `ready_s`, `peak_mb` (compat — напрямую между сайтами; stability — дельта к
   предыдущей строке, скачок > 300 МБ — находка), `restarted` (всегда находка).
   Доминирующая фаза медленного сайта — `--phases`: paint → CPU-растеризация
   (BUG-272, не дубликат); style_layout → `LUMEN_PROFILE_TREE`; net_parse → сеть/парсер.
3. Регрессия против прошлого прогона того же режима и маршрута: Δ > +20% — находка,
   меньше — шум.
4. Ошибки stderr/консоли: «X is not defined / is not a function» валит скрипты сайта
   целиком и маскирует остальное; паники, недекодированные форматы.
5. Точечно: `LUMEN_PROFILE_TREE=1` / `LUMEN_FRAME_LOG=2` / `LUMEN_MEM_REPORT=1`
   (docs/automation.md).

## Шаг 5. Наблюдение и сведение

- «Не отвечает» дольше 2 с, H2-таймауты, EvalError, белые кадры среди OK — в журнал
  всегда.
- **Одиночный HUNG/«Не отвечает» не заводить до повтора** (docs/probe-method.md §9):
  перепрогнать эти сайты `--only` тем же маршрутом; повторилось — headless
  `--dump-layout` через туннель без прокси, чтобы отделить движок от маршрута.
- Каждый BROKEN/DEGRADED — сравнить с Chrome (кадр, узлы, ошибки) и свести к
  локальной странице, снятой в обоих браузерах (docs/probe-method.md; перед пробой —
  docs/engine-gaps.md). **Не сводить**, пока открыт баг маршрута/тулинга, который сам
  даёт такие поломки (BUG-1209 → `421`): выйдут ложные находки. Отложенное — явно в журнал.

## Шаг 6. Журнал (коммитится)

1. `results.json` → `docs/perf/runs/<YYYY-MM-DD>-<корпус>[-<маршрут>].json`
   (например `2026-09-28-top100-split.json`); замер Chrome — с суффиксом `-chrome`.
2. Секция в `docs/perf/journal.md` по шаблону в шапке. Первой строкой — маршрут,
   холодный `data/`, отсутствие easylist, база Chrome; затем вывод `perf_compare.py`,
   подтвердилось/не подтвердилось, наблюдение, отложенное, заведённые баги.
   Скриншоты и stderr-логи не коммитить.

## Шаг 7. Баги и очередь

- Один баг = одна первопричина (не «сайт X медленный», а «фаза Y стоит Z секунд из-за
  W»). Против дубликатов — `grep -i` по `BUGS.md` и список известных из задания; уже
  открытые не заводить заново.
- **Номер — по `origin/main` прямо перед коммитом** (`git fetch` →
  `git ls-tree --name-only origin/main bugs/`), не по локальному дереву: параллельные
  сессии занимают номера (2026-09-28 — две коллизии).
- `bugs/BUG-NNN-OPEN.md` (симптом, цифры из Шага 4, репро, гипотеза, ссылка на
  журнал) + строка в `BUGS.md` (не через Python text mode — CR в ячейках).
- **Очередь P3:** баги, без которых следующий прогон бессмыслен (маршрут/прокси,
  тулинг, повторяющиеся HUNG), — **первыми строками** `STATUS-P3.md` в порядке
  исправления; остальные — в конец. Проверка: `python scripts/remap_status_pointers.py`.
- Перф-улучшение крупнее бага — предложение строки PERF в ROADMAP.md в отчёте.

## Шаг 8. Завершение

- Коммит явными путями → `merge --no-ff` в main → push → удалить ветку
  (docs/git-workflow.md).
- Остановить по PID прокси и оставшиеся процессы; убрать `proxy =` из `fingerprint.toml`.
- Отчёт пользователю: маршрут, таблица статусов, скорость/память против прошлого
  прогона и Chrome, что подтвердилось, заведённые баги и их место в очереди,
  отложенное и почему, команда следующего прогона.

## Что аудит НЕ покрывает (не выдумывать цифры)

- FPS/frame-time скролла — `scripts/scroll_perf.py` (PERF-3).
- GPU-время и память — не собираются (PERF-3/5); скриншоты — CPU-путь (BUG-221),
  могут отличаться от окна.
- Долгие сессии и утечки — `LUMEN_MEM_REPORT=1` вручную (PERF-5).
- `--phases`: три стадии повторяют работу друг друга, производные фазы приближённые.
