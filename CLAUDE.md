## What is this

**Lumen** — private, lightweight, transparent browser in Rust with a custom engine. Not a Chromium/WebKit wrapper; a standalone rendering engine with an embedded JS engine.

Current phase: **Phase 2 — v0.5 «Interactive» (complete)**, app version **v0.5.0**. Phase 0 (prototype) closed 2026-05-26; Phase 1 «Reader» largely complete. Phase 2 delivered: QuickJS, Canvas 2D, CSS Grid, Shadow DOM, accessibility tree, forms, find-in-page, DevTools/CDP, knowledge layer.

**JS engine: V8 (`rusty_v8`) is the ONLY JS engine, full stop.** S12b-F1 (2026-08-04) removed the `quickjs` shell rollback feature; `QuickJsRuntime` itself was deleted in S12b-F2 (2026-08-04); `dom.rs::install_primitives` (the rquickjs native-registration entry point, 2736 lines) was deleted in S12b-F3 (2026-08-04); S12b-F4 (2026-08-04, closing the `P3-v8-s12b` track) removed the `rquickjs`/`rquickjs-core`/`rquickjs-sys` dependency from `crates/js/Cargo.toml` and `Cargo.lock` outright — `rquickjs` is gone from the workspace entirely, not just unused. Never target new functionality, fixes, or investigation at the rquickjs path (it no longer exists); the JS shim (`WEB_API_SHIM` in `crates/js/src/dom.rs`, `#[cfg(feature = "v8-backend")]`) is evaluated only by the V8 install path (`v8_runtime.rs::install_dom`) and is the right place for engine-independent fixes. Validate JS work against the default (V8) build.

### Versioning & phase policy

Single source of truth for the version is `[workspace.package] version` in `Cargo.toml`. All machine-readable version strings (User-Agent, Sec-CH-UA, CDP `Browser.getVersion`, window title, startup banner) derive from `CARGO_PKG_VERSION` — do **not** hardcode a version number in code. The one manual-bump site is the `navigator.userAgent` literal in `crates/js/src/dom.rs` (JS shim string).

Version↔phase mapping (from `docs/plan/phases.md`): Phase 1 → v0.1, **Phase 2 → v0.5** (target on phase completion), Phase 3 → v1.0. Mid-phase the version climbs toward the target (Phase 2 reached its **0.5.0** target). Reaching Phase 3 → 1.0.0. Keep the phase label in sync across `README.md`, `docs/plan/phases.md`, this file, and the shell startup banner.

**Session start protocol:**
1. **`git pull origin main` first, before reading STATUS files or creating a branch/worktree.** Parallel Claude Code sessions push to `origin/main` independently, so local `main` can lag behind — starting from stale state means stale `STATUS-PN.md`/`ROADMAP.md` reads and, if the lag is large, a big multi-file merge conflict later instead of a small one now. If `pull` reports a diverged history with real conflicts (not just a fast-forward), resolve them file-by-file with full understanding of both sides' intent — do not blindly take one side — and re-verify with `cargo check`/`clippy`/scoped tests for every touched crate before committing the merge.
2. Read `STATUS-PN.md` — pointer lines to open tasks; `git branch` shows any `p<N>-…` task in progress
3. Run `git branch` — verify you're on main
4. Architecture context → `docs/plan/architecture.md` §1, §3; decisions → `docs/decisions/README.md`

**Push after every commit, not at session end.** Each commit is merged into `main` and pushed to `origin/main` as soon as it is made (see "Git workflow" below) — nothing waits for the end of a task or a session, because other parallel sessions rely on seeing it to avoid duplicate or conflicting work.

**Cargo output rules:** always `-p <crate>`, never `--workspace` (exception: P5). Success → 1 line. Errors → full `error[...]` block, skip all warnings. Test failure → test name + first 10 lines.

**Run discipline (details in `docs/commands.md`):** one cargo run — one log file (`> .tmp/<name>.log 2>&1`, then grep the file; never re-run cargo just to re-filter output). During iteration `cargo check -p` only; one `clippy -p` + targeted tests before the commit; full gates (workspace clippy + scoped-test) run exactly once inside `/lumen-task-finish`, synchronously in the foreground — never as background tasks. Don't hand-run expensive crate tests before the gate — `scoped-test.sh` repeats them.

**Long runs you are not blocked on** (baseline builds, `test --no-run`, the graphic pipeline) go to the background via the Bash tool's `run_in_background: true` — the harness notifies you on exit, so keep working meanwhile. Never `cmd &` **plus** `run_in_background` (silently kills the process) and never poll with `sleep N` — that pattern burned 76 of 188 minutes on 2026-07-27. Foreground-only exceptions: the final gates, and the full graphic pipeline (gdigrab needs a focused window; backgrounded, TEST-00 fails "magenta marker not found" and cascades).

## Code conventions

Full details (style, tests, error handling, unsafe) — [`docs/conventions.md`](docs/conventions.md).

- **Rust pinned to 1.97.0** (`rust-toolchain.toml`, since 2026-08-19 — it was a floating `"stable"`, which handed developers and CI runners different lint sets and made clippy green locally / red in CI). Edition 2024, resolver "3", MSVC on Windows. Raise the pin in its own commit after a clean `RUSTC_WRAPPER= cargo clippy --workspace`: a version bump invalidates every artifact in `target/` (stale ones surface as `E0786 "only metadata stub found for rlib dependency core"`, which reads like a broken dependency but is cured by `cargo clean`) and can add new lints.
- `cargo clippy -p <crate> --all-targets -- -D warnings` must pass before every commit.
- **sccache is off** (`rustc-wrapper` commented out in `.cargo/config.toml`, 2026-08-19): version 0.15.0 crashes every compiler invocation under toolchain 1.97.0 with `STATUS_STACK_BUFFER_OVERRUN` (`0xc0000409`) on crates with a long command line — `rustc` as well as `clippy-driver`, so it breaks plain `cargo test`, not just linting. Re-enable only after sccache is updated and `cargo test -p lumen-layout` passes through it. CI never used the wrapper.
- **`///` doc comments on all public structs, fields, and functions** — mandatory and **machine-checked** since 2026-08-18 (`missing_docs = "deny"` in `[workspace.lints.rust]`). Pre-existing debt (1866 items) is held behind **file-scoped** `#![allow(missing_docs)]` in 119 files, so a *new* file must document its public API even in a crate that still owes docs; the per-crate counts live in `docs/lint-policy.md` §10.
- No `panic!` / `unwrap()` / `expect()` in production code; allowed in tests. **All three machine-checked** since 2026-08-18 (`clippy::panic`, `clippy::unwrap_used`, `clippy::expect_used`, all `deny` in `[workspace.lints]`). `clippy.toml`'s `allow-*-in-tests` frees only the body of a `#[test]` fn, so test roots and `#[cfg(test)] mod`s carry their own `#![allow]`. Grandfathered sites carry a function-scoped `#[allow]` (an `impl`-scoped one where the function could not be identified), never a crate-scoped one; every allow is listed in `docs/lint-policy.md` §10.
- `unsafe` forbidden outside FFI boundaries; every block requires `// SAFETY:` comment. **Machine-checked** since 2026-08-18: `clippy::undocumented_unsafe_blocks = "deny"` in `[workspace.lints]`, so a missing comment is a build error, not a review finding. One comment above two adjacent `unsafe impl`s does not count as documenting the second.

All three prose policies above are now enforced by `[workspace.lints]` — tier 0 of [`docs/lint-policy.md`](docs/lint-policy.md) was completed on 2026-08-18 (five rules enabled, one rejected on measurement). What remains is the grandfathered debt behind `#[allow]`, listed per crate with owners in that file's §10. Rules are enabled in `[workspace.lints]` (root `Cargo.toml`), configured in `clippy.toml`; every member crate opts in with `[lints] workspace = true`. **A new crate must carry that stanza** or it silently escapes every project lint — `/lumen-new-crate` adds it.
- Names: `snake_case` functions/fields, `PascalCase` types, `SCREAMING_SNAKE` constants.

## Git workflow

Full protocol (commits, worktree isolation, zombie worktree, 7-step checklist) — [`docs/git-workflow.md`](docs/git-workflow.md).

**All work happens in feature branches. Direct commits to `main` are forbidden.**

Branch naming: `p<N>-<task-name>` (P1–P5 prefix mandatory). `--no-ff` required on merge. Commit message in Russian, subject under 80 chars, body explains *why*.

**Forbidden:** direct commit to main · force-push · rewriting history · `git config` · `--no-verify` · `git push` without explicit user request.

**Every session MUST work in its own `git worktree`** — use your **persistent pool slot**, one per developer, instead of creating a worktree per task:

```bash
cd "$(bash scripts/worktree-pool.sh p<N>-work p<N>-task-name | tail -1)"   # occupy
bash scripts/worktree-pool.sh list                                        # who holds what
bash scripts/worktree-pool.sh release p<N>-work                           # free (step 3 of the checklist)
```

The slot (`.claude/worktrees/p1-work` … `p5-work`, plus `perf-base`) is created once and reused — only the branch changes, so `target/` stays warm and rebuilds are incremental. `git worktree remove` after every task deleted that cache and cost 9–15 min of cold build per task, plus 3 min for the `add` itself. Build **only `dev-release`** inside a slot (warm `dev-release` ≈ 4.7 GB; five slots on `debug` would be ~70 GB). The script refuses to switch a slot with uncommitted or unmerged work. Details — [`docs/git-workflow.md`](docs/git-workflow.md).

**Merge and push after EVERY commit** (user, 2026-08-19). Do not accumulate commits on a branch until the task is done: local gate → commit → `git merge --no-ff` into `main` → `git push origin main`, per commit. Feature branches and `--no-ff` stay mandatory; what changed is the cadence. Rationale: unpushed work does not exist for anyone else — on 2026-08-19 several roles held unmerged branches at once, the root checkout trailed `origin/main` by 21 commits, and parallel sessions duplicated work and collided on bug numbers. Frequent small merges also trade one large conflict for several trivial ones.

**Do not wait for CI before merging** (same decision). The local gate is the only pre-merge check; watch CI on `main` afterwards and fix it if it goes red. Waiting per-commit would cost ~30 min each.

**Task-completion checklist** (all mandatory, full details in `docs/git-workflow.md`). Steps 1–3 already ran per commit under the rule above; at task end they cover whatever the last commit left:
1. `cargo clippy -p <crate> -- -D warnings` + `cargo test -p <crate>`
2. `git merge --no-ff p<N>-task-name -m "Merge …"`
3. `git push origin main`
4. Delete pointer line from `STATUS-PN.md`, commit — then merge and push it too
5. `bash scripts/worktree-pool.sh release p<N>-work` then `git branch -d p<N>-task-name` (a slot holding the branch makes `branch -d` fail)
6. Pool slot — nothing to remove (freed in step 5). Ad-hoc worktree — `git worktree remove .claude/worktrees/<task-name>`
7. `git push origin --delete p<N>-task-name` if the branch was ever pushed — the remote task branch has served its purpose

The second is not a bug: a window opened on `about:blank` never gets a JS context, so *every* `eval` fails there regardless of what you navigate to afterwards — start the browser on a real http page instead (`--mcp-live-port N http://…`). Slice 6 hit both at once and recorded "the live window is broken in this environment"; it was not. **Consequence for any probe page:** never put an `<audio>` on it unless the audio is what you are probing, and read evidence from the browser's own stderr (`console.log`) when the page under test might be the frozen one — a wedged page cannot answer `eval` at all.

- **An `.xhtml`/`.xht`/`.svg` page that prints nothing is not a hung page — its scripts were dropped at parse time, and the file's own markup tells you which of three ways.** Navigation has no XML path at all: `crates/shell/src/main.rs:5365` runs `lumen_html_parser::parse` on every response and only stamps `document.contentType` from the header afterwards ([BUG-786](bugs/BUG-786-OPEN.md), third facet, measured WPT-RUN-6 slice 16 by `tests/wpt/verify_document_and_record_gaps.py`). A prefixed `<h:script src>` never becomes a script — the external file is not even requested, so *no* error appears anywhere; a self-closing `<script src="…"/>` is not self-closing in HTML, so everything up to the next `</script>` becomes its text and the rest of the document silently ceases to exist; `<![CDATA[` at the head of an inline script is `Unexpected token '<'`, which BUG-591 then swallows. The content type is irrelevant — the same bytes served as `text/html` fail identically — and an SVG-namespaced `<script>` inside an ordinary HTML page runs fine, so do not generalize this to "scripts in `<svg>`". **Consequence for triage:** before probing an XML test's JS behaviour, check whether its harness loaded at all (grep the run log for a `GET` of `testharness.js`); and never write a probe page whose script is CDATA-wrapped, or it will measure this bug instead of your subject.

- **Any script that greps WPT sources for markers has two blind spots that fail silently: a UTF-16 test file and an `.mjs` helper.** Both were found in `tests/wpt/timeout_audit.py` (WPT-RUN-6 slice 16) and are fixed there — copy its `_decode_source` (BOM sniff, `\xff\xfe`/`\xfe\xff` → `utf-16`) rather than re-deriving it. Read as UTF-8 with `errors="replace"`, a UTF-16 file keeps its ASCII characters but separates every one of them with a replacement byte, so no regex can ever match and the file reads as "contains nothing" — that is how all 20 `html/infrastructure/urls/resolving-urls/query-encoding/utf-16{le,be}.html` ids stayed unattributed. And a modern WPT test increasingly pulls its helper in as an ES module with an `.mjs` extension (`import {createIframe} from "./resources/helpers.mjs"`), so an extension check written as `endswith(".js")` skips exactly the file the evidence is in. Third, less obvious: a `?include=<key>` id (`common/subset-tests-by-key.js`) runs only the `subsetTestByKey('<key>', …)` blocks of its file, so reading the whole helper attributes one variant's hang to a sibling variant's code.

- **Two things a WPT probe must not take on trust: that a `PerformanceObserver` entry type in `supportedEntryTypes` is actually delivered, and that a `test_driver.*` call does anything.** Both were measured 2026-08-21 (WPT-RUN-6 slice 17) and both fail *silently*, so they read as engine hangs. `PerformanceObserver.supportedEntryTypes` lists `layout-shift` and `observe()` accepts it, yet no entry is ever produced — the shell-side trigger `deliver_layout_shift` (`crates/shell/src/main.rs:2925`) is `#[allow(dead_code)]` with no call site in layout/reflow at all ([BUG-809](bugs/BUG-809-OPEN.md)); the advertisement is what makes these tests TIMEOUT rather than FAIL, because WPT's `ScoreWatcher` helper only throws when the type is *absent*. The list is a promise about the type, not about delivery — check for a call site before believing it. And of the ~30 `test_driver_internal` actions, `executorlumen.py::_handle_action` implements exactly two (`click`, `generate_test_report`); every other one is rejected — at the time of this measurement (2026-08-21) the page never saw the rejection at all (BUG-716, fixed 2026-08-22), so the test hung to the runner timeout with an empty log ([BUG-810](bugs/BUG-810-OPEN.md)) — 193 ids of the WPT-RUN-5 snapshot; with BUG-716 fixed this should now surface as a fast FAIL naming the unimplemented action instead, pending re-measurement. An element-targeted action does not even reach the executor: `testdriver-extra.js::get_context` throws on the still-missing `document.defaultView` ([BUG-622](bugs/BUG-622-OPEN.md)). **Consequence:** never write a probe whose result depends on `test_driver.Actions()`/`send_keys` working, and when a category of input-driven tests times out wholesale, check the executor's action table before filing an engine bug.

- **Three things a probe page cannot use on this engine without measuring itself instead of its subject: CSP, a relative-URL `XMLHttpRequest`, and anything a worker has to say.** All measured 2026-08-21 (WPT-RUN-6 slice 18, `tests/wpt/verify_csp_url_worker_gaps.py`). CSP is parsed (`crates/network/src/csp.rs`, `crates/storage/src/csp_policies.rs`) and never enforced — `script-src 'self'` does not stop an inline script, and `securitypolicyviolation` is never dispatched although `SecurityPolicyViolationEvent` exists, so a wait on it can only hang ([BUG-811](bugs/BUG-811-OPEN.md)); the `_lumen_dispatch_csp_violation` hook has no caller outside its own unit test. `XMLHttpRequest.open()` keeps the URL verbatim (`crates/js/src/xhr.rs:231`), so any relative URL dies in the network layer as `invalid url: missing scheme` while the identical URL through `fetch()` succeeds ([BUG-780](bugs/BUG-780-OPEN.md), which absorbed the duplicate BUG-812) — spell XHR URLs out absolutely in any harness or probe. And a worker is silent in three separate ways: an exception inside a *started* worker fires `error` nowhere ([BUG-813](bugs/BUG-813-OPEN.md) — the `error` path exists only for a failed script *fetch*), the worker global scope defines neither `navigator` nor `location`, so reading either throws on the first line ([BUG-776](bugs/BUG-776-OPEN.md), which absorbed the duplicate BUG-814), and worker timers are flushed only when a message is dispatched to that worker, with `setInterval` aliased to `setTimeout` ([BUG-815](bugs/BUG-815-OPEN.md)) — a worker nobody writes to never runs its timers at all. **Consequence:** a worker probe must avoid `navigator`, must be poked with a `postMessage` to get its timers to run, and cannot report a failure by throwing; and never read a silent `<img>` as evidence that a policy blocked it — a parser-written `<img>` fires neither `load` nor `error` regardless of CSP ([BUG-804](bugs/BUG-804-OPEN.md)).

- **A page that does not scroll under a probe is usually the probe's fault, and a page that scrolls without firing `scroll` is the engine's.** Both halves were measured 2026-08-21 (WPT-RUN-6 slice 19, `tests/wpt/verify_stream_scroll_message_gaps.py`). The shell derives `content_height` from the **display list**, so a spacer that paints nothing — the reflexive `<div style="height:4000px"></div>` — leaves `max_scroll()` at 0 and `window.scrollTo(0, 300)` genuinely does nothing; give the spacer a background and the same call moves the page and `window.scrollY` reports 300. What it never does is dispatch a `scroll` event: `fire_window_scroll` has exactly one call site in the whole workspace, the mouse-wheel branch of `crates/shell/src/main.rs:16085` ([BUG-821](bugs/BUG-821-OPEN.md)), so the event is bound to an input device rather than to a position change. `scrollend` is worse — no function to dispatch it exists at all, and `'onscrollend' in window` is false ([BUG-822](bugs/BUG-822-OPEN.md)). Element scrolling is fine on both counts except `scrollend` (`scrollTo` and `scrollTop=` alike fire `scroll`), and `scrollIntoView` never falls back to scrolling the page when no ancestor is a scroll container. **Consequence for any probe or harness:** never wait on a page-level `scroll`/`scrollend` to know a scroll happened — poll the position on a timer instead, and paint the spacer.
- **Three more surfaces that answer a probe with silence rather than an error: the Streams error paths, `<video>`, and `window.postMessage`'s modern overload.** Measured the same day (same probe). Streams work on the happy path — the shim's own header comment claiming `pull` is called only once is stale, and a demand-driven source, an async `start()` and a hand-made `TransformStream` all behave — but every error/close/cancel path leaves its promise pending forever (`writer.closed` never settles, `controller.error()` reaches only already-queued reads, a promise returned from `start()` is dropped, the sink's `abort()` is never called), and `tee()`/BYOB/`Symbol.asyncIterator`/`TextDecoderStream`-close are missing outright ([BUG-823](bugs/BUG-823-OPEN.md), [BUG-824](bugs/BUG-824-OPEN.md)). Because `testharness.js` runs `promise_test`s sequentially, one such subtest takes the whole rest of the file with it — which is why 35 of 36 residual `streams/*` files stop mid-run. `<video>` is a thinner stub than `<audio>`: no `volumechange` in either handler form, no `networkState`/`currentSrc`, no resource selection (`src=` and `load()` produce no event at all), and `readyState === 4` before anything is assigned ([BUG-825](bugs/BUG-825-OPEN.md)) — so a media probe must be run against **both** tags before concluding anything. And `window.postMessage` implements only the legacy string `targetOrigin`: the one-argument form, the `WindowPostMessageOptions` dictionary and a URL-shaped origin all drop the message with no error, and `transfer` never produces `e.ports` ([BUG-717](bugs/BUG-717-OPEN.md)) — a self-`postMessage` handshake, the cheapest way to sequence a probe page, therefore hangs unless it passes the literal `'*'`.

- **A subresource a page asks for through a `<link>` hint is never fetched, and the browser's own log says otherwise.** Measured 2026-08-22 (WPT-RUN-6 slice 20, `tests/wpt/verify_preload_script_audio_gaps.py`): a `rel=preload`, `rel=modulepreload` or `rel=prefetch` link — created from script or written by the parser — produces no HTTP request at all and fires neither `load` nor `error`, while the `rel=stylesheet` control on the same page loads and fires ([BUG-826](bugs/BUG-826-OPEN.md)). The hint reaches `Event::SubresourceHintFound`, whose only consumer in the workspace is the stderr logger at `crates/shell/src/main.rs:285`, so `⤷ preload js [medium] <URL>` appears in the log for a request that was never made — do not read that line as evidence of a fetch. **Consequence for any probe:** the way to prove a request happened is to record it on the server side; this probe's own http server logs every path it is asked for, which is what separated "the element fired no event" from "nothing was ever requested". Reuse that pattern instead of believing the page or the log.
- **The parser→JS boundary is silent in both directions: a parser-inserted element reports neither its insertion nor its load.** `MutationObserver` armed on `document.documentElement` with `{childList, subtree}` hears nothing about a `<div>`/`<script>` the parser writes right below it, while the same observer reports a node appended from script ([BUG-827](bugs/BUG-827-OPEN.md) — `_mo_notify` has six call sites, all inside the shim's own DOM wrappers, none in `crates/shell/`); and a parser-inserted `<script src>`/`<link rel=stylesheet>` runs/loads but dispatches `load` to neither `addEventListener` nor `onload` ([BUG-804](bugs/BUG-804-OPEN.md), re-measured the same day with a server-held resource so the listener is certainly attached first). A `<style>` fires `load` however it was inserted, and its `.sheet` stays `null`. **Consequence:** never wait on a parser-inserted element to announce itself — and when a WPT family goes wholly silent with no log line at all, check whether its `promise_setup` awaits a mutation record before blaming the tests themselves.
- **Web Audio renders silence and hides the evidence.** `OfflineAudioContext.startRendering()` resolves at once with an all-zero buffer of the right length (`crates/js/src/web_audio.rs:638` — "Phase 0: immediately resolve with a silent buffer"), a source node never fires `ended`, and `AudioParam` automation changes neither `.value` nor the output ([BUG-828](bugs/BUG-828-OPEN.md)). Decisive for triage: the shim calls `oncomplete` inside `try { … } catch (e) {}`, so the comparison every `webaudio/resources/audioparam-testing.js` test runs from that handler dies without a word — which is why those files TIMEOUT instead of failing. The `AudioContext` state machine (`suspend`/`resume`/`close` + `statechange`) works fully, so "Web Audio responds" is not evidence that anything is rendered.
- **`history.pushState` puts the raw argument into `location`.** After `history.pushState(s, '', '?x')` the engine reports `location.href === '?x'` and leaves `location.search` empty; a relative path lands in `href` verbatim ([BUG-829](bugs/BUG-829-OPEN.md) — `_lumen_location_update` parses the unresolved string, and the shim's own comment at `crates/js/src/dom.rs:11438` already records this). `history.state`, `history.length` and `popstate` delivery are fine; traversal does not restore the URL. **Consequence:** in any probe or harness, never identify a document by `location.href`/`search` after a same-document navigation — the value can be a fragment of a URL rather than a URL.

- **Three ways a navigation probe silently re-runs itself forever, and one way it freezes.** Measured 2026-08-22 (WPT-RUN-6 slice 21, `tests/wpt/verify_navigation_form_import_gaps.py`). A click on `<a href="#x">` is a *full* navigation, not a fragment one — link activation calls `_lumen_navigate` directly (`crates/js/src/dom.rs:14634`), bypassing the working `_lumen_navigate_or_fragment`, so the document restarts from scratch, `hashchange` never fires, and a page that clicks such a link from script reloads endlessly ([BUG-833](bugs/BUG-833-OPEN.md)). `sessionStorage` is empty on every new document (`ss_store` is built fresh per `install_dom`, `crates/js/src/v8_runtime.rs:1358`), so the reflexive «set a flag, reload once» brake never engages and `location.reload()` loops too ([BUG-836](bugs/BUG-836-OPEN.md)) — use `localStorage`, which does survive. And `history.back()` across a document boundary freezes the calling document permanently: no traversal, no request, no `pageshow`, and **no timer ever runs again** ([BUG-835](bugs/BUG-835-OPEN.md), 1 tick against ~26 in 14 s) — which also makes it a prime candidate for the `hung-browser` mechanism that eats the rest of a WPT shard. Only `pagehide` marks a page leaving; `unload`/`beforeunload`/`visibilitychange` are never dispatched at all ([BUG-834](bugs/BUG-834-OPEN.md)), so never sequence a probe on them.
- **Two silent drops that make a probe look like an engine hang: a string timer handler and a click on the wrong node.** `setTimeout("code", 0)`/`setInterval` open with `if (typeof fn !== 'function') return 0;` (`crates/js/src/dom.rs:6810`, `:6828`) — the string is never compiled and a plausible timer id comes back, so nothing throws and nothing runs ([BUG-831](bugs/BUG-831-OPEN.md); `eval` itself works, so this is the timer path only). And activation behaviour is looked up on the clicked node rather than on the nearest activatable ancestor (`:14679`, `:4030`), so `label > span`.click() — or a click on the `<img>` inside an `<a>`, or the `<svg>` inside a `<button>` — dispatches the event and then does nothing ([BUG-837](bugs/BUG-837-OPEN.md)); click the activatable element itself in a probe. Related shape worth knowing when reading a WPT residual: a test whose wait lives in the *child* document (`parent.done()` from an `<iframe>`) shows no wait at all in its own source — `timeout_audit.py` now has a fifth `classify_source` stage that reads the subframe for exactly that reason (47 ids, all BUG-480).

- **Four APIs that answer a probe by working just well enough to mislead it: IndexedDB, `EventSource`, Compression Streams and the Performance Timeline.** Measured 2026-08-22 (WPT-RUN-6 slice 22, `tests/wpt/verify_perf_idb_sse_gaps.py`), and in two of the four the family name pointed at the wrong thing. IndexedDB's basics are fine (open, upgrade, `put` → `oncomplete`, the spec order of two transactions, `TransactionInactiveError`, `deleteDatabase`, `createIndex`), but a transaction with **no requests in it never commits** — only a request queues one ([BUG-841](bugs/BUG-841-OPEN.md)) — there is no connection queue at all, so `versionchange`/`blocked` never fire ([BUG-843](bugs/BUG-843-OPEN.md)), and WPT's own `keep_alive` idiom (a request re-armed from its own `onsuccess`) **freezes the page**: `_idb_flush_txn` drains the queue in a `while` inside one microtask, so 16.3M iterations run in 6 s with no timer, no rendering and no later script of the document — a prime `hung-browser` source ([BUG-842](bugs/BUG-842-OPEN.md)). `EventSource` delivers messages, `lastEventId` and `Last-Event-ID` correctly, yet a stream ended by the response body rather than by a socket close — i.e. every `.py` handler under `wptserve` — is never treated as ended: no `error`, no reconnect, `readyState` stays 1 forever ([BUG-844](bugs/BUG-844-OPEN.md)); reconnects that do happen fire no `open`, and the trailing incomplete block survives the disconnect and is merged into the next connection's data ([BUG-845](bugs/BUG-845-OPEN.md)). `DecompressionStream` decodes correctly but emits nothing until `writer.close()`, so the reflexive write-then-read hangs ([BUG-846](bugs/BUG-846-OPEN.md)), and `new Response(stream).arrayBuffer()` resolves with 0 bytes (BUG-824). `PerformanceObserver` delivers `mark`/`measure` including `buffered: true`, while `resource` — advertised in `supportedEntryTypes` and accepted by `observe()` — is never produced on a live page ([BUG-839](bugs/BUG-839-OPEN.md), the BUG-809 shape again), the callback gets two arguments instead of three, and **an exception it throws is swallowed** by the shim's own `try/catch` ([BUG-840](bugs/BUG-840-OPEN.md)) — the BUG-828 trap in a second place. **Consequence for a probe:** close the writable side before reading a compression stream, never sequence anything on an `EventSource` reconnect or on a page-level IDB spin, and treat "the API responded" as saying nothing about whether it delivered.
- **A `setTimeout` delay above 2^31-1 never fires, and an image source that is not an `<img>` is never fetched.** The timer shim clamps only the lower bound (`crates/js/src/dom.rs:7345`), so the WebIDL `long` conversion that turns `Math.pow(2, 32)` into `0` never happens and the callback is scheduled 49 days out ([BUG-847](bugs/BUG-847-OPEN.md)). And `collect_requests_inner` (`crates/engine/layout/src/box_tree.rs:2262`) matches `name.local == "img"` and nothing else: `<video poster>`, `<input type=image>`, an SVG `<image href>` and `<link rel=icon>` produce no HTTP request and no `load`/`error` at all ([BUG-848](bugs/BUG-848-OPEN.md)) — proven by recording requests on the probe's own server, since the browser log is not evidence here (BUG-826). **Consequence:** a probe that needs a subresource must use `<img>`, `<link rel=stylesheet>`, `<script src>` or `fetch()`; anything else measures this bug.
