# lumen-encoding ✅ (detector + decoders + Unicode provider + hyphenation)

- **Done:** decoding tables for `Windows-1251`, `KOI8-R`, `CP866` (per WHATWG Encoding Standard) + **UTF-16/UTF-32 LE/BE decoders** with surrogate pair handling (U+10000+ supplementary plane), lone surrogate → U+FFFD, non-multiple-of-unit-size byte count → trailing U+FFFD. Decoder `decode(encoding, bytes) → String` for all eight variants with lossy handling of illegal bytes and automatic stripping of UTF-8/UTF-16/UTF-32 BOM; `decode_to_string_opts(encoding, bytes, ignore_bom)` is the same decode with BOM-stripping made optional (`ignore_bom: true` keeps a leading BOM as a literal character) — added for `crates/js`'s `TextDecoder`'s `ignoreBOM` option ([BUG-357](../bugs/BUG-357-FIXED.md)). Detector `detect(bytes, content_type_hint) → Encoding` with priorities: BOM (`EF BB BF` → UTF-8, `FF FE`/`FF FE 00 00` → UTF-16/32 LE, `FE FF`/`00 00 FE FF` → UTF-16/32 BE) → `<meta charset>`/`<meta http-equiv>` in first kilobyte → HTTP content-type hint → valid UTF-8 → frequency heuristics over Russian letters (weighted score from 32 frequencies). Implements `lumen_core::ext::EncodingDetector` via `HeuristicDetector`. `Encoding::from_label` parses WHATWG aliases (`cp1251`, `koi8r`, `ibm866`, `utf-16` → LE, `utf-16le`, `utf-16be`, `unicode` → LE, `ucs-2` → LE, `utf-32`/`utf32` → LE). `crates/js/src/v8_runtime.rs` bridges `from_label`/`decode_to_string_opts` to the WEB_API_SHIM `TextDecoder`/`TextEncoder` (native functions `_lumen_text_encoding_for_label`/`_lumen_text_decode`) — a label for any encoding outside this crate's eight variants (Shift_JIS, GBK, windows-1252, …) is a deliberate `RangeError`, not a gap: `docs/plan/tech-stack.md` explicitly rejects `encoding_rs`/porting the full WHATWG label table in favor of this crate's own tables, so the Cyrillic-web + Unicode set above is the intended permanent scope, not a Phase-0 stub awaiting completion.
- **`Icu4xUnicodeProvider`** (`unicode_provider.rs`): implements `lumen_core::ext::UnicodeProvider` via ICU4x 2.2.0. `line_break_opportunities` — UAX #14 via `LineSegmenter` (auto/LSTM + non-complex-scripts variants). `grapheme_boundaries` — UAX #29 via `GraphemeClusterSegmenter`. `word_boundaries` — UAX #29 via `WordSegmenter`. `bidi_runs` — UAX #9 via `unicode-bidi` 0.3. Stores `*Borrowed<'static>` (references to compile-time embedded tables) — `Copy + Clone`; requires `unsafe impl Send + Sync` (no heap `Rc`, only `&'static` refs). `icu_segmenter = { version = "2", features = ["compiled_data"] }` embeds Unicode data at compile-time; no runtime data loading.
- **`KnuthLiangHyphenation`** (`hyphenation_impl.rs`): implements `lumen_core::ext::HyphenationProvider` via provisional `hyphenation = "0.8"` crate (Knuth–Liang algorithm, embedded TeX dictionaries via `embed_all`). Supports 11 locales: en, ru, de, fr, uk, nl, es, pt, it, pl, cs. Lazy per-locale dictionary loading with `Mutex<HashMap<String, Standard>>` cache. `hyphenate(word, locale) → Vec<usize>` returns byte-offset break positions. Empty locale defaults to English. `Send + Sync`. Used by `lumen-shell` via `lumen_layout::layout_measured_hyp` when CSS `hyphens: auto` is active. Dep provisional: graduation → permanent when hyphenation becomes standard pipeline (Phase 2-3+).
- **Deferred:** ISO-8859-5 and MacCyrillic (not encountered in practice), full HTML5 prescan algorithm §12.2.3.2 (our sniff is simpler than spec, but sufficient in practice), windows-1252 and the rest of the WHATWG legacy/CJK encodings (Shift_JIS, GBK, Big5, EUC-JP/KR, ISO-2022-JP, gb18030, …) — out of scope by design (see `docs/plan/tech-stack.md`), not merely unimplemented.
- 94 unit tests + 6 integration round-trip tests (prev 90 + 4 new `ignore_bom` decoder tests).
