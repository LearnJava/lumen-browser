# lumen-media-mse 🚧 (модель SourceBuffer для MSE; COMPAT-MSE срез 1)

- **Scope:** байты `appendBuffer` → кадры по дорожкам → `buffered`/`remove`/выдача кадров плееру. Не декодирует и не знает про JS. Зависит только от `lumen-media-demux`.
- **Как разбирает:** `units.rs` копит байты и режет на сегменты (MP4: `ftyp`+`moov` = init, `moof`…`mdat` = media; WebM: EBML+`Info`+`Tracks` = init, `Cluster` = media, в т. ч. неизвестной длины). Сегмент разбирает обычный `Demuxer` на склейке `init ++ сегмент` (`units::assemble`; для WebM собирается заголовок `Segment` с точной длиной, у init-сегмента без кадров подставляется пустой `Cluster` — `matroska-demuxer` не открывает файл без кластера). Метки, ключевые кадры и конфигурации кодеков — те же, что у воспроизведения файла.
- **Модель** (`SourceBufferModel`): `append` (частичные сегменты копятся, ошибка → `MseError::Decode`, разбор сбрасывается), `abort`, `remove(start,end)` (+ зависимые некючевые кадры до следующего ключевого), `buffered_us` (пересечение дорожек; склейка зазора ≤ длительности предыдущего кадра), `highest_end_us`, `frames(track)` (порядок декодирования, `Arc<[u8]>`), `generation`, `timestampOffset`, окно добавления, режим `Sequence`. Перекрытие: новый сегмент вытесняет старые кадры с показом в его диапазоне.
- **Не сделано (срезы COMPAT-MSE):** JS API `MediaSource`/`SourceBuffer`/`URL.createObjectURL`; `isTypeSupported` по реестру декодеров; плеер поверх буфера (сессия `VideoDecodeSession` из кадров буфера, `waiting`, `readyState` по `buffered`); вытеснение и `QuotaExceededError`; `changeType`; `endOfStream`/`duration`. План — в строке `COMPAT-MSE` в `ROADMAP.md`.
- **Тесты:** `src/tests.rs` — `frag.mp4` (`crates/engine/media-demux/tests/data`) и `tests/wpt/media/test-av-384k-…webm`: целиком и кусками по 777/1013 байт дают одни и те же кадры.
- **Срез 2 (сделано, ветка `p1-compat-mse`):** `media_source.rs` — `MediaSourceCore` (буферы + `duration` + `ended`), общий реестр `create_source/source/drop_source` (по числовому номеру, общий для потока V8 и оболочки), `MseReader` (курсор плеера: `next_packet` → `Packet`/`Pending`/`End`, `seek_us` на ключевой кадр; дорожки разных буферов нумеруются `buffer*TRACK_STRIDE+id`). В `lumen-media-native`: `open_mse(SharedMediaSource)` и `Source::{File,Mse}` в `session.rs`; когда кадры кончились раньше `endOfStream`, `frame_at` оставляет последний кадр (флаг `starved`, декодер не сливается). Тесты: `cargo test -p lumen-media-mse -p lumen-media-native mse`.
