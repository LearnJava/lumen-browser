# lumen-media-ffmpeg 🟡 (VideoDecoder через hand-rolled FFmpeg FFI, feature `ffmpeg`, off by default)

- **Scope:** GAP-MEDIADECODE (ROADMAP.md, ADR-030) — Lumen сегодня декодирует только анимированный GIF (`lumen-image`); `video/mp4`/`video/webm`/`video/ogg` не воспроизводятся вовсе. Пользователь выбрал стратегию «FFmpeg целиком» (не узкий набор кодек-крейтов, не внешний процесс-декодер).
- **Почему hand-rolled FFI, не `ffmpeg-sys-next`:** `ffmpeg-sys-next`'s `bindgen`-генерация даёт несовпадающий layout для набора структур FFmpeg (`AVFormatContext`, `AVFilterContext`, …) и `libc::tm` на `x86_64-pc-windows-msvc` — измеренный живой блокер (ADR-030), воспроизведён на FFmpeg 9.0.1 и 7.1 одинаково. Обход: объявлять руками только те структуры/функции, которые реально используются, опираясь на реальные заголовки установленного дистрибутива, а не на догадки. Три категории в `src/ffi.rs`: полностью opaque (`AVFormatContext`, `AVCodecContext`, `AVCodecParameters`, `AVCodec`, `SwsContext`, `AVIOContext`), "head"-структуры до последнего реально читаемого поля (`AVFormatContextHead`, `AVStreamHead`, `AVFrameHead` — ABI FFmpeg добавляет поля только в хвост), и `AVPacket` целиком (FFmpeg документирует весь его layout как стабильный публичный API).
- **Feature-gated, не влияет на дефолтную сборку.** `ffmpeg` (Cargo feature, off по умолчанию) — без неё крейт компилируется (`cargo check -p lumen-media-ffmpeg`), но не экспортирует ничего и не линкует FFmpeg. `build.rs` линкует `avformat`/`avcodec`/`avutil`/`swscale` только когда feature включена, и требует `FFMPEG_DIR` (панике с понятным сообщением, если её нет — build-скрипт не входит в продукт, `#![allow(clippy::panic)]` тот же паттерн, что и `crates/chrome/build.rs`). `cargo check --workspace` без флагов не трогает FFmpeg ни на одной машине (измерено, срез 4).
- **In-memory ввод, не путь на диске.** `VideoDecoder::open(&self, bytes: &[u8])` получает байты контейнера (тело сетевого ответа/Blob), а не файл — `FfmpegSession::open` заводит FFmpeg-у custom `AVIOContext` (`avio_alloc_context` + hand-written `read_packet`/`seek` `extern "C" fn` над боксовым `Vec<u8>`), а не временный файл. `AVFMT_FLAG_CUSTOM_IO` выставлен на `AVFormatContext.ctx_flags` до `avformat_open_input` — из-за этого флага `avformat_close_input` не освобождает `pb` сам, `Drop`/error-пути `FfmpegSession` делают это явно через `avio_context_free`.
- **`FfmpegVideoDecoder`/`FfmpegSession`** (`src/decoder.rs`) реализуют `lumen_core::ext::VideoDecoder`/`VideoDecodeSession` (trait-anchor из среза 2). `open()` сразу декодирует первый кадр (даёт реальные `width`/`height` для `dimensions()` и превращает "контейнер открылся, но ни одного декодируемого кадра" в ошибку `open()`, а не в ленивую ошибку первого `frame_at`). `frame_at(secs)` всегда делает `av_seek_frame` (`AVSEEK_FLAG_BACKWARD`) + `avcodec_flush_buffers`, затем декодирует вперёд до первого кадра с `pts >= secs` — нет пути "декодировать следующий кадр без seek", поэтому повторный вызов `frame_at` с близким временным кодом не дешевле первого; кэшируется только самый первый декодированный кадр (`open()`'s), чтобы немедленный `frame_at(0.0)` не платил за лишний seek.
- **Найденный живьём баг layout (срез 4):** `AVFrameHead` из среза 3 не содержал `sample_aspect_ratio` (`AVRational`, два `c_int`) между `pict_type` и `pts` (`libavutil/frame.h`) — срез 3 не читал `pts`, только `width`/`height`/`format`/`data`/`linesize`, так что смещение было невидимым, пока срез 4 не добавил seek (нужен `pts` для сравнения с целевым временем). Симптом до фикса — `pts ≈ 2^32` (заведомо нереальное значение); после — `pts = 0.000` для первого кадра. Урок: hand-transcribed структура надёжна ровно настолько, насколько её реально читаемые поля были живьём проверены — непроверенные поля за пределами уже использованных остаются под подозрением.
- **Тесты** (`src/lib.rs`, `#[cfg(all(test, feature = "ffmpeg"))]`): `cargo test -p lumen-media-ffmpeg --features ffmpeg` (нужен `FFMPEG_DIR` + те же `bin/`-DLL на `PATH` в рантайме) декодирует `tests/wpt/css/css-sizing/aspect-ratio/support/2x2-green.webm` (VP8/9, проверяет `rgba[0..4] == [0, 127, 0, 255]`, тот же ассерт, что и scratch-PoC ADR-030 срез 3) и `tests/wpt/css/css-ui/support/test.mp4` (H.264, размеры + `frame_at(1.0)` через реальный seek).
- **Лицензия — заметка, не `cargo-deny`-запись:** FFI ручной, в `Cargo.lock` не появилось ни одной новой Rust-зависимости с лицензией, которую надо флагать — GPL/LGPL-поверхность живёт в связанных FFmpeg DLL (дистрибутив), а не в графе Cargo, который `cargo-deny` инспектирует. Обязательство остаётся тем же (full_build-дистрибутивы несут GPL-компоненты), просто отслеживается здесь и в ADR-030, а не в `deny.toml`.
- **Doc-дрейф исправлен (срез 11):** предыдущая ревизия этого файла (написана на срезе 4) утверждала, что крейт «самодостаточен, ничем в workspace не используется» — устарело: срезы 6-10 подключили его к `crates/js/src/video_bindings.rs`'s resource-selection алгоритму целиком (feature `ffmpeg-video`, `Lumen::tick_video_ffmpegs` в `crates/shell`), включая обработку ошибочных путей (срез 9, `VideoGifStore::load_failures`) и живой прогон битого контейнера (срез 10). Подробная хронология срезов — `ROADMAP.md::GAP-MEDIADECODE`, не здесь.
- **Deferred:** аудиодорожка (trait-anchor явно вне объёма — `<audio>` идёт своим путём, `audio_element.rs`), `frame_at` без re-seek на каждый вызов (нужно для реалтайм-плейбека — не решено, годится ли текущий подход по скорости).
