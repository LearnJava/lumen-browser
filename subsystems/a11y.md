# lumen-a11y

Accessibility tree construction and platform bridge infrastructure.

## Scope

Builds a language-neutral `AXTree` from a Lumen DOM `Document`. Each `AXNode` maps to a
WAI-ARIA role, accessible name, description, and a full set of ARIA state/property flags.
Platform bridge stubs route tree updates to OS accessibility APIs.

**Not in scope:** JavaScript `aria-*` mutation observation (P3 task), live-region
announcement timing (P3 task), actual COM/Objective-C/D-Bus Phase 1 native bindings.

## Done

- **AX tree construction** (`lib.rs`): `build_ax_tree(doc, root_id, flat_tree)` → `AXTree`.
  Shadow DOM composed-tree traversal via `FlatTree`. `aria-hidden` subtrees excluded.
- **67 ARIA roles** (`roles.rs`): `AXRole` enum + `implicit_role(node)` from HTML tag.
  `AXRole::as_str()` for string serialization. Context validation (row requires table parent, etc.).
- **Accessible name/description** (`names.rs`): WAI-ARIA Accessible Name and Description §4.
  aria-labelledby → aria-label → alt → text content → title chain.
- **Full ARIA state set** (`lib.rs`): `AXState` — checked / disabled / expanded / hidden /
  selected / pressed / required / readonly / invalid / busy / tab_index / level / set_size /
  pos_in_set / live / multiline / multiselectable / horizontal / current / modal /
  role_description / value_now / value_min / value_max / value_text.
- **Relationship attributes**: aria-controls / aria-owns / aria-flowto / aria-details —
  stored as `NodeId` references.
- **Constraint-validation integration** (`lib.rs`): `element_validity()` feeds `AXState::invalid`
  when aria-invalid is absent but the form control fails HTML5 validation.
- **Platform bridge infrastructure** (`platform/`): `PlatformBridge` trait + `NullBridge`.
  `platform_bridge()` factory selects `WinUiaBridge` / `MacA11yBridge` / `AtSpiBridge`
  at compile time by `target_os`. Windows (`WinUiaBridge`) is Phase 1, real: `NotifyWinEvent`
  fires `EVENT_OBJECT_REORDER`/`EVENT_OBJECT_FOCUS`/`EVENT_OBJECT_STATECHANGE`, `WM_GETOBJECT`
  returns a real MSAA root via `CreateStdAccessibleObject`. macOS/Linux still hold the last
  `AXTree` clone in memory only (Phase 0).
- **Synthetic chrome nodes** (`chrome.rs`, DS-17): `ChromeSnapshot`/`chrome_nodes()` turn the
  shell's own tab-strip/toolbar/omnibox state into synthetic `TabList[Tab×N]`/`ToolBar[Button×K,
  ComboBox]` `AXNode`s (not derived from any DOM); `attach_chrome()` sews them onto the
  DOM-derived tree as siblings under one `AXRole::Generic` wrapper root. Node IDs are
  synthesized by counting down from `u32::MAX` (`synthetic_id`) so they never collide with a
  real DOM node index. Superseded by CC-13 below and unreachable since CC-15-6 —
  kept as the `None`-arm of the shell's always-`Some` `chrome_doc`.
- **Engine-derived chrome nodes** (`chrome.rs`, CC-13, the only live path):
  `chrome_root_from_document(doc, root_id, flat_tree)` runs the same `build_ax_tree` pages use
  over `chrome_doc` — roles/names/states come from `role=`/`aria-*` attributes
  `scripts/gen_chrome_assets.py` injects into `assets/chrome/chrome.html` at generation time
  (`add_aria_roles`/`add_aria_labels`), not hand-maintained Rust. Node ids are remapped into the
  same synthetic `u32::MAX`-descending range `chrome_nodes` uses (`chrome_doc` and the page
  `Document` both number `NodeId`s from 0 — same collision class CC-11 solved for the animation
  scheduler), so the result attaches via `attach_chrome` exactly like the synthetic nodes did.
  Side effect: every chrome panel (history/bookmarks/settings/downloads/palette/…) gets real
  ARIA nodes for free, since under the flag they're genuine DOM, not just the tab strip/toolbar
  DS-17 covered.
- **Shell wiring** (`shell/src/main.rs`): `Lumen::update_platform_ax_tree()` called after every
  full page load (`apply_loaded_page`), tab restore (`restore_page_snapshot`), and tab switch
  (`switch_tab`, DS-17 — keeps the `TabList`'s `selected` state live without a navigation).
  `Lumen::chrome_ax_nodes()` (CC-13) is the single branch point: `chrome_root_from_document`
  when `chrome_doc` is `Some` (flag on), else the DS-17 `chrome_snapshot()`/`chrome_nodes()`
  path — never both, mirroring the "one or the other" panel-gating CC-10a's invisible-legacy-
  panel-eats-clicks bug taught. Both `update_platform_ax_tree()` and the live-automation
  `automation_a11y_tree()` (`AutomationCommand::A11yTree`, MCP `resource://a11y_tree`) call
  `chrome_ax_nodes()`. `focused_node_changed()` called on click focus change.
- **Tests**: 125 `ax_tree` + 9 `chrome` integration tests (`tests/all.rs`, 134 total) + 23
  platform/lib unit tests (`platform/mod.rs`, `platform/windows.rs`). 157 `lumen-a11y` tests pass.

## Deferred

- **Phase 2 native bindings**: Windows UIA COM (`IRawElementProviderSimple` exposing every
  `AXNode` as a named UIA element — Phase 1 already fires the coarse `NotifyWinEvent`/
  `WM_GETOBJECT` events), macOS `NSAccessibilityElement` + notifications, Linux AT-SPI2 D-Bus
  service via `atspi`+`zbus`. Each platform file has detailed Phase-2 comments. No new Cargo
  deps required for Windows (uses `windows`/`windows-sys` crates already in the dep graph via winit).
- **DS-17/CC-13 follow-up**: neither the synthetic nor the engine-derived chrome nodes reach
  the Windows MSAA bridge's per-node child objects yet (Phase 2 territory above) — today they
  only reach AT via the serialized `AXTree` (MCP/BiDi) and the coarse whole-tree
  `NotifyWinEvent` reorder signal.
- **Live region announcement timing**: `aria-live="polite/assertive"` — state is captured,
  announcement scheduling is shell/P3 territory.
- **`aria-*` mutation observation**: P3 task — hook DOM mutation events to call
  `update_platform_ax_tree()` between full page loads.

## Invariants

- `AXTree` has exactly one root node (the document root).
- `aria-hidden="true"` nodes are excluded entirely from the tree (subtree pruned, not just flagged).
- `NodeId` references (controls/owns/flowto/details) may point to nodes absent from the AX tree
  if the target node is aria-hidden.
- Platform bridges must be `Send + 'static` (box-erased, moved into `Lumen` struct on main thread).
- The `platform_bridge()` factory does not fail — returns `NullBridge` on unsupported platforms.
