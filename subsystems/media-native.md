# lumen-media-native ✅ (собственный `VideoDecoder` «lumen-native»: реестр декодеров поверх демуксеров, без FFmpeg)

- **Scope:** UX-VIDEO-NATIVE ([ADR-035](../docs/decisions/ADR-035-media-decoding-without-ffmpeg.md) п.1). `NativeVideoDecoder` реализует `lumen_core::ext::VideoDecoder`; контейнер разбирает `lumen-media-demux`, видео-/аудиопакеты декодируют бэкенды реестра. Подключён в штатной сборке: `window_mode.rs` вызывает `lumen_js::set_video_decoder(NativeVideoDecoder)` до создания JS-контекстов; с фичей шелла `ffmpeg-video` вместо него встаёт `FfmpegVideoDecoder` (dev-бэкенд).
- **Реестр** (`registry.rs`): список бэкендов кодеков. Встроенные: AV1 → `lumen-av1` (rav1d), Vorbis → `lewton` (`Registry::bundled()`). Бэкенды ОС (`COMPAT-MEDIA-OSDEC-*`) стоят перед ними (`Registry::builtin()` = ОС + встроенные): сейчас Windows — Media Foundation (см. ниже), macOS/Linux — `-MAC`/`-LINUX` (VideoToolbox / VA-API). Порядок по кодеку: аппаратный ОС → программный ОС → встроенный свободный. Реестр отвечает на `canPlayType` (`probably` — все кодеки из `codecs=` открываются, `maybe` — контейнер без `codecs`, `""` — иначе), поэтому страница не получает обещание на то, что не заиграет (ADR-034 п.2).
- **Сессия** (`session.rs`, `NativeSession`): один курсор демуксера на видео и звук. `frame_at(secs)` идёт вперёд без повторного чтения, перемотка назад/далеко вперёд — с ключевого кадра; `decode_audio_pcm` продолжает с позиции видео и отбрасывает устаревший звук. Поэтому порядок вызовов в шелле `frame_at` → `decode_audio_pcm`.
- **Путь в браузере:** `shim/video_element.js` (`startContainerLoad`, расширения `.mp4/.m4v/.webm/.ogg/.ogv`) → `__lumen_video_container_load(nid, src)` (зарегистрирован, только если установлен декодер) → `VideoGifStore::pending_container_loads` → `Lumen::tick_video_sessions` (`crates/shell/src/page_load.rs`): загрузка байтов (`fetch_video_bytes`, `RequestDestination::Media`), `decoder.open`, первый кадр, `VideoPlaybackState` в общую карту `playback`; сбой — в `load_failures` (`error` на элементе). Звук идёт в `platform::video_audio_sink::VideoPcmAudioSink` (rodio).
- **Известное ограничение:** нераспознанный кодек даёт `MEDIA_ERR_DECODE` (3), а не `SRC_NOT_SUPPORTED` (4) — развести можно типом сбоя в `load_failures`. Файл целиком читается в память до `open` (потоковой загрузки нет — как и у демуксера).
- **Windows: Media Foundation** (`mf/`, `cfg(windows)`, COMPAT-MEDIA-OSDEC-WIN, ADR-035 п.3): H.264 / HEVC (Annex B из `avcC`/`hvcC` — `annexb.rs`) и AAC-LC/HE (сырые кадры) декодируют готовые синхронные MFT ОС (`IMFTransform`), пакеты им отдаёт наш демуксер (`IMFSourceReader` не нужен — общий курсор держит видео и звук синхронными). Видео: NV12/P010 → RGBA (`yuv.rs`), звук → PCM i16. Функции `mfplat.dll` (`MFStartup`, `MFTEnumEx`, `MFCreate*`) **не линкуются**: `Api::get()` берёт их через `LoadLibraryExW(System32)`+`GetProcAddress`, иначе exe не запустится на Windows N/KN без Media Feature Pack. `mf::availability()` один раз опрашивает ОС, есть ли MFT для H.264/HEVC/AAC; реестр отвечает на `canPlayType` по факту (`avc1.PPCCLL` только Baseline/Main/High, `hvc1` Main/Main10, `mp4a.40.2/5/29`), `lumen_media_native::os_codec_status()` отдаёт оболочке те же флаги (`media_feature_pack_missing()` — N/KN), `WINDOWS_OPTIONAL_FEATURES_URI` — адрес страницы установки. `LUMEN_OS_DECODERS=0` (читается один раз при первой загрузке MF) отключает декодеры ОС — поведение N-редакции для отладки. Зависимость `windows` 0.58 (COM-интерфейсы).
- **Не сделано (отдельные задачи):** плашка «установите Media Feature Pack» на N-редакции (`COMPAT-MEDIA-OSDEC-WIN-BAR`: нужен сигнал JS→оболочка о сбое открытия `<video>` и новый инфобар по образцу `#loginBar`); аппаратный D3D11VA с откатом на программный MFT и блок-листом драйверов (`COMPAT-MEDIA-OSDEC-WIN-D3D`). Сейчас используются только программные синхронные MFT; HEVC без расширения «HEVC Video Extensions» даёт `canPlayType` `""`.
- **Фикстуры:** `tests/data/av1-vorbis.webm` (ffmpeg 9: libaom-av1 + libvorbis), `tests/data/h264-aac.mp4` (320×180, 25 кадр/с, 2 с, B-кадры, AAC-LC стерео 44,1 кГц). Тесты — `src/tests.rs` (модуль `os_decoders` — `cfg(windows)`, при отсутствии декодера у машины пропускает проверки воспроизведения; отрицательные тесты идут на `Registry::bundled()` и не зависят от ОС).
