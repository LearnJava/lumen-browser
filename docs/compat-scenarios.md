# Сквозные сценарии совместимости (корпус S, SPR-w)

Сценарий — путь пользователя через живой сайт: вход до пароля, оплата до 3DS, видео, почта, документ, файл.
Раннер [`scripts/compat_scenarios.py`](../scripts/compat_scenarios.py) ведёт окно Lumen через MCP, после шагов
ждёт оракул конца и пишет исход. Метрика **SPR-w** — взвешенная доля пройденных сценариев
(отчёт [`research/site-compat/report.md`](research/site-compat/report.md) §7.8, §8.8). Журнал прогонов —
[`perf/journal.md`](perf/journal.md).

## Файлы

| Что | Где |
|---|---|
| Сценарии на живых сайтах | `docs/perf/scenarios/{login,bank-pay-gov,media-mail-docs,web}.toml` |
| Плановые передачи (вне SPR-w) | `docs/perf/scenarios/handoffs.toml` |
| Стенды самопроверки раннера (`stand = true`) | `docs/perf/scenarios/stands.toml` + `samples/compat-scenarios/` |
| Раннер и тесты | `scripts/compat_scenarios.py`, `scripts/test_compat_scenarios.py` (`--self-test`) |
| Результат прогона (не коммитится) | `.tmp/compat-scenarios/<время>/` — `results.jsonl`, `summary.md`, `summary.json`, кадры провалов |

## Формат сценария (TOML, `[[scenario]]`)

| Поле | Обяз. | Смысл |
|---|---|---|
| `id` | да | `[a-z0-9-]+`, уникален по всем файлам |
| `title` | да | одна строка: путь и ожидаемый итог |
| `category` | да | `login bank payment gov` (вес 3) · `video mail docs call` (вес 2) · `file shop news search social maps other` (вес 1) |
| `lang` | нет | `ru` или `en` (по умолчанию `en`) |
| `weight` | нет | 1, 2 или 3 — перекрывает вес категории |
| `mode` | нет | `nightly` (по умолчанию, идёт в ночной прогон) или `manual` |
| `handoff` | нет | `drm gost ep calls` — плановая передача (ADR-035): не запускается, в SPR-w не входит. Категория `call` — только с `handoff = "calls"` |
| `stand` | нет | `true` — стенд самопроверки раннера, в SPR-w не входит |
| `account` | нет | префикс переменных окружения `<ACC>_USER` / `<ACC>_PASS`; без них — `skip no_account`; в шагах доступны `{user}`, `{pass}` |
| `timeout_s` | нет | потолок сценария (по умолчанию 90 с) |
| `oracle_wait_s` | нет | сколько ждать оракул после шагов (по умолчанию 10 с) |
| `steps` | да | список шагов |
| `oracle` | да | оракул конца: **все** проверки выполняются одновременно |

### Шаги (`do = ...`)

| Шаг | Поля | Действие |
|---|---|---|
| `navigate` | `url` | открыть адрес (`{stand}` — корень локального стенда) |
| `click` | `selector` | клик в центр элемента (CSS-селектор верхнего документа) |
| `click_text` | `text` (регулярка), `scope` | клик по видимому кликабельному элементу с таким текстом |
| `type` | `selector`, `text` | фокус и ввод текста |
| `wait` | `cond` = `document_ready` · `visible` · `stable` · `network_idle` · `js_idle`; `selector`, `timeout_s` | ожидание |
| `sleep` | `seconds` | пауза |
| `eval` | `code`, `expect` | выполнить JS; с `expect = true` ложный результат — провал шага |

Любой шаг с `optional = true` не проваливает сценарий (баннер согласия, который есть не на всех точках).

### Оракул (`kind`)

`visible` — селектор виден (список через запятую допустим) · `url` — регулярка по адресу · `text` — регулярка по
видимому тексту (без учёта регистра) · `not_text` — такой регулярки нет · `eval` — JS возвращает истину.

Правила хорошего оракула: проверять **итог пути** (шаг пароля, сообщение «аккаунта нет», карточка товара, метаданные
видео), а не «страница загрузилась»; принимать все честные исходы сайта (шаг пароля *или* «аккаунт не найден»);
не опираться на внутренние классы вёрстки, которые меняются раз в месяц; без реальных учётных записей —
несуществующий логин.

## Исходы и «распознанный экран»

`pass` · `fail` (шаг или оракул не выполнились) · `crash` (окно упало) · `hang` (окно не отвечает) ·
`skip` (`handoff:*`, `no_account`, `ref_fail`). **Крах и зависание — провал.** Провалившийся сценарий
повторяется один раз; прошёл со второго раза — `pass` с пометкой `flaky`.

У каждого провала записан `screen.class`: `crash`, `hang` (в том числе «поток движка занят» — MCP не получил ответ за 5 с),
`cert_error` (навигацию отвергла проверка сертификата — например, цепочка НУЦ без согласия хоста), `lumen_error` (страница ошибки `ERR_*`), `wall`
(стена антибота, подписи — `scripts/wall_signatures.py`), `captcha`, `consent` (баннер согласия закрывает
страницу), `blank` (пустой экран), `content` (обычная страница, но ожидаемого нет), плюс кадр `*.png`,
адрес, заголовок и начало видимого текста.

## Метрика SPR-w

`SPR-w = Σ вес(пройденных) / Σ вес(исполненных)` по сценариям, входящим в метрику (не передачи, не стенды,
не `skip`). База считается достигнутой при ≥40 исполненных сценариях (`base_reached` в `summary.json`).

## Калибровка оракулов

Оракул, не проходящий в Chrome, — неверный оракул или отказ сайта эталону, а не дефект Lumen.

1. `python scripts/compat_scenarios.py --chrome-only --headless --no-rerun` — прогон только в Chrome for Testing
   (без окна Lumen); провал разбирается по `failed_oracle`/`failed_step` и кадру в `results.jsonl`.
2. Исправить селектор/регулярку; сценарий, который нельзя стабилизировать (гео-блок, капча у эталона), —
   `mode = "manual"` с комментарием, почему.
3. Боевой прогон: `python scripts/compat_scenarios.py --ref --nightly --exe <свежий lumen.exe>` —
   каждый сценарий сначала проходит в Chrome; не прошёл там — `skip ref_fail`, в SPR-w не идёт.

Маршрут сети: Lumen не читает системный прокси и `HTTPS_PROXY` (Chrome-эталон читает), поэтому иностранные сайты Lumen открывает
только с явным `--proxy`. Раннер ведёт два прохода: `--lang ru` (напрямую) и `--lang en --lumen-arg=--proxy
--lumen-arg=<url прокси>` (`--lumen-arg` повторяемый, значение с дефисом — через `=`); итог — один `results.jsonl`.
Сценарий с `lang = "ru"` на иностранном узле (Telegram) идёт вторым проходом через `--only`.

Маршрут сети влияет: с зарубежной точки RU-сайты часто отдают стену, с российской — часть зарубежных
сервисов. Точку прогона записывать в журнале рядом с базой.

## Границы (чего раннер пока не умеет)

- **Смена и закрытие вкладок** — MCP даёт `navigate/click/type/wait/eval`, но не `list_tabs/switch_tab/close_tab`
  (`crates/mcp/src/server.rs`); попап OAuth и окно 3DS в отдельной вкладке проверяются только через стенд
  с кадром (`stand-3ds-iframe`) и прямую навигацию на страницу входа IdP.
- **Ввод внутри чужих кадров** — `type`/`click` работают в верхнем документе; карточная форма в iframe
  эквайера проверяется только на «кадр отрисован».
- **Диалог выбора файла** — открытие системного окна блокирует прогон; загрузка файла проверяется на
  отрисовку поля и зоны перетаскивания.
