# TEXTQ-5 — измерение ширины текста в раскладке через шейпер

Дорожка TEXTQ, срез 5. Владелец — P1. Крейты — `lumen-paint` (измеритель), `lumen-layout`. **Зависит от:** TEXTQ-4.

## Зачем

Раскладка меряет текст посимвольно: `try_char_width` / `try_char_width_varied` ([paint/src/lib.rs:711](../../crates/engine/paint/src/lib.rs#L711)) — advance из `hmtx` по `cmap`, без кернинга и лигатур. После TEXTQ-4 отрисовка шейпит, а раскладка — нет: ширина строки в боксе расходится с нарисованной, переносы строк и центрирование отличаются от Chrome.

## Что сделать

1. Ширину слова/run-а считать шейпером (`active_text_shaper()`) с теми же `font_features` и variation coords, что у отрисовки; посимвольную сумму оставить только как fallback, если шейпинг недоступен.
2. Кэш измерений по `(face, text, size, features, coords)` — раскладка меряет одни и те же слова многократно. Замер времени раскладки на тяжёлой текстовой странице до/после; регрессия не больше 10 %, иначе — оптимизировать кэш.
3. Убедиться, что граница переноса (break opportunity) и измеряемый отрезок совпадают: кернинг через границу слов не учитывается, лигатура не рвётся.
4. Отрисовка (GPU и CPU) и раскладка должны давать одну ширину для одного run-а — тест.

## Готово, когда

1. Юнит-тест: ширина `AVATAR` из измерителя = ширине, нарисованной GPU-путём и CPU-путём (±0,01 px).
2. Замер времени раскладки до/после — в ROADMAP-строке.
3. Полный `python graphic_tests/run.py --continue-on-fail` (сдвинется много эталонов — перегенерировать все затронутые наборы в том же коммите: Edge-diff, `graphic_tests/snapshots/cpu/`, `tests/snapshots/*.snap`); diff против Edge по тестам с текстом не хуже, чем до.
4. `scripts/scoped-test.sh` для `lumen-layout` и `lumen-paint` зелёный, `cargo clippy` по обоим крейтам чисто.
