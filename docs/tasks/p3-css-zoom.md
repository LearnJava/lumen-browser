# p3-css-zoom — CSS `zoom` + остаток по рендеру tbank.ru

Хендофф следующей сессии. Ветка `p3-css-zoom`, 3 коммита, `main` не тронут.
Статус: свойство реализовано и протестировано, **но заявленную цель (вписать
tbank.ru в окно) пока не даёт** — см. §4.

---

## 1. С чего началось и что уже НЕ является проблемой

Заявка: `https://www.tbank.ru/` почти ничего не отображает, не работает переход
в «Личный кабинет». Скриншоты пользователя — `tbank.png`, `tbank1.png` в корне.

**Пустая страница оказалась устаревшим `target/dev-release/lumen.exe`, а не
дефектом движка.** После пересборки с актуального HEAD страница стабильно
рендерится: ~2690 элементов, React монтируется, `SyntaxError` в консоли нет.
[BUG-702](../../bugs/BUG-702-FIXED.md) и [BUG-703](../../bugs/BUG-703-FIXED.md)
не воспроизводятся (проверено 9 подряд чистыми прогонами).

**Ловушка измерения, стоившая времени:** странице нужно **~15 секунд** после
`document_ready` (28 внешних бандлов, два по 1.5–2 МБ). На 5-й секунде DOM ещё
~170 узлов и все рамки нулевые — это выглядит как «движок ничего не нарисовал».
Всегда ждать 15 с и только потом мерить.

Кнопка «Личный кабинет» — это `button[aria-label="Личный кабинет"]`, **не
ссылка**; навигации по клику не должно быть и в оригинале (открывает виджет
логина). Геометрия после 15 с корректная: x≈944, y≈41, 167×44.

## 2. Что сделано в ветке

| Коммит | Содержание |
|---|---|
| `8e14b4ee2` | Реализация `zoom` |
| `30fef033e` | 7 юнит-тестов |
| `d0097bd65` | Строка в `CSS-SPECS.md` (🟡 + список ограничений) |

Всё в `crates/engine/layout/src/style.rs`:

* `ComputedStyle::effective_zoom: f32` — перемножается по дереву
  (`inherited.effective_zoom * own_zoom`). Начальное значение `1.0`.
* `parse_zoom()` — `<number>` / `<percentage>` / `normal` / `reset`.
  Невалидное значение → `None`, декларация отбрасывается (а не сбрасывает
  накопленное в 1).
* `apply_zoom_to_lengths()` + хелперы `zoom_length` / `zoom_length_or_auto` —
  масштабируют **только `Length::Px`** ненаследуемых свойств блочной модели:
  width/height/min/max, margin, padding, inset (top/right/bottom/left),
  border-width, row/column-gap. Вызов — в самом конце `compute_style`, после
  всех пассов, чтобы каждое значение отмасштабировалось ровно один раз.
* Пре-пасс `zoom` в `compute_style` — **до** пре-пасса font-size, потому что
  zoom множит и его.
* `font_size`: объявленный на самом элементе берёт полный `effective_zoom`,
  унаследованный — только собственный множитель (вклад предков уже в нём).

Почему относительные единицы не трогаются: `em`/`%` резолвятся против базисов
(`font_size`, containing block), которые уже отмасштабированы, — их отдельная
обработка дала бы двойное применение.

### Проверено

* 7 новых юнит-тестов + **3632** теста `lumen-layout` зелёные.
* `cargo clippy -p lumen-layout --all-targets -- -D warnings` чист.
* Через `--dump-layout` на синтетике работает во всех формах: inline `style=`,
  `<style>`, **линкованный** CSS, `@media screen and (…)`, голый `@media`,
  точный узкий диапазон tbank `(min-width:1024px) and (max-width:1029px)`,
  `:not()`, перемножение по дереву.
* Neutrality: начальное значение `1.0` + ранний выход из
  `apply_zoom_to_lengths` ⇒ для страниц без `zoom` изменение — no-op. Косвенно
  подтверждено тем, что все 3632 теста прошли без правок ожиданий.

## 4. Главный незакрытый вопрос: почему на живом tbank.ru эффекта нет

На живом окне контейнер `div.ab7IwJCWZ` по-прежнему **1104px** в viewport
1024px (`getComputedStyle(...).minWidth === "1104px"`, `getBoundingClientRect()
.width === 1104`), т.е. zoom к нему не применился. При этом в headless всё
работает. Переменную «headless vs живое окно» изолировать не успел.

### Проверено и ОТБРОШЕНО (не повторять)

* **Медиазапрос совпадает.** В живом окне
  `matchMedia('screen and (min-width:1024px) and (max-width:1029px)').matches
  === true`, `document.documentElement.clientWidth === 1024`.
* **Правило-перебивка обрабатывается верно.** В `desktop-navigation.css` есть
  `[data-atom-type=desktop-container] .ab7IwJCWZ[data-atom-type=desktop-container]{zoom:normal}`.
  У элемента атрибут есть на нём самом, но **ни у одного предка** (проверена вся
  цепочка до `<html>`), поэтому descendant-селектор совпадать не должен — и
  Lumen действительно не совпадает (синтетический тест: элемент с атрибутом
  только на себе зумится, настоящий потомок — корректно перебивается).
* **Медиазапросы в линкованных таблицах работают** (проверено отдельным файлом).
* **Узкий диапазон работает** в headless при viewport 1024.
* **`html[data-zoom-enabled=true]` — не тот механизм.** В `platform.css` есть
  зум на корне, но Edge отдаёт `data-zoom-enabled="false"`, т.е. и в эталоне он
  выключен; Edge вписывает страницу именно правилом контейнера из `nav.css`.

### Что проверить дальше (в порядке убывания вероятности)

1. **Какой viewport видит движок стилей в живом окне.** `clientWidth` (JS) и
   `viewport`, передаваемый в `compute_style`, — разные пути. Если второй ≠
   [1024, 1029] (например 1008 или дробное значение из-за DPI), медиазапрос в
   CSS не совпадёт, хотя `matchMedia` вернёт `true`. Быстрая проба: положить в
   локальную страницу правило с **узким** диапазоном и открыть её **в живом
   окне** (не headless), сверив с поведением того же файла в `--dump-layout`.
   Мои синтетические тесты все шли через headless — именно поэтому расхождение
   и не всплыло.
2. **Пересчитывается ли стиль после динамической вставки `<link>`.** Микроблоки
   вставляют свои CSS скриптом (ср. [BUG-722](../../bugs/BUG-722-FIXED.md)).
   Если правила из динамически вставленной таблицы применяются к уже
   существующим узлам не полностью, `min-width` мог прийти из другого источника,
   а `zoom` — потеряться. Проверить: применяется ли вообще ХОТЬ ОДНО правило из
   медиаблока `nav.css` на живой странице.
3. **Выставить `effective_zoom` наружу** — добавить `zoom` в сериализацию
   `getComputedStyle` (`selector_query::computed_style_to_map`). Это и полезно
   само по себе, и превращает диагностику в одну строку вместо косвенных
   измерений через ширины.

## 6. Грабли этой сессии

* **Heredoc в bash съедает `\\`** — Python-скрипты писать только через `Write`, не
  через `cat <<'EOF'`. Один скрипт уже сломался на `.replace('\\','/')`.
* **`file://` как аргумент CLI не грузится** ([BUG-651](../../bugs/BUG-651-OPEN.md)) —
  стартовать с `about:blank` и потом звать `navigate`. При этом живой `eval` по
  `file://`-странице у меня отвечал `JS context not available`; для локальной
  синтетики надёжнее `--dump-layout`, он и быстрее.
* **`taskkill` в Git Bash требует `//PID`**, не `/PID`.
* **Не убивать процессы по имени образа** — рядом идёт параллельная сессия
  (слот `p3-work`, ветка `p3-bug-386`), её `cargo.exe` трогать нельзя.
* **Сборка в отдельный `--target-dir` — холодная и очень долгая.** Собирать в
  корне, где `target/` прогрет (2 мин против десятков).
* В корневом дереве лежат **чужие незакоммиченные** изменения (`.gitignore`,
  `STATUS-P2.md`, `.kilo/`, `tbank*.png`) — не коммитить их.
