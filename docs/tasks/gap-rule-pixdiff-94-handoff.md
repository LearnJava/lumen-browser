# Срез 94 css-gaps (p4-gap-rule-pixdiff-94) — заметка передачи

Ветка `p4-p4-gap-rule-pixdiff-94`, слот `p4-work`. Кода среза нет: сессия ушла на разведку, чтобы выбрать, что чинить. Базовая картина (`css-gaps`, 800×600, `.tmp/gp.py '**'` = pixel compare Lumen-страницы с Lumen-ref): identical 300, thick 11, thin-only 2.

## Что выяснено (проверено в `msedge --headless`, инструменты — `.tmp/edge/shot.py`, `.tmp/edge/rects.py`; `.tmp` не коммитится, скрипты воссоздаются за минуты: скриншот + `getClientRects()` через `--dump-dom`)

- **`flex/fragmentation/020` (362 px)** — причина найдена. Chrome балансирует колонки до `502/5 = 100.40625` px (фрагменты flex `h=100.40625`, DIV1 режется на 99.40625 + 0.59375, правила на `y = 0.5/3.5`), Lumen держит 101 (лимит `height`). Виновник — `emit_grid_fragments` в `box_tree/multicol_trampoline.rs` (~стр. 1081–1115): для `col_flex` `tallest = max(item_h)` (здесь 400, от item `height: 400px`) поднимает нижнюю границу бисекции до `limit`, поэтому `cut_at = limit`. В Chrome элемент выше колонки просто режется, нижняя граница — `total/n`, и дальше «растёт до fits» с шагом `LayoutUnit` (1/64). Править: `tallest` должен учитываться только пока он ≤ лимита (элемент выше лимита режется всё равно), а `lo`/`hi` брать без округления до целых (после бисекции округлить вверх до 1/64). Проверить, что `flex/fragmentation/005/014/…` и 19 identical остаются identical (`005`: `n_cols` = 2 из-за `column-width: 110px` при `width: 330px`, 114/2 = 57, лимит 47 → `total_h < limit*n` ложно, путь не меняется).
- Пробная правка `Model::balanced` (`multicol_flow.rs`) на шаг 1/64 вместо целых пикселей css-gaps не изменила (flex идёт не через неё) — откачена, но для атомного/`emit_sliced_fragments` пути Chrome тоже балансирует в `LayoutUnit`, это отдельный возможный срез.
- **`flex/fragmentation/008` (2500 px)** — слой раскладки: Lumen не разрывает row-wrap flex по `break-before: column` у первого item строки (всё остаётся в колонке 1). В Chrome строка 1 (items 1, 2) — в колонке 1, `break-before` у item 2 (не первого в строке) игнорируется, строка 2 (3, 4) — в колонке 2, но items лежат **внизу** фрагмента (`y=50..80` при высоте фрагмента 84, колонка 2 при `height: 170`, фрагмент 1 потребил 90; при `height: 230` — `y=80`): строка 2 вытянута `align-content: stretch` до остатка, а item прижат к её низу не из-за `align-*`. Правило не понято; нужна серия проб Edge (меняя `height`, `row-gap`, число items).
- **`flex/fragmentation/013` (1000 px)** — Chrome кладёт второй item строки 2 колонкового flex на 10 px ниже, чем Lumen (`Four` в колонке 2 на `y=25`, не 15), когда первый item строки (`Three`) разрезан границей колонки — «лишняя» щель после разрезанного item. Только раскладка, не отрисовка правил.
- **`multicol` `writing-mode` (11400 / 21700 px)** — нужен вертикальный multicol layout (сейчас `vertical_trampoline` игнорирует колонки; весь `multicol_*` — только `HorizontalTb`); по объёму это отдельная задача уровня `grid_vertical.rs`, не срез.
- `subgrid/fragmentation/013` (11000), `multicol/006/007` (вложенный фрагментированный multicol) — без новых данных.
