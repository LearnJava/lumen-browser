# WPT-RUN-17 — результат каждого теста в снимке прогона и потестовое сравнение

**Developer:** P2  
**Ветка:** `p2-wpt-run-17`  
**Размер:** M  
**Крейты:** нет (Python: `tests/wpt/run_corpus.py`, новый `tests/wpt/run_diff.py`, `scripts/quality_report.py`, `docs/wpt/`)

## Зачем

В WPT-RUN-16 (`docs/wpt/pass-rate.md` §«Четвёртая полная цифра», «Оговорки этой цифры»)
два падения категорий получили вердикт «движок», но локализовать их до теста не удалось:

- `quirks` 20.30 → 17.83: минус 3 рефтеста, какие — неизвестно;
- `workers` 199.08 → 197.41: прошедших сабтестов столько же, тестов стало больше, а где именно
  перераспределилось — неизвестно.

Причина: снимок `docs/wpt/runs/<дата>.json` (пишет `run_corpus.py` под `--run-json`, около строки
2135) хранит только агрегаты — `scored.per_category`, `status_counts`, `totals`, `shards`, — а
сырые отчёты wptrunner после прогона удаляются ради места на диске. Каждый следующий полный прогон
упрётся в то же самое: «категория просела» без списка тестов не превращается в баг.

Вторая дыра того же прогона: **7 тестов без вердикта**. wptrunner молча выбрасывает тест, если
браузер не поднялся после рестарта под нехваткой памяти (`Max restarts exceeded` — `css/css-break`
5, `css/css-ui` 1; гонка `init_failed in state RunningState` — `editing` 1): тест есть в
`suite_start`, а `test_start` по нему нет. В снимке такие тесты нигде не видны.

## Что сделать

1. **Файл результатов по каждому тесту рядом со снимком.** При `--run-json docs/wpt/runs/<имя>.json`
   писать ещё `docs/wpt/runs/<имя>.ids.tsv.gz` — по строке на каждый тест знаменателя (68 116 на
   сегодня), сортировка по id: `id`, `тип` (testharness/reftest/…), `статус` (OK/PASS/FAIL/TIMEOUT/
   ERROR/CRASH/NOT-RUN/SKIP/…), `сабтесты прошло/всего`, `балл` (тот же, что идёт в
   `score_reports`), `шард`. Данные уже есть в `load_results()`/`score_reports()` — не считать
   заново. Перед реализацией замерить размер: цель — не больше ~1.5 МБ на прогон в репозитории;
   если gzip-TSV больше — сократить столбцы, а не отказываться от потестовых данных. Снимок `.json`
   получает поле `"ids_file": "<имя>.ids.tsv.gz"`.
2. **Тесты, которые раннер потерял.** Тест из `suite_start`, у которого нет `test_start`, —
   отдельный статус `DROPPED` в `.ids.tsv.gz` и счётчик в `scored.coverage`. При
   `--retry-timeouts`/`--resume` такие тесты перезапускаются так же, как TIMEOUT. В `_selftest`
   добавить случай с синтетическим логом.
3. **`tests/wpt/run_diff.py A.json B.json`** — потестовое сравнение двух снимков с `ids_file`:
   по категориям (и с `--prefix` по подкаталогу) списки «стал хуже» / «стал лучше» с переходом
   статусов (`PASS→FAIL`, `OK→TIMEOUT`, …) и разницей баллов; `--json` для машинного вывода;
   `--min-delta` для отсечения шума. Тесты — `tests/wpt/test_run_diff.py` (stdlib, без сети).
4. **Отчёт качества.** `scripts/quality_report.py`: если у обоих сравниваемых снимков есть
   `ids_file`, в разделе «Просадки» под каждой просевшей категорией выводить до 10 худших тестов из
   `run_diff`. Без `ids_file` — как сейчас.
5. **Восстановить данные WPT-RUN-16, если сырые отчёты ещё на диске.** Поискать `--out-dir`
   прогона 2026-10-22 (по умолчанию `.tmp/wpt-corpus` основного checkout, а также `.tmp/` слотов
   пула, в том числе `p2-work`). Если отчёты есть — `run_corpus.py --aggregate-only --out-dir <dir>`
   с новым кодом и записать `runs/2026-10-22-popups.ids.tsv.gz`; если нет — записать это в
   `docs/wpt/pass-rate.md` одной строкой и не тратить на это время.
6. **Документация:** `docs/wpt/pass-rate.md` (формат снимка, как сравнивать прогоны),
   `docs/commands.md` — команда `run_diff.py`.

## Готово, когда

- Прогон на маленьком префиксе (`run_corpus.py --prefixes quirks,workers --run-json .tmp/a.json`)
  дважды подряд даёт два снимка с `ids_file`; `run_diff.py .tmp/a.json .tmp/b.json` показывает
  потестовые расхождения (или пустой список).
- `python tests/wpt/run_corpus.py --selftest` и `python -m pytest tests/wpt/test_run_diff.py`
  (или их stdlib-аналог) зелёные; `python scripts/test_quality_report.py` зелёный.
- Размер `.ids.tsv.gz` для полного корпуса оценён (по п. 5 или экстраполяцией с префикса) и
  записан в `docs/wpt/pass-rate.md`.
- `quirks` и `workers` из WPT-RUN-16: если п. 5 удался — найденные тесты записаны в
  `docs/wpt/pass-rate.md`, каждый дефект движка заведён `bugs/BUG-NNN-OPEN.md` + строка `BUGS.md`
  + указатель в `STATUS-P3.MD`.

## Не делать

- Не менять скоринг (`score_reports`) — цифры старых снимков должны остаться сопоставимыми.
- Не коммитить сырые отчёты wptrunner (`*.json` из `--out-dir`) — только сжатый TSV.
