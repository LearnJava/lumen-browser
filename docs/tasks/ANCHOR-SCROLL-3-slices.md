## ANCHOR-SCROLL-3-S1: пробел между inline-block и inline-элементом
- **Точка входа:** `crates/engine/layout/src/box_tree/build.rs:1342-1356` (функция `build_box_inner`, ветка `is_inline_content(...)` внутри сборки `InlineBlockRow`). Сейчас `had_ws` дописывает пробел только в `pending.last_mut()`; когда предыдущим соседом был атомарный inline (`pending` пуст, `row_items` не пуст), пробел теряется. Проба: `<div><span style="display:inline-block;width:100px;height:20px"></span> <b>foo</b></div>` даёт `InlineRun` в x=100, а с текстовым узлом ` foo` — в x=120 (ширина пробела учтена через `inline_run_lead_space`, `layout_dispatch/dispatch_box.rs:~1418`).
- **Сделать:** ввести флаг `lead_space = had_ws && pending.is_empty() && pending_escapes.is_empty() && !row_items.is_empty()` до вызова `collect_inline_segments`; после вызова, если в `pending` появился новый сегмент (`pending.len() > before`), и его `style.white_space` не сохраняет пробелы, а текст не начинается с `is_wrap_whitespace`, — вставить в начало текста первого нового сегмента `' '` (`folded_gap` не нужен: перед сегментом перевода строки нет). Именно префикс-пробел, а не `BoxKind::InlineSpace`: ширина `InlineSpace` берётся как `char_width(' ')` и у Ahem даёт 5 px вместо 20, префикс идёт по пути ` foo`, который мерит верно.
- **Не трогать:** ветку атомарного inline (`build.rs:1376`, `InlineSpace` между двумя inline-block), `segment_break.rs`, `inline_wrap`.
- **Готово, когда:** (1) новый unit-тест рядом с `box_tree/tests/anchor_inline.rs` или `empty_inline_rects.rs`: `<div id=d><span style="display:inline-block;width:100px;height:20px"></span> <b>foo</b></div>` — `InlineRun` стоит правее блока ровно на ширину пробела (то же значение, что у варианта ` foo` без `<b>`); (2) `anchor-scroll-001.html`, `anchor-scroll-update-001/002/003/004/007.html` дают PASS в `python tests/wpt/run_report.py --binary <dev-release lumen.exe> --all --root css/css-anchor-position --processes 4` (запуск — `.tmp/runwpt.sh`-рецепт из памяти `project_anchor_scroll2_slice2_2026_10_26`, 4–8 минут; допустимо проверить эти 6 id попиксельно через `reftest_pixdiff.classify` — ожидается `identical`).
- **Гейт:** `cargo clippy -p lumen-layout --all-targets -- -D warnings`; `cargo test -p lumen-layout --profile dev-release anchor_inline` и новый тест; раскладка двигает пиксели — полный `python graphic_tests/run.py --continue-on-fail` и перегенерация эталонов в том же коммите (docs/graphic-tests.md). Обновить `CAPABILITIES.md` (строка про CSS Anchor Positioning) только если меняется формулировка.

## ANCHOR-SCROLL-3-S2: position-area в прокручиваемом содержащем блоке

## ANCHOR-SCROLL-3-S3: position: fixed следует за прокруткой страницы
- **Решение принято здесь:** якорь в потоке документа, цель `position: fixed` — рисовать цель как содержимое страницы (она прокручивается вместе со страницей), а не как viewport-оверлей. Раскладка цели уже даёт позицию в координатах документа при нулевой прокрутке (`apply_anchor_positions_rec` берёт `viewport_rect = (0,0,w,h)` и документный rect якоря), так что при прокрутке 200 цель с `top: anchor(top)` окажется на `anchor_top - 200` — это и ждёт эталон `reference/anchor-scroll-fixedpos-ref.html` (`left:400px; top:100px` при якоре на 300). Вариант «добавить id вьюпорта в `PushScrollLayer`» отвергнут: у страницы нет id-слоя прокрутки, потребовался бы новый механизм рендерера.
- **Точка входа:** layout — `crates/engine/layout/src/box_tree/container_anchor.rs:326 anchor_scroll_for` и `:377 scroll_of` (возвращает `None` при пустом списке скроллеров — нужно вернуть `Some`, если выставлен `page`), `AnchorScroll` в `box_tree/types.rs:~35` (добавить `pub page: bool`), реестр — `anchor.rs:~205 AnchorRegistry` и `collect_anchors_rec` (~345): завести `fixed_anchors: HashSet<NodeId>` — якоря, лежащие внутри `position: fixed` бокса или сами `fixed` (в кадре стека `collect_anchors_rec` носить флаг `in_fixed`, как носится `scrollers`). Paint — `crates/engine/paint/src/display_list/walk.rs:1186` (`let is_fixed = Fixed && !in_fixed_cb`), смежные проверки `Position::Fixed`: `display_list/box_layer.rs:719-726`, `display_list/svg_text_decoration.rs:1184`.
- **Сделать:** (1) `anchor_scroll_for` получает признак «бокс `Position::Fixed` и `fixed_cb == None`» (передать параметром из `apply_anchor_positions_rec`, где `fixed_cb` уже есть) и возвращает `page = true`, когда якорь не в `fixed_anchors`; при `page` список `scrollers` может быть пуст. Цепочки (`chained`, ~строка 280) переносят `page`: если цель следует за якорем, у которого `page`, она тоже `page`. (2) `LayoutBox::anchor_scroll` для `page`-бокса — `Some` с пустым или непустым `scrollers`. (3) В paint: `is_fixed` ложно, если `b.anchor_scroll.as_ref().is_some_and(|a| a.page)` — `BeginFixedLayer`/`EndFixedLayer` не открываются, остальные проверки `Position::Fixed` привести к тому же условию там, где они решают «viewport-оверлей или контент страницы». (4) `refresh_anchor_scroll` (`lib.rs:2092`) и `collect_anchor_scrollers` (`lib.rs:2127`) учитывают пустой `scrollers` без паники.
- **Не трогать:** `_lumen_get_scroll_shift` и `getBoundingClientRect` (геометрия для скриптов fixed-цели остаётся как есть — отдельный остаток), hit-test, `overlay_partition.rs`, компоновщик прокрутки; якорь внутри fixed-поддерева (`anchor-scroll-fixedpos-002/003/004`) должен остаться viewport-оверлеем.
- **Готово, когда:** (1) unit-тест в `box_tree/tests/anchor_scroll.rs`: `<div id=a style="margin:300px;width:100px;height:100px;anchor-name:--a"></div><div id=t style="position:fixed;position-anchor:--a;left:anchor(right);top:anchor(top)"></div>` — у `#t` `anchor_scroll.page == true`; тот же `#t` при якоре с `position: fixed` — `anchor_scroll` без `page`; (2) unit-тест в `crates/engine/paint/src/display_list/tests/` (рядом с существующими на anchor-scroll): список команд для первого случая не содержит `BeginFixedLayer`, для второго содержит; (3) `anchor-scroll-fixedpos.html` и `anchor-scroll-fixedpos-nested-001.html` — PASS в `run_report.py --all --root css/css-anchor-position` (`-nested-002` — по возможности, не обязательно); `anchor-scroll-fixedpos-002/003/004` и все `anchor-scroll-00x` без регрессий.
