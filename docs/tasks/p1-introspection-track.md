# Дорожка DEVX-7…16 — интроспекция движка (provenance → инварианты → explain)

Бриф для ROADMAP.md-задач `DEVX-7`…`DEVX-16` (Фаза 3, родитель `DEVX`).
Владелец — **P1** (движковые срезы: layout/paint/driver), кроме `DEVX-14`/`DEVX-16`,
которые может взять **P3** (механическая выдача + флаги).

Решения, которые эта дорожка реализует:
[ADR-024](../decisions/ADR-024-introspection-api-levels.md) (уровни API) и
[ADR-025](../decisions/ADR-025-identity-propagation.md) (контракт идентичности).
**Оба приняты 2026-07-30** — вопросов, требующих решения пользователя, не осталось.
Из ADR-024 для дорожки следуют два жёстких правила: (1) escape hatch
`--mcp-allow-anonymous` **не существует** — токен обязателен всегда; (2) уровня L2
до v1.0 **нет** — каждый новый wire-инструмент дорожки идёт как L1 с `x-`-префиксом
и `"experimental": true`. Уже существующие непрефиксные инструменты
(`navigate`/`wait`/`query`/`eval`/`screenshot`) не переименовываются — это
непромотированный L1 с legacy-именами.

Параллельная и независимая дорожка измерения — `WPT-RUN`,
[`p2-wpt-runner-throughput.md`](p2-wpt-runner-throughput.md). Они не конкурируют
за файлы и идут одновременно.

---

## Зачем

Обсуждение 2026-07-30 (четыре круга, два внешних ревьюера) установило пять
фактов, проверенных по коду. Дорожка следует из них, а не из списка желаемых фич.

1. **Интроспекция в Lumen односторонняя.** Дампы всех стадий, профиль по фазам,
   детерминизм, типизированные снимки driver-API — всё есть
   ([`docs/automation.md`](../automation.md)). Чего нет — обратного хода: мутация
   DOM не вызывает релейаут (BUG-221), поэтому цикла
   «изменил → пересчитал → сравнил» не существует ни на одном пути.
2. **Идентичности узла в display list нет.** `DisplayCommand` — ~40 вариантов
   чистой геометрии; `node_id` только у `LazyImageSlot`/canvas, на inline-путях
   заглушка `0`. Вопросы «была ли создана команда для этого узла», «отбракован ли
   он клипом», «в каком слое» неотвечаемы.
3. **Идентичность в layout уже перегружена тремя способами** — анонимные боксы
   переиспользуют id родителя, сентинел «нет DOM-происхождения» совпадает с
   корнем документа, псевдоэлементы вообще без id. Детали и ссылки на строки — в
   [ADR-025](../decisions/ADR-025-identity-propagation.md). Следствие: наивный
   provenance будет **врать**, а не воздерживаться.
4. **Инвариантного слоя нет** — 2 `debug_assert` и 14 проверок на NaN/∞ на весь
   крейт `lumen-layout`. Ошибки обнаруживаются на три стадии позже места, где
   возникли.
5. **Карта багов — это карта измерений, а не карта качества.** 429 багов в
   `BUGS.md`: js 115, layout 134, paint 123, css-parser 13. Но категория `css/`
   WPT (34607 id — крупнейшая поверхность реализации) прогнана на **1.1%**, и на
   этой пробе падает половина сабтестов базового box-model CSS1/CSS2. Низкий счёт
   багов в style означает «не измеряли», а не «работает».

Из (5) следует, что дорожку диагностики нельзя делать вместо дорожки измерения:
инструмент, чей ответ на любом сайте — «размер 0×0 из-за нашего бага в flex»,
не отличает один баг от двадцати. Из (3) следует порядок внутри дорожки:
контракт идентичности идёт раньше всего остального.

## Порядок и зависимости

```
ADR-024  (уровни API, решение пользователя по Q1/Q2)
ADR-025  (контракт идентичности, ревью)
   │
   ├─→ DEVX-7   provenance в display list ──┬─→ DEVX-8b  paint-инварианты
   │                                        ├─→ DEVX-10  explain_element
   │                                        ├─→ DEVX-12  скоупинг на поддерево
   │                                        └─→ DEVX-13  структурный дифф
   │
   └─→ DEVX-8a  геометрия/style-инварианты ─────→ DEVX-11 explain_page
                                                    ↑        ↑
                                          DEVX-10 ──┘   DEVX-13 (общий ратчет)

DEVX-9   релейаут после мутации   — независим, третьим по значимости
DEVX-14  MCP-ресурсы             — независим, берётся в любой момент
DEVX-15  аутентификация MCP/BiDi — независим, гейт релиза
DEVX-16  детерминизм до JS       — независим, предпосылка для записи по кадрам
```

Рекомендуемый старт: **`DEVX-7` и `DEVX-8a` параллельно** (разные крейты, разные
файлы), затем `DEVX-8b`, затем `DEVX-9`. `DEVX-14`/`15`/`16` можно брать в любой
момент — они ни от чего не зависят.

**Почему 7 и 8 взаимно проверяют друг друга.** Самые ценные инварианты
(«каждая команда принадлежит ровно одному span», «порядок команд согласован со
stacking-деревом») невозможно сформулировать без provenance — значит `DEVX-8b`
идёт после `DEVX-7`. И наоборот: корректность provenance проверяется именно
инвариантом — значит `DEVX-8b` служит приёмкой `DEVX-7`. Поэтому `DEVX-8`
расщеплена: `8a` без зависимостей, `8b` — приёмка `DEVX-7`.

**Почему `DEVX-9` не первым.** В первом круге обсуждения релейаут стоял первым,
потому что разблокирует итеративные сценарии (AI-дизайнер, авто-фикс CSS,
итеративная визуальная регрессия). Эти сценарии в том же обсуждении сознательно
отложены — значит и задача, которая их разблокирует, теряет приоритет. Но она не
«только для AI»: у неё есть неотложенный потребитель, см. DoD ниже.

## DEVX-7: provenance в display list (L, P1)

**Прогресс (P1, 2026-08-02):** пункты 1–3 состава ниже закрыты —
`BoxOrigin`/`BoxRole` в `lumen-layout` (`box_tree.rs`), заполнены во всех
продакшн- и тестовых конструкторах `LayoutBox` по всему workspace (box_tree.rs,
incremental.rs, mathml.rs, ruby.rs, shell/main.rs, shell/forms.rs,
shell/animation_scheduler.rs + тестовые фикстуры anchor.rs/masonry.rs/table.rs/
text_iter.rs/selection.rs/scroll_timeline.rs), сентинел `NodeId::from_index(0)`
для «нет DOM-происхождения» убран (заменён на `origin.node: None`) на всех трёх
найденных production-сайтах (box_tree.rs, mathml.rs, ruby.rs — исходный аудит
ADR-025 нашёл только box_tree.rs). `graft_geometry`'s identity-гейт учитывает
`origin.role` (два анонимных бокса на одном узле больше не грейфтятся друг в
друга). Уточнение по ADR-025 §1 (разрешено правкой без нового ADR): `BoxRole`
не включает отдельный `TableFixup` — аудит `table.rs` не нашёл ни одного сайта
синтеза анонимных table-боксов (`_ => {}` в `collect_table_structure` молча
игнорирует orphan-контент вместо генерации fixup-бокса; это отдельная, не
задокументированная ранее находка про сам layout, не про provenance — не
заведена багом в этом заходе, т.к. вне скоупа DEVX-7). `PseudoKind` расширен
`Before`/`After`/`FirstLine`/`Marker` (было только `None`/`FirstLetter`) —
переиспользуется как `BoxRole::Pseudo(PseudoKind)` тег, `anon_inline_run` теперь
принимает явный `role: BoxRole` параметр вместо одного жёстко зашитого
значения. Гейт: `dump_golden.py` пустой дифф (6 страниц × 2 дампа, включая
table/grid/flex/transform) — чисто аддитивное поле, ничем ещё не читается,
полный графический прогон признан избыточным для этого коммита (обоснование в
теле коммита).

**Остаётся (пункт 4):** `ProvenanceIndex`/`ProvenanceSpan` рядом с
`DisplayList` в `lumen-paint`. Важная находка для следующего захода:
**`DisplayList` — это `pub type DisplayList = Vec<DisplayCommand>` (алиас, не
структура)** — код ADR-025 §3 (`struct ProvenanceIndex` «рядом» с `DisplayList`)
предполагает структуру с полем `commands`, которой не существует. Варианты:
(а) превратить `DisplayList` в структуру с `Deref<Target=Vec<DisplayCommand>>`
(минимальный блэст-радиус, но `DisplayList::new()`/прямые присваивания из `Vec`
по всему workspace потребуют правки — грубая оценка ~15 сайтов вне `display_list.rs`:
shell/main.rs, shell/forms.rs, shell/animation_scheduler.rs, тесты driver/paint);
(б) вернуть `(DisplayList, ProvenanceIndex)` кортежем из точек входа. Второй
открытый вопрос: реальный рендер-путь шелла — **не** простой `walk`
(`build_display_list`/`_with_selection`/`_with_anim`), а
`fill_buckets`/`build_display_list_ordered*` (stacking-context bucket-сборка,
`main.rs:6146`/`15983`/`16161`) — четырёхфазная пересборка `ScBucket{pre,
root_bg, contents, post}` в финальный список делает in-flight span-tracking
заметно сложнее, чем в линейном `walk`. Разбирать оба вопроса вместе, не
начинать с одного `walk`-пути и не подменять реальный рендер-путь.

Реализует §3 [ADR-025](../decisions/ADR-025-identity-propagation.md).

**Зависит от:** ADR-025 принят. Включает расшивку перегруженной идентичности —
именно она делает размер L, а не M.

**Состав:**
1. `BoxOrigin { node: Option<NodeId>, role: BoxRole }` в `lumen-layout`; заполнение
   во всех конструкторах боксов `box_tree.rs`, включая `anon_inline_run`,
   `anon_inline_block_row` и пути table-fixup.
2. Убрать сентинел `NodeId::from_index(0)` как обозначение «нет DOM-происхождения»
   (коллизия с корнем документа) — заменить на `None`.
3. Сохранение origin в `incremental::graft_geometry` и во всех путях, клонирующих
   боксы.
4. `ProvenanceIndex` рядом с `DisplayList` — побочная таблица span'ов, парные
   маркеры открытия/закрытия в эмиттере по образцу уже существующего
   `PushClipRect`/`PopClip`. **`DisplayCommand` не меняется.**

**DoD:**
- `explain`-запрос «какие команды породил этот узел» отвечается для элементных,
  анонимных и псевдо-боксов, и различает их между собой.
- Ни один вариант `DisplayCommand` не изменил размер (проверяется
  `size_of` — тест).
- Существующий `node_id` у `LazyImageSlot`/canvas не тронут (у него другой
  потребитель — реестр битмапов шелла `canvas:{node_id}`).

**Гейт:** пункт 4 (побочная таблица) display-list-нейтрален — доказывается пустым
диффом `python graphic_tests/dump_golden.py`. Пункты 1–3 трогают конструирование
боксов и **могут двигать пиксели** (анонимные боксы, `::first-letter`) → полный
20-минутный графический прогон + перегенерация детерминированных CPU-эталонов
(`SAVE_CPU_SNAPSHOTS=1 cargo test -p lumen-driver --features cpu-render cases::snapshot_cpu`)
в том же коммите. Разделять пункты по коммитам можно и полезно: 4 первым, с
дешёвым гейтом.

**Ловушка:** соблазн сделать `BoxOrigin` заменой `LayoutBox.node` целиком. Не
делать — `node` нужен горячим путям layout для «чей стиль здесь применяется», и
его аудит вынесен из скоупа осознанно (ADR-025 §Consequences).

## DEVX-8a: геометрические и style-инварианты (M, P1/P3)

**Зависит от:** ничего. Стартует немедленно, параллельно `DEVX-7`.

**Состав** (только `debug_assert!`/`cfg(debug_assertions)`, нулевая стоимость в
release):
- Геометрия: rect ребёнка ⊆ rect родителя, если нет `overflow`/позиционирования;
  нет NaN/∞ ни в одной координате или размере.
- После style: не осталось неразрешённых custom properties (`var()`).
- После layout: у каждого бокса есть containing block.
- DOM: нет циклов.
- `PropertyTrees`: каждый `ClipNode` достижим от корня.

**DoD:** все инварианты включены в debug-сборке; `cargo test -p lumen-layout` и
`-p lumen-paint` зелёные; ни один инвариант не срабатывает на наборе страниц
`graphic_tests/` и `samples/` — а если срабатывает, это баг, и он заводится в
`BUGS.md`, а инвариант **не ослабляется** под него.

**Гейт:** `scripts/scoped-test.sh` (изменения только в debug-путях, пиксели
двигать не может).

**Ловушка:** инвариант, который срабатывает на живой странице, — это находка, а
не помеха. Ослаблять условие, чтобы «прогон стал зелёным», запрещено: то же
правило, что для порогов графических тестов и для вендоренных WPT-тестов.

## DEVX-8b: paint-инварианты поверх provenance (S, P1)

**Зависит от:** `DEVX-7`. Является его приёмкой.

**Состав:** инварианты из §4 [ADR-025](../decisions/ADR-025-identity-propagation.md) —
каждая команда внутри ровно одного span; origin каждого span разрешается;
вложенность span'ов сбалансирована и согласована с глубиной клип-стека; у каждого
бокса с видимым фоном/границей есть хотя бы один span; порядок команд внутри
stacking-контекста согласован со stacking-деревом.

**DoD:** те же правила, что у `DEVX-8a`. Дополнительно: инвариант «у бокса с
видимым фоном есть span» прогнан по всему набору `graphic_tests/` — это и есть
доказательство, что provenance не врёт.

## DEVX-9: релейаут после мутации в `InProcessSession` (M, P1)

Закрывает цикл `mutate → style → layout → paint → snapshot` на headless-пути
(BUG-221).

**Зависит от:** ничего.

**Состав:** после мутации DOM через `click`/`type_text`/`eval` в
`crates/driver/src/session.rs` пересчитывать layout, чтобы `layout_snapshot`,
`layout_box_by_selector` и `screenshot` отражали текущее состояние, а не состояние
на момент `navigate()`.

**DoD:** тест, который через `eval` меняет геометрию элемента и видит новое
значение в `layout_box_by_selector` и на CPU-скриншоте.

**Неотложенный потребитель (не AI-сценарий):** детерминированный CPU-гейт
(`cases::snapshot_cpu`, `cases::scripted_render`) сейчас гоняет инлайновые скрипты
до layout, но геометрию после мутации DOM не пересчитывает — страницы, чьи скрипты
меняют размеры, этим гейтом не покрываются в принципе. `DEVX-9` расширяет самый
дешёвый гейт проекта (без GPU, без Edge, кроссплатформенный).

**Гейт:** может сдвинуть CPU-эталоны на скриптованных страницах → перегенерация
в том же коммите, с глазной проверкой, что новые PNG корректны, а не мусор.

## DEVX-10: `explain_element(selector)` (S, P1)

**Зависит от:** `DEVX-7`.

**Состав:** причинная цепочка одним запросом —
`есть в DOM → стили применились → попал в layout → размер → stacking-контекст →
порождены ли команды → отбракован ли клипом → в каком слое`. Первые четыре звена
уже отвечаются существующим driver-API (`computed_style_snapshot`,
`layout_box_by_selector`), последние три — только через `ProvenanceIndex`.

Эвристическая подсказка о причине (например «родитель `display:flex`,
`min-height:auto` → схлопнулся») выдаётся **отдельным полем и помечается как
эвристика**. Она не выводится из диффа и не должна выглядеть как факт.

**Уровень по ADR-024:** L1, имя `x-explain-element`.

**DoD:** на подготовленной странице с элементом `0×0` внутри `overflow:hidden`
инструмент показывает, на каком именно звене цепочка обрывается; на элементе
внутри анонимного бокса не приписывает его paint родителю.

## DEVX-11: `explain_page()` (S, P1)

**Зависит от:** `DEVX-8a`, `DEVX-10`. Смыкается с `DEVX-13`.

**Состав:** агрегат по странице — срабатывания инвариантов по категориям
**плюс телеметрия**: число боксов, анонимных боксов, элементов с overflow,
релейаутов, команд, максимальная глубина клип-стека, время по фазам.

**Проектное ограничение (важно):** счётчики машинно-читаемые и предназначены для
**сравнения**, а не для чтения человеком. «17 overflow» в отрыве не значит ничего;
смысл появляется в двух режимах — дифф против предыдущего прогона той же страницы
и профиль по корпусу. Поэтому вывод — стабильный набор именованных счётчиков в
JSON, человеческий отчёт — производная над ним. Это делает `explain_page` и
`DEVX-13` одним ратчетом: дифф деревьев и дифф счётчиков.

Часть счётчиков уже считается: `box_tree.rs` носит поля с наносекундами
`extract_clean_subtrees` и прочую инкрементальную бухгалтерию — их надо выставить,
а не считать заново.

**Уровень по ADR-024:** L1, имя `x-explain-page`.

## DEVX-12: скоупинг операций на поддерево (M, P1)

**Зависит от:** `DEVX-7`, `DEVX-9`.

**Состав:** `query`/`eval`/`screenshot`/дамп display list/релейаут в границах
селектора, а не всей страницы. Частичный релейаут поддерева — это уже влитая

**Граница со приостановленной задачей:** BUG-341 (инкрементальный restyle)
остановлен решением пользователя 2026-07-28 и **эта задача его не возобновляет**.
Использовать влитую часть — можно. Если выяснится, что нужного не хватает, это
упирается в приостановленную задачу → остановиться и спросить пользователя, а не
доделывать BUG-341 под видом `DEVX-12`.

**Уровень по ADR-024:** L1.

данные только через `InProcessSession`, для живого окна это заглушка — гэп
SDC-2 MVP, зафиксирован в `docs/automation.md`).

**Уровень по ADR-024:** L1 (`x-` префикс обязателен).

## DEVX-15: аутентификация и модель доступа MCP/BiDi (M, P1/P3)

Реализует §Access model [ADR-024](../decisions/ADR-024-introspection-api-levels.md).
**Гейт релиза, а не гейт дорожки.**

**Состав:** токен обязателен по умолчанию (автогенерация на запуск, печать в
stderr рядом со строкой порта, приём как параметр MCP `initialize` и как
capability BiDi `session.new`); bind остаётся loopback-only. **Escape hatch
`--mcp-allow-anonymous` не делать** — решение пользователя 2026-07-30 (Q1 в
ADR-024): все потребители этих портов сегодня наши, поэтому строгость стоит
одноразовой правки, а флаг удобства пережил бы удобство. Заводить его «только для
CI» нельзя без нового ADR.

**Почему это здесь:** сейчас `--mcp-port`/`--mcp-live-port`/`--bidi-port`/
`--ipc-server` слушают `127.0.0.1` без аутентификации
(`crates/mcp/src/main.rs:31`) — любой локальный процесс может водить браузер,
читать DOM, снимать скриншоты и исполнять JS. Для браузера, чьё заявленное
отличие — приватность, это нельзя нести в релиз вместе с богатой интроспекцией.

**Ловушка:** правок нужно ровно столько же в нашем собственном тулинге —
`graphic_tests/run.py`, `scripts/*_perf.py`, `tests/wpt/*`. Считать их частью
задачи, а не follow-up'ом.

## DEVX-16: довести детерминизм до JS-рантайма (S, P3)

**Зависит от:** ничего.

**Состав:** `--rng-seed` и `--monotonic-clock` сейчас разбираются в `DetConfig`,
но до JS-рантайма не доходят — сид всегда выводится из хеша URL, значение флага
игнорируется (зафиксировано в `docs/automation.md` §CLI flags).

**Почему это важно для дорожки:** без полного детерминизма запись внутреннего
состояния по кадрам (обсуждалась и отложена) не даёт воспроизводимости, ради
которой затевается. `DEVX-16` — её предпосылка, а не самостоятельная фича.

## Что сознательно отложено (и почему — не заводить как задачи)

| Идея | Почему отложена |
|---|---|
| Запись внутреннего состояния по кадрам (DOM/style/layout/paint на кадр) | До `DEVX-16` не даёт воспроизводимости, ради которой затевается; консервирует структуры движка, который переписывается (снос `rquickjs`). |
| Кросс-движковый пробник (DOM / `getComputedStyle` / `getBoundingClientRect` против Chromium) | После `WPT-RUN-3`. WPT уже содержит **ожидаемый** ответ из спеки, а кросс-движковый дифф даёт только «две реализации расходятся, кто прав — неизвестно». Заводить сейчас — создавать дублирующий источник истины раньше основного. Сравнивать внутренние деревья (layout tree, display list) между движками бессмысленно: нет общего определения анонимных боксов, фрагментации и назначения слоёв. Сравнимы только специфицированные API — эти три. |
| AI-дизайнер, авто-фикс CSS, итеративная оптимизация по рендеру | Надстройка над `DEVX-9` и над корректностью движка. Пока падает половина базового box-model, агент будет оптимизировать под наши собственные баги. |
| Новый IR `RenderArtifact` между layout и paint | Разобрано в [ADR-025](../decisions/ADR-025-identity-propagation.md) §Alternatives: побочная таблица даёт то же свойство развязки без переписывания эмиттера в файле на 18605 строк. |

## Как этой дорожкой пользоваться из новой сессии

1. Прочитать оба ADR — [024](../decisions/ADR-024-introspection-api-levels.md) и
   [025](../decisions/ADR-025-identity-propagation.md). Оба `Accepted`, спрашивать
   ничего не нужно. Два правила, которые нарушаются по невнимательности: токен
   без исключений (никакого `--mcp-allow-anonymous`, даже «только для CI» — это
   требует нового ADR) и `x-`-префикс на каждом новом wire-инструменте.
2. Взять первую строку `STATUS-P1.md`, как обычно, сверху вниз. Порядок в этом
   брифе — про зависимости внутри дорожки, он не даёт права обойти строки выше в
   `STATUS-P1.md`.
   Pointer-строки `DEVX-7…16` в `STATUS-P1.md` идут **в порядке зависимостей**
   (`ROADMAP.md:665`…`675` = `DEVX-7`, `8a`, `8b`, `9`, `10`, `11`, `12`, `13`,
   `14`, `15`, `16`), поэтому обычное правило «строго сверху вниз» само выводит
   на разблокированную задачу. Если строка сверху заблокирована незакрытой
   зависимостью — сказать об этом и спросить, а не молча спуститься ниже.
3. Перед первым Edit — проверить ветку и работать в слоте пула
   (`bash scripts/worktree-pool.sh p1-work p1-devx-NN`).
4. Гейт выбирать по правилу из `CLAUDE.md`: всё, что может двигать пиксели, —
   полный графический прогон + перегенерация CPU-эталонов; всё остальное —
   `scripts/scoped-test.sh` + пустой дифф `dump_golden.py` как доказательство
   нейтральности.
5. Уровень по ADR-024 выбирается **в том же коммите**, что и инструмент. Новый
   wire-инструмент без `x-`-префикса и без `"experimental": true` — ошибка ревью.
