# WASM-V8-NATIVE — срезы
Задача: убрать самописный MVP-интерпретатор WebAssembly и работать на родной реализации V8. Сделано до начала: разведка WPT-WASM-SCOUT (`docs/wpt-vendor-notes/wasm.md`, кластеры W1-W3), эксперимент без шима (не влит, diff в `.tmp/wasm-native-experiment.diff` слота `p2-work`) дал 60.93 %, `core/*` 99.99 % сабтестов. Предусловие — [BUG-1752](bugs/BUG-1752-OPEN.md) (JS-поток не прокачивает очередь задач платформы V8: без него асинхронный `WebAssembly.compile`/`instantiate` не резолвится, 311 из 612 id в TIMEOUT). Срезы S1-S3 идут строго по порядку; между S1 и S2 стриминг временно отсутствует (родной V8 не заводит `compileStreaming` без embedder-колбэка), поэтому S2 берут сразу следом.

Что уже верно в коде: V8 из `rusty_v8` 150.1.0 даёт `Isolate::set_wasm_streaming_callback` (`isolate.rs:1851`, колбэк получает `source: Local<Value>` и `WasmStreaming<false>` с `on_bytes_received`/`finish`/`abort`/`set_url`, `wasm.rs`) и `Isolate::set_allow_wasm_code_generation_callback` (`isolate.rs:1551`, тип `AllowWasmCodeGenerationCallback = unsafe extern "C" fn(Local<Context>, Local<String>) -> bool`). CSP `script-src` на `eval`/wasm в движке не исполняется вовсе (`UnsafeEval` только разбирается в `crates/network/src/csp.rs:59`), поэтому колбэк возвращает `true` без проверки политики.

## WASM-V8-NATIVE-S1: родной WebAssembly вместо шима
- **Точка входа:** `crates/js/src/v8_runtime.rs:1256` (`install_v8!(webassembly::install_webassembly_bindings_v8)`), `crates/js/src/worker.rs:524` (тот же вызов в общей функции воркеров, комментарий BUG-1078 выше него), `crates/js/src/v8_runtime/thread.rs:79` (рядом с `codegen_hook::install`), `crates/js/src/lib.rs:106` (`pub mod webassembly`).
- **Сделать:** (1) убрать оба вызова установки и файл `webassembly.rs` целиком (шим на JS-строке, натив `__lumen_wasm_*`, его юнит-тесты на `webassembly.rs:683`); `pub mod wasm` (`lib.rs:107`) и `clear_registry` в `thread.rs` пока оставить — это работа S3, публичный модуль не даёт dead-code. (2) В `thread.rs` после `codegen_hook::install` вызвать `inner.isolate.set_allow_wasm_code_generation_callback(f)` с `unsafe extern "C" fn(Local<Context>, Local<String>) -> bool { true }`: без колбэка V8 для wasm смотрит на `Context::set_allow_generation_from_strings(false)`, которое `codegen_hook` выставляет всегда, и закрывает кодоген. (3) Заменить комментарий BUG-1078 в `worker.rs` на пометку «родной глобал V8, стриминг — S2». (4) Тест `v8_worker_globals_have_wasm_streaming` (`worker.rs:2607`) на время S1 сузить до `compile`/`instantiate`/`validate` (стриминговые проверки вернёт S2). (5) Новый файл тестов `crates/js/src/dom/tests/v8_wasm_native.rs` (подключить в `dom/tests/mod.rs`, образец — `v8_cssanim_model.rs`): синхронные `new WebAssembly.Module(bytes)` с `anyref`-обёрткой, SIMD-модуль, `WebAssembly.validate`, `new WebAssembly.Instance`, вызов экспорта; тот же вызов с включённым `require-trusted-types-for 'script'` (образец — `dom/tests/v8_trusted_types.rs:806`).
- **Не трогать:** `crates/js/src/wasm/`, `structuredClone` для `Module`/`Memory` (задача WASM-CLONE), ESM-интеграцию wasm (WASM-ESM).
- **Готово, когда:** тесты `v8_wasm_native` зелёные; `python tests/wpt/run_corpus.py --categories wasm --prefixes wasm/core --processes 8` (venv `tests/wpt/.venv`, бинарь `dev-release`) — нет TIMEOUT и ≥ 99 % сабтестов; в `wasm/jsapi` не меньше 108 баллов из 110 (по эксперименту).
- **Гейт:** `cargo clippy -p lumen-js --all-targets --features v8-backend -- -D warnings`; `cargo test -p lumen-js --features v8-backend v8_wasm_native`; WPT-команда выше (собрать `dev-release`).
- **Зависит от:** BUG-1752 (без прокачки очереди платформы асинхронные тесты `wasm/core` висят; синхронные юнит-тесты S1 от него не зависят).

## WASM-V8-NATIVE-S2: нативный стриминг
- **Точка входа:** `crates/js/src/v8_runtime/thread.rs:~36` (создание изолята и `v8::Context::new` — колбэк обязан быть выставлен до создания контекста, иначе V8 не заведёт `compileStreaming`/`instantiateStreaming`), новый файл `crates/js/src/v8_runtime/wasm_streaming.rs` (подключить в `v8_runtime.rs` рядом с `mod codegen_hook;` на строке 82), место установки JS-помощника — то же, где S1 убрал шим (`v8_runtime.rs:1256` и `worker.rs:524`).
- **Сделать (решение принято здесь):** колбэк `fn(scope, source, WasmStreaming<false>)` кладёт стрим в `thread_local! HashMap<u32, WasmStreaming<false>>` под новым id, достаёт глобал `__lumen_wasm_stream_start` и вызывает его с `(source, id)`; нет функции — `abort` с `TypeError`. JS-помощник (константа-строка, вычисляется в окне и во всех воркерах): `Promise.resolve(source).then(resp => …)` проверяет `resp instanceof Response` (иначе `TypeError`), `resp.type` не `opaque`/`opaqueredirect`, `Content-Type` побайтово-регистронезависимо равен `application/wasm` (заголовок с параметрами — `TypeError`), `resp.ok`, `!resp.bodyUsed`; затем `resp.arrayBuffer()` одним куском и `__lumen_wasm_stream_finish(id, buf)`; любая ошибка (включая отклонение исходного промиса) — `__lumen_wasm_stream_abort(id, err)`. Нативы регистрируются через `register_native_scoped` (образец — удалённый в S1 `__lumen_wasm_instantiate`, в git истории): `finish` берёт `ArrayBuffer`, вызывает `on_bytes_received` и `finish`, `abort` зовёт `abort(Some(err))`; `set_url(resp.url)` перед байтами. Потоковое чтение чанками не делаем (один `arrayBuffer()`).
- **Не трогать:** `fetch`/`Response` шимы; `webapi/esm-integration` (W5).
- **Готово, когда:** `python tests/wpt/run_corpus.py --categories wasm --prefixes wasm/webapi --processes 8` — `webapi/contenttype.any.html` и `origin.sub.any.html` все сабтесты PASS; `instantiateStreaming.any.html`, `instantiateStreaming-bad-imports`, `invalid-args`, `invalid-code`, `abort`, `rejected-arg`, `body`, `empty-body`, `status`, `modified-contenttype` не хуже, чем у шима (снять базу до начала: `--prefixes wasm/webapi` на коммите S1 даст «минус 27.6 п.п.» из разведки, поэтому сравнивать со значениями разведки: 44 id webapi кроме esm — OK); `v8_worker_globals_have_wasm_streaming` снова проверяет пять функций, включая `compileStreaming`/`instantiateStreaming`; юнит-тест: `WebAssembly.compileStreaming(new Response(bytes, {headers: {'Content-Type': 'application/wasm;'}}))` отклоняется `TypeError`, с `application/wasm` — резолвится `Module` (асинхронные тесты по образцу `tc39_proposals.rs:1135`).
- **Гейт:** `cargo clippy -p lumen-js --all-targets --features v8-backend -- -D warnings`; `cargo test -p lumen-js --features v8-backend wasm_stream`; WPT-команда выше.
- **Зависит от:** WASM-V8-NATIVE-S1 (шим удалён) и BUG-1752 (резолв промисов после компиляции).

## WASM-V8-NATIVE-S3: удалить интерпретатор, документы

- **Сделать:** удалить каталог, `pub mod wasm`, вызов `clear_registry`, мёртвые помощники `v8_compat.rs`; убрать зависимости `crates/js/Cargo.toml`, которыми пользовался только интерпретатор (проверить `cargo clippy`/`grep`, при сомнении оставить). Тесты интерпретатора заменены тестами S1/S2; добавить 2-3 нативных теста на то, что интерпретатор давал (вызов экспорта, `Memory.grow`, импорт функции хоста). `CAPABILITIES.md`: строка WebAssembly — родной V8 (GC, EH, memory64, multi-memory, SIMD, JSPI, js-string builtins), стриминг через embedder-колбэк; `docs/wpt-status.md` — новый процент по `wasm`; в `docs/wpt-vendor-notes/wasm.md` отметить кластеры W1-W3 закрытыми.
