# TEST-10 — сводный отчёт качества (quality_report.py)

Дорожка TEST. Владелец — P2. Только Python-тулинг и docs, движок не трогать.

## Зачем

Чтобы ответить «стал ли браузер лучше за неделю», сейчас надо вручную смотреть четыре места:
`docs/wpt-status.md`, `graphic_tests/results/*.json`, `BUGS.md`, `docs/perf/journal.md`.
Нужен один генерируемый отчёт с дельтами к прошлому прогону. Пользователь читает его сверху вниз:
первая строка — общий тренд, колонка Δ — что сломали/починили, раздел «Просадки» — регрессии.

## Что сделать

1. Новый скрипт `scripts/quality_report.py` (без новых зависимостей, stdlib only). Источники:
   - **WPT**: самый свежий и предыдущий агрегат `docs/wpt/runs/*.json` (пишет
     `tests/wpt/run_corpus.py --run-json`). Счётчики строго раздельно: PASS / FAIL / CRASH /
     TIMEOUT / UNSUPPORTED / SKIPPED — незапущенное не считать пройденным. Группировка по
     верхнеуровневой категории, сверх неё — свод по подсистемам: HTML-парсер (`html/syntax`),
     DOM (`dom`), CSS layout (`css`), рендеринг (reftests), сеть (`fetch`, `xhr`, `cors`),
     остальные API.
   - **graphic_tests**: два свежих `graphic_tests/results/*.json` (ключи `timestamp`, `git`,
     `summary`, `tests`) — pass rate, список тестов, сменивших статус.
   - **BUGS.md**: открытые BUG-NNN по подсистемам; топ-5 багов по числу заблокированных
     WPT-тестов (связь тест→баг брать из таблиц `docs/wpt-status.md` и колонки `bugs`
     в `ROADMAP.md`). Читать `BUGS.md` только с `newline=''` (CLAUDE.md §gotchas).
2. Выход: перезаписываемый `docs/quality-report.md` (дата, коммит из поля `git`, итоговая строка,
   таблица подсистем с Δ, раздел «Просадки с прошлого отчёта», «Топ-5 багов», блок graphic_tests)
   плюс машиночитаемый срез `docs/quality/runs/<YYYYMMDD-HHMMSS>.json` для истории.
3. Если какого-то источника нет (нет второго прогона — нет дельты), отчёт генерируется с пометкой
   `n/a`, а не падает.
4. `--check`-режим: только печатает итоговую строку в stdout (для ручного запуска после мержа).
5. Документация: раздел в `docs/graphic-tests.md` или новый `docs/quality-report-howto.md`
   (3–5 строк: когда запускать, что читать первым) + ссылка из `docs/INDEX.md`.

## Done when

- `python scripts/quality_report.py` на текущих данных репозитория создаёт валидный
  `docs/quality-report.md` и JSON-срез; повторный запуск идемпотентен.
- Счётчики сходятся с `summary` исходных JSON (проверить вручную на одном прогоне).
- UNSUPPORTED/SKIPPED нигде не попадают в числитель PASS.

## Не трогать

- Сами раннеры (`run_corpus.py`, `graphic_tests/run.py`) — только читать их выход.
- `docs/wpt-status.md` — он остаётся ручным журналом назначений, отчёт его не перезаписывает.
