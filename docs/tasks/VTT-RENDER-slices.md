# VTT-RENDER — срезы
Сейчас cue рисует самодельный оверлей `crates/shell/src/tracks.rs::build_cue_overlay` (`:116`): шрифт Inter, кегль 6 % высоты, свой фон; он дописывается в display list только в обработчике кадра окна (`crates/shell/src/app/window_event/redraw_requested.rs:1128-1190`), поэтому `--screenshot` и `--ipc-server` его не видят (BUG-1748). Данные: Rust-разбор `parse_vtt` (`crates/engine/dom/src/vtt.rs:49`) хранит из настроек только пять сырых строк (`VttCueSettings`, `:12`), текст cue — плоская строка (`strip_cue_markup`, `:247`); JS-объект cue (`crates/js/src/shim/video_element.js:286`) настройки не получает из файла вовсе (BUG-902 п.2). Готового: UA-теневой корень `<video>` без слотов (`crates/engine/dom/src/lib.rs:1649` `attach_ua_shadow_root`, `:327` `UaShadowKind::NoSlot`), прецедент ролей узлов UA-тени (`ua_slot_role` `:1690`, `apply_ua_slot` в `crates/engine/layout/src/style/ua.rs:916`), единицы `lh` и `%` в layout, `writing-mode`.

Решения, принятые в брифе. (1) Архитектура: cue — настоящие DOM-узлы в закрытой UA-тени `<video>` (как в Chromium), а не оверлей поверх display list: тогда окно, `--screenshot`, `--ipc-server`, CPU-растр и `--dump-display-list` видят их одним и тем же кодом layout/paint, а `::cue` (P4) получит узлы для привязки. Единственный писатель — JS-шим: он один знает актуальные cue (в том числе созданные скриптом), поэтому native `__lumen_video_render_cues` вызывается из шима, а не из shell. (2) Геометрия бокса cue (позиция, размер, `writing-mode`) пишется в атрибут `style` бокса cue строкой CSS: свойства положения не входят в белый список `::cue` (§8.2.1), перекрыть их автору нечем. Свойства текста (шрифт, цвет, фон, `white-space`) выставляет `apply_ua_vtt` в UA-фазе каскада с наименьшим приоритетом, чтобы `::cue` мог их переопределить. (3) Единица строки cue — `lh` бокса cue (в референсах `line:-2` даёт `bottom: 9px` при шрифте 9px: `(|line| - 1) * lh`). (4) Размер шрифта по умолчанию `5vh` в §7.4 относится к области видео, не к окну: брать 5 % высоты бокса `Video` (в `build.rs:708-720` высота известна, по умолчанию 150px). (5) Бокс cue — `div`, содержимое — один фоновый `span` (`.cue-background` в референсах `support/webvtt-ref.css`) и дальше узлы WebVTT как `span`/`i`/`b`/`u`/`ruby`/`rt`; роли узлов хранятся атрибутами `data-lumen-vtt` (`container`/`cue`/`bg`) и `data-lumen-vtt-type` (`c`/`v`/`lang`…), классы и аннотации — `class`, `data-lumen-vtt-voice`, `lang`; достоверность роли проверяет `ua_vtt_role` по принадлежности UA-тени. (6) Контейнер — обычный блок в потоке (`position: relative; height: 100%; overflow: hidden`), боксы cue — `position: absolute` внутри него (у `<video>` нет позиционирующего предка).

Важное ограничение. Все рефтесты `webvtt/rendering/cues-with-video/processing-model` подключают `support/webvtt-test.css`, где шрифт Ahem 9px, зелёный цвет и фон задаются правилом `::cue {...}`, а эталон `webvtt-ref.css` рисует то же. Пока нет `::cue` (CSS-SPECS.md:796, P4, зависит от этой задачи), рефтесты не могут быть PASS, как бы точно ни стояли боксы. Поэтому критерии срезов — тесты `lumen-dom`/`lumen-layout`/`lumen-js` и дампы display list; прогон `run_corpus.py --prefixes webvtt/rendering/cues-with-video/processing-model --processes 6` после S6 выполняется один раз информационно (записать, у скольких id снимок теста перестал быть пустым). Вне срезов: `VTTRegion` и рендер регионов (R4, ждёт BUG-902 п.3), перерисовка при правке свойств cue из скрипта (`dom_override_*`, R2: свойства cue — data-свойства без сеттеров, ждёт BUG-1751), `::cue` (P4), `display: ruby` для `bidi_ruby` (если layout его не поддерживает, ruby идёт как inline), фон вложенных inline (BUG-1750), перепроверка активных cue после загрузки трека (BUG-1749 — S5 только вызывает рендер из существующих точек и из `mode`).
