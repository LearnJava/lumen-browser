# NAV-API-2 — срезы

Источник — разведка WPT-NAV-SCOUT (`docs/wpt-vendor-notes/navigation-api.md`, кластеры G–K) и код: JS-шим Navigation API целиком в `crates/js/src/navigation_api.rs` (строка `NAVIGATION_API_SHIM`), оболочка — `crates/shell/src/lumen/navigation.rs`, `lumen/nav_state.rs`, `app/about_to_wait.rs`. Из описанного в задаче ничего не сделано (`git log --grep=NAV-API` — только разведка): `get activation()` возвращает `null`, у `NavigateEvent` нет `sourceElement`/`downloadRequest`/`formData`/`scroll()`, `intercept()` читает только `handler`.

Общая оговорка по зависимостям: задача стартует после BUG-1700 (same-document навигация без перезагрузки) и BUG-1703 (синхронный диспатч `navigate`). Юнит-тесты срезов от них не зависят (они зовут `_lumen_dispatch_navigate`/`navigation.navigate()` в одном V8-рантайме, как `crates/js/src/dom/tests/v8_bug639_navigation_api.rs`), а WPT-критерии без обоих багов не измерить. Если BUG-1703 переместит точку диспатча (вынесет `_lumen_dispatch_navigate` из оболочки в JS), сохраняйте имена и сигнатуры, добавленные срезами, и переносите только место вызова. Сегодняшняя модель: оболочка коммитит перехваченную навигацию действием 6 уже ПОСЛЕ завершения `handler` (`about_to_wait.rs`, ветка `6 =>`), по спецификации коммит идёт до `handler`; перестройка порядка в срезы не входит.

Тестовые модули lumen-js регистрируются в `crates/js/src/dom/tests/mod.rs` рядом с `mod v8_bug639_navigation_api;` (строка ~494); каркас `runtime()`, `bool_of`, `str_of`, `set_state` скопировать из `v8_bug639_navigation_api.rs`. Прогон WPT: `python tests/wpt/run_corpus.py --prefixes navigation-api/<подкаталог>` на `dev-release` (рецепт — `tests/wpt/README.md`).

## NAV-API-2-S1: NavigationActivation
- **Точка входа:** `crates/js/src/navigation_api.rs` — геттер `activation()` (сейчас `return null`), класс `NavigationHistoryEntry` как образец токен-защищённого конструктора, `exportIface`, `Navigation._sync()`; оболочка — `crates/shell/src/lumen/nav_state.rs:30` `commit_nav_state` (вызывается и из `page_load.rs` `apply_loaded_page`).
- **Сделать:**
  - JS: класс `NavigationActivation` (геттеры `entry`, `from`, `navigationType`, конструктор бросает `TypeError` как у соседей), `exportIface('NavigationActivation', …)`. В JSON `_lumen_navigation_set_state` новое необязательное поле `"activation": {"fromKey": "<key>" или null, "type": "push" или "replace" или "reload" или "traverse"}`. `Navigation` принимает его только из ПЕРВОЙ публикации, где оно есть (срок жизни реалма), и строит `_activation = {entry: текущая запись, from: запись по fromKey или null, navigationType}`. Позднейшие публикации (same-document) активацию не меняют. Поле нет в публикации — `activation === null`.
  - Оболочка: поле `last_published_nav: Option<(Vec<String>, String)>` (ключи стеков и ключ текущей) в состоянии `Lumen` (`crates/shell/src/lumen/state.rs`). Чистая функция `activation_for_load(prev: Option<(&[String], &str)>, new_keys: &[String], new_cur: &str) -> Option<(Option<String>, &'static str)>`: нет `prev` → `(None, "push")`; `new_cur == prev_cur` → `(prev_cur, "reload")`; `new_cur` есть в `prev_keys` → `(prev_cur, "traverse")`; иначе `prev_cur` отсутствует в `new_keys` → `(prev_cur, "replace")`, иначе `(prev_cur, "push")`. Поле `activation` кладётся в JSON только когда `commit_nav_state` вызван из `apply_loaded_page` (полная загрузка документа); остальные вызовы поле опускают. После каждой публикации `last_published_nav` обновляется.
  - Решение принято здесь: тип выводится из разницы стеков, а не из нового параметра через все пути навигации (`nav_timing.rs` документирует, что все пути сходятся в `reload()` без метки).
- **Не трогать:** iframe-варианты активации (нужен BUG-1701), bfcache-варианты (`activation-after-bfcache*`), `navigation.transition`.
- **Готово, когда:** новый файл `crates/js/src/dom/tests/v8_nav_activation.rs`: (1) без поля `activation` в публикации `navigation.activation === null`; (2) с полем `{"fromKey":"nav-1","type":"push"}` и двумя записями `activation.entry === navigation.currentEntry`, `activation.from === navigation.entries()[0]`, `navigationType === 'push'`; (3) вторая публикация с другой текущей записью активацию не меняет (`activation.entry !== currentEntry`); (4) `fromKey: null` даёт `from === null`; (5) `typeof NavigationActivation === 'function'` и `new NavigationActivation()` бросает `TypeError`. Тест оболочки на `activation_for_load` покрывает все пять веток выше. WPT: `activation-history-pushState.html` и `activation-history-replaceState.html` (оба на верхнем уровне, без iframe) — все подтесты PASS; остальные 13 id каталога используют iframe/bfcache и в критерий не входят.
- **Гейт:** `cargo clippy -p lumen-js -p lumen-shell --all-targets -- -D warnings`; `cargo test -p lumen-js v8_nav_activation`; `cargo test -p lumen-shell activation_for_load` (обе фичи как в `docs/commands.md`: js — `v8-backend`); WPT `--prefixes navigation-api/navigation-activation`.
- **Зависит от:** NAV-API-2 (то есть BUG-1700 и BUG-1703 для WPT-части).

## NAV-API-2-S5: scroll и NavigateEvent.scroll()
- **Точка входа:** `crates/js/src/navigation_api.rs` — `NavigateEvent.intercept`, `_lumen_dispatch_navigate`, `_lumen_fire_navigate_success`, класс `Navigation` (карта по ключам записей рядом с `_states`).
- **Сделать:**

  - `navigation._scrollPos: Map(ключ записи → {x, y})`: в `_lumen_dispatch_navigate` сохранять `window.scrollX/scrollY` текущей записи до навигации.
  - `NavigateEvent.scroll()`: `InvalidStateError`, если событие не перехвачено, ещё диспатчится, уже прокручено (`_scrolled`) или навигация завершена. Иначе выполняет алгоритм прокрутки и ставит `_scrolled = true`.

- **Готово, когда:** новый `crates/js/src/dom/tests/v8_nav_scroll.rs` (в тесте `window.scrollTo` и `Element.prototype.scrollIntoView` заменены записывающими заглушками): (1) `intercept({scroll:'bad'})` — `TypeError`; (2) push на `#frag` с перехватом по умолчанию → после успеха один вызов `scrollIntoView` на `#frag`; (3) `scroll:'manual'` → ни одного вызова до `e.scroll()`, после него один; (4) повторный `e.scroll()` и `e.scroll()` без перехвата → `InvalidStateError`; (5) traverse назад → `scrollTo(x, y)` с сохранёнными координатами записи; (6) push без фрагмента → `scrollTo(0, 0)`. WPT `scroll-behavior/`: `manual-basic`, `after-transition-basic`, `manual-scroll-push`, `manual-scroll-replace`, `after-transition-push`, `after-transition-replace`, `scroll-without-intercept`, `scroll-after-preventDefault` — все подтесты PASS (остальные id каталога не обязательны, записать итог).
- **Гейт:** `cargo clippy -p lumen-js --all-targets -- -D warnings`; `cargo test -p lumen-js v8_nav_scroll`; WPT `--prefixes navigation-api/scroll-behavior`.
