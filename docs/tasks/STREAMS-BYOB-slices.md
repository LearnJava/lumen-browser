# STREAMS-BYOB — срезы

Сейчас байтовые потоки — упрощённая реализация в `crates/js/src/shim/streams_shim.js:465-665` (секция «ReadableByteStreamController §3.11», BUG-824): очередь `Uint8Array` без записи о смещении, `desiredSize` — константа 1 (`this.desiredSize = 1`, строка 483), читатель BYOB хранит ожидающие view в `_byobViews`, `enqueue`/`respond` не отсоединяют буфер, `respond` кладёт байты в ту же очередь, `tee()` (строка 266) знает только дефолтные ветки. Ничего из STREAMS-BYOB не влито (`git log --grep=STREAMS` — только разведка WPT-STREAMS-SCOUT). Цифры — `docs/wpt-vendor-notes/streams.md`, кластер B: 30 id, 279/741 сабтестов, потолок ≈ 18.9 балла.

Отсоединение буфера не требует Rust-хука: V8 150 имеет `ArrayBuffer.prototype.transfer` и `ArrayBuffer.prototype.detached`, `web_api_shim_tail_b.js:260` (`_lumen_transfer_one`) уже вызывает `buffer.transfer()`. `TransferArrayBuffer` из спецификации = `buffer.transfer()` (бросает `TypeError` для отсоединённого буфера и для `WebAssembly.Memory.buffer` — именно это ждут `non-transferable-buffers`). Файл один (`streams_shim.js`), крейт один (`lumen-js`); срезы идут по слоям спецификации WHATWG Streams §4.9 «ReadableByteStreamController», каждый оставляет проходящими unit-тесты `v8_whatwg_streams.rs` (BUG-824-тесты около строки 751 и 1589-1640 проверяют интерфейс и поведение `byobRequest`).

Зависимость от STREAMS-LAZY-PULL: байтовый контроллер получает собственный `CallPullIfNeeded`, который опирается на флаг «`start()` завершён» (`_rs_started`, строки 166-222; после LAZY-PULL `pull` идёт после микрозадачи и ожидания промиса `start()`). До начала S1 проверить, что LAZY-PULL влита (`git log --oneline --grep=STREAMS-LAZY-PULL`) и что публичный путь `fetch`-тела по-прежнему синхронный (BUG-703) — байтовые потоки в нём не участвуют (`grep -rn "type: *'bytes'" crates/js/src --include=*.js` вне streams_shim.js пуст).

Команда замера для всех срезов (Python из `tests/wpt/.venv` корневого checkout, `dev-release`-бинарник): `python tests/wpt/run_corpus.py --binary target/dev-release/lumen.exe --categories streams --prefixes streams/readable-byte-streams --processes 4 --skip-manifest-update`. Числа «из N» ниже — для варианта `*.any.html` одного файла (подсчёт `test(`/`promise_test(` в файле); общий знаменатель 741 — все варианты окружения. Пороги — нижние оценки; если не достигнуты, перечислить красные subtest-ы в итоговом сообщении и в vendor-notes, а не снижать порог молча.

## STREAMS-BYOB-S1: очередь, enqueue/close/error, pull-планировщик, дефолтный читатель
- **Точка входа:** `crates/js/src/shim/streams_shim.js:476` `ReadableByteStreamController`, `:489` `enqueue`, `:501` `close`, `:507` `error`, `:538` `_rbs_drain`, конструктор `ReadableStream` `:168-222` (ветка `isBytes`, `:187`), `ReadableStreamDefaultReader.prototype.read` `:443`. Спецификация: Streams §4.9 «ReadableByteStreamControllerEnqueue», «EnqueueChunkToQueue», «ShouldCallPull», «CallPullIfNeeded», «GetDesiredSize», «PullSteps» (ветка очереди), «CancelSteps».
- **Сделать:**
  1. Запись очереди — `{buffer, byteOffset, byteLength}` плюс `_queueTotalSize`; `_rbs_fill` (`:523`) и `_rbs_drain` адаптировать под запись (старый BYOB-читатель на `_byobViews` пока остаётся рабочим, его заменит S2).
  2. `enqueue(chunk)` по порядку проверок спецификации: не `ArrayBufferView` → `TypeError`; `byteLength` 0 → `TypeError`; `buffer.byteLength` 0 → `TypeError`; `closeRequested` → `TypeError`; состояние не `readable` → `TypeError` (сейчас молча `return`); отсоединённый буфер (`chunk.buffer.detached`) → `TypeError`; `transferred = chunk.buffer.transfer()`. Если у читателя есть ожидающие `read()` дефолтного читателя — отдать `Uint8Array(transferred, byteOffset, byteLength)` первому запросу, иначе положить в очередь. Затем `CallPullIfNeeded`. Ветку «есть pending pull-into» оставить как есть до S2.
  3. `close()`: `TypeError`, если уже `closeRequested` или состояние не `readable`; непустая очередь → только `closeRequested`.
  4. `desiredSize` — геттер на прототипе контроллера (`null` при ошибке, 0 при закрытии, иначе `highWaterMark - queueTotalSize`), вместо данных `this.desiredSize = 1`. Стратегия байтового потока: `highWaterMark` по умолчанию 0 (`ExtractHighWaterMark`; если BUG-1740 уже даёт общий помощник — использовать его), `strategy.size !== undefined` → `RangeError` в конструкторе (`general.any.js:2308`).
  5. `CallPullIfNeeded`: условия `ShouldCallPull` (started, не closeRequested, есть читатель с запросами или `desiredSize > 0`), флаги `pulling`/`pullAgain`, исключение из `pull` ошибает поток, отказ промиса `pull` ошибает поток; вызов `pull(controller)` с `this === source`.
  6. Дефолтный `read()` на байтовом потоке: непустая очередь → `Uint8Array` из первой записи, `HandleQueueDrain` (закрыть поток, когда очередь пуста и `closeRequested`); пустая → запрос чтения + `CallPullIfNeeded`.
- **Не трогать:** `ReadableStreamBYOBReader.read`/`_rbs_byob_request`/`respond` (S2), `tee()` (S4), небайтовый `ReadableStreamDefaultController` и `_rs_pull_if_needed` (:135, зона LAZY-PULL).
- **Готово, когда:** новые unit-тесты в `crates/js/src/dom/tests/v8_whatwg_streams.rs` (enqueue отсоединяет `chunk.buffer` — `chunk.buffer.detached === true`/`byteLength === 0`; повторный `enqueue` отсоединённого буфера → `TypeError`; `enqueue` после `close()` и `close()` дважды → `TypeError`; `desiredSize` 0 → 1 → 0 по мере `enqueue`/`read`; `strategy.size` у байтового потока → `RangeError`) зелёные; `non-transferable-buffers.any.html` тест «enqueue() with a non-transferable buffer» PASS; `general.any.html` не меньше 45 из 101.
- **Гейт:** `cargo clippy -p lumen-js --all-targets -- -D warnings`; `cargo test -p lumen-js --features v8-backend -- v8_whatwg_streams`; замер WPT командой выше с `--prefixes streams/readable-byte-streams/general,streams/readable-byte-streams/non-transferable-buffers`.
- **Зависит от:** STREAMS-LAZY-PULL (влита), BUG-1740 желательно (общий помощник `ExtractHighWaterMark`).

## STREAMS-BYOB-S2: pull-into дескрипторы, BYOB read, byobRequest, respond, autoAllocate
- **Точка входа:** `streams_shim.js:515-660` (`_rbs_same_kind`, `_rbs_fill`, `_rbs_drain`, `_rbs_byob_request`, `_rbs_respond`, `ReadableStreamBYOBRequest`, `ReadableStreamBYOBReader`). Спецификация: Streams §4.9 «ReadableByteStreamControllerPullInto», «FillPullIntoDescriptorFromQueue», «FillHeadPullIntoDescriptor», «CommitPullIntoDescriptor», «ConvertPullIntoDescriptor», «ProcessPullIntoDescriptorsUsingQueue», «Respond», «RespondInternal», «RespondInClosedState», «RespondInReadableState», «RespondWithNewView», «GetBYOBRequest», «InvalidateBYOBRequest», «ShiftPendingPullInto», «ClearPendingPullIntos»; §4.7 «ReadableStreamBYOBReaderRead»; `[[PullSteps]]` с `autoAllocateChunkSize`.
- **Сделать:**
  1. Список `pendingPullIntos` дескрипторов `{buffer, bufferByteLength, byteOffset, byteLength, bytesFilled, minimumFill, elementSize, viewConstructor, readerType}`; `minimumFill` пока равен `elementSize` (поддержка `min` — S3).
  2. `BYOBReader.read(view)`: `TransferArrayBuffer(view.buffer)` — при `TypeError` (отсоединён, не передаваем) вернуть отклонённый промис и НЕ вызывать `pull`; закрытый поток → `{value: пустой view того же типа над передаваемым буфером, done: true}`; очередь непуста → `FillPullIntoDescriptorFromQueue`, при полном заполнении `HandleQueueDrain` и немедленный результат; `closeRequested` с пустой очередью → ошибка потока `TypeError` и отказ чтения; иначе дескриптор в список и `CallPullIfNeeded`.
  3. `byobRequest` — геттер контроллера с кэшем (`_byobRequest`), `view` строится над `firstDescriptor.buffer` со смещением `byteOffset + bytesFilled`; `respond(n)`/`respondWithNewView(view)` — разбор по состоянию (`closed`/`readable`), `RespondInReadableState`: остаток `bytesFilled % elementSize` кладётся в очередь, `CommitPullIntoDescriptor`, `ProcessPullIntoDescriptorsUsingQueue`. Повторный `respond` на том же объекте → `TypeError` (после `InvalidateBYOBRequest` `request._controller = null`).
  4. `enqueue()` при непустом `pendingPullIntos`: `InvalidateBYOBRequest`, передача буфера первого дескриптора, `ProcessPullIntoDescriptorsUsingQueue` (спецификационная ветка, оставленная в S1).
  5. `autoAllocateChunkSize`: `PullSteps` дефолтного читателя при пустой очереди создаёт дескриптор `readerType: 'default'` на `new ArrayBuffer(autoAllocateChunkSize)`; `Convert` для него выдаёт `Uint8Array` дефолтному запросу.
  6. `cancel()` очищает дескрипторы и очередь; `error()` отклоняет все read-into-запросы; `close()` с `bytesFilled % elementSize !== 0` → ошибка `TypeError`.
  7. Удалить `_byobViews` и ссылки на него (`:111`, `:126`, `:621`), `_rbs_fill`/`_rbs_drain`/`_autoView`.
- **Не трогать:** опцию `min` (S3), `releaseLock()` с ожидающими чтениями (S3), `tee()` (S4), валидацию `respond(bytesWritten)` сверх `RangeError`/`TypeError` старого кода (S3).
- **Готово, когда:** `non-transferable-buffers.any.html` 4/4; `enqueue-with-detached-buffer.any.html` 1/1; `general.any.html` не меньше 70 из 101; в выводе прогона нет `Cannot read properties of null (reading 'view')`; unit-тесты BUG-824 BYOB в `v8_whatwg_streams.rs` (около строк 751-800) зелёные; новый unit-тест: `read(view)` отсоединяет `view.buffer` и результат — view над переданным буфером того же класса.
- **Гейт:** `cargo clippy -p lumen-js --all-targets -- -D warnings`; `cargo test -p lumen-js --features v8-backend -- v8_whatwg_streams`; WPT `--prefixes streams/readable-byte-streams`.
- **Зависит от:** STREAMS-BYOB-S1.

## STREAMS-BYOB-S3: min, валидация respond/view, releaseLock, конструктор читателя
- **Точка входа:** `ReadableStreamBYOBReader.prototype.read` (`streams_shim.js:630`), `ReadableStreamBYOBRequest.prototype.respond`/`respondWithNewView` (`:603-612`), `_rs_install_reader_common` `releaseLock` (`:437-444`), `ReadableStreamBYOBReader` (`:615`). Спецификация: Streams §4.7 `ReadableStreamBYOBReader.read(view, options)` (WebIDL `ReadableStreamBYOBReaderReadOptions`, `min`), §4.7 «ReadableStreamBYOBReaderRelease»/«ReadableStreamReaderGenericRelease», §4.9 «ReadableByteStreamControllerRespondInternal» (проверки), `[[ReleaseSteps]]`.
- **Сделать:**
  1. `read(view, {min})`: `min` не 0/отрицательный (`TypeError`), не больше `view.length` (`RangeError`, для `DataView` — `byteLength`); `minimumFill = min * elementSize`; `Fill…FromQueue`/`Commit` уже используют `minimumFill` из S2.
  2. `respond(n)`: нет `view` у `byobRequest` (запрос недействителен) → `TypeError`; в состоянии `closed` ожидается 0, иначе `TypeError`; `n > view.byteLength` → `RangeError`; `respondWithNewView(view)`: `byteOffset`, `byteLength` и `buffer.byteLength` должны совпасть с дескриптором (`RangeError`), `view.byteLength` 0 в состоянии `closed`, нет детача (`TypeError`).
  3. `releaseLock()` дефолтного и BYOB-читателя: ожидающие чтения отклоняются `TypeError` (а не бросают исключение, как сейчас на `:441`), у первого дескриптора `readerType = 'none'`; ответ `respond` для такого дескриптора кладёт данные в очередь (`EnqueueDetachedPullIntoToQueue`), следующий читатель их получает.
  4. Конструктор `ReadableStreamBYOBReader(stream)`: не `ReadableStream` → `TypeError`, заблокирован → `TypeError`, не байтовый → `TypeError`; `new ReadableStreamBYOBReader(rs)` работает напрямую (`general.any.js:2267-2285`).
- **Не трогать:** `tee()` (S4), небайтовый путь `releaseLock` в `ReadableStreamDefaultReader` для обычных потоков — поведение «ожидающие чтения отклоняются» должно подойти и ему, но если ломает тест `v8_whatwg_streams.rs`, оставить прежнее для небайтовых потоков и отметить в итоге.
- **Готово, когда:** `read-min.any.html` не меньше 21 из 24 (исключения — только subtest `tee() with read({min})` до S4); `bad-buffers-and-views.any.html` не меньше 22 из 24; `respond-after-enqueue.any.html` 3/3; `construct-byob-request.any.html` без FAIL; `general.any.html` не меньше 90 из 101; все unit-тесты `v8_whatwg_streams` зелёные.
- **Гейт:** `cargo clippy -p lumen-js --all-targets -- -D warnings`; `cargo test -p lumen-js --features v8-backend -- v8_whatwg_streams`; WPT `--prefixes streams/readable-byte-streams`.
- **Зависит от:** STREAMS-BYOB-S2.
