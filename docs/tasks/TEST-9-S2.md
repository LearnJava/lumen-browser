# TEST-9-S2 — графтесты: `--ipc` по умолчанию, gdigrab только для GPU-подмножества

Срез 2 из TEST-9 (ROADMAP:681). Владелец — P2. Область — `graphic_tests/run.py`.

## Цель

1. Дефолтный захват — IPC (CPU-снимок). Для тестов, у которых `capture_mode_for(tid) == 'gdigrab'` (S1), поднимается живой клиент и gdigrab.
   - Точка развилки — [run.py:1582](../../graphic_tests/run.py#L1582) (`_IPC_CLIENT` / `_LIVE_CLIENT`).
   - Флаг `--ipc` остаётся как «всё через IPC». Новый `--gdigrab` (или `--all-gdigrab`) даёт старое поведение.
   - Четвёртого способа захвата не заводить (граница из ROADMAP:681).
2. Отдельная таблица должников для IPC-пути рядом с таблицей `:343-653`. Каждый debtor-тест получает базу по способу, которым его теперь снимают.
   - Разжаловать 135 и 136: они дают FAIL при меньшем дифе, ратчет требует пересмотра.
3. Убрать пометки «ТРЕБУЕТ gdigrab» у TEST-57 и 129-138 (`:305-333`), основание для них снято. Тесты, которые остались в `GPU_CAPTURE`, пометку сохраняют.

## Не трогать

- Offscreen-GPU-захват через `Renderer::new_headless`: это отдельное решение.
- Кроп эталона Edge (ffmpeg остаётся).

## Готово, когда

1. Полный прогон по умолчанию, `python graphic_tests/run.py --continue-on-fail`, **в foreground на активном рабочем столе** (gdigrab из фона даёт ложные FAIL). Ожидается ~5 мин IPC и несколько минут gdigrab.
2. Сверка с `results/20260919-131021.json` (ipc) и `results/20260919-133745.json` (gdigrab). Статус каждого теста совпадает со статусом в прогоне его способа захвата.
3. Расхождения объяснены в коммите. Новые FAIL не прикрыты молча.
4. `--self-test` из S1 зелёный.
