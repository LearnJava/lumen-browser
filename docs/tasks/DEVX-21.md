# DEVX-21 — кэш сборки между worktree: sccache, инкрементальность, rusty_v8

**Developer:** P1  
**Ветка:** `p1-devx-21`  
**Размер:** M  
**Крейты:** нет (настройки сборки: `.cargo/config.toml`, `Cargo.toml` `[profile.*]`, `docs/commands.md`)

## Зачем

Каждый новый worktree собирает workspace почти с нуля. Замер 2026-10-22, три параллельных
агента в свежих worktree (`chat-split-*`) + `cargo test --workspace`:

| Показатель `sccache --show-stats` | Значение |
|---|---|
| Попадания в кэш | 59 % (981 из 1659) |
| Некэшируемые вызовы | 642, из них `incremental` — 220 |
| Размер кэша | 10 GiB из 10 GiB (полон, идёт вытеснение) |

Причины:
1. Кэш `sccache` забит до предела по умолчанию (10 GiB) — записи вытесняются раньше, чем
   переиспользуются.
2. Профиль dev собирает крейты workspace инкрементально, а `sccache` инкрементальную компиляцию
   не кэширует (причина `incremental` в статистике) — все крейты `lumen-*` в новом worktree
   компилируются заново.
3. Ключ кэша для крейтов workspace зависит от пути worktree (`CARGO_MANIFEST_DIR`, пути
   исходников), поэтому результат из `.claude/worktrees/a` не подходит для `.claude/worktrees/b`.
   Зависимости из `~/.cargo/registry` лежат по одному пути и попадают в кэш.
4. Build-скрипт крейта `v8` кладёт готовую `rusty_v8.lib` (~212 MB) в
   `target/<profile>/gn_out/` каждого target-каталога заново (скачивание или копия).

## Что сделать

Каждый шаг — отдельное решение с замером «до/после»; шаг, не давший выигрыша, не вливать, а
записать результат в `docs/commands.md` §Build cost.

0. **Замер «до».** В свежем worktree от `origin/main`: `sccache --zero-stats`, затем
   `cargo check -p lumen-shell --all-targets` (время по часам) и `sccache --show-stats`
   (hits/misses/non-cacheable). Повторить во втором свежем worktree — это и есть сценарий
   «агенты в параллельных worktree». Свободное место на диске кэша — записать.
1. **Предел кэша.** `SCCACHE_CACHE_SIZE = "40G"` (или сколько позволяет диск, проверить
   свободное место на `C:`) в `[env]` файла `.cargo/config.toml`. Учесть, что сервер `sccache`
   читает настройку при старте: после правки `sccache --stop-server`, затем проверить
   `Max cache size` в `--show-stats`. Порт сервера уже задан там же (`SCCACHE_SERVER_PORT`).
2. **Инкрементальность.** Сравнить два режима на двух сценариях:
   (а) холодная сборка в новом worktree, (б) правка одной строки в `crates/engine/layout` →
   `cargo check -p lumen-shell` (цикл «правка — проверка» разработчика). Варианты:
   `[profile.dev] incremental = false` в корневом `Cargo.toml` или `CARGO_INCREMENTAL=0` в
   `[env]`. Если (б) заметно замедляется — не выключать глобально, а оставить инкрементальность
   и описать в `docs/commands.md`, как сессии-агенты в свежем worktree выключают её на один
   прогон (`CARGO_INCREMENTAL=0 cargo …`).
3. **Пути worktree в ключе кэша.** Выяснить по документации `sccache` 0.17 (у нас ровно эта
   версия, см. CLAUDE.md), умеет ли он нормализовать базовый каталог для Rust-компиляций
   (параметры вида basedir / path prefix), и проверить `--remap-path-prefix` в `RUSTFLAGS`
   (`[build] rustflags` в `.cargo/config.toml`). Критерий — замер: второй свежий worktree после
   первого даёт попадания по крейтам `lumen-*`. Если не даёт — записать, почему, и не вливать.
   Внимание: `RUSTFLAGS` меняет отпечаток всех крейтов — первая сборка после правки полная.
4. **`rusty_v8.lib`.** Крейт `v8` берёт готовую библиотеку из переменной `RUSTY_V8_ARCHIVE`,
   если она задана (иначе скачивает). Подобрать вариант, при котором все worktree используют
   один экземпляр файла. Путь вне репозитория (переменная окружения пользователя,
   `~/.cargo/config.toml`) — это правка вне рабочей границы CLAUDE.md: описать её и
   **согласовать с пользователем**, сам не применять. В `.cargo/config.toml` абсолютные пути
   машины не класть (`scripts/check_claude_md.py` и CI-проверки).
5. **Замер «после»** тем же сценарием, что в шаге 0; таблицу «до/после» — в
   `docs/commands.md` §Build cost.

## Готово, когда

- В `docs/commands.md` §Build cost есть таблица «до/после» по шагам 0–5: время холодного
  `cargo check -p lumen-shell --all-targets` в новом worktree, процент попаданий `sccache`,
  число некэшируемых вызовов, время цикла «правка layout → check shell».
- Влиты только шаги с измеренным выигрышем; для отклонённых — строка с причиной.
- Второй свежий worktree подряд собирается заметно быстрее первого (цифры в таблице).
- `cargo clippy --workspace --all-targets -- -D warnings` чист после правок конфигурации;
  CI (`ci.yml`) не сломан изменением `rustflags`/профиля.
- Правки вне репозитория (шаг 4) — только описаны и согласованы, не применены самовольно.
