# Пять невлитых веток в `origin` — что с ними делать

**Кому:** следующей сессии (роль P5 — чистка веток входит в её домен, `docs/dev-roles.md`).
**Когда собрано:** 2026-08-31, после чистки `origin` с 31 ветки до 6 (влитые удалены).
**Состояние:** решение по четырём веткам за пользователем, факты собраны и проверены ниже.

Осталось в `origin` шесть ссылок: `main`, постоянный полигон `p1-exp-wgpu-only` и четыре
ветки, у каждой из которых есть коммиты, отсутствующие в `main`. Именно поэтому они и не
были удалены вместе с остальными: удалять ветку, содержимое которой нигде больше не лежит,
без спроса нельзя.

---

## Общие правила, прежде чем что-то делать

**1. Ни одну из этих веток НЕЛЬЗЯ вливать через `git merge`.** Все они старше двух месяцев и
предшествуют перестройкам репозитория. Проверено на `p1-wgpu-cross-platform`: её слияние
УДАЛИЛО бы `.claude-manager/` и воскресило `.claude/memory/*` — раскладку, которой в проекте
больше нет. Если из ветки что-то нужно, брать это `git cherry-pick <sha>` или патчем по
конкретным путям:

```bash
git diff origin/main...origin/<ветка> -- <путь> > .tmp/patch.diff   # посмотреть
git apply --3way .tmp/patch.diff                                     # применить точечно
```

**2. Удаление ветки обратимо, пока известен SHA.** Все они записаны ниже. Восстановление:

```bash
git push origin <sha>:refs/heads/<имя-ветки>
```

Поэтому «удалить» здесь — не необратимый шаг, а «убрать с глаз, зная, куда вернуться».
Коммиты живут в `origin` до сборки мусора; после неё восстановит только локальная копия.

**3. Проверять надо содержимое, а не название.** Ветка `merge-tmp-bug591-sw` в этой же
чистке выглядела как «застрявшая чужая работа», а по факту оба родителя её merge-коммита
уже лежали в `main`, и единственной собственной правкой было разрешение конфликта в
`CLAUDE.md`. Признак «в ветке есть коммиты, которых нет в main» ничего не говорит о том,
есть ли в main их СОДЕРЖИМОЕ.

## `p1-p3-bfcache` — содержимое уже в `main`, можно удалять

`decda3173d318e9d1b59e467fb7787fdbcc9854e`, 1 коммит, 2026-06-24, автор Claude.
«Bfcache Phase 3: add FrozenPage payload support», трогает `crates/storage/src/bfcache.rs`.

`main` другим путём.

```bash
grep -n "BfCachePayload\|FrozenPage\|has_frozen" crates/storage/src/bfcache.rs   # всё на месте
git diff origin/main...origin/p1-p3-bfcache -- crates/storage/src/bfcache.rs      # сверить остаток
```

**Рекомендация:** удалить. Если сверка покажет что-то сверх уже влитого — не удалять, а
завести задачу на это конкретное «сверх».

## `merge-p2-bug076` — почти наверняка устарело, но нужна сверка

`7d29255525d34c3b3c0b8db5cf962ba16ef19bcf`, 4 коммита, 2026-06-12, автор Claude.
Трогает `crates/engine/paint/src/display_list.rs` (+50), `backends/femtovg_backend.rs` (+19),
`renderer.rs` (+2) — итого 58 вставок в 4 файлах.

**Что известно:** [BUG-076](../../BUGS-FIXED.md) (box-shadow blur spread) закрыт в `main`
2026-06-11 — на день РАНЬШЕ последнего коммита ветки. То есть ветка либо доводила уже
закрытое, либо чинила параллельно и не понадобилась.

**Почему нельзя просто удалить не глядя:** это единственная из четырёх, где содержимое не
проверено построчно. При этом `renderer.rs` и `display_list.rs` с тех пор разобраны дорожкой
SPLIT на десятки файлов, поэтому патч, скорее всего, уже не приложится — и это само по себе
не довод «выбросить», а довод «понять, что там, прежде чем выбрасывать».

```bash
git log --format='%ad %s' --date=short origin/main..origin/merge-p2-bug076
git diff origin/main...origin/merge-p2-bug076 -- crates/engine/paint/ | head -120
```

**Рекомендация:** прочитать диф (он маленький, 58 строк). Если это доводка уже закрытого
BUG-076 — удалить. Если там отдельная правка, которой в `main` нет, — завести баг с этим
дифом в теле и удалить ветку.

## Порядок действий одной командой

Когда решения приняты, удаление выглядит так (SHA сохранены выше — восстановление возможно):

```bash
git push origin --delete p1-p3-bfcache merge-bug085-temp
# merge-p2-bug076 — после чтения дифа
# p1-wgpu-cross-platform — только после ответа пользователя
```

После удаления обновить эту записку (или удалить её, если список исчерпан) и снять указатель
из `STATUS-P5.md`.
