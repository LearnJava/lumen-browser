# TEXTQ-3 — прокрутка без дробного сдвига полосы

Дорожка TEXTQ, срез 3. Владелец — P1. Крейт — `lumen-paint`. **Зависит от:** TEXTQ-1.

## Зачем

Прокручиваемая полоса страницы копируется на экран квадом с `Linear`-сэмплером (`page-band-sampler`, [construct.rs:687](../../crates/engine/paint/src/renderer/construct.rs#L687)); при нецелом `scroll_y` блит идёт на дробный сдвиг ([band_compose.rs:130](../../crates/engine/paint/src/renderer/band_compose.rs#L130), `band_blit_quads`). После TEXTQ-1 текст в самой полосе лежит ровно на пикселях, но при каждой прокрутке на дробную позицию весь текст снова размывается на полпикселя — и «мерцает» резкость во время скролла.

## Что сделать

1. Привязать сдвиг блита полосы к целым device px: `dy_dev = round(dy_css × dpr)`, в квад — `dy_dev / dpr`. Аналогично фаза кольца (`phase_px`) — уже целая строка текстуры, проверить.
2. Проверить, что то же самое делается для других композитных слоёв с текстом (кэш слоёв ADR-008, sticky, overlay) — найти места, где слой блитится со смещением скролла, и привязать так же. Слои с `transform` (масштаб/поворот) не трогать — там дробность законна.
3. Если после привязки блит всегда целочисленный — можно перейти на `Nearest` для этого сэмплера; если нет — оставить `Linear` (комментарий о шве кольца в `band_compose.rs` остаётся в силе).

## Готово, когда

1. Юнит-тест `band_blit_quads`: при `dpr = 1` и `1.5` и дробном `dy_css` координаты квада кратны `1/dpr`.
2. Живая проверка: длинная текстовая страница, плавная прокрутка колесом и тачпадом (`--maximized`, `LUMEN_NO_ADBLOCK=1`) — текст не «плывёт» по резкости; кадры не дёргаются (прокрутка остаётся плавной, сдвиг ≤ 0,5 device px).
3. Полный `python graphic_tests/run.py --continue-on-fail`, затронутые эталоны перегенерированы в том же коммите.
4. `cargo clippy -p lumen-paint --all-targets -- -D warnings` чисто.
