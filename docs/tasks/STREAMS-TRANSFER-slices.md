# STREAMS-TRANSFER — срезы

Ничего из STREAMS-TRANSFER не сделано (`git log --grep=STREAMS` — только разведка WPT-STREAMS-SCOUT). Сейчас: `structuredClone` (`web_api_shim_tail_b.js:304`) переносит только `ArrayBuffer`/`OffscreenCanvas`/`ImageBitmap` (`_lumen_transfer_one`, `:260`), остальное в `transfer` — `DataCloneError`; поток вне списка клонируется как простой объект со служебными полями шима (`_rs_*`), отсюда «Converting circular structure to JSON». `MessagePort.prototype.postMessage(message)` (`message_channel_shim.js:58`) и `window.postMessage` (`web_api_shim_mid_b4.js:2204`) игнорируют список `transfer`; `MessageEvent` (`web_api_shim_mid_b3.js:513`) не имеет `ports`; `MessagePort` внутри одной области не переносится (мост портов `_lumen_port_prepare_transfer` работает только на границе страница-воркер). Цифры — `docs/wpt-vendor-notes/streams.md`, кластер X: `transferable/*` 12 id, 12/85 сабтестов.

Механизм (выбран здесь, исполнитель не выбирает): как в спецификации Streams §8 «Transferable streams» — передаваемый поток через `MessageChannel`. Отправитель: `ReadableStream` блокируется конвейером `value.pipeTo(writable)`, где `writable` — «кросс-реалмовая» запись в `port1` (`SetUpCrossRealmTransformWritable`): сообщения `{type:'chunk', chunk}`, `{type:'close'}`, `{type:'error', reason}`; обратное давление — сообщение `{type:'pull'}` от приёмника; приёмник — `new ReadableStream` с `highWaterMark: 0` над `port2` (`SetUpCrossRealmTransformReadable`), его `pull` шлёт `{type:'pull'}`, `cancel(reason)` шлёт `{type:'error', reason}` и закрывает порт. Для `WritableStream` половины меняются местами. Чанки и причины проходят через `structuredClone` внутри `MessagePort.postMessage`, поэтому «причина, сериализуемая `structuredClone`» получается сама; несериализуемая причина (`DataCloneError` при отправке) превращается в `{type:'error', reason: <DataCloneError>}` и закрывает порт. Служебные функции остаются в области шима (файлы шимов конкатенируются в одну область, `dom.rs:608`, `typeof _lumen_… === 'function'`-проверка как у `_lumen_image_bitmap_transfer`), на публичные прототипы ничего не добавляется.

Зависимости: STREAMS-LAZY-PULL (иначе `pull` приёмника вызывается синхронно в конструкторе) и BUG-1740 (форма классов, `Symbol.toStringTag`). Желательно STREAMS-PIPETO влита до S1 (отправитель использует `pipeTo`, ошибки приёмника должны доходить до источника и наоборот); если нет, использовать существующий `ReadableStream.prototype.pipeTo` (`streams_shim.js:359`) и записать в итог, какие subtest-ы `reason.html` зависят от PIPETO. Вне срезов остаются: iframe (`transferable/window.html` «transfer to and from an iframe», `deserialize-error.window.js` — нужен BUG-480), `service-worker.https.html` (BUG-1226), `SharedWorker` (`shared-worker.html`, 2 сабтеста: мост `shared_worker.rs` сериализует `JSON.stringify(data)` без механизма переноса портов — отдельная задача), `type: 'owning'`/`VideoFrame` (кластер O), `*-members.any.js` в варианте воркера (в воркере `structuredClone` урезан, `worker.rs:472-500`).

Команда замера: `python tests/wpt/run_corpus.py --binary target/dev-release/lumen.exe --categories streams --prefixes streams/transferable --processes 4 --skip-manifest-update` (Python из `tests/wpt/.venv` корневого checkout). Числа «из N» — подсчёт `test(`/`promise_test(` в файле: `readable-stream.html` 16, `writable-stream.html` 8, `transform-stream.html` 5, `reason.html` 8, `window.html` 4, `worker.html` 3, `transfer-with-messageport.window.js` 10; пороги — нижние оценки, непройденное перечислить в итоге.

## STREAMS-TRANSFER-S1: передача ReadableStream в structuredClone
- **Точка входа:** `crates/js/src/shim/web_api_shim_tail_b.js:260` `_lumen_transfer_one` (добавить ветку `if (typeof _lumen_stream_transfer === 'function') { var moved = _lumen_stream_transfer(orig); if (moved !== null) return moved; }` перед финальным `DataCloneError`) и `:346` `clone()` (поток вне `transfer` — `DataCloneError`, до ветки «простой объект»); реализация `_lumen_stream_transfer` и пары `_xr_setup_writable(port)`/`_xr_setup_readable(port)` — в `crates/js/src/shim/streams_shim.js` рядом с `TransformStream` (`:1143`). Спецификация: Streams §8.1 «Transferable streams», §4.2 ReadableStream `[[TransferSteps]]`/`[[TransferReceivingSteps]]`.
- **Сделать:**
  1. `_lumen_stream_transfer(orig)`: `orig` не `ReadableStream` → вернуть `null` (остальные классы — S2); заблокирован → `DataCloneError` (`DOMException`); `ch = new MessageChannel()`; `writable = new WritableStream(...)` с `write`/`close`/`abort`, шлющими `chunk`/`close`/`error` в `ch.port1`, `highWaterMark: 1`; обратное давление — промис, который решается сообщением `pull`; `orig.pipeTo(writable)` с `_stream_mark_handled`; вернуть `new ReadableStream` над `ch.port2` (`start`/`pull`/`cancel`, `highWaterMark: 0`).
  2. Слушатель сообщений порта: `chunk` → `controller.enqueue`; `close` → `controller.close()` и `port.close()`; `error` → `controller.error(reason)` и `port.close()`; ошибка `enqueue` → отправить `error` обратно.
  3. Тесты на дубликаты в `transfer` и на `[rs, rs]` в данных (получатель один и тот же объект) обеспечиваются уже существующим `memory` в `structuredClone`; проверить.
- **Не трогать:** `MessagePort.postMessage`/`window.postMessage` (S3), `WritableStream`/`TransformStream` как передаваемые (S2), воркеры (S4), `streams_shim.js` вне нового блока.
- **Готово, когда:** новые unit-тесты в `crates/js/src/dom/tests/v8_whatwg_streams.rs`: (а) `structuredClone(rs, {transfer: [rs]})` возвращает `ReadableStream`, `rs.locked === true`, клон читает `'a'`, затем `done: true`; (б) десять чанков подряд приходят по порядку; (в) `controller.error(e)` источника с `e = new Error('x')` ошибает клон причиной с тем же `message`; (г) `clone.cancel('r')` отменяет источник причиной `'r'`; (д) заблокированный поток в `transfer` → `DataCloneError`; (е) `structuredClone({s: rs})` без `transfer` → `DataCloneError`; существующие тесты `v8_whatwg_streams` и `structuredClone` (`v8_url_abort_clone_blob.rs`) зелёные.
- **Гейт:** `cargo clippy -p lumen-js --all-targets -- -D warnings`; `cargo test -p lumen-js --features v8-backend -- v8_whatwg_streams v8_url_abort_clone_blob`.
- **Зависит от:** STREAMS-LAZY-PULL, BUG-1740 (влиты), STREAMS-PIPETO желательно.

## STREAMS-TRANSFER-S2: WritableStream и TransformStream
- **Точка входа:** `_lumen_stream_transfer` из S1 (`streams_shim.js`); `TransformStream` `:1143`, `_ts_setup` `:1150`; тест-образец — `tests/wpt/streams/transferable/transform-stream-members.any.js`, `writable-stream.html`, `transform-stream.html`.
- **Сделать:**
  1. `WritableStream`: заблокирован → `DataCloneError`; `ch = new MessageChannel()`; `readable = new ReadableStream` над `ch.port1` (`_xr_setup_readable`), `readable.pipeTo(orig)` (ошибки записи приёмника отправителю не нужны — спецификация использует `pipeTo` с `preventClose/Abort/Cancel` false); вернуть `new WritableStream` над `ch.port2` (`_xr_setup_writable`).

## STREAMS-TRANSFER-S3: transfer в postMessage, перенос MessagePort, MessageEvent.ports

- **Сделать:**
  1. `MessagePort.postMessage(message, transferOrOptions)`: второй аргумент — последовательность или `{transfer}`; клон — `structuredClone(message, {transfer: list})`; порты из списка уходят в `ev.ports` получателя.
  2. `window.postMessage(message, targetOrigin, transfer)` и `(message, {targetOrigin, transfer})` (сейчас `transfer` отброшен, `:2204`): `structuredClone(message, {transfer: list})`, события получают `ports`.
  3. `_lumen_transfer_one`: ветка для `MessagePort` — новый `MessagePort` забирает `_other` (с повторной сцепкой партнёра: `partner._other = moved`), `_queue`, `_started`, слушатели; исходный порт получает `_neutered = true`, `_other = null`; отсоединённый порт в списке или повторный перенос → `DataCloneError`.
