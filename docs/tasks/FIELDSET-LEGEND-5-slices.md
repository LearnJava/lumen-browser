# FIELDSET-LEGEND-5 — срезы
Остаток FIELDSET-LEGEND-4 состоял из пяти пунктов. Проба против Edge (`msedge --headless --dump-dom` плюс скриншот, страницы-пробы в `.tmp/slices/probe/` слота планировщика) показала: пункты (1) и (3) в основном уже выполнены или устарели и срезов не требуют. Float-legend (`float: right`, ширина 60px, поля `0 5px`), legend внутри `display: inline-block` fieldset и legend с `display: table` дают по `getBoundingClientRect` те же координаты и размеры, что Edge (fieldset 10,8,322,46, legend 256,14,60,20; inline-block 222x60; table-legend 26,113,80,16), попиксельный диф отличается только сглаживанием текста. `dir`-атрибут в `direction` уже отображается (`crates/engine/layout/src/style/presentational.rs:370`, `apply_dir_presentational_hint`), `fieldset[dir=rtl] legend` встаёт к правому краю как в Edge; `display: table` на обычном `<div>` раскладывается shrink-to-fit (9x18 у Edge, 10x19 у Lumen из-за шрифта), а не блоком высотой 0. Неподтверждённым остаётся лишь то, почему два подтеста WPT `legend-align` (`fieldset[dir=rtl] legend`) и `legend-display` красные, если красные: баз прогона у планировщика не было, нужен прогон `run_report.py` по `html/rendering/non-replaced-elements/the-fieldset-and-legend-elements` отдельной задачей P2.

Реальные расхождения подтверждены пробой: (2) legend шире content box (Edge: `align=right` 41, `align=center` 41, без `align` 31, Lumen 21/31/31 при content_x = 21); (4) `border-radius` у `groove` не скругляется ни у `div`, ни у fieldset (Edge рисует кольцо, Lumen — прямоугольные полосы); (5) `inline-flex` вертикальный fieldset с legend: Edge 74x112 во всех трёх вариантах, Lumen 62x156, 82x106, 82x156 (legend учтён как элемент контейнера по inline-оси и по-разному по block-оси). Побочное наблюдение вне срезов: Edge учитывает у legend `text-align: right/center` (`legend-align-text-align.html` в WPT, наоборот, требует, чтобы `align` не отображался в `text-align`; Lumen следует спеке через `justify-self`), и `justify-self: end` при переполнении Edge не применяет — это расхождение Edge со спекой, не берём.

Уже снято: ltr при content_x = 21: без `align` 31, `align=right` 41, `align=center` 41; rtl-fieldset без `align` 31. - **Готово, когда:** юнит-тесты с числами из таблицы Edge зелёные, `160-fieldset-legend` и `172-fieldset-vertical-flex-grid` по-прежнему 0.00 % к Edge.

## FIELDSET-LEGEND-5-S2: интринсики вертикального fieldset
- **Точка входа:** `crates/engine/layout/src/box_tree/intrinsic.rs:99` (`max_content_outer_height`): ветка `FLEX-VWM-5` (`items` по `child_outer_height`, сумма плюс gap) и ветка `GRID-VWM` (`grid_col_intrinsic_sum`, `intrinsic.rs:336`, использует `grid_item_indices` с `rendered_legend_idx_of` на строках 542/662); образец для горизонтального режима — `flex_row_intrinsic_sum`, `intrinsic.rs:761-795` (legend исключён из элементов и берётся максимумом, `.max(legend_w)`); ещё `vertical_block_extent` (`intrinsic.rs:212`) для блочного fieldset.
- **Сделать:** в ветках вертикального flex/grid для бокса с `fieldset_legend` отфильтровать индекс `rendered_legend_idx_of(b)` из элементов и вернуть `max(сумма элементов + рамка, высота legend + его поля)`. Расхождение есть и по block-оси: Edge даёт 74 во всех трёх случаях (vertical-rl flex, vertical-lr grid, flex с max-content), у Lumen 62, 82, 82 — block-размер должен быть `max(legend + его поля, border блока-начала) + содержимое + остальная рамка` (смотри `placed_content_offset`, `fieldset.rs:93`); если block-ось не укладывается в срез, оставить её и отметить остаток.
- **Не трогать:** саму раскладку (`lay_out_legend_vertical`, `settle_legend_vertical`), горизонтальные пути.
- **Готово, когда:** проба (`fieldset{display:inline-flex; writing-mode:vertical-rl; margin:0}` + `legend{width:40px; height:90px; padding:0}` + элемент `width:20px; height:50px`; то же `inline-grid`/`vertical-lr`; то же `display:flex; width:max-content`) даёт у Lumen `getBoundingClientRect` 74x112, как Edge; три таких случая — тесты в `fieldset_legend.rs`; графтест 172 — 0.00 % к Edge.
- **Гейт:** `cargo clippy -p lumen-layout --all-targets -- -D warnings`; `cargo test -p lumen-layout fieldset_legend`; графтест 172 по рецепту Edge headless.

## FIELDSET-LEGEND-5-S3: скруглённый groove/ridge
- **Точка входа:** `crates/engine/paint/src/cpu_raster.rs:2623` (`rasterize_draw_border`: ветка `uniform_solid` с `rasterize_rounded_border_ring`, остальное — `paint_bevel_sides`), `crates/engine/paint/src/border_bevel.rs` (геометрия полос и оттенки `groove_shades`, юнит-тесты на строках ~428-500), `push_rounded_rect_outline` (`cpu_raster.rs:~2680`).
- **Сделать:** при `!radii.all_zero()` и одинаковых по четырём сторонам `groove` или `ridge` (одна толщина, один цвет) рисовать внешнюю полосу (толщина `ceil(N / 2)`) и внутреннюю (остаток) кольцами между скруглёнными прямоугольниками: внешний контур — рамка бокса с радиусами, граница полос — рамка, сдвинутая внутрь на `ceil(N / 2)` с радиусами минус сдвиг (не меньше 0), внутренний — padding box. Цвет каждой части: тёмный/светлый по диагональному разбиению (верх-лево тёмные у внешней полосы `groove`, низ-право светлые, у внутренней наоборот; `ridge` — зеркально), разбиение — клип по двум полигонам, как стыки в `paint_bevel_sides`. Подобрать форму разбиения у углов по пиксель-диффу к Edge. `inset`/`outset` и неоднородные рамки — прежним путём. Затрагивается только CPU-растеризатор; wgpu/femtovg (`border_bevel` общий) — вне среза, отметить в `CAPABILITIES.md`/`docs/engine-gaps.md`, если разница остаётся.
- **Не трогать:** `solid`/`dashed`/`dotted`/`double` с радиусами, раскладку, GPU-бэкенды.

- **Гейт:** `cargo clippy -p lumen-paint --all-targets -- -D warnings` (с `--features backend-femtovg`, если чек без него падает на мёртвом коде paint); `cargo test -p lumen-paint border`; полный `graphic_tests/run.py` (или рецепт Edge headless с A/B `--dump-display-list` по корпусу, если gdigrab недоступен); регистрация теста в `graphic_tests/COVERAGE.md` и `PAGES` драйвера (`driver/tests/cases/snapshot_cpu.rs`).
