# WPT vendor notes — `contenteditable`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-25 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-contenteditable`, `docs/wpt-status.md`), in-scope (⬜, `contenteditable`/`isContentEditable`/`document.designMode` — already partially implemented in Lumen, `crates/js/src/dom.rs`). Same pinned commit, `git sparse-checkout` at the same commit hash, 6 files (`META.yml`, `WEB_FEATURES.yml`, `designmode-iscontenteditable.html`, `plaintext-only.html`, `select-text-change-crash.html`, reftest pair `synthetic-height.html`+`synthetic-height-ref.html`). No out-of-category helpers — every test references only the already-vendored `/resources/testharness.js`+`testharnessreport.js`. Small category: of 5 real test files, the manifest only treats 2 as automatically runnable testharness tests — `select-text-change-crash.html` is WPT-manifest type `crashtest` (no `testharness.js`/`match` link, same class of gap as `acid`/`accessibility`'s crashtests) and `synthetic-height.html` is a `reftest` (`<link rel=match>` to `synthetic-height-ref.html`), both unsupported by the minimal executor. `run_report.py --all --root contenteditable --recursive` completed in ~1:08: `designmode-iscontenteditable.html` (declarative Shadow DOM `<template shadowrootmode="open">` + `document.designMode` + 4 `test()`s reading `isContentEditable` across the shadow boundary) — the `browsingContext.navigate` BiDi command itself timed out (`automation command timed out`), the harness never got to run a single `test()`; isolated `--dump-layout` repros of the design-mode-only and shadow-only halves don't reproduce a hang, so this looks like a live/interactive-path-only defect, not a parse-time one — filed as [BUG-345](../../bugs/BUG-345-FIXED.md) (a navigation-command hang is a more severe class of gap than the usual first-pass finding, in the same user-visible category as BUG-307). `plaintext-only.html` — harness OK, 0/2 subtests FAIL: `contentEditable`'s getter/setter don't recognize the spec's third state, `"plaintext-only"` (folds into `inherit` instead) — filed as [BUG-344](../../bugs/BUG-344-FIXED.md). 1/2 harness OK, 0/2 subtests. Both filed explicitly (unlike most first-pass vendor entries) — both are functional defects in already-implemented parts of the engine (`contentEditable` IDL, live navigation), not missing APIs. See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-25 (`tests/wpt/contenteditable/`, 6 файлов: `META.yml`, `WEB_FEATURES.yml`, `designmode-iscontenteditable.html`, `plaintext-only.html`, `select-text-change-crash.html`, reftest-пара `synthetic-height.html`+`synthetic-height-ref.html`). Внекатегорийных хелперов не обнаружено. Манифест отбирает только 2 из 5 реальных тестов как автопрогоняемые testharness (`select-text-change-crash.html` — WPT-манифест тип `crashtest`, `synthetic-height.html` — `reftest`, оба не поддержаны минимальным исполнителем, тот же класс гэпа, что `acid`/`accessibility`): `designmode-iscontenteditable.html` (декларативный Shadow DOM + `document.designMode`) — сама BiDi-команда `browsingContext.navigate` таймаутится (`automation command timed out`), харнесс не успел выполнить ни одного `test()` — заведён [BUG-345](../../bugs/BUG-345-FIXED.md) (навигационное зависание, не рядовой executor-гэп); `plaintext-only.html` — harness OK, 0/2 сабтестов FAIL (`contentEditable`-геттер/сеттер не распознают спековое значение `plaintext-only`, сворачивают в `inherit`) — заведён [BUG-344](../../bugs/BUG-344-FIXED.md). 1/2 harness OK, 0/2 сабтестов. Оба заведены явно (не «первый проход без BUG-NNN») — оба функциональные дефекты уже реализованных частей движка (contentEditable IDL, live-навигация), а не отсутствующие API
