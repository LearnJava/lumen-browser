A live probe (`--mcp-live-port`, independent of the WPT runner) found two new, previously unfiled defects: [BUG-719](../../bugs/BUG-719-OPEN.md) (`MIDIPort`/`MIDIInput`/`MIDIOutput`/`MIDIAccess` are plain `class X extends EventTarget`/`_ETBase` with no constructor guard — same defect class as [BUG-672](../../bugs/BUG-672-OPEN.md)/[BUG-629](../../bugs/BUG-629-OPEN.md)/[BUG-374](../../bugs/BUG-374-OPEN.md)/[BUG-713](../../bugs/BUG-713-OPEN.md), fifth independent surface) and [BUG-720](../../bugs/BUG-720-OPEN.md) (spec-mandated `MIDIInputMap`/`MIDIOutputMap` globals don't exist at all — a single non-standard `MIDIPortMap` stands in for both). See `docs/wpt-status.md` for the full breakdown.

Скоуп 🚫 не по причине пустого движка — `crates/js/src/web_midi.rs` реально реализует Phase 0 заглушку, `requestMIDIAccess()` резолвится сразу с пустыми `inputs`/`outputs`.
