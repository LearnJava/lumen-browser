# WPT vendor notes — `selection`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-06 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-selection`, `docs/wpt-status.md`). Same pinned commit, `git sparse-checkout add` at the same commit hash, `LICENSE-WPT.md` copied from the sibling `element-timing` category, 100 files (`META.yml`, `WEB_FEATURES.yml`, root tests plus `anonymous/`, `bidi/`, `caret/`, `contenteditable/`, `shadow-dom/`, `textcontrols/` subdirs). No `.https.` files, 7 `variant` hits, 31/100 files pull `testdriver.js`; the `editing/include/editor-test-utils.js`/`tests.js` cross-category dependency is already vendored (`tests/wpt/editing/`, present since an earlier category). `run_report.py --all --root selection --recursive` completed in ~5:32 (128 selected ids): **68/128 harness OK, 22/375 subtests**. Dominant failure classes are all reconfirmations of already-open bugs — [BUG-368](../../bugs/BUG-368-OPEN.md) (`innerHTML` text stub — markup set via `innerHTML` never parses into real elements, so `querySelector` returns `null` and downstream `setBaseAndExtent(null, …)` yields "Selection.getRangeAt: no range"), [BUG-384](../../bugs/BUG-384-OPEN.md) (named access on `window` missing — bare `container`/`input1`/etc. identifiers throw `ReferenceError`), [BUG-346](../../bugs/BUG-346-OPEN.md) (`..` dot-segments not collapsed by `Url::resolve()` — literal `../../editing/include/editor-test-utils.js` 404s), [BUG-462](../../bugs/BUG-462-OPEN.md) (`Node.contains` missing — blocks `test_driver.click()`), [BUG-415](../../bugs/BUG-415-OPEN.md) (detached `createHTMLDocument()` document has no Node methods/HTML accessors — `foreignDoc.body` is `undefined`, the single largest ERROR cluster via the shared `selection/common.js::setupRangeTests` helper, 15 files). A live probe (`--mcp-live-port`, independent of the WPT runner) found one new, previously unfiled defect — [BUG-671](../../bugs/BUG-671-OPEN.md): `window.Selection` (the global interface constructor) doesn't exist at all, even though `getSelection()` works and returns a Selection-shaped plain object (`constructor.name === "Object"`), so `getSelection() instanceof Selection` throws instead of returning `true` — blocks the sanity-check assertion repeated at the top of nearly every file in the category. See `docs/wpt-status.md` for the full breakdown.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-08-06 (коммит `35be3b44`, `tests/wpt/selection/`, 100 файлов: `anonymous/`, `bidi/`, `caret/`, `contenteditable/`, `shadow-dom/`, `textcontrols/`). Весь доминирующий сигнал — реконфирмация уже открытых дефектов: [BUG-368](../bugs/BUG-368-OPEN.md) (`innerHTML` — текстовая заглушка, вставленная разметка не парсится, `querySelector` не находит вставленные узлы → `setBaseAndExtent(null,…)` → «Selection.getRangeAt: no range», крупнейший кластер `anonymous/setBaseAndExtent-start-or-end-in-anonymous-shadow-container.html`); [BUG-384](../bugs/BUG-384-OPEN.md) (именованный доступ `window.<id>` не реализован — `container is not defined` роняет `bidi/modify.tentative.html` до регистрации тестов); [BUG-346](../bugs/BUG-346-OPEN.md) (`..`-сегменты в `Url::resolve()` не схлопываются — `../../editing/include/editor-test-utils.js` 404-ит буквально); [BUG-462](../bugs/BUG-462-OPEN.md) (`Node.contains` отсутствует — блокирует `test_driver.click()`, 28 сабтестов); [BUG-415](../bugs/BUG-415-OPEN.md) (отсоединённый документ `createHTMLDocument()` без Node-методов/HTML-аксессоров — `foreignDoc.body === undefined`, крупнейший ERROR-кластер через общий `selection/common.js::setupRangeTests`, 15 файлов). Живая проба (`--mcp-live-port`) нашла независимую новую находку — [BUG-671](../bugs/BUG-671-OPEN.md): глобальный интерфейс-конструктор `window.Selection` отсутствует вовсе (`'Selection' in window === false`), при этом `getSelection()` работает и возвращает Selection-подобный объект с `constructor.name === "Object"` — `instanceof Selection` бросает `TypeError` вместо `true`, блокируя sanity-check, повторённый почти в каждом файле категории
