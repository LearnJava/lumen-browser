# WPT vendor notes — `geolocation-sensor`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-28 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-geolocation-sensor`, `docs/wpt-status.md`), included despite its 🚫 scope note (hardware sensor API) by the same standing user decision as `accelerometer`/`gamepad`/`generic-sensor`. Same pinned commit, `git sparse-checkout` at the same commit hash, 3 files (`META.yml`, `historical.https.html`, `LICENSE-WPT.md` — no `WEB_FEATURES.yml`). The smallest category in the backlog so far: a single executable file, and not a member of the Sensor API family — a "historical" regression test. The `geolocation-sensor` spec was published and later marked Discontinued Draft by W3C (`https://www.w3.org/TR/2026/DISC-geolocation-sensor-20260203/`); the sole test asserts `GeolocationSensor` must **not** be defined on `window`. `run_report.py --all --root geolocation-sensor --recursive` completed in **33 s**: **0/1 harness OK, 0/0 subtests** (1 TIMEOUT, ordinary HTTPS-port gap — the one file is `.https.html`, no testdriver.js). Since the run produced no signal, a headless `--mcp-port`/`eval` probe (no live window needed — fully synchronous check) confirmed the assertion directly: `'GeolocationSensor' in window` → `false`, `typeof window.GeolocationSensor` → `'undefined'`; a grep of `crates/` confirms the name doesn't appear anywhere in the engine. The only vendored category so far where the probe comes back positive with zero findings — Lumen correctly does not implement the discontinued draft, no bug filed.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/geolocation-sensor/`, 3 файла: `META.yml`, `historical.https.html`, `LICENSE-WPT.md` — `WEB_FEATURES.yml` у категории нет), включена вопреки скоупу 🚫 (датчик устройства) тем же постоянным решением пользователя, что `accelerometer`/`gamepad`/`generic-sensor`. Самая маленькая категория backlog-а на сегодня — один-единственный исполняемый файл, не обёртка над семейством сенсоров, а «historical» regression-тест: спека `geolocation-sensor` была опубликована и затем помечена W3C как Discontinued Draft (`https://www.w3.org/TR/2026/DISC-geolocation-sensor-20260203/`), и единственное, что тест проверяет — что `GeolocationSensor` **не** появился в `window`. `run_report.py --all --root geolocation-sensor --recursive` — **33 с, 0/1 harness OK, 0/0 сабтестов** (1 TIMEOUT, обычный HTTPS-порт-гэп — единственный файл `.https.html`, без testdriver.js). Раз прогон не исполнился, применена проба «прогони даже без сигнала» ([BUG-393](../bugs/BUG-393-FIXED.md)/[BUG-395](../bugs/BUG-395-FIXED.md) методология): headless `--mcp-port`/`eval` (категория целиком синхронная, живое окно не нужно) — `'GeolocationSensor' in window` → `false`, `typeof window.GeolocationSensor` → `'undefined'`. Grep по `crates/` подтверждает: имя `GeolocationSensor` в кодовой базе не встречается вовсе. Единственная вендоренная категория backlog-а с положительным результатом пробы и без единой находки — Lumen корректно не реализует свёрнутый черновик, багов не заведено.
