# WPT vendor notes — `encoding-detection`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-27 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-encoding-detection`, `docs/wpt-status.md`), in-scope (⬜, the tentative Encoding Detection spec — heuristic detection of a legacy encoding from content bytes plus page language, observed through `document.characterSet`). Same pinned commit, `git sparse-checkout` at the same commit hash, 109 files: 75 root-level `*.tentative.html`/`.html` tests, `support/` with the 31 `*-late.sub.html` popup fixtures, the two `__dir__.headers` files (`X-Content-Type-Options: nosniff`, which is load-bearing here — it suppresses MIME sniffing so only the encoding heuristic decides), and `LICENSE-WPT.md`. Upstream ships neither `META.yml` nor `WEB_FEATURES.yml` for this category. **No out-of-category dependencies at all** — the tests reference only `/resources/testharness.js`+`testharnessreport.js`, so unlike `FileAPI`/`ai`/`encoding` there is no survey gap here; there are also no `<meta name=variant>` files and no `.https.` tests, which makes this the cheapest category in the backlog so far: `run_report.py --all --root encoding-detection --recursive` finished in **8 min 25 s**, 75 selected files → exactly 75 ids, no fan-out. Result: **44/75 harness OK, 0/44 subtests passed**, and the category splits into two blocks with one cause each. **(a) The 44 executing tests all fail on [BUG-358](../../bugs/BUG-358-OPEN.md)**: the live global `document` exposes none of the document-metadata IDL attributes — `characterSet`, `charset`, `inputEncoding`, `compatMode`, `contentType`, `URL`, `documentURI`, `location` are all absent (`'characterSet' in document` === false). Every test here is the same three lines (`assert_equals(document.characterSet, "<enc>", …)`), so the failure text is uniform: `expected (string) "…" but got (undefined) undefined` ×43, plus one `document.characterSet.toUpperCase()` variant dying with `Cannot read properties of undefined`. Those attributes exist only on detached documents (`_lumen_build_detached_document`, `crates/js/src/dom.rs:4762-4769`); the live `document` is a separate hand-written literal (`dom.rs:6989+`) that never got them. **(b) All 31 TIMEOUTs are exactly the `*-late.tentative.html` set, all on [BUG-359](../../bugs/BUG-359-FIXED.md)**: those tests do `window.open("support/…-late.sub.html")` and the relative URL is never resolved against the document base, reaching the network layer verbatim (`invalid url: missing scheme`) — a third independent site of the same family as [BUG-346](../../bugs/BUG-346-OPEN.md)/[BUG-347](../../bugs/BUG-347-OPEN.md). A second barrier sits behind it: `window.open` returns a stub with no real `opener`/`postMessage` and the shell opens a new tab, so these tests would still time out even with the URL fixed. Both bugs confirmed outside WPT with `--dump-layout` probes. Worth recording for whoever fixes BUG-358: even with `characterSet` wired up at most 2 of the 44 could pass — the tests assert 22 distinct target encodings and `lumen_encoding::Encoding` (`crates/engine/encoding/src/lib.rs:41-54`) implements two of them (windows-1251, IBM866; its third legacy member is koi8-**r** while the category tests koi8-**u**). See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-27 (коммит `35be3b44`, `tests/wpt/encoding-detection/`, 109 файлов: 75 корневых `*.tentative.html`/`.html`-тестов, `support/` — 31 `*-late.sub.html`-фикстура, два `__dir__.headers` (`X-Content-Type-Options: nosniff`), `LICENSE-WPT.md`; ни `META.yml`, ни `WEB_FEATURES.yml` в апстриме у категории нет), в скоупе (⬜, tentative-спека Encoding Detection — эвристическое определение legacy-кодировки по байтам содержимого + языку страницы, наблюдаемое через `document.characterSet`). Внекатегорийных хелперов нет вовсе — категория самодостаточна, `<meta name=variant>` не используется ни в одном файле, `.https.`-тестов нет; поэтому прогон дешёвый: `run_report.py --all --root encoding-detection --recursive` уложился в **8 мин 25 с** на 75 id — 75 отобранных файлов дали ровно 75 id, без раскрытия. Результат: **44/75 harness OK, 0/44 сабтестов**. Два блока, у каждого ровно одна причина. **(а) 44 исполнившихся теста — 0 пройденных сабтестов, все на [BUG-358](../bugs/BUG-358-OPEN.md)**: живой глобальный `document` не отдаёт `characterSet` (как и `charset`/`inputEncoding`/`compatMode`/`contentType`/`URL`/`documentURI`/`location`) — свойства нет вовсе, `'characterSet' in document` === false. Каждый тест категории это три строки `assert_equals(document.characterSet, "<enc>", …)`, поэтому текст падения одинаков: `expected (string) "…" but got (undefined) undefined` (43 теста) плюс один вариант с `document.characterSet.toUpperCase()` → `Cannot read properties of undefined`. Атрибуты определены ТОЛЬКО на detached-документах (`_lumen_build_detached_document`, `crates/js/src/dom.rs:4762-4769`), живой документ (`dom.rs:6989+`) — отдельный рукописный литерал, в который их не добавили. **(б) 31 TIMEOUT — ровно все `*-late.tentative.html`, все на [BUG-359](../bugs/BUG-359-FIXED.md)**: тест делает `window.open("support/…-late.sub.html")`, относительный URL не резолвится против базы документа и уходит в сеть дословно (`invalid url: missing scheme`) — третий независимый сайт того же семейства, что [BUG-346](../bugs/BUG-346-OPEN.md)/[BUG-347](../bugs/BUG-347-OPEN.md). Там же второй барьер: `window.open` возвращает заглушку без реального `opener`/`postMessage`, а шелл открывает новую вкладку, поэтому `-late`-тесты не прошли бы и с починенным URL. Оба бага подтверждены вне WPT через `--dump-layout`-пробы. Отдельно зафиксировано для будущего фикса: даже с подключённым `characterSet` прошли бы максимум 2 из 44 — 44 теста требуют 22 различные кодировки, а `lumen_encoding::Encoding` (`crates/engine/encoding/src/lib.rs:41-54`) знает из них только windows-1251 и IBM866 (третья legacy-члена — koi8-**r**, а категория тестирует koi8-**u**)
