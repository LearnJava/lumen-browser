# WPT vendor notes — `layout-instability`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-05 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-layout-instability`, `docs/wpt-status.md`), scope ⬜ (candidate, Layout Instability API / `LayoutShift`). Same pinned commit, `git sparse-checkout add` at the same commit hash, 87 files (`META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` copied from the sibling `element-timing` category, 82 top-level test files, `resources/util.js`). No `variant` hits, no `.https.` files, 6 `testdriver.js` hits. `run_report.py --all --root layout-instability --recursive` completed in ~5:49 (82 selected ids): **53/82 harness OK, 17/82 subtests passed**. Key finding: the API is declared in the JS shim but never wired to the engine — `PerformanceObserver.supportedEntryTypes` lists `'layout-shift'` and the JS-side delivery hook `_lumen_deliver_layout_shift` exists (`crates/js/src/dom.rs`), but the Rust trigger `deliver_layout_shift` (`crates/shell/src/main.rs`) is marked `#[allow(dead_code)]` and is never called from real layout/reflow — shifts never reach an observer (28 TIMEOUT on `ScoreWatcher.promise`, which never resolves); `window.LayoutShift` (constructor, `toJSON()`, the `layoutShift` entry in `supportedEntryTypes`) isn't implemented at all (5 FAIL `assert_implements: Layout Instability is not supported`). The remaining 29 FAIL are known masks, not new findings: 23 [BUG-384](../bugs/BUG-384-FIXED.md) (named access on Window — `target`/`sticky`/`multicol`/`transformed`/… don't resolve as globals), 2 [BUG-525](../bugs/BUG-525-OPEN.md) (`document.scrollingElement` missing, `Cannot set properties of undefined (setting 'scrollTop')`), 4 `test_driver.Actions is not a constructor` (the executor doesn't implement `Actions`-based input, same class of gap as `send_keys`). No bug filed: first pass documenting a declared-but-unwired API. See `docs/wpt-status.md` for the full breakdown.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-08-05 (коммит `35be3b44`, `tests/wpt/layout-instability/`, 87 файлов: `META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` скопирован из соседней `element-timing`, 82 тестовых файла верхнего уровня, `resources/util.js`), скоуп ⬜ (кандидат, Layout Instability API / `LayoutShift`). `run_report.py --all --root layout-instability --recursive` — ~5:49, 82 отобранных id (без `.https.`): **53/82 harness OK, 17/82 сабтестов**. Остальные 29 FAIL — известные маски, не новые находки: 23 [BUG-384](../bugs/BUG-384-FIXED.md) (named access на Window — `target`/`sticky`/`multicol`/`transformed`/… не резолвятся как глобалы), 2 [BUG-525](../bugs/BUG-525-OPEN.md) (`document.scrollingElement` отсутствует, `Cannot set properties of undefined (setting 'scrollTop')`), 4 `test_driver.Actions is not a constructor` (executor не реализует `Actions`-based ввод, тот же класс ограничения, что и `send_keys` — `docs/wpt-status.md`/CLAUDE.md). Новых багов не заведено — первый проход по объявленному, но не подключённому к движку API.
