# WPT vendor notes — `wasm`

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-08-09 (пинованный коммит `35be3b44`, `git sparse-checkout add wasm`, `tests/wpt/wasm/`, 830 файлов — `core/` 530 (включая проповедальные подкаталоги `gc`/`exceptions`/`memory64`/`multi-memory`/`simd`/`relaxed-simd`/`bulk-memory`), `jsapi/` 141, `webapi/` 90, `serialization/` 64). `run_report.py --all --root wasm --recursive --processes=4` — ~6:04, 405 отобранных id: **342/373 harness OK, 11314/179992 сабтестов (~6.3%)**. Заголовочная цифра harness OK обманчива — почти все «OK»-файлы всё равно провалили большинство своих сабтестов. Два независимых, подтверждённых живой пробой дефекта объясняют доминирующую часть провалов: [BUG-700](../bugs/BUG-700-OPEN.md) — `parse_element_section` (`crates/js/src/wasm/parser.rs:547-599`) реализует только element-segment flags 0/1/2, апстримный генератор spec-тестов по умолчанию эмитит flags 3-7 (expr-encoded elements) почти в каждом файле, включая обычные control-flow тесты без всякого отношения к GC/SIMD/memory64 (`br.wast:3` — воспроизведено на точных байтах теста: `WebAssembly.validate()` → `false`, `WebAssembly.compile()` → `CompileError: unsupported element segment flags 4`); режет `wasm/core` (49513 FAIL), `wasm/core/simd` (32443), `wasm/core/relaxed-simd` (19725), `wasm/core/memory64` (10751), `wasm/core/multi-memory` (8932) примерно равномерно, поскольку зависит от энкодера, а не от тестируемого proposal-а. [BUG-699](../bugs/BUG-699-OPEN.md) — `WebAssembly.Table` конструктор (`crates/js/src/webassembly.rs:112-125`) кидает `TypeError: Cannot mix BigInt and other types` на `descriptor.initial | 0`/`.maximum | 0` при BigInt-аргументах, а общий harness-сетап каждого файла (`js/harness/async_index.js::reinitializeRegistry`) строит именно такую 64-битную таблицу (`table64: new WebAssembly.Table({initial: 10n, maximum: 20n, address: "i64"})`) — бросок происходит внутри общей promise-цепочки `chain`, отравляя её на первом же звене; все последующие `module()`/`instance()`/`run()` того же файла наследуют ту же самую устаревшую ошибку («Cannot read properties of undefined (reading 'source'/'run'/…)»), 510 unhandled-rejection «Reinitialize the default imports» из 373 файлов. `CAPABILITIES.md`'s заявка «SIMD/relaxed-SIMD fully supported» непроверяема по спек-корпусу до фикса BUG-700 — подавляющее большинство SIMD-тестов не доходят до успешного `compile()`. GC/memory64/multi-memory/exceptions отказы дополнительно (и ожидаемо) объясняются отсутствием этих proposal-ов в движке (не заявлены в CAPABILITIES.md), но точную долю «реального отсутствия фичи» от «доли BUG-700/BUG-699» нельзя измерить без повторного прогона после фиксов.
