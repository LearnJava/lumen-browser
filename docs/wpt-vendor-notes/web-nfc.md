# WPT vendor notes — `web-nfc`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-09 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-web-nfc`, `docs/wpt-status.md`), scope 🚫 (out of scope — hardware NFC API, no reader hardware or OS NFC stack to bind to). Same pinned commit, `git sparse-checkout add` at the same commit hash, `LICENSE-WPT.md` copied from the sibling `web-locks` category, 20 files (`META.yml`, `WEB_FEATURES.yml`, `README.md`, `resources/` — `nfc-helpers.js`+`support-iframe.html`, 11 non-manual root test files, 4 `-manual` root test files excluded by `run_report.py`'s own selection). 18 of 20 files `.https.`; only 2 files pull `testdriver.js`. `run_report.py --all --root web-nfc --recursive` selected 11 ids, completed in ~3:27: **1/11 harness OK, 0/1 subtests**. The 9 `.https.` ids TIMEOUT on the standard TLS `UnknownIssuer` gap ([BUG-657](../../bugs/BUG-657-OPEN.md)). The one non-`.https.` test that ran (`nfc_insecure_context.html`) reached harness OK but its single subtest FAILed: `assert_false(isSecureContext)` got `true` — same root cause as `web-locks`, reconfirmation of already-open [BUG-399](../../bugs/BUG-399-FIXED.md) (`isSecureContext` hardcoded `true` even for `file:`/non-`.https.` pages). The sibling `.https.` `nfc_permission.https.window.html` ERRORed instead of timing out (`AssertionError: Got results from nfc_insecure_context.html, expected nfc_permission.https.window.html`) — reconfirmation of already-open [BUG-380](../../bugs/BUG-380-FIXED.md) (stale results from a reused browsing context leaking into the next test after a failed navigation). Live probe (`--mcp-live-port`) of the category's own API confirmed `navigator.nfc`/`NDEFReader`/`NDEFMessage`/`NDEFRecord`/`NDEFReadingEvent` are all `undefined` (`grep -rni nfc crates/js/src crates/shell/src` — the only hit is the unrelated Permissions-Policy `'nfc'` feature-name string) — expected for a 🚫-scope category, not a bug. No new bug filed this pass. See `docs/wpt-status.md` for the full breakdown.
