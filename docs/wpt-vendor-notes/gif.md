# WPT vendor notes — `gif`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-28 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-gif`, `docs/wpt-status.md`), scope ⬜ (candidate). Same pinned commit, `git sparse-checkout` at the same commit hash, 4 files (`META.yml` — no `WEB_FEATURES.yml`, `reset-no-gce-1.html`+`reset-no-gce-ref.html` — one `rel=match` reftest pair, `reset-no-gce.gif` — the fixture image, `LICENSE-WPT.md`). One out-of-category helper (`/common/reftest-wait.js`) not vendored, same documented survey gap as `FileAPI`. The smallest fully-original category so far: a single reftest, no testharness at all. `run_report.py --all --root gif --recursive` confirmed the expected outcome in ~24 s: the sole test is WPT-manifest type `reftest`, unsupported by the minimal executor (`Unsupported test type reftest for product lumen`, same class as `apng`/`acid`/`animation-worklet`) — **0/0**, no signal from the run. Per the "probe even when the run yields nothing" rule, the fixture GIF itself was fed directly to Lumen's own decoder (`lumen-image`, `include_bytes!` + `cargo test`, since the reftest can't be driven): `decode_gif_animated` on `reset-no-gce.gif` (2×2, 3 frames — this is exactly the GIF disposal-method edge case the WPT test exercises: frame 0 has GCE+`transparent_index=0`(no-op), frame 1 has GCE+`transparent_index=2`(fully transparent), frame 2 has **no preceding GCE at all**, which the upstream test comment calls out explicitly) decodes frame 0 correctly (`[255,0,0,255]`×4) then fails on frame 1 with `DecodeError("invalid code in LZW stream")` — reproduced identically with both `ColorOutput::RGBA` and the default indexed output, so it's not an RGBA-compositing bug. Cross-checked with Pillow (`tests/wpt/.venv`, an independent decoder) on the byte-identical vendored file (confirmed via `xxd` diff against the upstream sparse-checkout, so no vendoring corruption): Pillow decodes all 3 frames cleanly and produces exactly what the upstream comment describes (opaque red → fully transparent → opaque green). New finding: BUG-396 — fixed by P3 on 2026-08-11, and this first diagnosis ("a bug in the `gif` crate, not in Lumen's glue") turned out to be wrong. GCE plays no part: all three frames carry structurally identical LZW and every pixel decodes correctly. The stream was written by an early-change encoder (giflib family), so bits remain past the frame's last pixel that `weezl` reads as a non-existent code — and it was `gif.rs`'s own glue that walked into them, because `next_frame_info()`+`read_into_buffer()` forces the LZW decoder to drain the frame's tail, which neither Blink nor Pillow ever do. The two passes are now split (container pass with `skip_frame_decoding`, per-frame `FrameDecoder`); the crate stays at 0.14.2. BUG-763 was filed on the side: frames smaller than the logical screen are not composited with `left`/`top`/disposal.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/gif/`, 4 файла: `META.yml` — `WEB_FEATURES.yml` у категории нет, `reset-no-gce-1.html`+`reset-no-gce-ref.html` — reftest-пара `rel=match`, `reset-no-gce.gif` — фикстура, `LICENSE-WPT.md`), скоуп ⬜ (кандидат). Внекатегорийный хелпер `/common/reftest-wait.js` не довендорен, та же методология, что `FileAPI`. Самая маленькая категория backlog-а с полностью оригинальным (не переиспользованным) содержимым: единственный тест — reftest, testharness нет вовсе. `run_report.py --all --root gif --recursive` — **~24 с, 0/0**: единственный файл — WPT-манифест тип `reftest`, исполнитель не поддерживает (`Unsupported test type reftest`, тот же класс, что `apng`/`acid`/`animation-worklet`), сигнала прогон не дал. По правилу «пробуй даже без сигнала» ([BUG-395](../../bugs/BUG-395-FIXED.md) методология) сама GIF-фикстура скормлена напрямую декодеру Lumen (`lumen-image`, `include_bytes!`+`cargo test`, раз reftest прогнать нечем): `decode_gif_animated` на `reset-no-gce.gif` (2×2, 3 кадра — ровно тот edge case disposal-метода, который тестирует WPT: кадр 0 с GCE и `transparent_index=0` (без эффекта), кадр 1 с GCE и `transparent_index=2` (кадр целиком прозрачен), кадр 2 **вовсе без предшествующего GCE**, что явно оговорено в комментарии апстрима) декодирует кадр 0 корректно (`[255,0,0,255]`×4), затем падает на кадре 1 с `DecodeError("invalid code in LZW stream")` — воспроизведено одинаково и с `ColorOutput::RGBA`, и с дефолтным индексированным выводом, значит не баг RGBA-компоузинга. Сверено с Pillow (`tests/wpt/.venv`, независимый декодер) на побайтово идентичном вендоренном файле (подтверждено `xxd`-диффом против апстримного sparse-checkout — повреждения при вендоринге нет): Pillow декодирует все 3 кадра чисто и даёт ровно то, что описывает апстримный комментарий (непрозрачный красный → полностью прозрачный → непрозрачный зелёный). Новая находка: [BUG-396](../../bugs/BUG-396-FIXED.md) — **закрыт P3 2026-08-11**, и первичный диагноз («дефект крейта `gif`, не кода Lumen») оказался не тем: GCE ни при чём, все три кадра несут структурно одинаковый LZW и декодируются верно, а поток писал энкодер early-change-семейства (giflib), поэтому за последним пикселем кадра остаются биты, которые `weezl` читает как несуществующий код. Ломала анимацию именно склейка в `gif.rs`: пара `next_frame_info()`+`read_into_buffer()` заставляла LZW-декодер дочитывать хвост кадра, чего Blink и Pillow не делают. Проходы разведены (контейнерный `skip_frame_decoding` + `FrameDecoder` на кадр), крейт остался на 0.14.2. Побочно заведён [BUG-763](../../bugs/BUG-763-OPEN.md) — кадры меньше экрана не компонуются с учётом `left`/`top`/disposal.
