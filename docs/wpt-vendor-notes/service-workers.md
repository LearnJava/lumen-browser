# WPT vendor notes — `service-workers`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-06 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-service-workers`, `docs/wpt-status.md`). Same pinned commit, `git sparse-checkout add` at the same commit hash, `LICENSE-WPT.md` copied from the sibling `serial` category, 794 files (`META.yml`, `WEB_FEATURES.yml`, `cache-storage/`, `service-worker/`). Almost the whole category is `.https.` (305/312 test-ish files), only 6 files pull `testdriver.js` directly. `run_report.py --all --root service-workers --recursive --processes=4` completed in ~34:24 (297 selected ids): **1/287 harness OK, 0/1 subtests**. 285 ids TIMEOUT on the already-documented WPT-RUN-2 TLS `UnknownIssuer` gap; 1 ERROR is a stuck-browsing-context artifact (same class as BUG-380 — `AssertionError: Got results from data-iframe.html, expected data-transfer-files.https.html`, caught by the executor's own `assert result_url == test.url`, not a false pass); the single non-`.https.` test that actually ran (`service-worker/data-iframe.html`) itself failed its one subtest on an unrelated 500 from `resources/test-helpers.sub.js` (a `.sub.html` template-substitution gap in `wptserve/pipes.py`, same class documented for `focus`/`clear-site-data`). A live probe (`--mcp-live-port`, independent of the WPT runner, driving the real `navigator.serviceWorker`/`_lumen_sw_*`/`_sw_origin` machinery in `crates/js/src/dom.rs`+`crates/js/src/v8_runtime.rs`) found two new, previously unfiled defects: [BUG-674](../../bugs/BUG-674-FIXED.md) — the Service Worker registration table and Cache Storage are both keyed by an unauthenticated JS-string "origin" argument with no server-side binding to the page's real navigated origin, so any page script can register/read/write another origin's registrations and cache entries (same defect class as [BUG-371](../../bugs/BUG-371-FIXED.md)); [BUG-675](../../bugs/BUG-675-FIXED.md) — `navigator.serviceWorker.register()` performs no validation of its script-URL argument at all, so a cross-origin script URL and a `javascript:`-scheme URL both register successfully instead of rejecting (same "no argument validation" class as BUG-646/656/666/667). See `docs/wpt-status.md` for the full breakdown.

## Разведка WPT-SW-SCOUT (2026-10-27)

Статус: закрыта 2026-10-27. Баги [BUG-1742](../../bugs/BUG-1742-OPEN.md)…[BUG-1747](../../bugs/BUG-1747-OPEN.md) и дополнение к [BUG-1226](../../bugs/BUG-1226-OPEN.md) (очередь P3 в порядке J → C → A → F → D → E → G), задачи SW-MSG, SW-MODULE, SW-PRELOAD-ROUTER (очередь P1). Код не менялся.

**Прогон** (`run_corpus.py --prefixes service-workers --processes 6`, `dev-release` от `main` `c9bcc4bab`, 1133 с): 331 id, **11.52 %** (в WPT-RUN-16 — 11.44 %), балл 38.14, harness OK 161, сабтесты 299 / 2 367. Статусы: OK 160, PASS 1, TIMEOUT 146, ERROR 21, CRASH 2, FAIL 1. Одно убийство по RSS-лимиту (4.02 ГБ).

**Главное.** Сервис-воркер в Lumen — имитация на таймерах: регистрация не исполняет скрипт до «активации», `postMessage` в обе стороны — no-op, `clients` — заглушки. Почти все тесты `service-worker/` отдают результат из воркера сообщением, поэтому B (сообщения) и C (жизненный цикл) — TIMEOUT целиком. Второй по весу корень — J: тесты строят SW-окружение в iframe, а фасад `iframe.contentWindow` отдаёт глобалы по значению. `cache-storage/` живёт отдельно: в окне Cache API работает с ошибками формы (E), в воркерах `caches` нет вовсе (F).
