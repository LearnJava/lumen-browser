# WPT vendor notes — `service-workers`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-06 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-service-workers`, `docs/wpt-status.md`). Same pinned commit, `git sparse-checkout add` at the same commit hash, `LICENSE-WPT.md` copied from the sibling `serial` category, 794 files (`META.yml`, `WEB_FEATURES.yml`, `cache-storage/`, `service-worker/`). Almost the whole category is `.https.` (305/312 test-ish files), only 6 files pull `testdriver.js` directly. `run_report.py --all --root service-workers --recursive --processes=4` completed in ~34:24 (297 selected ids): **1/287 harness OK, 0/1 subtests**. 285 ids TIMEOUT on the already-documented WPT-RUN-2 TLS `UnknownIssuer` gap; 1 ERROR is a stuck-browsing-context artifact (same class as BUG-380 — `AssertionError: Got results from data-iframe.html, expected data-transfer-files.https.html`, caught by the executor's own `assert result_url == test.url`, not a false pass); the single non-`.https.` test that actually ran (`service-worker/data-iframe.html`) itself failed its one subtest on an unrelated 500 from `resources/test-helpers.sub.js` (a `.sub.html` template-substitution gap in `wptserve/pipes.py`, same class documented for `focus`/`clear-site-data`). A live probe (`--mcp-live-port`, independent of the WPT runner, driving the real `navigator.serviceWorker`/`_lumen_sw_*`/`_sw_origin` machinery in `crates/js/src/dom.rs`+`crates/js/src/v8_runtime.rs`) found two new, previously unfiled defects: [BUG-674](../../bugs/BUG-674-OPEN.md) — the Service Worker registration table and Cache Storage are both keyed by an unauthenticated JS-string "origin" argument with no server-side binding to the page's real navigated origin, so any page script can register/read/write another origin's registrations and cache entries (same defect class as [BUG-371](../../bugs/BUG-371-OPEN.md)); [BUG-675](../../bugs/BUG-675-OPEN.md) — `navigator.serviceWorker.register()` performs no validation of its script-URL argument at all, so a cross-origin script URL and a `javascript:`-scheme URL both register successfully instead of rejecting (same "no argument validation" class as BUG-646/656/666/667). See `docs/wpt-status.md` for the full breakdown.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-08-06 (коммит `35be3b44`, `tests/wpt/service-workers/`, 794 файла: `cache-storage/`, `service-worker/`). `run_report.py --all --root service-workers --recursive --processes=4` — ~34:24, 297 отобранных id, почти все `.https.`: **1/287 harness OK, 0/1 сабтестов**. 285 TIMEOUT на уже задокументированном TLS-гэпе `UnknownIssuer`; 1 ERROR — артефакт застрявшего browsing context (класс BUG-380, `AssertionError: Got results from data-iframe.html, expected data-transfer-files.https.html`); единственный исполнившийся не-`.https.` тест (`data-iframe.html`) сам провалил единственный сабтест на постороннем 500 (`resources/test-helpers.sub.js`, `.sub.html`-гэп `wptserve/pipes.py`). Живая проба (`--mcp-live-port`) реальной SW-инфраструктуры (`_sw_origin`/`_lumen_sw_*` натив, `_sw_container.register`) нашла два новых бага: [BUG-674](../bugs/BUG-674-OPEN.md) — реестр Service Worker и Cache Storage ключуется недоверенной JS-строкой origin без серверной привязки к реально навигированному origin (любой скрипт может подделать/прочитать чужой origin, класс [BUG-371](../bugs/BUG-371-OPEN.md)); [BUG-675](../bugs/BUG-675-OPEN.md) — `navigator.serviceWorker.register()` не валидирует script URL вовсе (cross-origin и `javascript:`-схема успешно регистрируются, класс BUG-646/656/666/667)
