# WPT vendor notes — `webdriver`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-09 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-webdriver`, `docs/wpt-status.md`), scope 🚫 (WPT's own WebDriver/BiDi protocol conformance suite, not a web-page feature). Same pinned commit, `git sparse-checkout add` at the same commit hash, `LICENSE-WPT.md` copied from the sibling `webauthn` category, 942 files: 889 `.py` files under `tests/classic/`, `tests/bidi/`, `tests/interop/`, `tests/support/` (pytest-based, `wdspec` manifest type — protocol-level tests driving a real WebDriver session, not testharness JS), plus a handful of `.html`/`.js`/fixture files. `run_report.py --all --root webdriver --recursive` selected 1 id: **0/1 harness OK**. All 889 `.py` tests are excluded from the run queue entirely (`Unsupported test type wdspec for product lumen` — `tools/wptrunner/wptrunner/browsers/lumen.py`'s `__wptrunner__["executor"]` registers only `"testharness"`, same class of gap as the `reftest`/`crashtest` exclusions already documented for `accessibility`/`acid`). The one selectable testharness file, `tests/classic/idlharness.window.html` (WebIDL-conformance check for `Navigator.webdriver`), TIMEOUTs — it pulls the shared `/resources/idlharness.js` + `/resources/WebIDLParser.js` helpers, neither of which is vendored (same documented survey gap as `WebCryptoAPI`/`FileAPI`), so `idl_test is not defined`. Code review of `crates/js/src/surface_api.rs:1-45` (ADR-007, "Surface API without automation markers") confirmed the underlying behavior the test would have exercised: `navigator.webdriver` is deliberately *absent* (`'webdriver' in navigator` is `false`, not merely `undefined`) as an anti-fingerprinting measure — this diverges from the WebDriver spec (which mandates a `boolean`), but is a documented architectural decision with its own unit tests (`webdriver_is_undefined`, `webdriver_absent_in_navigator`), not an engine defect. No new BUG-NNN filed. See `docs/wpt-status.md` for the full breakdown.

Единственный testharness-файл категории — `tests/classic/idlharness.window.html` (проверяет WebIDL-форму `Navigator.webdriver`) — TIMEOUT: тянет невендоренные общие хелперы `/resources/idlharness.js`+`WebIDLParser.js` (тот же документированный гэп, что у `WebCryptoAPI`/`FileAPI`). Код-ревью `crates/js/src/surface_api.rs:1-45` (ADR-007, «Surface API без automation-маркеров») подтвердил: `navigator.webdriver` намеренно полностью отсутствует (`'webdriver' in navigator === false`, seal через `Object.defineProperty` отсутствием, не через `undefined`-геттер) как антидетект-мера — расходится со спекой WebDriver (там обязателен `boolean`), но это документированное архитектурное решение с собственными юнит-тестами (`webdriver_is_undefined`, `webdriver_absent_in_navigator`), не движковый дефект. Новый BUG-NNN не заводился.
