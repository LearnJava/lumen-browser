# WPT vendor notes — `eyedropper`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-28 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-eyedropper`, `docs/wpt-status.md`), out of scope (🚫, the niche EyeDropper API — W3C Color WG screen colour picker) but vendored anyway per the backlog's blanket coverage rule. Same pinned commit, `git sparse-checkout add` at the same commit hash, 7 files (`eye-dropper-abort-signal.tentative.https.html`, `idlharness.https.window.js`, `manual/eye-dropper.tentative.html`, `manual/eye-dropper-srgb.tentative.html`, `manual/resources/eye_dropper_icon.svg`, `WEB_FEATURES.yml`, `LICENSE-WPT.md`; the category has no `META.yml`). **The smallest category in this backlog.** Out-of-category helpers not vendored: `/resources/testdriver.js` + `testdriver-actions.js` + `testdriver-vendor.js` (the single non-idlharness test) and `/resources/WebIDLParser.js` + `/resources/idlharness.js` — the same documented survey gap as `accname`/`audio-session`/`entries-api`. No `<meta name=variant>`. `run_report.py --all --root eyedropper --recursive` completed in **1 min 36 s**: **0/2 harness OK, 0/0 subtests**, with both ids unreachable for different reasons — `eye-dropper-abort-signal.tentative.https.html` SKIP (`Executor does not support testdriver.js`: `open()` requires transient user activation per spec, so the test synthesizes a click through `new test_driver.Actions()`), and `idlharness.https.window.html` TIMEOUT on the HTTPS-port gap (`invalid url: invalid port: "None"`, same class as `WebCryptoAPI`/`ai`/`ambient-light`/`encrypted-media`) — it never even reaches the 404 on the un-vendored IDL-harness pair. **A defect in our own tooling was recorded here:** `run_report.py` printed «running 4 all vendored (eyedropper) WPT tests» while the manifest selected 2 — its `all_vendored_test_ids()` (`run_report.py:94`) filters manual tests by the `-manual` substring in the *filename* only, so both tests living in the `manual/` *directory* without that suffix inflate the id count, even though the upstream `MANIFEST.json` classifies them as `support` (they contain neither `testharness.js` nor a reftest link) and wptrunner never runs them. The already-vendored `accname`, `core-aam`, `dpub-aam` and `editing` categories have `manual/` directories too and are affected by the same inflation; their published counts were not rewritten retroactively — narrowing the filter is a DEVX candidate. The run itself could not produce engine findings, but a `--dump-layout` probe outside WPT produced one, and it is atypical for a 🚫-scoped category: EyeDropper **is implemented** in Lumen (`crates/js/src/eye_dropper.rs`, installed on both the V8 path `v8_runtime.rs:3893` and the rquickjs path `lib.rs:1187`) and 100% broken — `open()` always rejects with `ReferenceError: _lumen_eye_dropper_open is not defined` ([BUG-365](../../bugs/BUG-365-FIXED.md)): the native binding is never registered as a global (Rust only has an unconnected `extern "C"` stub at `eye_dropper.rs:24`), and `_lumen_eye_dropper_open?.call?.(null)` does not help — optional chaining short-circuits on `null`/`undefined`, but resolving an undeclared identifier happens first and throws. The documented «fall back to `#ffffff` when the binding is absent» branch, the JSON parsing and the late-`abort` path are therefore all dead code; only the early return on an already-aborted `AbortSignal` works. Notably the 6 `eye_dropper::tests` unit tests are green throughout (verified in-session, 6/6): they assert only `result instanceof Promise` — true for a rejected promise as well — and put their real assertions inside a `.then(...)` that a rejection never runs. See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/eyedropper/`, 7 файлов: 2 корневых теста `eye-dropper-abort-signal.tentative.https.html` и `idlharness.https.window.js`, `manual/` — 2 ручных демо `eye-dropper.tentative.html`/`eye-dropper-srgb.tentative.html` + `manual/resources/eye_dropper_icon.svg`, `WEB_FEATURES.yml`, плюс `LICENSE-WPT.md`; `META.yml` у категории нет), включена несмотря на скоуп 🚫 (нишевый EyeDropper API, W3C Color WG — экранная пипетка). **Самая маленькая категория бэклога.** Невендоренные внекатегорийные зависимости: `/resources/testdriver.js`+`testdriver-actions.js`+`testdriver-vendor.js` (единственный не-idlharness тест) и `/resources/WebIDLParser.js`+`/resources/idlharness.js` — тот же survey-gap, что `accname`/`audio-session`/`entries-api`. `<meta name=variant>` не используется. `run_report.py --all --root eyedropper --recursive` — **1 мин 36 с**, результат **0/2 harness OK, 0/0 сабтестов**, причём оба id недоступны исполнителю по разным причинам: `eye-dropper-abort-signal.tentative.https.html` — SKIP (`Executor does not support testdriver.js`: `open()` по спеке требует пользовательской активации, поэтому тест синтезирует клик через `new test_driver.Actions()`), `idlharness.https.window.html` — TIMEOUT по HTTPS-порт-гэпу (`invalid url: invalid port: "None"`, минимальный исполнитель не поднимает HTTPS-порт — тот же класс, что `WebCryptoAPI`/`ai`/`ambient-light`/`encrypted-media`); до 404 на невендоренную пару IDL-харнеса выполнение даже не доходит. **Отдельно зафиксирован дефект собственного тулинга:** `run_report.py` напечатал «running 4 all vendored (eyedropper) WPT tests», а манифест отобрал 2 — его `all_vendored_test_ids()` (`tests/wpt/run_report.py:94`) отсеивает ручные тесты только по подстроке `-manual` в имени файла, поэтому оба теста из каталога `manual/`, не имеющие такого суффикса, попадают в счётчик id, хотя апстримовый `MANIFEST.json` классифицирует их как `support` (в них нет ни `testharness.js`, ни reftest-ссылки) и wptrunner их не запускает. Тем же завышением затронуты уже вендоренные категории с каталогом `manual/` — `accname`, `core-aam`, `dpub-aam`, `editing`; опубликованные там счётчики задним числом не переписывались, сужение фильтра — кандидат в дорожку DEVX. Проба `--dump-layout` вне WPT дала единственную реальную находку категории и она нетипична для 🚫-скоупа: EyeDropper в Lumen **реализован** (`crates/js/src/eye_dropper.rs`, шим ставится и на V8 `v8_runtime.rs:3893`, и на rquickjs `lib.rs:1187`), `new EyeDropper()` работает — но `open()` **всегда** отклоняется `ReferenceError: _lumen_eye_dropper_open is not defined` ([BUG-365](../bugs/BUG-365-FIXED.md)): нативная привязка нигде не регистрируется как глобал (в Rust есть только несвязанная `extern "C"`-заглушка `eye_dropper.rs:24`), а запись `_lumen_eye_dropper_open?.call?.(null)` от этого не спасает — опциональная цепочка коротит на `null`/`undefined`, но разрешение необъявленного идентификатора происходит раньше и бросает. Поэтому документированный фолбэк «вернуть `#ffffff`, если привязки нет», разбор JSON-ответа и поздний `abort` — мёртвый код; живёт только ранний выход по уже прерванному `AbortSignal` (он корректно даёт `DOMException` с `name === "AbortError"`). Показательно, что 6 юнит-тестов `eye_dropper::tests` при этом зелёные (прогнано в сессии, `cargo test -p lumen-js --profile dev-release eye_dropper` → 6/6): они проверяют только `result instanceof Promise` (истинно и для отклонённого промиса) и вешают утверждения внутрь `.then(...)`, который на отклонении не вызывается, — набор проверяет форму API и ни одного его наблюдаемого результата. Сопутствующие отклонения от WebIDL, проверенные той же пробой и записанные в тот же баг: `EyeDropper.length` === 1 вместо 0, отсутствует `Symbol.toStringTag`, у инстанса есть лишнее собственное свойство `options`, требование transient user activation (`NotAllowedError`) не реализовано; корректны вызов без `new` → `TypeError` и расположение `open` на прототипе. Оба WPT-теста категории подтвердят фикс только после появления testdriver-исполнителя и HTTPS-порта
