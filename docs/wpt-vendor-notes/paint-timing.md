# WPT vendor notes — `paint-timing`

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-08-05 (коммит `35be3b44`, `tests/wpt/paint-timing/`, 65 файлов: `META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` скопирован из соседней `largest-contentful-paint`, `fcp-only/`, `first-paint-only/`, `with-lcp/`, `with-paint-timing-mixin/`, `resources/`). Ни variant-ов, ни `.https.`, ни `testdriver.js` — самодостаточная категория. `run_report.py --all --root paint-timing --recursive` (~4 мин, 56 отобранных id): **34/56 harness OK, 1/36 сабтестов**. Доминирующая причина отказа (20/36 сабтестов): каждый тест начинается с `assert_implements(window.PerformancePaintTiming, …)`, а этого глобального интерфейса в шиме нет вовсе — заведён [BUG-645](../bugs/BUG-645-OPEN.md) (тот же класс, что [BUG-624](../bugs/BUG-624-OPEN.md)/[BUG-637](../bugs/BUG-637-OPEN.md)/[BUG-589](../bugs/BUG-589-OPEN.md)). Уточняет более раннюю запись `largest-contentful-paint` («ни `LargestContentfulPaint`, ни `PerformancePaintTiming` не реализованы вовсе»): доставка `first-paint`/`first-contentful-paint` в реальный рендер-пайплайн на самом деле подключена (`crates/shell/src/main.rs:15551-15566` зовёт `deliver_paint_timing(...)` на первом непустом display list каждой загрузки, `PerformanceObserver.supportedEntryTypes` честно перечисляет `'paint'`) — отсутствует только сам конструктор-интерфейс, а не весь механизм. Оставшиеся 21 harness-TIMEOUT: 20 из `fcp-only/` — реконфирмация [BUG-346](../bugs/BUG-346-OPEN.md) (`<script src="../resources/utils.js">` не резолвится, сетевой 404, хотя файл реально вендорен); `idlharness.window.html` — известный невендоренный `idlharness.js`+`WebIDLParser.js` (тот же класс, что `FileAPI`/`netinfo`).
