# WPT vendor notes — `loading`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-05 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-loading`, `docs/wpt-status.md`), scope ⬜ (candidate). Same pinned commit, `git sparse-checkout add` at the same commit hash, 119 files (`LICENSE-WPT.md` copied from the sibling `js` category, `early-hints/` — 47 `.h2.`-suffixed tests for HTTP/2 103 Early Hints plus `resources/` `.h2.py` handlers, 7 top-level `preloader-*.html`, `resources/dummy.css`+`dummy.js`). No `variant` hits, no `testdriver.js` hits. `run_report.py --all --root loading --recursive` completed in ~12:50 (53 selected ids): **7/53 harness OK, 0/7 subtests passed**. All 46 `early-hints/*.h2.window.html` TIMEOUT on the standard self-signed-cert TLS gap (`invalid url: invalid port: "None"`, same class as `jpegxl`/`keyboard-lock`/`keyboard-map`); a `crates/net`/`crates/shell` grep for `103`/`Early-Hint` found nothing — HTTP 103 Early Hints is entirely unimplemented, same first-pass-absent-API pattern as the rest of the TLS-gap cluster. The 7 `preloader-*.html` (no `.https.`) actually ran, each harness OK with exactly one FAIL subtest — both failure classes re-confirm already-open bugs, not new findings: 5 `preloader-css-import*.html` FAIL on `first.responseEnd` being `undefined` because Resource Timing (`performance.getEntriesByType('resource')`) is never populated for real loads — [BUG-520](../bugs/BUG-520-OPEN.md) (the native hook `_lumen_record_resource_timing` exists but the network layer never calls it for any resource kind); `preloader-link-media.html` FAIL — same BUG-520, the non-matching-media `?print` stylesheet never gets a resource-timing entry at all; `preloader-template.html` FAIL — `document.body.appendChild` on `null` — [BUG-417](../bugs/BUG-417-OPEN.md) (a `<template>` encountered before `<body>` exists prevents the parser from ever creating `<body>`). No bug filed. See `docs/wpt-status.md` for the full breakdown.
