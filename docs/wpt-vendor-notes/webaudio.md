# WPT vendor notes — `webaudio`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-09 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-webaudio`, `docs/wpt-status.md`), scope ⬜ (candidate — Web Audio is genuinely implemented, `crates/js/src/web_audio.rs`, Phase 0 graph-only, no DSP). Same pinned commit, `git sparse-checkout add` at the same commit hash, `LICENSE-WPT.md` copied from the sibling `wasm` category, 415 files (`META.yml`, `README.md`, `js/`, `resources/`, `the-audio-api/`). Almost entirely self-contained — only 3 files pull `testdriver.js`, out-of-category deps are just `/resources/testharness.js`+`testharnessreport.js` — but 60 files are `.https.`. `run_report.py --all --root webaudio --recursive --processes=4` (~7 min) selected 321 ids: **205/321 harness OK, 1894/3213 subtests** — one of the highest-signal runs in this backlog (comparable to `fetch`). Two new bugs from live probe (`--mcp-live-port`): [BUG-707](../../bugs/BUG-707-OPEN.md) — `ConstantSourceNode`/`IIRFilterNode` are entirely absent (no global constructor, no `create*` factory), and `createMediaStreamDestination()` returns a plain `AudioNode` instead of a `MediaStreamAudioDestinationNode` (its stream stub also lacks `getAudioTracks()`) — the single largest failure cluster (84+49+6 occurrences). [BUG-708](../../bugs/BUG-708-OPEN.md) — `AnalyserNode.fftSize`, `ConvolverNode.buffer`, `AudioNode.channelCountMode`/`channelInterpretation` are plain unchecked fields (no `Object.defineProperty`, unlike the validated `OscillatorNode.type`/`BiquadFilterNode.type` pattern already in the same file) — accept any value silently instead of throwing/ignoring per WebIDL. The remaining large failure cluster (channel up/down-mix combinatorics, `renderSizeHint`, DSP-accuracy assertions) is the already-documented Phase-0 "no DSP" gap (`CAPABILITIES.md`), not a new finding. See `docs/wpt-status.md` for the full breakdown.
