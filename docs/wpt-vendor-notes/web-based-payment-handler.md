# WPT vendor notes — `web-based-payment-handler`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-09 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-web-based-payment-handler`, `docs/wpt-status.md`), included despite its 🚫 scope note (Payment Handler API — service-worker-based payment app registration, distinct from the already-vendored 🚫-scope Payment Request API family: `payment-request`/`payment-method-id`/`payment-method-basic-card`) by the same standing user decision as `subapps`/`vibration`/`video-rvfc`. Same pinned commit, `git sparse-checkout add` at the same commit hash, `LICENSE-WPT.md` copied from the sibling `payment-request` category, 33 files (`META.yml`, `WEB_FEATURES.yml`, 7 `app-*.js` mock payment-app scripts, `payment-app/` — 2 support HTML pages, `idlharness.https.any.js`, 9 non-`-manual` root test files, 6 `-manual` root test files + their `-manifest.json` siblings excluded by `run_report.py`'s own selection). Every non-manual root test file is `.https.`. `run_report.py --all --root web-based-payment-handler --recursive` completed in ~3:15 (8 selected ids): **0/8 harness OK**, all 8 TIMEOUT on the standard TLS `UnknownIssuer` gap. Live probe (`--mcp-live-port`) of the object this whole category depends on — a service worker's `ServiceWorkerRegistration`, since `PaymentRequestEvent`/`CanMakePaymentEvent` are dispatched to it — confirmed `typeof ServiceWorkerRegistration === 'undefined'` on a real page, reconfirmation of already-open [BUG-657](../../bugs/BUG-657-OPEN.md) (the global class is never defined in the production V8 install; only per-module unit-test stubs define it). `PaymentRequestEvent`/`CanMakePaymentEvent`/`PaymentManager` are absent entirely, expected for a 🚫-scope category, not a bug. No new bug filed this pass. See `docs/wpt-status.md` for the full breakdown.
