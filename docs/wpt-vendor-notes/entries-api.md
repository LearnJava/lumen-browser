# WPT vendor notes — `entries-api`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-28 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-entries-api`, `docs/wpt-status.md`), in-scope (⬜, File and Directory Entries API — `FileSystemEntry`/`FileSystemFileEntry`/`FileSystemDirectoryEntry`/`FileSystemDirectoryReader`, `DataTransferItem.webkitGetAsEntry`, `<input webkitdirectory>`). Same pinned commit, `git sparse-checkout` at the same commit hash, 29 files (`META.yml`, `WEB_FEATURES.yml`, `README.md`, 14 `*-manual.html`, `idlharness.window.js`, `idlharness-manual.window.js`, `support.js`, `support/` — 8 drag-and-drop data fixtures, `LICENSE-WPT.md`). One out-of-category dependency pair not vendored: both idlharness tests reference `/resources/WebIDLParser.js`+`/resources/idlharness.js`, same documented survey gap as `FileAPI`/`audio-session`. Manual by spec design (upstream README: "most of the tests are manual and require drag-and-drop of test data files") — 15 of the 16 test files are `-manual`, excluded by `run_report.py`'s own filter, so the manifest selects exactly one id: `idlharness.window.html`. No `<meta name=variant>`, no `.https.` tests, and the only out-of-category `src=` are the already-vendored `/resources/testharness.js`+`testharnessreport.js` — the cheapest survey profile in this backlog: `run_report.py --all --root entries-api --recursive` completed in **1 min 13 s**, the single id TIMEOUT (`idl_test is not defined`, 404 on the two un-vendored IDL-harness files), the same pattern as `audio-session`/`background-sync`/`autoplay-policy-detection`. 0/1 harness OK, 0/0 subtests. A `--dump-layout` probe confirms the API itself is entirely unimplemented (all five `FileSystem*` interfaces `undefined`; `webkitdirectory`/`webkitEntries` absent on `<input>`, `webkitRelativePath` absent on `File.prototype`, `webkitGetAsEntry` absent on `DataTransferItem.prototype` — the latter two interfaces do exist), so even the 15 manual tests would fail on `assert_implements`; no BUG-NNN filed — first pass only vendors + runs. See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/entries-api/`, 29 файлов: 14 `*-manual.html`, `idlharness.window.js`, `idlharness-manual.window.js`, `support.js`, `support/` — 8 файлов-фикстур для drag-and-drop (`a/b/c/…`, `upload/…`), `META.yml`/`WEB_FEATURES.yml`/`README.md`, плюс `LICENSE-WPT.md`), в скоупе (⬜, File and Directory Entries API — `FileSystemEntry`/`FileSystemFileEntry`/`FileSystemDirectoryEntry`/`FileSystemDirectoryReader`, `DataTransferItem.webkitGetAsEntry`, `<input webkitdirectory>`). **Категория ручная по замыслу спеки** — апстрим-README прямо пишет: «most of the tests are manual and require drag-and-drop of test data files», поэтому 15 из 16 тестовых файлов это `-manual`, отсекаемые собственным фильтром `run_report.py`; манифест отобрал ровно один id — `idlharness.window.html`. Профиль стоимости самый дешёвый в бэклоге: `<meta name=variant>` не используется, `.https.`-тестов нет, единственные внекатегорийные `src=` — уже вендоренные `/resources/testharness.js`+`testharnessreport.js`; `run_report.py --all --root entries-api --recursive` уложился в **1 мин 13 с**. Результат — **0/1 harness OK, 0/0 сабтестов**: единственный id ушёл в TIMEOUT по уже известной причине — оба idlharness-теста тянут невендоренные `/resources/WebIDLParser.js`+`/resources/idlharness.js` (404 → `idl_test is not defined`, гарнес не доходит до `test_start`), тот же survey-gap, что в `audio-session`/`background-sync`/`autoplay-policy-detection`, а не дефект движка. Проба `--dump-layout` вне WPT: сам Entries API не реализован ни в каком виде — `FileSystemEntry`/`FileSystemFileEntry`/`FileSystemDirectoryEntry`/`FileSystemDirectoryReader`/`FileSystem` все `undefined`; `DataTransferItem`/`DataTransfer` существуют, но без расширения (`'webkitGetAsEntry' in DataTransferItem.prototype` === false), `'webkitdirectory' in input` === false, `'webkitEntries' in input` === false, `'webkitRelativePath' in File.prototype` === false. То есть и 15 ручных тестов, и idlharness с починенными зависимостями упали бы на `assert_implements` — новых багов не заведено, первый проход только вендорит и гоняет
