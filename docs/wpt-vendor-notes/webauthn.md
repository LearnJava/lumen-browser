# WPT vendor notes — `webauthn`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-09 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-webauthn`, `docs/wpt-status.md`), scope 🚫 (WebAuthn — separate crypto/platform integration). Same pinned commit, `git sparse-checkout add` at the same commit hash, `LICENSE-WPT.md` copied from the sibling `webaudio` category, 60 files. 53 of 58 test files `.https.`, 50 of 58 pull `testdriver.js`. `run_report.py --all --root webauthn --recursive --processes=4` (~14 min) selected 54 ids: **1/54 harness OK, 0/1 subtests**. 53 TIMEOUT on the standard TLS `UnknownIssuer` gap ([BUG-657](../../bugs/BUG-657-OPEN.md)); the one non-`.https.` id that ran (`securecontext.http.html`) is harness OK but its one subtest FAILs — `navigator.credentials.create` is reachable in a non-secure context, reconfirmation of already-open [BUG-399](../../bugs/BUG-399-OPEN.md). Code review plus a temporary local test (added, verified, then removed — `git diff` on the test file is empty) surfaced [BUG-709](../../bugs/BUG-709-OPEN.md): neither the JS shim (`CREDENTIALS_SHIM` in `crates/js/src/credentials.rs`), the native bindings, nor `VirtualAuthenticator` (`crates/network/src/webauthn.rs`) validate `rp.id`/`rpId` against the calling document's actual origin (WebAuthn L2 §5.1.3) — a page at `https://example.com/login` successfully mints a credential scoped to `rp.id: 'attacker-controlled-unrelated.example'`. Currently unreachable in the shipped browser (`set_credential_provider` is never called anywhere under `crates/shell/`, confirmed by grep), but a real defect in fully-implemented, unit-tested crypto code — not a Phase-0 stub gap. See `docs/wpt-status.md` for the full breakdown.

## Прогон и находки (`docs/wpt-status.md`)

WebAuthn — отдельная крипто/платформенная интеграция. Вендорена целиком 2026-08-09 (коммит `35be3b44`, `tests/wpt/webauthn/`, 60 файлов, `LICENSE-WPT.md` скопирован из `webaudio`). 53/58 тестовых файлов `.https.`, 50/58 тянут `testdriver.js`. `run_report.py --all --root webauthn --recursive --processes=4` (~14 мин): 54 отобранных id — **1/54 harness OK, 0/1 сабтестов**. 53 TIMEOUT на TLS-гэпе `UnknownIssuer` ([BUG-657](../bugs/BUG-657-OPEN.md)); единственный исполнившийся не-`.https.` тест (`securecontext.http.html`) формально OK, но его сабтест FAIL — `navigator.credentials.create` доступен в небезопасном контексте — переподтверждение [BUG-399](../bugs/BUG-399-OPEN.md). Код-ревью + временный локальный тест (удалён до коммита) вскрыли [BUG-709](../bugs/BUG-709-OPEN.md): ни JS-шим (`CREDENTIALS_SHIM`), ни нативные биндинги, ни `VirtualAuthenticator` не проверяют `rp.id`/`rpId` против фактического origin страницы (WebAuthn L2 §5.1.3) — страница `https://example.com/login` успешно создаёт credential с `rp.id: 'attacker-controlled-unrelated.example'`. Сейчас недостижимо в собранном браузере (`set_credential_provider` нигде не вызывается под `crates/shell/`), но реальный дефект в полностью реализованном и юнит-протестированном крипто-коде (`VirtualAuthenticator` — настоящий ES256/RFC 6979), не Phase-0-заглушка.
