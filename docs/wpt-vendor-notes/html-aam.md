# WPT vendor notes — `html-aam`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-04 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-html-aam`, `docs/wpt-status.md`), scope ⬜ (candidate, HTML Accessibility API Mappings — how HTML-specific semantics/roles map onto platform accessibility APIs). Same pinned commit, `git sparse-checkout` at the same commit hash, 19 files (`META.yml`, `WEB_FEATURES.yml`, 16 test files — 15 `.html`/`.tentative.html` + one `.tentative.window.js`, `LICENSE-WPT.md`). Unlike `core-aam`/`dpub-aam`/`graphics-aam` (near-100% `-manual.html`/ATTAcomm), every file here is automatically runnable — the category's own `testharness` mechanism, not a human-driven AT protocol. One out-of-category helper not vendored: `/wai-aria/scripts/aria-utils.js` (shared ARIA role-verification harness), same documented gap as `core-aam`/`dpub-aam`/`graphics-aam`/`graphics-aria` — `wai-aria` itself isn't vendored yet. `run_report.py --all --root html-aam --recursive` completed in ~2:41 (16 selected ids): **2/16 harness OK, 0/7 subtests**. Distinct failure mode from the sibling AAM categories: 13 of 14 files that reference `aria-utils.js` don't get flagged `testdriver` in the manifest despite pulling `testdriver.js`/`testdriver-actions.js`/`testdriver-vendor.js` too (same predictor inversion documented for `fledge`/`font-access`), so instead of an instant SKIP they actually navigate, hit `ReferenceError: AriaUtils is not defined` inside a `script error` (not a thrown exception the harness can catch), and hang to TIMEOUT — a third failure shape for the same un-vendored-helper class, next to `core-aam`'s pre-emptive SKIP and `dpub-aam`'s SKIP. The remaining 2 ids (`aside-in-prefixed-article.html`, not `AriaUtils`-dependent; `roles-dynamic-switch.tentative.window.html`) both reached harness OK and gave the category's only real signal, 7 subtests, all FAIL on the same root cause: `TypeError: element.getRootNode is not a function` — no new finding, this is the already-filed [BUG-599](../bugs/BUG-599-OPEN.md) (`Node.prototype.getRootNode()` missing entirely), independently reconfirmed through a different test file than the `html/interaction` slice that found it. See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-08-04 (коммит `35be3b44`, `tests/wpt/html-aam/`, 19 файлов: `META.yml`, `WEB_FEATURES.yml`, 16 тестовых файлов, `LICENSE-WPT.md`), скоуп ⬜ (кандидат, HTML Accessibility API Mappings). В отличие от `core-aam`/`dpub-aam`/`graphics-aam` (почти целиком `-manual.html`/ATTAcomm) здесь каждый файл автоматически исполняем. Внекатегорийный хелпер `/wai-aria/scripts/aria-utils.js` не довендорен — та же методология, что `core-aam`/`dpub-aam`/`graphics-aam`/`graphics-aria`. `run_report.py --all --root html-aam --recursive` — **~2:41, 2/16 harness OK, 0/7 сабтестов**: 13 из 14 файлов, ссылающихся на `aria-utils.js`, не получили флаг `testdriver` в манифесте несмотря на подключение `testdriver.js`/`testdriver-actions.js`/`testdriver-vendor.js` (та же инверсия предсказателя, что у `fledge`/`font-access`), поэтому вместо мгновенного SKIP реально навигируют, падают на `ReferenceError: AriaUtils is not defined` внутри `script error` (не перехватываемое исключение) и виснут до TIMEOUT — третья форма отказа для того же класса невендоренного хелпера. Оставшиеся 2 id (`aside-in-prefixed-article.html`, `roles-dynamic-switch.tentative.window.html`) дали единственный реальный сигнал категории — 7 сабтестов, все FAIL на одной причине: `TypeError: element.getRootNode is not a function`. Не новая находка — независимое переподтверждение уже заведённого [BUG-599](../bugs/BUG-599-OPEN.md) (`Node.prototype.getRootNode()` отсутствует целиком) через другой тестовый файл, не тот, что нашёл его в срезе `html/interaction`.
