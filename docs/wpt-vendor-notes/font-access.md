# WPT vendor notes — `font-access`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-28 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-font-access`, `docs/wpt-status.md`). Same pinned commit, `git sparse-checkout` at the same commit hash, 20 files (`META.yml`, `WEB_FEATURES.yml`, `README.md`, 6 `font_access_*.tentative.https.window.js`, `permissions-policy/` — 6 html + 2 `.headers`, `resources/` — `font-asserts.js`/`font-data.js`/`font-test-utils.js`). One out-of-category helper (`/permissions-policy/resources/permissions-policy.js`, referenced by the 5 `.sub.html` tests) not vendored — same documented survey gap as `FileAPI`/`ai`. `run_report.py --all --root font-access --recursive` completed in 6:51 (12 selected ids): 5 SKIP (`Executor does not support testdriver.js`), 6 TIMEOUT (all six `.window.js`, the usual HTTPS-port gap), 1 `Test OK` with its single subtest FAIL. This category is the smallest clean reproduction of the `fledge` testdriver-predictor inversion and is worth keeping as the reference case: `grep -rl testdriver` matches 11 of 21 files, but `MANIFEST.json` flags `testdriver: true` on exactly the 5 `.sub.html` files that pull it via a `<script src=…>` tag — the 6 `.window.js` files that pull the same file via `// META: script=…` get no flag, reach the HTTPS-port gap and pay a full ~65 s TIMEOUT each, which is the entire runtime. Note also that the *first* run of the same command reported 0/12: the one executed test's result was computed and then discarded past wptrunner's external timeout, after which the browser process could not be stopped (`IO Completion Port failed to signal process shutdown`). Deliberately tested and refuted as a poisoning-by-previous-failed-navigation effect (1 and 6 preceding failed navigations both leave the test green); treat it as an intermittent on the shutdown path, and re-run any category whose whole signal rests on one or two executed tests. See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/font-access/`, 20 файлов: `META.yml`, `WEB_FEATURES.yml`, `README.md`, 6 `font_access_*.tentative.https.window.js`, `permissions-policy/` — 6 html + 2 `.headers`, `resources/` — `font-asserts.js`/`font-data.js`/`font-test-utils.js`, `LICENSE-WPT.md`), скоуп ⬜ (кандидат). Внекатегорийный хелпер `/permissions-policy/resources/permissions-policy.js` (5 ссылок) не довендорен — та же методология, что `FileAPI`/`ai`. `run_report.py --all --root font-access --recursive` — **6 мин 51 с, 1/12 harness OK, 0/1 сабтест** (5 SKIP, 6 TIMEOUT, 1 `Test OK` с падающим сабтестом). **Категория — минимальное чистое воспроизведение инверсии предсказателя testdriver, найденной на `fledge`, и стоит того, чтобы держать её как эталон:** `grep -rl testdriver` даёт 11 файлов из 21, а флаг `testdriver: true` в `MANIFEST.json` стоит ровно у **5** — тех самых `permissions-policy/*.https.sub.html`, что подключают его тегом `<script src=…>`. Шесть `.window.js`, подключающих тот же файл строкой `// META: script=/resources/testdriver.js`, флага не получают, доходят до HTTPS-порт-гэпа и платят полный ~65-секундный TIMEOUT каждый — это и есть все 6:51 прогона. То есть в одной 20-файловой категории видны оба режима сразу: 5 мгновенных SKIP по флагу и 6 полных TIMEOUT без флага. **Методологическое предупреждение: первый прогон этой же команды дал 0/12, а не 1/12.** Единственный исполняющийся тест отработал (страница загрузилась, `testharness.js` подтянулся, 18 DOM-узлов), его результат был вычислен вместе с сабтестом (`TestharnessResult TIMEOUT` + `FAIL`, видно в строке `Command left in command_queue during cleanup`), но пришёл позже внешнего таймаута wptrunner и был выброшен; следом браузерный процесс не удалось остановить (`Failed to stop either the runner or the browser process`, `OSError: IO Completion Port failed to signal process shutdown` из `mozprocess`). Гипотезу «предыдущие провалившиеся HTTPS-навигации отравляют следующий тест» (класс [BUG-380](../../bugs/BUG-380-FIXED.md)) проверили прямо: прогон 1 провалившейся навигации + этот тест → `Test OK`; 6 провалившихся + этот тест → `Test OK`; повторный полный прогон → `Test OK`. То есть это интермиттент на пути завершения, а не детерминированное отравление, и отдельный баг на него не заводился. Правило на будущее: **категорию, весь сигнал которой держится на одном-двух исполнившихся тестах, надо прогнать дважды прежде чем публиковать её число** — здесь один прогон из трёх соврал ровно на весь сигнал категории. Единственный не-`.https.` тест — `permissions-policy/local-fonts-supported-by-permissions-policy.html` — падает на [BUG-361](../../bugs/BUG-361-FIXED.md) (`document.permissionsPolicy.features()` отдаёт `[]`); font-access — **четвёртая** категория бэклога на этой строке после `accelerometer`/`ambient-light`/`encrypted-media`, и здесь её цена максимальна: этот баг в одиночку определяет результат категории. Сама Local Font Access в движке реализована (`crates/js/src/local_font_access.rs`, Phase 0), поэтому проба `--dump-layout` дала две новые находки. [BUG-385](../../bugs/BUG-385-FIXED.md) (закрыт 2026-08-10: установлена спековая точка входа `queryLocalFonts()`, форма WebIDL приведена в порядок, гейты §2 fail-closed; перечисления шрифтов ОС по-прежнему нет — Phase 0 отдаёт `[]`, пока открыт BUG-386): шим написан по устаревшему черновику WICG — установлен `navigator.fonts.query()` (резолвится пустым массивом), а спековой точки входа `self.queryLocalFonts()`, с которой начинается **каждый** из 6 тестов категории, нет вовсе; значит и после закрытия HTTPS-гэпа, и после обещанной в doc-комментарии Phase 1 категория не даст ни одного зелёного теста. Плюс форма WebIDL: `FontData`/`FontAccessManager` конструируются со страницы (по спеке конструктора у обоих нет), четыре поля `FontData` — собственные записываемые перечисляемые данные вместо readonly-геттеров прототипа, `Symbol.toStringTag` нет, `navigator.fonts` — собственное записываемое свойство вместо аксессора прототипа (класс [BUG-366](../../bugs/BUG-366-FIXED.md)); отдельно `window.FontData({family:'X'})` не бросает `TypeError`, а заводит на `window` четыре перечисляемых глобала `postscriptName`/`fullName`/`family`/`style`. [BUG-386](../../bugs/BUG-386-FIXED.md) — находка «на уровень выше», в разделяемом контейнере: `navigator.permissions.query()` отвечает `granted` на любое имя вне зашитого списка из 11 запрещённых, включая нереализованные (`geolocation`, `notifications`, `persistent-storage`, `local-fonts`) и заведомо выдуманные (`totally-made-up-permission-xyz` → `granted`), тогда как спека требует `TypeError` на нераспознанное имя; `PermissionStatus` не наследует `EventTarget`, `name`/`state` записываемы, интерфейса `Permissions` нет, `navigator.permissions` перезаписывается страницей целиком. Приватностный итог категории: разрешение `local-fonts` — один из сильнейших векторов отпечатка — уже выдано по умолчанию, так что реализация перечисления шрифтов (BUG-385, Phase 1) без BUG-386 заработала бы молча и без спроса. `CAPABILITIES.md` поправлена: `Permissions Policy` вынесена из списка ✅ в 🟡 вместе с новыми 🟡-строками про Permissions API и Local Font Access.
