# WPT vendor notes — `gyroscope`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-28 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-gyroscope`, `docs/wpt-status.md`), included despite its 🚫 scope note (device sensor) by the same standing user decision as `accelerometer`/`generic-sensor`/`gamepad`. Same pinned commit, `git sparse-checkout` at the same commit hash, 16 files (`META.yml`, `WEB_FEATURES.yml`, 9 `*.https(.html)`/plain `.html` root tests, 2 `.headers` sidecars, `idlharness.https.window.js`, `resources/sensor-data.js`, `LICENSE-WPT.md`). Two out-of-category helpers reused from already-vendored categories: `/generic-sensor/generic-sensor-tests.js` and `/permissions-policy/resources/permissions-policy.js` (the latter itself not vendored — same documented gap as `accelerometer`). `run_report.py --all --root gyroscope --recursive` completed in ~4 min 19 s (10 selected ids): 2 SKIP (testdriver.js), 5 `.https.` TIMEOUT (HTTPS-port gap), 1 ERROR (`idlharness.https.window.html` — session-reuse artifact of the class `accelerometer`/`ambient-light`, result tagged with the previous test's URL), 2 FAIL — the two non-`.https.` files actually ran: `Gyroscope-supported-by-permissions-policy.html` (`document.permissionsPolicy.features()` doesn't list `"gyroscope"`, the same recurring defect as `accelerometer`/`ambient-light`, already filed as BUG-361) and `Gyroscope_insecure_context.html` (`assert_false('Gyroscope' in window)` — not decisive on its own, since this ran over loopback `http://127.0.0.1`, a potentially-trustworthy origin per W3C Secure Contexts §3.1, same environment/spec mismatch already documented for `audio-output`'s `secure-context.html`; reading the code the FAIL led to found a real, broader defect instead — BUG-399, `window.isSecureContext` hardcoded `true` unconditionally rather than computed from the page's actual protocol/host). See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/gyroscope/`, 16 файлов: `META.yml`, `WEB_FEATURES.yml`, 9 `*.https(.html)`/plain `.html` root-тестов, 2 `.headers`-сайдкара, `idlharness.https.window.js`, `resources/sensor-data.js`, `LICENSE-WPT.md`), скоуп 🚫 (датчик устройства), включена по постоянному решению пользователя (тот же класс, что `accelerometer`/`generic-sensor`/`gamepad`). Два внекатегорийных хелпера переиспользованы из уже вендоренных категорий: `/generic-sensor/generic-sensor-tests.js` (довендорен) и `/permissions-policy/resources/permissions-policy.js` (не довендорен — тот же пробел, что у `accelerometer`). `run_report.py --all --root gyroscope --recursive` — **4 мин 19 с, 2/10 harness OK, 0/2 сабтестов** (2 SKIP по testdriver.js, 5 `.https.` TIMEOUT на HTTPS-порт-гэпе, 1 ERROR — `idlharness.https.window.html`, session-reuse артефакт класса `accelerometer`/`ambient-light`). Оба не-`.https.` файла реально исполнились и оба FAIL: `Gyroscope-supported-by-permissions-policy.html` бьёт в уже заведённый [BUG-361](../bugs/BUG-361-FIXED.md) (`document.permissionsPolicy.features()` не отдаёт список поддерживаемых фич, всегда `[]` без заголовка — тот же повторяющийся дефект, что у `accelerometer`/`ambient-light`); `Gyroscope_insecure_context.html` (`assert_false('Gyroscope' in window)`) сам по себе неокончателен — прогон шёл через loopback `http://127.0.0.1`, который по W3C Secure Contexts §3.1 — legitimately trustworthy origin, тот же класс несовпадения теста с окружением, что уже задокументирован для `audio-output`'s `secure-context.html`. Разбор причины FAIL, однако, привёл к новой находке: [BUG-399](../bugs/BUG-399-OPEN.md) — `window.isSecureContext` (`crates/js/src/dom.rs:11531`) захардкожен `true` безусловно вместо вычисления из уже распарсенного протокола/хоста страницы (`_lumen_loc_parts`, `dom.rs:7397`), то есть ни один `[SecureContext]`-гейтинг в движке никогда реально не срабатывает, даже на настоящем небезопасном (не-loopback `http://`) origin — дефект шире одной категории `gyroscope`.
