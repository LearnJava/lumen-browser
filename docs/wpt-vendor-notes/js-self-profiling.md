Same pinned commit, `git sparse-checkout add` at the same commit hash, 42 files (`META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` copied from the sibling `js` category, 20 top-level testharness files + `js-profiling-mode/`, `tentative/`, `with-document-policy/`, `without-document-policy/` subdirs, `resources/profile-utils.js`+`profiling-script.js`). No `variant` hits, 1 `testdriver.js` file (`idlharness.https.html`'s `WebIDLParser.js`/`idlharness.js` pair), 20 of 24 selected ids `.https.`/`.sub.https`. `run_report.py --all --root js-self-profiling --recursive` completed in ~4:43 (24 selected ids): **5/24 harness OK, 0/7 subtests passed**. 19 of the 24 ids TIMEOUT on the standard self-signed-cert TLS gap (`network error: TLS handshake: invalid peer certificate: UnknownIssuer`, same class as `jpegxl`); 4 of those TIMEOUTs manifest as `TEST_END: ERROR` instead because the next test's harness start immediately re-reads the previous test's stale result — the [BUG-380](../bugs/BUG-380-FIXED.md) browsing-context-reuse contamination pattern. The 5 ids that actually ran over plain HTTP (`cross-origin-script-cors.sub.html`, `cross-origin-script-no-cors.sub.html`, `inline-script.html`, `max-buffer-size.window.html`, `time-domain.window.html`) all fail identically with `ReferenceError: Profiler is not defined` (one with `ProfilingScript is not defined`, the category's own cross-origin-attribution helper global) — the JS Self-Profiling API (`Profiler`/`ProfilingScript`) is not implemented at all. No bug filed: same as `navigator.scheduling` in `is-input-pending`, this is a first pass documenting an entirely absent candidate feature, not a defect in an existing one. See `docs/wpt-status.md` for the full breakdown.
