Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/fs/`, 88 файлов: `META.yml`, `README.md` — `WEB_FEATURES.yml` у категории нет, 42 исполняемых файла верхнего уровня, `resources/` из 17 хелперов, `script-tests/` из 20 общих сценариев, `LICENSE-WPT.md`), скоуп ⬜ (кандидат). Категория — File System API (`FileSystemSyncAccessHandle`, `FileSystemObserver`, `move()`), не путать с уже вендоренной `file-system-access` (picker-based, BUG-371..374): общие только базовые классы `FileSystemFileHandle`/`FileSystemDirectoryHandle`. `run_report.py --all --root fs --recursive` — **21 мин, 0/32 harness OK, 0/0 сабтестов** (32 TIMEOUT): все 42 файла категории — `.https.`, `testdriver.js` не встречается ни разу, вариантов нет — чистая HTTPS-порт-гэп стена без единого исполнившегося теста, самый однородный ценник среди WPT-VENDOR категорий на сегодня. Пробовать headless (`--dump-layout`) для async-кода бессмысленно (нет живого event loop для резолва промисов) — использован `--mcp-live-port` с retry-до-готовности `eval`. Проба дала [BUG-389](../bugs/BUG-389-OPEN.md) (новый): вся API-поверхность, вокруг которой построена категория, отсутствует целиком — `FileSystemSyncAccessHandle`, `FileSystemObserver`, общий базовый `FileSystemHandle`, `FileSystemHandle.prototype.move()`, везде `typeof === 'undefined'`. Попутно проба независимо подтвердила уже заведённый [BUG-372](../bugs/BUG-372-FIXED.md) (`navigator.storage.getDirectory()` отдаёт теневой `FileSystemDirectoryHandle`, не `instanceof` реального класса) тем же классом симптомов, что и на категории `file-system-access` — не заводился отдельной строкой.
