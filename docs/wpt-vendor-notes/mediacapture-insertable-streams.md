Same pinned commit, `git sparse-checkout add` at the same commit hash, 13 files (`META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` copied from the sibling `mediacapture-image` category, `idlharness.any.js`, 2 root `.https.html` files, `legacy/` (8 `.https.html`), `tentative/` (2 `.https.html`)). No `variant` hits; out-of-category deps are `../webrtc/RTCPeerConnection-helper.js` and `../mediacapture-streams/permission-helper.js` (both unvendored); 12 of 13 files are `.https.`; 5 files reference `testdriver.js`. `run_report.py --all --root mediacapture-insertable-streams --recursive` completed in ~3:23 (13 ids from the glob, 12 actually selected by wptrunner): **0/12 harness OK, 0/0 subtests**. All 12 TIMEOUT on the standard TLS `UnknownIssuer` gap (same class as `mediacapture-handle`/`mediacapture-extensions`). The 13th glob id, `idlharness.any.html`, reported "Not run" — `idlharness.any.js` declares `// META: global=dedicatedworker`, so wptrunner's manifest only generates the `.any.worker.html` variant and never a `.any.html` one; `run_report.py`'s glob-based `all_vendored_test_ids()` doesn't parse `META: global` and assumes the default window+worker split, overcounting by 1 (the known "report the wptrunner number, not the glob's" gap — see `reference_wpt_run_report_invocation_recipe.md`). A `crates/js/src/` grep for `MediaStreamTrackProcessor`/`VideoTrackGenerator`/`MediaStreamTrackGenerator` found zero matches — the whole Insertable Streams for MediaStreamTrack API is unimplemented. No bug filed — first pass of an absent 🚫-scope API, same class as `mediacapture-handle`/`mediacapture-fromelement`. See `docs/wpt-status.md` for the full breakdown.
