# WPT vendor notes — `merchant-validation`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-05 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-merchant-validation`, `docs/wpt-status.md`), included despite its 🚫 scope note (Payment Request API — no pipeline) by the same standing user decision as the `mediacapture-*`/`mediasession` backlog. Same pinned commit, `git sparse-checkout add` at the same commit hash, 5 files (`META.yml`, `LICENSE-WPT.md` copied from the sibling `mediasession` category, 4 root test files: `complete-method.tentative.https.html`, `constructor.tentative.http.html`, `constructor.tentative.https.html`, `onmerchantvalidation-attribute.https.html`). No `variant` hits, no `testdriver.js` references; 3 of 4 files are `.https.`. `run_report.py --all --root merchant-validation --recursive` completed in ~55s (4 selected ids): **1/4 harness OK, 0/1 subtests passed**. Three `.https.` tests TIMEOUT/ERROR on the standard TLS `UnknownIssuer` gap; one ERROR is a reconfirmation of the already-filed BUG-380 (executor reuses the browsing context after a failed TLS navigation and returns the previous test's stale results). The one non-`.https.` test, `constructor.tentative.http.html`, ran and surfaced a genuine engine defect: `assert_false("MerchantValidationEvent" in Window)` throws `ReferenceError: Window is not defined` instead of evaluating to `false` — the global `Window` interface object doesn't exist at all (`typeof Window === "undefined"`), unlike `Document`/`Element` (both `"function"`). Confirmed live via `--mcp-live-port`. Filed as [BUG-637](../../bugs/BUG-637-OPEN.md) — same class as [BUG-624](../../bugs/BUG-624-OPEN.md) (`Navigator`) and [BUG-589](../../bugs/BUG-589-OPEN.md) (`window` not a proper WebIDL exotic object): the `window` global isn't backed by a real interface prototype chain. The finding is engine-wide, not specific to Payment Request. See `docs/wpt-status.md` for the full breakdown.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-08-05 (коммит `35be3b44`, `tests/wpt/merchant-validation/`, 5 файлов: `META.yml`, `LICENSE-WPT.md` скопирован из соседней `mediasession`, 4 корневых тестовых файла: `complete-method.tentative.https.html`, `constructor.tentative.http.html`, `constructor.tentative.https.html`, `onmerchantvalidation-attribute.https.html`), включена несмотря на скоуп 🚫 (Payment Request API, нет конвейера) по тому же постоянному решению пользователя, что весь бэклог `mediacapture-*`/`mediasession`. Ни variant-ов, ни `testdriver.js`; 3 из 4 файлов `.https.`. Прогон `run_report.py --all --root merchant-validation --recursive` (~55с): 4 отобранных id, **1/4 harness OK, 0/1 сабтестов passed**. Три `.https.`-теста TIMEOUT/ERROR на стандартном TLS-гэпе (`UnknownIssuer`), один ERROR — переподтверждение уже заведённого BUG-380 (исполнитель не проверяет исход `browsingContext.navigate` и переиспользует browsing context). Единственный не-`.https.` тест (`constructor.tentative.http.html`) исполнился и дал реальную находку: `assert_false("MerchantValidationEvent" in Window)` бросает `ReferenceError: Window is not defined` вместо возврата `false` — глобальный интерфейсный объект `Window` не установлен вовсе (`typeof Window === "undefined"`), в отличие от `Document`/`Element` (оба `"function"`). Подтверждено живой пробой `--mcp-live-port`. Заведён [BUG-637](../../bugs/BUG-637-OPEN.md) — тот же класс, что [BUG-624](../../bugs/BUG-624-OPEN.md) (`Navigator`) и [BUG-589](../../bugs/BUG-589-OPEN.md) (`window` не полноценный WebIDL exotic object): `window`-глобал не подкреплён настоящей цепочкой прототипов интерфейсов. Находка движковая, не специфична для Payment Request
