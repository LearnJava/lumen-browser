# WPT vendor notes — `input-events`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-05 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-input-events`, `docs/wpt-status.md`), scope ⬜ (candidate). Same pinned commit, `git sparse-checkout add` at the same commit hash, 29 files (`META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` copied from the sibling `inert` category, 21 test files, one shared `input-events-get-target-ranges.js` helper). No `.https.` files; 4 files use `variant`. `run_report.py --all --root input-events --recursive` completed in ~1 min (33 selected ids): **30/33 harness OK, 106/1728 subtests passed**. Every failure traces to already-open defects, dominant one confirmed live via `--mcp-live-port`: [BUG-368](../bugs/BUG-368-OPEN.md) (`innerHTML` setter is a text-node stub — `div.innerHTML = '<p>a<span>b[]</span>c</p>'` produces one `#text` child instead of parsed markup) drives the `TypeError: Cannot read properties of null/undefined (reading 'firstChild'/'nextSibling'/…)` cascade across all `input-events-get-target-ranges-*` files, whose shared helper parses `[]`/`{}` cursor markers by walking the tree `innerHTML` just built. Also reconfirmed: [BUG-574](../bugs/BUG-574-OPEN.md) (`elementDocument.contains is not a function` inside vendored `testdriver.js`, breaks `test_driver.send_keys`/`.click()`) and [BUG-533](../bugs/BUG-533-OPEN.md) (`StaticRange` undefined). Two harness-level TIMEOUTs (`input-events-arrow-key-on-number-input-delete-document.html`, `input-events-spin-button-click-on-number-input-delete-document.html`) — live probe confirmed [BUG-480](../bugs/BUG-480-OPEN.md) (`<iframe>` has no separate browsing context: setting `frame.srcdoc`/`frame.src` never fires `load`, `contentDocument` stays `null`, so the test's `await` on the iframe's `load` event hangs until wptrunner's outer timeout). Two more known infra-gap classes, not engine bugs: `test_driver.Actions is not a constructor` (346 subtests — `/resources/testdriver-actions.js` not vendored) and `EditorTestUtils is not defined` (8 subtests — out-of-category `../editing/include/editor-test-utils.js` not vendored); the third TIMEOUT (`idlharness.window.html`) is the same un-vendored `/resources/WebIDLParser.js`+`idlharness.js` gap as `input-device-capabilities`. No new bugs filed. See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-08-05 (коммит `35be3b44`, `tests/wpt/input-events/`, 29 файлов: `META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` скопирован из соседней `inert`, 21 тестовый файл + 1 общий `.js`-хелпер), скоуп ⬜ (кандидат). `run_report.py --all --root input-events --recursive` — ~1 мин, 33 отобранных id: **30/33 harness OK, 106/1728 сабтестов**. Весь провал сводится к уже открытым дефектам, доминирующий подтверждён живой пробой (`--mcp-live-port`): [BUG-368](../bugs/BUG-368-OPEN.md) (`innerHTML`-сеттер — текстовая заглушка, кладёт разметку одним текстовым узлом) — объясняет каскад `TypeError: Cannot read properties of null/undefined (reading 'firstChild'/…)` во всех `input-events-get-target-ranges-*`, которые парсят курсорные маркеры внутри вставленной через `innerHTML` разметки. Также переподтверждены [BUG-574](../bugs/BUG-574-OPEN.md) (`elementDocument.contains is not a function` в `testdriver.js`, блокирует `test_driver.send_keys`/`.click()`) и [BUG-533](../bugs/BUG-533-OPEN.md) (`StaticRange` не определён). Два TIMEOUT (`*-delete-document.html`) — живой пробой подтверждён [BUG-480](../bugs/BUG-480-OPEN.md) (`<iframe>` без отдельного browsing context: `frame.srcdoc =`/`frame.src =` не эмитит `load`, `contentDocument` остаётся `null`, тест висит на ожидании `load` до внешнего таймаута wptrunner). Ещё два класса невендоренной инфраструктуры (не движковые баги): `test_driver.Actions is not a constructor` (346 сабтестов, `/resources/testdriver-actions.js` не довендорен) и `EditorTestUtils is not defined` (8 сабтестов, внекатегорийный `../editing/include/editor-test-utils.js` не довендорен); третий TIMEOUT (`idlharness.window.html`) — невендоренные `/resources/WebIDLParser.js`+`idlharness.js`, тот же класс, что `input-device-capabilities`. Новых багов не заведено.
