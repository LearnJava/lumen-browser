One out-of-category helper (`/permissions-policy/resources/permissions-policy.js`, referenced by the 5 `enabled-by-*`/`disabled-by-*` `.sub.html` tests) not vendored, same documented survey gap as `FileAPI`/`gamepad`. `run_report.py --all --root geolocation --recursive` completed in **1 min 58 s** (20 selected ids): **1/20 harness OK, 4/4 subtests passed** — 12 SKIP (testdriver.js, tag-based `<script src>` so the manifest flag agrees with the grep, same class as `fullscreen`), 6 TIMEOUT (ordinary HTTPS-port gap, same class as `WebCryptoAPI`/`ai`/`ambient-light`), 1 ERROR (`permission.https.html` — session-reuse artifact of the same class as `gamepad`/`fledge`'s BUG-380: its result came back tagged with the previous test's URL, `non-secure-contexts.http.html`). The sole executed test — `non-secure-contexts.http.html`, the category's only non-`.https.` file — passed cleanly, confirming `getCurrentPosition`/`watchPosition` correctly and asynchronously reject with `PERMISSION_DENIED` outside a secure context. The category's real finding came from reading the shim source rather than the run: BUG-395, fixed P3 2026-08-11 (the follow-up BUG-762 — `PositionOptions` never read by the shim — stays open): (`crates/js/src/geolocation.rs`'s `GEO_SHIM` — `getCurrentPosition`/`watchPosition` never throw `TypeError` for a missing/`null`/wrong-type success callback; the vendored `getCurrentPosition_TypeError.https.html`/`watchPosition_TypeError.https.html` test this directly but are themselves unreachable by this run via the HTTPS-port gap, not testdriver — the same "probe even when the run yields nothing" lesson as `generic-sensor`'s BUG-393/394). `clearWatch` matches spec (never throws on an invalid id) — no regression there. See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/geolocation/`, 28 файлов: `META.yml`, `WEB_FEATURES.yml`, 22 `*.https(.sub).html`/`*.https.window.js`, 1 `.http.html`, `resources/`, `support.js`, `LICENSE-WPT.md`), скоуп ⬜ (кандидат). Внекатегорийный хелпер `/permissions-policy/resources/permissions-policy.js` (5 ссылок) не довендорен — та же методология, что `FileAPI`/`gamepad`. `run_report.py --all --root geolocation --recursive` — **1 мин 58 с, 1/20 harness OK, 4/4 сабтеста** (12 SKIP по testdriver.js — тег-based `<script src>`, флаг манифеста совпадает с грепом, тот же класс, что `fullscreen`; 6 TIMEOUT — обычный HTTPS-порт-гэп класса `WebCryptoAPI`/`ai`/`ambient-light`; 1 ERROR — `permission.https.html` получил результаты предыдущего `non-secure-contexts.http.html`, session-reuse артефакт класса BUG-380). Единственный исполнившийся тест — `non-secure-contexts.http.html`, единственный не-`.https.` файл категории — прошёл полностью (4/4): подтверждает, что `getCurrentPosition`/`watchPosition` корректно и асинхронно отклоняют запрос с `PERMISSION_DENIED` вне безопасного контекста. Реальная находка категории получена не прогоном, а чтением исходника шима: [BUG-395](../../bugs/BUG-395-FIXED.md) (закрыт P3 2026-08-11; следом заведён [BUG-762](../../bugs/BUG-762-OPEN.md) — `PositionOptions` шимом не читаются вовсе) — `crates/js/src/geolocation.rs`'s `GEO_SHIM`: `getCurrentPosition`/`watchPosition` никогда не бросают `TypeError` на отсутствующий/`null`/невалидный success-колбэк; вендоренные `getCurrentPosition_TypeError.https.html`/`watchPosition_TypeError.https.html` проверяют это напрямую, но сами недостижимы этим прогоном из-за HTTPS-порт-гэпа, а не testdriver — тот же урок «пробуй, даже если прогон ничего не дал», что и BUG-393/394 на `generic-sensor`. `clearWatch` соответствует спеке (не бросает на невалидный id) — регрессии нет.
