# WPT vendor notes — `graphics-aria`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-28 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-graphics-aria`, `docs/wpt-status.md`), scope ⬜ (candidate), spec `https://w3c.github.io/graphics-aria/`. Same pinned commit, `git sparse-checkout` at the same commit hash, 3 files (`META.yml`, `graphics-roles.html`, `LICENSE-WPT.md` — no `WEB_FEATURES.yml`). Smallest fully-automated category so far: a single `testharness` test, checking the same three roles as the already-vendored (manual/ATTAcomm) `graphics-aam` — `graphics-document`/`graphics-object`/`graphics-symbol` — via `AriaUtils.verifyRolesBySelector` instead of a human-driven ATTAcomm protocol. One out-of-category helper not vendored: `/wai-aria/scripts/aria-utils.js` (`wai-aria` itself isn't vendored yet), same gap as `core-aam`/`dpub-aam`/`graphics-aam`. `run_report.py --all --root graphics-aria --recursive` completed in ~24 s (1 selected id): **0/1 harness OK, 0/0 subtests** — SKIP (`Executor does not support testdriver.js`; the file pulls `testdriver.js`/`testdriver-actions.js`/`testdriver-vendor.js` in `<head>` without ever calling them, but the manifest flags on tag presence, not use). No new finding: the test targets the exact defect already filed as BUG-398 (the three Graphics ARIA roles are absent from `AXRole::parse`, `crates/engine/a11y/src/roles.rs`, falling back to `Generic`), found via a direct Rust probe when `graphics-aam` was vendored — re-probing would only reconfirm the same root cause through a different test file, so it wasn't repeated. See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/graphics-aria/`, 3 файла: `META.yml`, `graphics-roles.html`, `LICENSE-WPT.md` — `WEB_FEATURES.yml` у категории нет), скоуп ⬜ (кандидат), спека `https://w3c.github.io/graphics-aria/`. В отличие от уже вендоренной `graphics-aam` (набор ATTAcomm `*-manual.html`), здесь единственный тест — автоматический `testharness`, проверяющий те же три роли (`graphics-document`/`graphics-object`/`graphics-symbol`) через `AriaUtils.verifyRolesBySelector` вместо ручного ATTAcomm-протокола. Внекатегорийный хелпер `/wai-aria/scripts/aria-utils.js` не довендорен — категория `wai-aria` сама ещё не вендорена, та же методология, что `core-aam`/`dpub-aam`/`graphics-aam`. `run_report.py --all --root graphics-aria --recursive` — **~24 с, 0/1 harness OK, 0/0 сабтестов** (единственный id — SKIP, `Executor does not support testdriver.js`: тест подключает `testdriver.js`/`testdriver-actions.js`/`testdriver-vendor.js` в `<head>`, хотя сам их не вызывает — манифест решает по факту подключения тега, не по использованию). Прогон сигнала не дал; тест не даёт новой находки — он бьёт ровно в уже заведённый [BUG-398](../bugs/BUG-398-FIXED.md) (те же три роли Graphics ARIA отсутствуют в `AXRole::parse` целиком, откат к `Generic`), найденный прямой Rust-пробой на `build_ax_tree` при вендоринге `graphics-aam`, поэтому повторная проба не проводилась — независимое подтверждение через другой тестовый файл этой же спеки, не новый дефект
