Заведён [BUG-695](../../bugs/BUG-695-OPEN.md): `URLPattern` (`crates/js/src/url_pattern.rs`) — собственный доку-комментарий признаёт его «pure JavaScript implementation», рукописный мини pattern-matcher, а не портированный алгоритм WHATWG URLPattern Standard. Конструктор читает только `pathname`/`search`/`hash`/`hostname` из `init` — `protocol`/`port`/`username`/`password`/`baseURL` не читаются вовсе, отсюда 369/370 провалов в `urlpattern.any.html` («compiled pattern property 'protocol' expected … but got undefined»); нет компиляции/нормализации компонент; `test()`/`exec()` отдают плоский объект групп вместо `URLPatternResult`; нет `URLPattern.compareComponent` (`urlpattern-compare.tentative.any.html` 1/26); нет `.hasRegExpGroups` (`urlpattern-hasregexpgroups.any.html` 0/1); нет `.generate()` (`urlpattern-generate.tentative.any.html` 11/20); нет валидации синтаксиса паттерна — конструктор не бросает на незакрытом `%`-escape (`urlpattern-constructor.any.html` 1/2) и не парсит regexp-группы `(...)` вовсе, поэтому не бросает на пустой группе `()` (`urlpattern-empty-regexp-group.html` 1/2). `urlpattern-detached-frame-regexp.html` TIMEOUT (0/4) — та же отсутствующая regexp-группа плюс уже задокументированный [BUG-480](../../bugs/BUG-480-OPEN.md) (`<iframe>` без отдельного browsing context).
