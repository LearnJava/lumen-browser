# WPT vendor notes — `mediacapture-fromelement`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-05 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-mediacapture-fromelement`, `docs/wpt-status.md`), included despite its 🚫 scope note (media capture — no pipeline) by the same standing user decision as `mediacapture-extensions`/`media-capabilities`/`media-playback-quality`/`media-source`. Same pinned commit, `git sparse-checkout add` at the same commit hash, 11 files (`META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` copied from the sibling `mediacapture-extensions` category, 9 root test files including `idlharness.window.js`). No `variant` hits, no `.https.` files, no `testdriver.js` hits — only out-of-category deps are `../webaudio/resources/rms-utils.js` and `../webrtc/RTCPeerConnection-helper.js`, both un-vendored. `run_report.py --all --root mediacapture-fromelement --recursive` completed in ~44s (12 selected ids): **10/12 harness OK, 10/32 subtests passed**, no TLS gap (unlike the two prior mediacapture categories, since none of these files are `.https.`). Dominant signal: `HTMLCanvasElement.prototype.captureStream`/`HTMLMediaElement.prototype.captureStream` are both entirely absent (`TypeError: … .captureStream is not a function` / `assert_implements: … is not implemented`) — a `crates/js/src/` grep for `captureStream` found zero matches, confirming the whole Media Capture from DOM Elements API is unimplemented, not selectively missing like `mediacapture-extensions`. 2 harness TIMEOUTs (`idlharness.window.html`, `src-reset.html`) are downstream of the same absence. No bug filed — first pass of an absent 🚫-scope API, same class as `media-playback-quality`/`media-source`'s `MediaSource is not defined` finding. See `docs/wpt-status.md` for the full breakdown.
