# WPT vendor notes — `subresource-integrity`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-06 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-subresource-integrity`, `docs/wpt-status.md`), scope ⬜ (candidate). Same pinned commit, `git sparse-checkout add` at the same commit hash, 44 files (`META.yml`, root `subresource-integrity.html`+CSS/JS fixtures, `integrity-policy/`, `signatures/` incl. `tentative/`, `unencoded-digest/tentative/`, `tools/`); the one category-local helper the root test needs, `/resources/sriharness.js`, was missing from the already-vendored shared `tests/wpt/resources/` and was vendored alongside it in this pass. No `variant` hits beyond 6 (`integrity-policy/parsing.html?type=…`-style query fan-out), no `testdriver.js` references, 5 of 44 files are `.https.`. Out-of-category helpers not vendored: the entire top-level `/common/` directory (`dispatcher/dispatcher.js`, `utils.js`, `get-host-info.sub.js`) — same documented survey gap as `streams`' `/common/gc.js`/`signed-exchange`'s `get-host-info.sub.js`. `run_report.py --all --root subresource-integrity --recursive` completed in 7:59 (23 selected ids from the glob; wptrunner actually ran 30 due to the variant fan-out): **7/30 harness OK, 39/156 subtests**. No new engine defect: the un-vendored `/common/` cascades into `ReferenceError: token/get_host_info is not defined` on every non-`.https.` test that isn't itself `signatures/tentative/*`, including the category's own base (non-tentative) hash-integrity smoke test `subresource-integrity.html` — so the base SRI hash-checking path could not actually be exercised this pass, only the tentative Signature-based Integrity subtree could (see below). 2 `.https.` ids errored instantly instead of timing out (`AssertionError: Got results from <previous test>, expected <this test>`) — reconfirmation of [BUG-380](../../bugs/BUG-380-OPEN.md); the remaining `.https.` ids TIMEOUT on the standard TLS `UnknownIssuer` gap. `signatures/tentative/accept-signature.parser-inserted.html` (4/4 subtests FAIL, `Cannot read properties of undefined (reading 'setAttribute')` on `document.currentScript` inside a dynamically-loaded external script) — reconfirmation of [BUG-486](../../bugs/BUG-486-FIXED.md) (`document.currentScript` entirely missing). `signatures/tentative/inline.html` (6/21 subtests FAIL): inline `<script>`/`<style>`/SVG elements carrying a `signature` attribute without (or with an invalid) `integrity` assertion should be blocked from executing per the WICG Signature-based Integrity draft, but Lumen loads them anyway — a `crates/js/src/*.rs` grep for `signature` (excluding WebGPU/WebAuthn/WASM matches) found zero hits, so Signature-based Integrity is entirely unimplemented; the whole subtree lives under `signatures/tentative/`, same "unimplemented draft extension" class as `subapps`/`speculation-rules`'s `SpeculationMeasurement`, so no bug filed for it. No new bug filed this pass — all signal is either the `/common/` survey gap or a reconfirmation of BUG-380/BUG-486. See `docs/wpt-status.md` for the full breakdown.
