## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-25 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-bluetooth`, `docs/wpt-status.md`), included despite its 🚫 scope note (hardware API, no device-integration layer) by the same standing user decision as `accelerometer`/`acid`/`ai`/`ambient-light`/`appmanifest`/`attribution-reporting`/`audio-output`/`audio-session`/`autoplay-policy-detection`/`background-fetch`/`background-sync`/`badging`/`battery-status`. Same pinned commit, `git sparse-checkout` at the same commit hash, 187 files (`META.yml`, `WEB_FEATURES.yml`, `README.md`, `resources/` — 4 helpers, `bidi/` — 9 subcategories `adapter`/`characteristic`/`descriptor`/`device`/`getDevices`/`idl`/`requestDevice`/`script-tests`/`server`/`service` + `generate.py`+`generate_test.py`). Out-of-category helper not vendored: `/resources/testdriver.js`+`/resources/testdriver-vendor.js` (only referenced via `META: script=`; doesn't block a run unless a test actually issues a testdriver command). Largest category in this backlog by selected id count (155: 153 `.https.`-only, 2 non-https `idl-*` files) — the full `run_report.py --all --root bluetooth --recursive` did not complete: a bounded trial run (~11 min) processed 10 of the 153 `.https.` ids, all TIMEOUT (`invalid url: invalid port: "None"`, same HTTPS-port gap as `WebCryptoAPI`/`ai`), same limitation class as `ai` (a full run at this pace would take hours). The 2 non-https `idl-*` tests were run in isolation via `run_smoke.py`: 2/2 harness OK, 0/15 subtests (0/14 + 0/1) — `BluetoothUUID is not defined` and similarly for `navigator.bluetooth`, the Web Bluetooth API itself is unimplemented, expected for a 🚫-scope category. See `docs/wpt-status.md` for details.
