The WebHID API is actually implemented as a Phase 0 stub (`crates/js/src/webhid.rs`) and behaves exactly as its own doc comment describes (`requestDevice()` → `NotSupportedError`, `getDevices()` → `[]`) — not a bug. A live probe (`--mcp-live-port`, independent of the WPT runner) found one new, previously unfiled defect — [BUG-713](../../bugs/BUG-713-OPEN.md): `HIDManager`/`HIDDevice` are plain `class X extends EventTarget` with no constructor guard, so `new HIDManager()`/`new HIDDevice(1,2,'x')` both succeed even though the WICG WebHID spec defines no constructor operation for either — same defect class as [BUG-672](../../bugs/BUG-672-OPEN.md) (`Serial`/`SerialPort`, identical file structure), [BUG-629](../../bugs/BUG-629-OPEN.md) (`Report`), [BUG-374](../../bugs/BUG-374-FIXED.md) (`FileSystemFileHandle`) — fourth independent surface. See `docs/wpt-status.md` for the full breakdown.

## Прогон и находки (`docs/wpt-status.md`)

аппаратный API (HID), но `navigator.hid` реально реализован как Phase 0 заглушка (`crates/js/src/webhid.rs`). Вендорена целиком 2026-08-09 (коммит `35be3b44`, `tests/wpt/webhid/`, 11 файлов). `run_report.py --all --root webhid --recursive` — ~1:35, 5 отобранных id, все `.https.`: **0/5 harness OK**, все TIMEOUT на уже задокументированном TLS-гэпе `UnknownIssuer` — не новая находка. WebHID API ведёт себя ровно так, как описывает собственный doc-комментарий (`requestDevice()`→`NotSupportedError`, `getDevices()`→`[]`) — не баг. Живая проба через `--mcp-live-port` нашла [BUG-713](../../bugs/BUG-713-OPEN.md): `HIDManager`/`HIDDevice` — обычные `class X extends EventTarget` без guard на конструктор, `new HIDManager()`/`new HIDDevice(1,2,'x')` конструируются успешно, хотя спека не определяет конструктор ни для одного из них (тот же класс, что [BUG-672](../../bugs/BUG-672-OPEN.md)/[BUG-629](../../bugs/BUG-629-OPEN.md)/[BUG-374](../../bugs/BUG-374-FIXED.md), четвёртая независимая поверхность). Отдельно (не новый баг, покрыто [BUG-615](../../bugs/BUG-615-OPEN.md), уже называющим `webhid.rs`): `navigator.hid` продолжает утечку `_devices`/`onconnect`/`ondisconnect` как собственные перечислимые свойства.
