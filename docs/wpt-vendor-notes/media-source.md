# WPT vendor notes — `media-source`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-05 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-media-source`, `docs/wpt-status.md`), included despite its 🚫 scope note (MSE media pipeline) by the same standing user decision as `media-capabilities`/`media-playback-quality`/`audio-output`/`audio-session`. Same pinned commit, `git sparse-checkout add` at the same commit hash, 158 files (3.0 MB — `META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` copied from the sibling `media-playback-quality` category, ~70 `mediasource-*.html`/`SourceBuffer-*.html`/`URL-createObjectURL*.html` root tests + shared `mediasource-util.js`/`mediasource-changetype-util.js`/`mediasource-config-changes.js`, `dedicated-worker/` (20 files), `mp3/`+`mp4/`+`webm/` binary media fixtures (52 files), `mse-for-webcodecs/tentative/` (6 files)). One out-of-category dependency triple not vendored: three `mse-for-webcodecs` tentative tests reference `/encrypted-media/util/{clearkey-messagehandler,utf8,utils}.js`, same documented survey gap as `FileAPI`/`ai`. One `.https.` file (`mse-for-webcodecs/tentative/mediasource-encrypted-webcodecs-appendencodedchunks-play.https.html`); no `testdriver.js` hits, no `variant` hits. `run_report.py --all --root media-source --recursive` completed in ~1:06 with `--processes=4` (82 selected ids) and ~2:20 with `--processes=1` — **identical result both ways: 60/82 harness OK, 0/272 subtests**. Dominant signal on the 47 harness-OK-but-all-FAIL tests: `ReferenceError: MediaSource is not defined` (1026 occurrences) — the Media Source Extensions API is entirely unimplemented, expected on a 🚫-scope category's first pass, no bug filed for that part. A genuinely new finding on the other 13 tests (`mediasource-addsourcebuffer(-mode)`/`-changetype`/`-closed`/`-correct-frames(-after-reappend)`/`-endofstream-invaliderror`/`-h264-play-starved`/`-invalid-codec`/`-multiple-attach`/`-removesourcebuffer`/`-sourcebufferlist`/`-timestamp-offset.html`): the live `lumen.exe` process itself dies with a V8 fatal error (`Check failed: isolate_->IsOnCentralStack()`, stack through `Heap::CollectGarbage` ← `Object::GetOwnPropertyNames` ← unbounded recursion in `lumen_js::v8_runtime::from_v8`), which `wptrunner` reports as `WebSocket connection closed` — reproduced identically under both `--processes=1` and `--processes=4`, not a parallel-run artifact. Filed as [BUG-633](../../bugs/BUG-633-FIXED.md). See `docs/wpt-status.md` for the full breakdown.
