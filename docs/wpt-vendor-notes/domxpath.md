# WPT vendor notes — `domxpath`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-26 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-domxpath`, `docs/wpt-status.md`), in-scope (⬜, DOM XPath — `document.evaluate`/`XPathEvaluator`/`XPathExpression`/`XPathResult`/`XPathNSResolver`, not implemented in Lumen at all). Same pinned commit, `git sparse-checkout` at the same commit hash, 39 files (`META.yml`, `README.md`, `WEB_FEATURES.yml`, 34 root test files, `resources/` — `empty-document.html` + `invalid_namespace_test.js`). No out-of-category helpers — every runnable test references only the already-vendored `/resources/testharness.js`+`testharnessreport.js` (plus the category's own `helpers.js`/`resources/`). `run_report.py --all --root domxpath --recursive` selected 34 ids by file scan; wptrunner itself excluded 2 (`variables-in-expression-crash.html`, `xpath-evaluate-crash.html`) as manifest type `crashtest` (`-crash.html` naming convention, no `testharness.js` at all — same "unsupported test type" class as `accessibility`'s/`acid`'s crashtests/reftests), leaving 32 that actually ran, completing fully in ~2min: 28/32 harness OK, 2/126 subtests passed, 4 TIMEOUT (`evaluator-cross-realm.tentative.html`, `expression-cross-realm.tentative.html` — cross-realm `BroadcastChannel`-based helper hangs before the API it's testing is even reached; `xml_xpath_runner.html`, `xpathevaluatorbase-creatensresolver.html` — harness never reports, 0/0). Root cause for essentially the whole category is a single unimplemented feature — `document.evaluate`/`XPathEvaluator`/`XPathExpression`/`XPathResult`/`XPathNSResolver` all throw `ReferenceError`/`TypeError: ... is not a function` — not filed as a separate BUG-NNN (same "whole API missing" pattern as `document-policy`/`custom-elements`'s `registries/`). One incidental non-XPath finding surfaced by `xpath-shadow-dom.html`: its first subtest fails at `host.shadowRoot.getElementById('target')` before ever reaching `XPathEvaluator` — declarative Shadow DOM (`<template shadowrootmode="open">`) content isn't attached/queryable via `getElementById` the way the imperative-shadow-DOM sibling test is; its second subtest is a false PASS (the assertions inside a custom element's `connectedCallback` never execute, so the test trivially succeeds having asserted nothing) — a Custom-Elements/Shadow-DOM lifecycle gap, not an XPath one; not filed separately since `custom-elements`/BUG-341 already tracks related shadow-DOM/custom-element gaps. See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-26 (коммит `35be3b44`, `tests/wpt/domxpath/`, 39 файлов: `META.yml`, `README.md`, `WEB_FEATURES.yml`, 34 корневых теста, `resources/` — `empty-document.html`+`invalid_namespace_test.js`), в скоупе (⬜, DOM XPath — `document.evaluate`/`XPathEvaluator`/`XPathExpression`/`XPathResult`/`XPathNSResolver`, не реализовано в Lumen вовсе). Без внекатегорийных хелперов. `run_report.py --all --root domxpath --recursive` отобрал 34 id файловым сканом; wptrunner сам исключил 2 (`variables-in-expression-crash.html`, `xpath-evaluate-crash.html`) как манифест-тип `crashtest` (соглашение об имени `-crash.html`, без testharness.js вовсе — тот же класс "неподдерживаемый тип теста", что crashtests/reftests у `accessibility`/`acid`), осталось 32 в очереди, прошёл полностью (~2мин): 28/32 harness OK, 2/126 сабтестов passed, 4 TIMEOUT (`evaluator-cross-realm.tentative.html`, `expression-cross-realm.tentative.html` — cross-realm хелпер виснет; `xml_xpath_runner.html`, `xpathevaluatorbase-creatensresolver.html` — harness не репортит вовсе, 0/0). Корневая причина почти всей категории — единственная нереализованная фича: `document.evaluate`/`XPathEvaluator`/`XPathExpression`/`XPathResult`/`XPathNSResolver` все бросают `ReferenceError`/`TypeError: ... is not a function`, отдельный BUG-NNN не заводился (тот же паттерн "целиком отсутствующий API", что `document-policy`/`registries/` у `custom-elements`). Побочная находка не по теме XPath: `xpath-shadow-dom.html` падает на первом сабтесте ещё до `XPathEvaluator` — `host.shadowRoot.getElementById('target')` не находит элемент из декларативного Shadow DOM (`<template shadowrootmode="open">`); второй сабтест — ложный PASS (ассерты внутри `connectedCallback` кастомного элемента вовсе не выполняются, тест проходит, ничего не проверив) — гэп жизненного цикла Custom Elements/Shadow DOM, уже покрываемый BUG-341/`custom-elements`, отдельно не заводился
