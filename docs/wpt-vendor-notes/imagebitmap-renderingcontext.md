## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-04 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-imagebitmap-renderingcontext`, `docs/wpt-status.md`), scope ⬜ (candidate). Same pinned commit, `git sparse-checkout add` at the same commit hash, 16 files (`META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` copied from the sibling `html-ruby-extensions` category, 14 test files). Fully self-contained: zero `variant`/`testdriver.js` hits, only out-of-category `src=` refs are the already-vendored `/resources/testharness(report).js`. `run_report.py --all --root imagebitmap-renderingcontext --recursive` completed in ~48 s (14 selected ids): **12/14 harness OK, 1/20 subtests passed** — well above this backlog's recent average for harness-OK share, but almost every subtest fails. Two new bugs from real FAIL/TIMEOUT subtests, both confirmed live via `--mcp-live-port`: [BUG-616](../../bugs/BUG-616-OPEN.md) (`createImageBitmap()` rejects `HTMLCanvasElement` sources with `TypeError: unsupported source type` — only `OffscreenCanvas`/`ImageData`/`HTMLImageElement`/`Blob` are handled, the dominant failure — 15 FAIL + 1 TIMEOUT of 19 unexpected subtests) and [BUG-617](../../bugs/BUG-617-OPEN.md) (`ImageBitmapRenderingContext` has no global constructor at all — `typeof window.ImageBitmapRenderingContext === "undefined"` — plus `OffscreenCanvas.getContext()` only implements `'2d'`, always returning `null` for `'bitmaprenderer'`/`'webgpu'` even though the on-page-`<canvas>` factory in `dom.rs` supports both). One TIMEOUT (`toBlob-origin-clean-offscreen.sub.html`, a cross-origin-`<img>`-sourced test) is unattributed — no JS error precedes it in the log, likely blocked on the cross-origin `img.onload` never firing, not traced further. See `docs/wpt-status.md` for details.
