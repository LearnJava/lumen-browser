# WPT vendor notes — `cookies`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-25 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-cookies`, `docs/wpt-status.md`). Same pinned commit, `git sparse-checkout` at the same commit hash, 171 files (`META.yml`, `README.md`, `WEB_FEATURES.yml`, `attributes/`, `domain/`, `encoding/`, `name/`, `ordering/`, `origin-bound-cookies/`, `partitioned-cookies/`, `path/`, `prefix/`, `resources/`, `samesite/`, `samesite-none-secure/`, `schemeful-same-site/`, `secure/`, `size/`, `third-party-cookies/`, `value/`). One out-of-category helper (`/common/get-host-info.sub.js`) not vendored — used both directly by some tests and transitively by the in-category `resources/cookie-helper.sub.js`/`resources/cookie-test.js`, same documented survey gap as `FileAPI`/`ai`. `run_report.py --all --root cookies --recursive` completed in ~26:30 (82 selected ids): 25 SKIP (`Executor does not support testdriver.js`, same gap as `accname`/`attribution-reporting`); 40 TIMEOUT + 8 ERROR on `.https.`-only ids, the same HTTPS-port gap as `WebCryptoAPI`/`ai`/`background-fetch` (`invalid url: invalid port: "None"`) — the 8 ERROR ones are the same session-reuse-artifact manifestation as `accelerometer`/`ambient-light` (`Got results from X.html, expected X.https.html`) rather than a plain TIMEOUT; a handful of plain-HTTP tests also TIMEOUT because they depend on multi-window/iframe-navigation flows (`window.open`, form-target navigation, nested iframes) the minimal single-window executor can't drive, a different gap from the HTTPS-port one. 3/82 harness OK: `meta-blocked.html` (1/1 subtest PASS); `navigated-away.html` (0/1, `Cannot read properties of null (reading 'cookie')` — the test itself navigates an iframe to the un-vendored `/common/blank.html`, so the failure isn't trustworthy as a Lumen defect, same class of gap as the `get-host-info.sub.js` dependency); `document-cookie.non-secure.html` and `domain-attribute-missing.sub.html` FAIL with `<fn> is not defined` (`assert_dom_cookie`/`SECURE_SUBDOMAIN_ORIGIN`/`erase_cookie_from_js`) — these are defined in the vendored `resources/cookie-helper.sub.js`, but wptserve 500s serving it (`{{domains[www1]}}`/`{{ports[https]}}` substitution with no https port/extra domains configured), the same `AssertionError: deque([])` substitution gap already documented for `clear-site-data`. 1/7 subtests passed. Not filed as a separate BUG-NNN — every failure traces to an already-documented infra gap (testdriver.js, HTTPS port, `.sub.js` substitution, un-vendored `/common/`), not a fresh Lumen defect. See `docs/wpt-status.md` for details.
