# WPT vendor notes — `page-lifecycle`

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-08-05 (коммит `35be3b44`, `tests/wpt/page-lifecycle/`, 10 файлов: `META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` скопирован из соседней `orientation-sensor`, `child-display-none.tentative.html`, `child-out-of-viewport.tentative.html`, `freeze.html`, `idlharness.html`, `set-composited-layer-position(-ref).html`, `worker-dispay-none.tentative.html`, `resources/`). Ни variant-ов, ни `.https.`-файлов; `testdriver.js` только в `resources/window.html` (не отдельный тест) — самый дешёвый профиль. `run_report.py --all --root page-lifecycle --recursive` (~1 мин, 5 отобранных id): **0/5 harness OK, 0/3 сабтестов**. Все три iframe-теста (`child-display-none`/`child-out-of-viewport`/`worker-dispay-none`, единый сабтест "Child frame frozen") TIMEOUT — дочерний `<iframe>` грузит `resources/subframe.html`, который ждёт своего `load`-события, чтобы отправить `postMessage('load')` родителю; `load` у iframe не срабатывает вовсе — прямая реконфирмация [BUG-480](../../bugs/BUG-480-OPEN.md) (`<iframe>` не имеет отдельного browsing context). `freeze.html` TIMEOUT — `window.open('resources/window.html', …)` с относительным URL падает `invalid url: missing scheme: "resources/window.html"` (лог: `Reload: resources/window.html`) — прямая реконфирмация [BUG-359](../../bugs/BUG-359-FIXED.md) (`window.open`/навигация не резолвит относительный URL). `idlharness.html` TIMEOUT — тянет невендоренные `/resources/idlharness.js`+`WebIDLParser.js`, тот же класс, что уже задокументирован для `FileAPI`/`animation-worklet`/`netinfo` (`tests/wpt/VENDOR.md`). Новых багов не заведено — весь сигнал категории переподтверждает уже открытые дефекты
