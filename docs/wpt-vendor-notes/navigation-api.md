# WPT vendor notes — `navigation-api`

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-08-05 (коммит `35be3b44`, `tests/wpt/navigation-api/`, 493 файла, `LICENSE-WPT.md` скопирован из соседней `mimesniff`). API реально реализован (`window.navigation`), не заглушка — 0 `.https.`, testdriver-доля низкая (8/450 файлов), без HTTPS-порт-гэпа. Прогон `run_report.py --all --root navigation-api --recursive` (~21 мин, 475 отобранных id): **349/475 harness OK, но только 6/417 сабтестов passed (1.4%)**. Чтение `crates/js/src/navigation_api.rs` подтвердило причину — шим урезан относительно спеки: `NavigationCurrentEntryChangeEvent` глобал отсутствует (`currententrychange` диспатчит голый `Event`), `navigation.updateCurrentEntry()` не реализован, `NavigateEvent.destination` — голый `URL` вместо `NavigationDestination` (нет `sameDocument`/`getState()`/`key`/`id`/`index`), `NavigationHistoryEntry` не наследует `EventTarget` (нет `dispose`). Плюс нетронутый кластер `Cannot read properties of null (reading 'index')` (48 вхождений) на одно-документных тестах — вероятная гонка коммита навигации vs чтения `_lumen_navigation_entries_json()`, причина не установлена. `cross-window/*` тесты фейлятся отдельно, известным классом (нет multi-window/iframe browsing context, BUG-480). Заведён [BUG-639](../../bugs/BUG-639-FIXED.md); CAPABILITIES.md:195 снабжён 🟡-оговоркой в этом же коммите


## Разведка WPT-NAV-SCOUT (2026-10-26)

Источник — свежий прогон `run_corpus.py --prefixes navigation-api --processes 7` на `dev-release` от `main` `02531e0b7` (сырой лог шарда и `run.ids.tsv.gz` — `.tmp/wpt-nav/` слота p2-work): 478 id, **4.96 %** (23.7 балла из 478; 22 id пройдены целиком), harness OK у 301, сабтестов 32/443; статусы: OK 298, TIMEOUT 158, ERROR 18, PASS 3. Из 158 TIMEOUT 88 — «browser did not answer a BiDi call within 20s» (`LUMEN_WPT_HARD_CAP`), остальные — «Test timed out» внутри страницы.

Гипотеза задачи «основную массу покрывают [BUG-678](../../bugs/BUG-678-OPEN.md) и [BUG-881](../../bugs/BUG-881-OPEN.md)» **не подтвердилась**: BUG-678 (soft navigation) к `navigation-api` почти не относится, BUG-881 (`navigate` не приходит от `location`/якорей/`pushState`) объясняет лишь кластер E (42 id, 9 %). Главная масса — не отсутствие API, а то, что `navigation.navigate("#frag")` и `back()`/`traverseTo()` между записями одного документа идут как **полная навигация** (повторная загрузка страницы, новый realm): страница с безусловным `navigation.navigate("#foo")` уходит в цикл перезагрузок (≈230 мс на круг, `Reload: …#foo` в логе браузера) и ловит TIMEOUT. Второй по размеру дефект — `iframe.contentWindow.navigation` не имеет методов. Раннер ни при чём: история на каждый тест чистая (`navigation.entries().length === 1` в первом тесте и в каждом следующем при `run_smoke.py` с тремя id подряд), «раздутые» `entries()` — следствие цикла A.

«Потолок» = Σ(1 − доля сабтестов) по id кластера при полном исправлении; в п.п. корпуса = потолок / 68 116 (корпус WPT-RUN-16). Кластеры перекрываются (тест из A упирается затем в B или D), поэтому реальный прирост от одного кластера заметно ниже потолка. Распределение по кластерам — правилами по тексту первой ошибки, числу `Reload:` в логе шарда и исходнику теста (`.tmp/nav_classify.py`); кластер A включает 30 id с раздутым `entries()` без прямого свидетельства цикла (эвристика), кластер M — несгруппированный остаток.
