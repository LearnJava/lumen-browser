# WPT vendor notes — `domparsing`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-26 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-domparsing`, `docs/wpt-status.md`), in-scope (⬜, DOM Parsing and Serialization — `DOMParser`/`XMLSerializer`/`innerHTML`/`outerHTML`/`insertAdjacentHTML` — core DOM functionality, implemented in Lumen). Same pinned commit, `git sparse-checkout` at the same commit hash, 71 files (`META.yml`, `WEB_FEATURES.yml`, root `DOMParser-*`/`XMLSerializer-*`/`innerhtml-*`/`outerhtml-*`/`insert*` tests, `resources/` — 7 helpers, `tentative/` — 22 Sanitizer-API streaming/trusted-types tests + `resources/util.js`). One out-of-category helper not vendored: `tentative/`'s trusted-types tests reference `/trusted-types/support/helper.sub.js`, same documented survey gap as `FileAPI`/`ai`. `run_report.py --all --root domparsing --recursive` selected 55 ids and completed fully (~3:21): 38/52 harness OK, 59/1124 subtests passed, 9 TIMEOUT (mostly `tentative/` streaming tests hitting `trustedTypes is not defined`/the un-vendored helper's 404), 3 ERROR (session/URL-reuse artifact, same class as `accelerometer`/`beacon`/`clear-site-data`). Two new broad engine bugs found and filed together as [BUG-351](../../bugs/BUG-351-OPEN.md): (1) `insertAdjacentHTML` is missing entirely from the live `Element` (`insert-adjacent.html` 0/4, `insert_adjacent_html.html` 1/31) — its sibling `insertAdjacentText` was fixed under BUG-299, but `insertAdjacentHTML` — the far more common of the two in real-world code — never got the same fix; (2) `outerHTML` only exists on `VElement.prototype` (`dom_parser.rs:111`, the separate "virtual" tree `DOMParser.parseFromString()` builds), never on the live DOM `Element` (`outerhtml-01.html` 0/1, `outerhtml-02.html` 1/5 — assigning it silently no-ops instead of mutating the tree). Separately, `DOMParser`-produced `Document`s themselves are missing several facilities (`compatMode`/`location`/`styleSheets` undefined, `documentElement` typed as a bare `VElement` rather than `HTMLHtmlElement`, per-element `.style` undefined — `DOMParser-parseFromString-html.html` 3/10, `-stylesheets.html` 0/6, `style_attribute_html.html` 0/4) — a documented architectural limitation of the intentionally lightweight "virtual node" design (`dom_parser.rs` module doc comment), not filed as a separate bug. See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-26 (коммит `35be3b44`, `tests/wpt/domparsing/`, 71 файл: `META.yml`, `WEB_FEATURES.yml`, `DOMParser-*`/`XMLSerializer-*`/`innerhtml-*`/`outerhtml-*`/`insert*` root tests, `resources/`, `tentative/` — Sanitizer-API streaming/trusted-types тесты), в скоупе (⬜, DOMParser/innerHTML/outerHTML — ядро реализовано в Lumen). Один внекатегорийный хелпер не вендорен — `/trusted-types/support/helper.sub.js` (используется частью `tentative/`), тот же гэп, что у `FileAPI`/`ai`. `run_report.py --all --root domparsing --recursive` отобрал 55 id, прошёл полностью (~3:21): 38/52 harness OK, 59/1124 сабтестов passed, 9 TIMEOUT (в основном `tentative/`-стрим-тесты на `trustedTypes is not defined`/404 хелпера), 3 ERROR (session/URL-reuse артефакт, тот же класс, что `accelerometer`/`beacon`). Два новых широких движковых бага: (1) `insertAdjacentHTML` отсутствует целиком на живом `Element` (`insert-adjacent.html` 0/4, `insert_adjacent_html.html` 1/31) — сосед `insertAdjacentText` чинился под BUG-299, у `insertAdjacentHTML` фикса никогда не было; (2) `outerHTML` определён только на параллельном `VElement` (дерево `DOMParser`), у живого DOM геттера/сеттера нет вовсе (`outerhtml-01.html` 0/1, `outerhtml-02.html` 1/5). Оба объединены в [BUG-351](../bugs/BUG-351-OPEN.md). Отдельно: `DOMParser`-документы (не сам `DOMParser`, а результирующий `Document`) не полностью укомплектованы — `compatMode`/`location`/`styleSheets` undefined, `documentElement` не типизирован как `HTMLHtmlElement` (`DOMParser-parseFromString-html.html` 3/10, `-stylesheets.html` 0/6, `style_attribute_html.html` 0/4 — `div.style` тоже undefined) — задокументированное архитектурное ограничение «виртуального» DOMParser-дерева (`dom_parser.rs` модульный doc-комментарий), отдельный BUG-NNN не заводился.
