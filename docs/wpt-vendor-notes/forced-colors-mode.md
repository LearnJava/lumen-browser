## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/forced-colors-mode/`, 118 файлов: `README.txt`, `WEB_FEATURES.yml` — `META.yml` у категории нет, 92 файла верхнего уровня, в основном reftest-пары `-NN.html`/`-NN-ref.html` плюс 14 `testharness.js`-тестов, `backplate/` — 20 файлов той же структуры, `resources/` — 2 картинки, `LICENSE-WPT.md`), скоуп ⬜ (кандидат). **Первая категория бэклога, где находкой стал сам разрыв reftest/testharness.** 49 из файлов верхнего уровня — `rel=match` reftest-ы, а исполнитель (`browsers/lumen.py:36-37`) регистрирует единственный тип `testharness`: `reftest`/`print-reftest`/`crashtest` в логе явно помечены `Unsupported test type for product lumen` и не отбираются вовсе, поэтому `run_report.py --all --root forced-colors-mode --recursive` выбрал не 117, а ровно **63 из 117** id и уложился в **32 с**: **12/14 harness OK, 10/36 сабтестов** (2 TIMEOUT). Первая часть сигнала — позитивная: `forced-colors-mode-27.html` (html/head → `CanvasText`, PASS 1/1) и `forced-colors-mode-41.html` (`accent-color`/`background-color`/`border-*-color`/`caret-color`/`color`/`outline-color`, PASS 9/9) показывают, что forced-colors mode реализован по существу, а не заглушкой. Остальные 12 id распались на три причины: (а) 7 FAIL + оба TIMEOUT — уже заведённый [BUG-384](../bugs/BUG-384-FIXED.md) (named access on Window: тесты обращаются к элементам по `id` как к глобалам — `a`/`p`/`dark`/`visited_child`/`body`/`div`; в `-20`/`-21` обращение происходит на верхнем уровне скрипта, поэтому падает весь харнесс ещё до регистрации теста, отсюда TIMEOUT вместо FAIL); (б) новый [BUG-387](../bugs/BUG-387-OPEN.md) — `forced-colors-mode-40.html` 0/17: `element.computedStyleMap()` использует тот же класс и ту же нативную привязку (`_lumen_get_style_property`), что мутируемый `attributeStyleMap`, и обе читают только инлайн-атрибут `style=""`, а не каскад — `.get(prop)` на свойство из `<style>`-блока отдаёт `undefined`, хотя `getComputedStyle()` для того же свойства работает верно (свой сериализатор, `computed_style_to_map`); (в) новый [BUG-388](../bugs/BUG-388-OPEN.md) — `forced-colors-mode-54.html`/`forced-colors-mode-60.html`: `apply_forced_colors_mode` (`layout/style.rs:7996`) форсирует весь остальной набор свойств CSS Color Adjustment L1 верно, но не форсирует `scrollbar-color` → `auto` и `font-variant-emoji` → `text` (последнее как CSS-свойство в движке не реализовано вовсе). `CAPABILITIES.md`: строка Forced Colors Mode дополнена оговоркой про оба пропущенных свойства.
