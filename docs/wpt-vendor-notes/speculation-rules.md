All engine-attributable signal reconfirms already-open bugs, no new bug filed: [BUG-485](../../bugs/BUG-485-FIXED.md) (`document.head` entirely missing — the dominant subtest FAIL, `TypeError: Cannot read properties of undefined (reading 'appendChild')`, hit by every test that does `document.head.appendChild(...)` to inject a `<script type="speculationrules">`); the `performance.getSpeculations()`/`SpeculationMeasurement` gap and the complete absence of `load`/`error` events on `<script type="speculationrules">` elements both match the engine's own documented Phase 0 scope (`crates/js/src/speculation_rules.rs`: "not consumed by the engine in Phase 0", only `document.prerendering`/`getSpeculationRules()`/`onprerenderingchange` stubs and a no-op `_lumen_deliver_speculation_rules` hook exist) — not a bug; and the handful of `ERROR` results are the already-documented BUG-380 class (reused browsing context serving the previous test's stale result after a failed navigation). A live probe (`--mcp-live-port`, local `http.server`) independently confirmed the Phase 0 shim shape (`_lumen_deliver_speculation_rules` is a no-op `function`, `document.prerendering === false`, `getSpeculationRules() === []`) and that neither `onload` nor `onerror` fires on a `type="speculationrules"` `<script src>` — the element is fully inert, exactly as documented. See `docs/wpt-status.md` for the full breakdown.
