# WPT vendor notes — `webnn`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-09 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-webnn`, `docs/wpt-status.md`), scope 🚫 (out of scope — no ML inference runtime). Unlike `webmidi`/`webgpu`/`webhid` (all 🚫-scoped but backed by a real Phase 0 stub in `crates/js/src/`), `webnn` has **no engine surface at all** — no `web_nn.rs`, no `navigator.ml`/`MLContext`/`MLGraph` symbol anywhere under `crates/` (confirmed by grep before vendoring, and by a live-window probe after: `typeof navigator.ml` → `"undefined"`, `Object.getOwnPropertyNames(navigator)` has zero `/ml/i`-matching keys). Same pinned commit `35be3b44`, `git sparse-checkout add` at the same commit hash, `LICENSE-WPT.md` copied from the sibling `webhid` category — 196 files (`META.yml`, `README.md`, `WEB_FEATURES.yml`, `idlharness.https.any.js`, `helper-validation.window.js` (plain HTTP, not `.https.`), `permissions-policy/` — 8 files including 3 non-`.https.` html — `conformance_tests/` — 111 `.https.any.js` files, `validation_tests/` — 64 `.https.any.js` files, plus `resources/`/`tools/`). No `testdriver.js` references anywhere. 171 of the 175 `.any.js` files carry `// META: variant=?cpu`/`?gpu`/`?npu` (3-way fan-out, `global=window` only — no worker duplication), so the glob-based `all_vendored_test_ids()` count of 181 base ids understates the real wptrunner instance count by roughly 3x (≈520 instances, `conformance_tests`+`validation_tests` combined) — same undercount class already on record for `speculation-rules`.

## Прогон и находки (`docs/wpt-status.md`)

**Полный прогон не был доведён до конца** — той же методологией, что `mixed-content`/`css`/`content-security-policy` (`docs/wpt-vendor-notes/mixed-content.md`): 100% из отобранной категории — `.https.`, 0 `testdriver.js`, значит никакой SKIP-стены, каждый id полностью платит HTTPS-порт-гэп (~UnknownIssuer TLS-хендшейк, уже задокументированный `BUG-657`) до TIMEOUT. Измеренная стоимость на представительной выборке (`--processes=4`, два среза — 32 id из `conformance_tests` + 30 id, покрывающих `permissions-policy` и начало `validation_tests`) — **62/62 либо TIMEOUT на TLS UnknownIssuer, либо производный от него исход, нулевой разброс** на операциях самой разной формы (`abs`/`add`/`argMinMax`/`batchNormalization`/`cast`/`clamp`/`concat`/`constant*`/`conv2d`/`convTranspose2d`/`averagePool2d` и др.). Экстраполяция на полные ≈520 инстансов при той же скорости (~17 с/id при 4 процессах) — **≈2.5 часа** ради переподтверждения уже сотни раз задокументированного TLS-гэпа без единого исключения; продолжать признано нерентабельным (тот же trade-off, что `mixed-content`).

Два не-TIMEOUT исхода в выборке, оба — уже известные, не webnn-специфичные дефекты:
- `permissions-policy/permissions-policy-webnn.html` (единственный non-`.https.` тест в выборке, HTTP-навигация проходит) — harness OK, но 0/1 сабтестов: ожидаемо, страница проверяет, что фича `webnn` отключается Permissions-Policy, а `navigator.ml` не существует вовсе, так что весь тест беспредметен для этого движка.
- Следующий за ним тест (`webnn-supported-by-permissions-policy.html`) получил результаты предыдущего теста (`AssertionError: Got results from /webnn/permissions-policy/webnn-supported-by-permissions-policy.html, expected /webnn/validation_tests/batchNormalization.https.any.html?npu`) — уже задокументированный паттерн BUG-380 (browsing context переиспользуется, неудачная навигация «отравляет» опрос следующего теста), не новая находка.

Живая проба (`--mcp-live-port`, `navigate` на локальный `file://` со скриптом, retry-цикл на `window.__ready`) подтвердила: `typeof navigator.ml === "undefined"`, `typeof window.MLContext/MLGraph/MLGraphBuilder === "undefined"`, `Object.getOwnPropertyNames(navigator)` не содержит ни одного `/ml/i`-совпадения — WebNN отсутствует в движке целиком, без какой-либо частичной утечки поверхности (в отличие от `webmidi`/`webgpu`/`webhid`). Новый `BUG-NNN` не заводился.
