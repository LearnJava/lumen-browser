# WPT vendor notes — `density-size-correction`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-26 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-density-size-correction`, `docs/wpt-status.md`). Same pinned commit, `git sparse-checkout` at the same commit hash, 44 files (`WEB_FEATURES.yml`, `resources/` — 8 EXIF-tagged `.jpg` fixtures + `exify.js` + `third_party/piexif/` (piexif.js + LICENSE), ~22 root test files each with a `-ref.html` and/or `-cross-origin.sub.html` pair: `density-corrected-*`, `image-set-00{1,2,3}*`, `srcset*`). No out-of-category helpers — only the already-vendored `/resources/testharness.js`+`testharnessreport.js`. `run_report.py --all --root density-size-correction --recursive` selected 22 ids; 20/22 are WPT-manifest type `reftest`, unsupported by the minimal executor (`Unsupported test type reftest`, same class of gap as `acid`/`apng`/`avif`/`animation-worklet`) — excluded before the run queue. The remaining 2 `testharness` ids ran: `density-corrected-image-in-canvas.html` TIMEOUT (the very first `canvas.getContext('2d')` call inside an `image.onload` callback throws synchronously, so the enclosing promise never resolves), `density-corrected-natural-size.html` FAIL (harness OK, 0/1 subtest — `TypeError: Cannot set properties of null (setting 'fillColor')`, i.e. `canvas.getContext('2d')` itself returned `null`). Root-caused, not left as first-pass noise: filed as [BUG-348](../../bugs/BUG-348-FIXED.md) — `canvas.getContext('2d')` returns `null` unconditionally in the current default V8 build (`webgl_canvas.rs`'s `document.createElement` monkeypatch installs before `canvas2d` and permanently shadows the working `2d` accessor with a webgl-only-or-null one), confirmed independently of wptrunner (bare BiDi repro) and visually (`--screenshot graphic_tests/57-canvas-2d.html` renders all 6 canvases blank). Broad-impact, not WPT-specific — regression from `P3-v8-s8` (26309f646, 2026-07-14). 1/2 harness OK, 0/6 subtests. See `docs/wpt-status.md` for details.
