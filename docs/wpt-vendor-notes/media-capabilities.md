# WPT vendor notes — `media-capabilities`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-05 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-media-capabilities`, `docs/wpt-status.md`), included despite its 🚫 scope note (media pipeline) by the same standing user decision as `audio-output`/`audio-session`/`autoplay-policy-detection`. Same pinned commit, `git sparse-checkout` at the same commit hash, 10 files (`META.yml`, `README.md`, `WEB_FEATURES.yml`, `decodingInfo(-webrtc).any.js`, `decodingInfoEncryptedMedia.http(s).html`, `encodingInfo(-webrtc).any.js`, `idlharness.any.js`). One out-of-category dependency pair not vendored — `idlharness.any.js` references `/resources/WebIDLParser.js`+`/resources/idlharness.js`, same documented survey gap as `FileAPI`/`audio-session`. `run_report.py --all --root media-capabilities --recursive` completed in ~25s (7 selected ids): 6/7 harness OK, 10/94 subtests passed. `navigator.mediaCapabilities.decodingInfo`/`encodingInfo` are implemented as an explicit Phase 0 stub (`crates/js/src/media_capabilities.rs`) — any config with a valid string `type` resolves to `{supported:true, smooth:true, powerEfficient:false}` with no codec/field validation and no `keySystemAccess`; most FAILs are either an expected `TypeError` rejection on a malformed config (the stub rejects nothing) or `assert_equals(typeof info.keySystemAccess, "object")` against the missing field. `decodingInfoEncryptedMedia.https.html` hit the documented TLS `UnknownIssuer` gap (see `docs/wpt-status.md`); `idlharness.any.html` 404'd on its un-vendored helpers. No bug filed — a documented Phase 0 stub, not a new finding.
