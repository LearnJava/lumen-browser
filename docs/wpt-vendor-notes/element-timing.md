# WPT vendor notes — `element-timing`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-27 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-element-timing`, `docs/wpt-status.md`), in-scope (⬜, Element Timing API — the `elementtiming` attribute and `PerformanceElementTiming` entries). Same pinned commit, `git sparse-checkout` at the same commit hash, 70 files (`META.yml`, `WEB_FEATURES.yml`, 49 root `.html` tests, `idlharness.window.js`, `resources/` — `element-timing-helpers.js`, four `iframe-*.html` fixtures, `circle.svg`/`circle-tao.svg`(+`.headers`), `square100.png`/`square20.png`/`square20.jpg`, and the `wptserve` Python handlers `slow-image.py`/`progressive-image.py`/`multiple-redirects.py`/`TAOImage.py`). Incidentally closes a neighbouring category's survey gap: `container-timing` referenced the un-vendored `/element-timing/resources/element-timing-helpers.js` — it is now present. Still not vendored: `/images/black-rectangle.png` (13 references), `/images/green-100x50.png` (8), `/images/blue.png` (4), `/common/redirect.py` (2), plus `idlharness.window.js`'s `/resources/WebIDLParser.js`+`/resources/idlharness.js` — same documented survey gap as `FileAPI`/`ai`/`audio-session`. `run_report.py --all --root element-timing --recursive` completed fully in ~4:16 (52 selected ids, **not a single `.https.` file** — the HTTPS-port gap that dominates most categories in this backlog is absent here): 51/52 harness OK, 1/51 subtests passed. One root cause covers essentially the whole category — 50 subtests FAIL on `assert_implements: PerformanceElementTiming is not implemented` (the Element Timing API is not implemented in Lumen at all; that single string is 100% of the error text in the log); the one non-FAIL is `idlharness.window.html` TIMEOUT (404 on its two un-vendored dependencies → `idl_test is not defined`, same pattern as `audio-session`/`animation-worklet`/`beacon`). The single passing subtest, `supported-element-type.html` → *"supportedEntryTypes contains 'element'"*, is what exposed a genuine defect in an *implemented* feature rather than a missing-API gap: filed as [BUG-354](../../bugs/BUG-354-FIXED.md) — `PerformanceObserver.supportedEntryTypes` is a hardcoded 12-element literal, five of whose entries (`element`, `event`, `first-input`, `longtask`, `soft-navigation`) have no implementation whatsoever, so spec-sanctioned feature detection returns a false positive (and `observe({type:'element'})` silently "succeeds" while never firing). Verified outside WPT with a `--dump-layout` probe. The unimplementedness of Element Timing itself was not filed — ⬜ category, first pass. See `docs/wpt-status.md` for details.

Подтверждено вне WPT через `--dump-layout`-пробу. Нереализованность самого Element Timing отдельным багом не заводилась — ⬜-категория, первый проход
