# WPT vendor notes — `fullscreen`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-28 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-fullscreen`, `docs/wpt-status.md`), scope ⬜ (candidate). Same pinned commit, `git sparse-checkout` at the same commit hash, 111 files (`META.yml`, `WEB_FEATURES.yml`, `api/` — 64 files, `rendering/` — 19 files including 6 `rel=match` reftest pairs, `model/` — 11 files, `crashtests/` — 6 files, `LICENSE-WPT.md`). No out-of-category helpers beyond `/resources/testharness.js`+`testharnessreport.js`+`testdriver*.js`. Unlike the `fledge`/`font-access` testdriver-predictor inversion (`.window.js`/`.any.js` files whose `// META: script=` never sets the manifest flag), here the grep and the manifest mostly agree because the category is 91% `.html` (testdriver.js pulled via `<script src>`, which the manifest generator does see) — so 73% of files (80/110) correctly SKIP instead of paying a full TIMEOUT. `run_report.py --all --root fullscreen --recursive` completed in **1 min 37 s** (83 selected ids — the 6 `rel=match` reftest pairs in `rendering/` are dropped by the executor, same class as `forced-colors-mode`): **12/83 harness OK, 85/112 subtests passed** (64 SKIP, 7 TIMEOUT) — two orders of magnitude better subtest ratio than the typical backlog entry. The 6 exceptions to the testdriver-flag agreement (5 `document-fullscreen-keyboard-lock-*.window.js` plus `rendering/fullscreen-pseudo-class-support.html`, which inlines the same keyboard-lock assertions) executed and failed `ReferenceError: test_driver is not defined` — the familiar inversion class, not a new finding. The 12 tests that actually ran produced two new bugs: BUG-390 (`requestFullscreen()` implements only the happy path — `document.fullscreenEnabled` is hardcoded `true` so its own reject branch is dead code, connected-element/user-activation preconditions are never checked, the promise always resolves, and `fullscreenerror` is never dispatched anywhere in the shim) and BUG-391 (`Element.matches()`/`querySelector(All)`/`closest()` are designed to never throw `SyntaxError` for an invalid or unrecognized selector — `document.body.matches(':halfscreen')` silently returns `false`, breaking the standard WPT feature-detection precondition used across many categories, not just this one). One test (`document-fullscreen-enabled.html`, "same-origin iframe") hit the already-documented (not separately filed) Phase-0 limit that `<iframe>` has no browsing context (`contentDocument === null`, `CAPABILITIES.md`'s DOM line). `idlharness.window.html` TIMEOUT on `idl_test is not defined` — `/resources/idlharness.js`+`WebIDLParser.js` are not vendored, the same documented survey gap as `FileAPI`/`fetch`/`audio-session`, not a Lumen bug. `CAPABILITIES.md`'s DOM line gained both new caveats. See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/fullscreen/`, 111 файлов: `META.yml`, `WEB_FEATURES.yml`, `api/` — 64 файла, `rendering/` — 19 файлов (6 `rel=match` reftest-пар), `model/` — 11 файлов, `crashtests/` — 6 файлов, `LICENSE-WPT.md`), скоуп ⬜ (кандидат). В отличие от `fledge`/`font-access`, где предсказатель testdriver по `.window.js`/`.any.js` инвертируется, здесь категория на 91% состоит из `.html` (testdriver.js подключается тегом `<script src>`, который манифест видит), поэтому грепа и флага `testdriver: true` в `MANIFEST.json` почти совпадают: 73% файлов (80/110) корректно SKIP вместо полного TIMEOUT. `run_report.py --all --root fullscreen --recursive` — **1 мин 37 с, 12/83 harness OK, 85/112 сабтестов** (64 SKIP, 7 TIMEOUT; исполнитель отобрал 83 из 99 вендоренных id — 6 reftest-пар `rendering/` не выбираются, класс `forced-colors-mode`). Шесть исключений из совпадения флага (5 `document-fullscreen-keyboard-lock-*.window.js` + `rendering/fullscreen-pseudo-class-support.html`, инлайнящий те же keyboard-lock проверки) исполнились и упали `ReferenceError: test_driver is not defined` — известный класс инверсии, не новая находка. 12 реально исполнившихся тестов дали два новых бага. [BUG-390](../bugs/BUG-390-FIXED.md): `requestFullscreen()` реализует только happy path — `document.fullscreenEnabled` захардкожен `true` (собственная ветка reject мертва), отсоединённость элемента и user activation не проверяются, промис всегда резолвится, `fullscreenerror` нигде не диспатчится (`document-onfullscreenerror.html`, `element-request-fullscreen-not-allowed.html`, `promises-reject.html`). [BUG-391](../bugs/BUG-391-OPEN.md): `matches()`/`querySelector(All)`/`closest()` по дизайну (`selector_query.rs:335-422`, задокументировано в doc-комментариях) никогда не бросают `SyntaxError` на невалидный/неизвестный селектор — `document.body.matches(':halfscreen')` тихо `false` вместо исключения, ломая стандартный WPT-паттерн feature-detection (`rendering/fullscreen-pseudo-class-support.html`). Один тест (`document-fullscreen-enabled.html`, «same-origin iframe») упал на уже задокументированный (без отдельного номера) Phase-0 предел `<iframe>` без browsing context (`contentDocument === null`), тот же класс, что и на `focus`. `idlharness.window.html` — TIMEOUT на `idl_test is not defined`: `/resources/idlharness.js`+`WebIDLParser.js` не вендорены, тот же документированный пробел, что у `FileAPI`/`fetch`/`audio-session`, не Lumen-баг. `CAPABILITIES.md`: строка DOM дополнена обеими оговорками.
