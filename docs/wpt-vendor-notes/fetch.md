**Предложение (путь 3 WPT-RUN-10, расширенный).** `LUMEN_RESOLVE=host=ip[,host=ip…]` в движке — одна обёртка над `Arc<dyn DnsResolver>` ([`crates/network/src/dns.rs`](../../crates/network/src/dns.rs), рядом с `SystemDnsResolver`), проверяемая до любого резолвера (система/кэш/DoH/DoT), карта читается один раз в `OnceLock`, как `LUMEN_EXTRA_CA_CERT` ([`tls/mod.rs`](../../crates/network/src/tls/mod.rs)); IDN-имена — в punycode. Раннер (`tools/wptrunner/wptrunner/browsers/lumen.py`) возвращает `browser_host` к апстримному `web-platform.test` и передаёт в `LUMEN_RESOLVE` все 66 имён из `ConfigBuilder.all_domains` → `127.0.0.1`. Тогда оживают обе семьи (а), `www.web-platform.test` становится same-site, `http://web-platform.test` — недоверенным (б), и пропадает оговорка о `*.localhost` на Windows. Сертификат раннера — pregenerated ([`tests/wpt/certs/README.md`](../../tests/wpt/certs/README.md)): 34 SAN, из семейства `web-platform.test` только сам домен, `not-web-platform.test` нет вовсе, а wildcard rustls-webpki не принимает (BUG-1271) — его надо перевыпустить с явными SAN на все 66 имён, иначе `.https.`-половина упрётся в `certificate not valid for name`. Риск: смена `browser_host` двигает число всего корпуса (не только `fetch/`) — прогон нужен полный, со сравнением с 2026-10-22.

**Решение пользователя (2026-10-27): путь 3 полностью.** Движок — [`WPT-LUMEN-RESOLVE`](../../ROADMAP.md) (P1: `LUMEN_RESOLVE` поверх любого `DnsResolver`); раннер — [`WPT-HOST-WPT`](../../ROADMAP.md) (P2, после P1: `browser_host: web-platform.test`, `LUMEN_RESOLVE` из `ConfigBuilder.all_domains`, перевыпуск сертификата с явными SAN, полный прогон и сравнение с 2026-10-22, отдельно `fetch/metadata` и 1 129 id `--alt`). Варианты отклонены: только альтернативный домен при `localhost` — оставляет 661 сабтест (б) недостижимым; `/etc/hosts` — меняет машину пользователя.

- **`nonexistent.*` → TIMEOUT** (`iframe-`/`embed-network-error.sub.html`, `xhr/event-error.sub.any.worker.html`): Windows-getaddrinfo отвечает NXDOMAIN на любое несуществующее имя через ~11 с, а `nonexistent.localhost` движок раньше резолвил сам (RFC 6761) и получал отказ соединения сразу. **Исправлено здесь:** `LUMEN_RESOLVE` понимает `host=~NOTFOUND` (как `--host-resolver-rules … ~NOTFOUND` у Chrome), раннер отдаёт так `config.not_domains_set`. Перепрогон 37 id корпуса, где в исходнике есть `nonexistent`: +5 id (те три плюс `xhr/event-error.sub.any.html` и `object-fallback-failed-cross-origin-navigation.sub.html`), балл 11.11 → 12.86.
- **Один id упал из-за `~NOTFOUND` — тест был ложным PASS:** `html/links/icon/no-error-event.sub.html` проходил только потому, что ошибка DNS приходила позже двухсекундного окна теста. `<link rel=icon>` не должен слать `error` — [BUG-1766](../../bugs/BUG-1766-OPEN.md).
- **`connection-allowlist/tentative/*` (12 id, ≈ −5.5):** ложные PASS старого хоста. Сабтесты «fetch/навигация на `not-web-platform.test` должна быть заблокирована» проходили, потому что имя не резолвилось; теперь резолвится, а заголовок `Connection-Allowlist` (tentative) движок не реализует. Не баг — фича не начата; записано здесь.
- **Открылись пробелы движка** (на старом хосте тест не доходил до проверки): `fetch/api/cors/cors-cookies.any*` — в запрос на REMOTE попадает cookie `g=7`, выставленная ответом на `credentials: "omit"` к другому хосту ([BUG-1767](../../bugs/BUG-1767-OPEN.md)); `cookies/attributes/domain.sub.html` — на `localhost` был ERROR «Domain is malformed!», теперь первый сабтест виснет ([BUG-1768](../../bugs/BUG-1768-OPEN.md)); `workers/.../importScripts/catch.sub.any.worker.html` — кросс-ориджин ошибки `importScripts` не глушатся в `NetworkError` ([BUG-1769](../../bugs/BUG-1769-OPEN.md)); `beacon/headers/header-referrer-unsafe-url.https.html` — `http://localhost` был потенциально доверенным, теперь `sendBeacon` с https на http — mixed content: возвращает `true`, а запрос до сервера не доходит ([BUG-1770](../../bugs/BUG-1770-OPEN.md)).
