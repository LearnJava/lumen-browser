# WPT vendor notes — `fetch`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-28 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-fetch`, `docs/wpt-status.md`). Scope ⬜ (candidate) — unlike every category vendored before it, this one's API is actually implemented in Lumen, and the run reflects that. Same pinned commit, `git sparse-checkout add` at the same commit hash, 985 files: `META.yml`, `README.md`, 23 subdirectories (`api/` by far the largest, then `metadata/`, `fetch-later/`, `h1-parsing/`, `http-cache/`, `orb/`, `corb/`, `range/`, `redirects/`, `cross-origin-resource-policy/`, `local-network-access/`, `nosniff/`, `content-encoding/`, `compression-dictionary/`, `stale-while-revalidate/`, `security/`, …), 313 `.html`/`.htm`, 179 `.any.js`, 65 `.window.js`, 1 `.worker.js`, 78 Python `wptserve` endpoints, 48 `.headers` files, plus `LICENSE-WPT.md`. All in-category helpers are vendored (`fetch/metadata/resources/helper.sub.js` — 100 references, `fetch/fetch-later/resources/` — 36, `fetch/orb/resources/utils.js` — 6); the un-vendored out-of-category helpers are the usual survey gap: `/common/get-host-info.sub.js` (138 references), `/common/utils.js` (134), `/resources/testdriver.js`+`testdriver-vendor.js` (36 each), `/service-workers/service-worker/resources/test-helpers.sub.js` (14), `/common/subset-tests-by-key.js` (5), `/html/browsers/…` (6), `/permissions-policy/…` (4), `/webtransport/…` (4), `/common/security-features/…` (3), `/common/dispatcher/dispatcher.js` (3), `/resources/idlharness.js`+`WebIDLParser.js` (1 each) — same documented gap as `beacon`/`fenced-frame`. Five files use `variant` (three of them `.window.js` under `local-network-access/`), so 516 globbed ids vs wptrunner's 481 — report wptrunner's number. `run_report.py --all --root fetch --recursive` completed in **1 h 22 min 48 s: 176/481 harness OK, 364/2692 subtests** — two orders of magnitude better than any other vendored category (`fenced-frame` 1/199, `fedcm` 0/81), because only 3% of files pull `testdriver.js` (16 SKIP) and the tests reach real code instead of being cut off by executor gaps. Outcome shape (473 `TEST_END` records): 168 `Test OK` with subtest breakdown, 42 `Test TIMEOUT` with partial subtests, 190 TIMEOUT, 56 ERROR, 16 SKIP, 1 PRECONDITION_FAILED; 13 tests fully green. The run's main result is a **price tag on two already-filed bugs** rather than a new one: BUG-347 (`fetch()` does not resolve relative URLs) accounts for 201 `invalid url: missing scheme` log lines — this is the most on-point category it could possibly have — and BUG-346 (`Url::resolve()` does not collapse `..`) here hits an **in-category, actually-vendored file** for the first time: 69 404s on paths like `/fetch/api/cors/../resources/utils.js` while `tests/wpt/fetch/api/resources/utils.js` sits on disk perfectly readable. That one file defines `RESOURCES_DIR`, `dirname`, `stringToArray` and `requestForbiddenHeaders`, i.e. every `… is not defined` error in the log is the same single consequence — fixing BUG-346 unblocks the shared helper of the largest subdirectory (`api/`, 178 tests). The remaining bulk is the HTTPS-port gap (147 `invalid url: invalid port: "None"`; 166 of the category's files are `.https.`). Unlike `fedcm`/`fenced-frame`, where every id was unreachable and the `--dump-layout` probe *replaced* the run, here the probe's findings are **confirmed point-by-point by the tests themselves**: BUG-369 (`Headers` is an ES5 constructor over an array, not a WebIDL interface — not iterable, `entries()`/`keys()`/`values()` return `Array`s, `new Headers(headers)` silently loses the headers, no validation/guard/`getSetCookie`, `_map`/`_key` web-visible) ↔ `headers-record` 0/13, `headers-no-cors` 0/8, `header-setcookie` 2/24, `header-values-normalize` 1/62; BUG-370 (`Request` has no Body mixin at all, `url` not absolutized, no `Response.json()`, `Response.error().type` = `default`, `Response.redirect()` sets no `Location`, no argument validation anywhere) ↔ `request-consume` 0/45, `response-static-redirect` 0/11, `response-form-data` 0/14, `forbidden-method` 0/6. See `docs/wpt-status.md` for the full breakdown.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/fetch/`, 985 файлов: `META.yml`/`README.md`, 23 подкатегории (`api/` — крупнейшая, далее `metadata/`, `fetch-later/`, `h1-parsing/`, `http-cache/`, `orb/`, `corb/`, `range/`, `redirects/`, `cross-origin-resource-policy/`, `local-network-access/`, `nosniff/`, `content-encoding/`, `compression-dictionary/`, `stale-while-revalidate/`, `security/`, …), 313 `.html`/`.htm`, 179 `.any.js`, 65 `.window.js`, 1 `.worker.js`, 78 Python-эндпоинтов `wptserve`, 48 файлов `.headers`, плюс `LICENSE-WPT.md`). Первая в этом бэклоге категория со скоупом ⬜, чьё API в Lumen реально реализовано, — и это сразу видно по результату. `run_report.py --all --root fetch --recursive` — **1 ч 22 мин 48 с, 176/481 harness OK, 364/2692 сабтеста** (собственный глоб `run_report.py` насчитал 516 id — отчётным считается число wptrunner). Это **на два порядка лучший результат, чем у любой другой вендоренной категории** (ср. `fenced-frame` 1/199, `fedcm` 0/81): тесты не просто доходят до исполнения, они проверяют реальную реализацию и дают содержательный сигнал. Расклад по исходам (473 записи `TEST_END` в логе): 168 `Test OK` с разбором сабтестов, 42 `Test TIMEOUT` с частичными сабтестами, 190 TIMEOUT без harness-результата, 56 ERROR, 16 SKIP (`Executor does not support testdriver.js` — всего 3% файлов, в отличие от `fedcm`/`fenced-frame`), 1 PRECONDITION_FAILED. Полностью зелёных тестов 13 (61 сабтест), крупнейшие — `scheme-others.sub.any.html` 16/16, `h1-parsing/lone-cr.window.html` 10/10, `headers-structure.any.html` 8/8, `scheme-about.any.html` 7/7, `redirect-schemes.any.html` 6/6, `headers-casing.any.html` 4/4. **Главная находка прогона — не новый баг, а цена двух уже заведённых.** Первая половина отказов — [BUG-347](../bugs/BUG-347-OPEN.md) (`fetch()` не резолвит относительные URL): **201** строка `fetch error: invalid url: missing scheme` в логе. Это самая профильная категория для BUG-347 из возможных, и она первая даёт ему измеримый вес. Вторая — [BUG-346](../bugs/BUG-346-OPEN.md) (`Url::resolve()` не схлопывает `..`), и здесь он впервые бьёт по **внутрикатегорийному, реально вендоренному файлу**: 69 ответов 404 на пути вида `/fetch/api/cors/../resources/utils.js` (20), `/fetch/api/basic/../resources/utils.js` (18), `…/redirect/…` (8), `…/response/…` (6), `…/policies/…` (5), `…/request/…` (4) — а `tests/wpt/fetch/api/resources/utils.js` лежит на диске и вполне читаем. Именно этот файл определяет `RESOURCES_DIR`, `dirname`, `stringToArray`, `requestForbiddenHeaders` — т.е. все `… is not defined` в логе (12+6+1+1) это одно и то же последствие. Починка BUG-346 — одно изменение, разблокирующее общий хелпер самой крупной подкатегории `api/` (178 тестов). Остальное — два уже описанных гэпа исполнителя: HTTPS-порт (`invalid url: invalid port: "None"`, 147 строк — 166 файлов категории `.https.`) и survey-gap по невендоренным внекатегорийным хелперам: `/common/get-host-info.sub.js` (67 ответов 404, 138 ссылок в исходниках), `/common/utils.js` (64/134), `/common/subset-tests-by-key.js` (24/5), `/common/security-features/resources/common.sub.js` (3), `/common/dispatcher/dispatcher.js` (3), `/resources/testdriver*.js` (36 ссылок), `/service-workers/…/test-helpers.sub.js` (14), `/webtransport/…` (4), `/permissions-policy/…` (4), `/html/browsers/…` (6), `/resources/idlharness.js`+`WebIDLParser.js` (по 1) — тот же гэп, что `beacon`/`fenced-frame`. Внутрикатегорийные хелперы (`fetch/metadata/resources/helper.sub.js` — 100 ссылок, `fetch/fetch-later/resources/…` — 36, `fetch/orb/resources/utils.js` — 6) вендорены все. **Отличие этой категории от всех предыдущих: находки пробы `--dump-layout` здесь прямо подтверждаются результатами самих тестов**, а не заменяют их (в `fedcm`/`fenced-frame` все id были недоступны исполнителю). [BUG-369](../bugs/BUG-369-OPEN.md) (`Headers` — ES5-конструктор поверх массива `_map`, а не WebIDL-интерфейс): не итерируем — `Symbol.iterator` отсутствует, `for..of` бросает `TypeError`, а `Array.from(h)` тихо даёт `[]`; `entries()`/`keys()`/`values()` возвращают `Array` без `.next`; `new Headers(anotherHeaders)` молча теряет заголовки (ветка `Object.keys(init)` видит только служебный `_map`); нет валидации имён, guard-а, `getSetCookie()`, `Symbol.toStringTag`; `_map`/`_key` перечислимы и записываемы. Подтверждено тестами попунктно: `headers-record.any.html` 0/13 (копирование из record/Headers), `headers-no-cors.any.html` 0/8 и `headers-forbidden-override.any.html` 18/90 и `response-headers-guard.any.html` 0/1 (guard), `header-setcookie.any.html` 2/24 (`getSetCookie`), `headers-normalize.any.html` 0/3 и `header-values-normalize.any.html` 1/62 (валидация/нормализация), `headers-basic.any.html` 10/23 — при этом `headers-structure.any.html` 8/8 и `headers-casing.any.html` 4/4 зелёные целиком. [BUG-370](../bugs/BUG-370-OPEN.md) (`Request`/`Response` — Phase-0-приближения, что признано в комментарии `dom.rs:9025`): у `Request` **нет Body-mixin вовсе** (весь прототип — `clone`+`constructor`), `Request.url` не абсолютизируется (пятый сайт семейства BUG-346/347/359/362), нет `Response.json()`, `Response.error().type` = `default` вместо `error`, `Response.redirect()` не ставит `Location`, ни один конструктор не валидирует аргументы, атрибуты — записываемые свойства инстанса вместо геттеров прототипа, `JSON.stringify(new Response())` **бросает** на циклической ссылке в незапрятанном `ReadableStream`. Подтверждено: `request-consume.any.html` 0/45 и `request-consume-empty.any.html` 0/14 (Body-mixin), `forbidden-method.any.html` 0/6 и `request-init-002.any.html` 0/8 (валидация), `response-static-error.any.html` 0/2 (`Response.error()`), `response-static-redirect.any.html` 0/11 (`Response.redirect()`), `response-form-data.html` 0/14 (нет `formData()`), `request-structure.any.html` 4/24 (форма интерфейса). Корректно работающее, что не надо сломать фиксом: разбор схем URL (`scheme-others` 16/16, `scheme-about` 7/7, `redirect-schemes` 6/6), парсинг HTTP/1.1 с одиночным CR (`lone-cr` 10/10), регистронезависимость заголовков, `Response.body` как настоящий `ReadableStream` с ленивой подкачкой (`response-stream-disturbed-2/3/5` по 8/12), `AbortController`/`AbortSignal` (включая статики `abort`/`timeout`/`any`), `nosniff` (6/6), `content-length` (4/4), `content-type` (4/4), `data-urls` (3/3)
