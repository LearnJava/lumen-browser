# WPT vendor notes — `eventsource`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-28 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-eventsource`, `docs/wpt-status.md`), in-scope (⬜, Server-Sent Events — `EventSource`, the `text/event-stream` wire format, reconnection/`Last-Event-ID`). Same pinned commit, `git sparse-checkout add` at the same commit hash, 95 files (33 root `.any.js`, 12 root `.window.js`, 2 root `.htm`, `dedicated-worker/` — 7 `.htm` + 9 worker scripts + 1 `.any.js` + 1 `.worker.js`, `shared-worker/` — 7 `.htm` + 7 worker scripts, `resources/` — 9 `wptserve` Python handlers + 2 `.event_stream` fixtures + 2 `.htm` fixtures, `META.yml`, `WEB_FEATURES.yml`, `README.md`, `LICENSE-WPT.md`). **No out-of-category dependencies at all** — the only external `src=` references are the already-vendored `/resources/testharness.js`+`testharnessreport.js`; no `<meta name=variant>`, no `.https.` tests, no `testdriver.js`, so 61 candidate files gave exactly 61 ids (`run_report.py`'s own glob selects only the window-scope `.any.html`, so the `.any.js` files do not fan out into `.any.worker.html`). `run_report.py --all --root eventsource --recursive` completed in **8 min 1 s**: **16/61 harness OK, 2/100 subtests**. **The first category in this backlog whose failures are engine defects rather than executor gaps** — `EventSource` is genuinely implemented in Lumen (real SSE stack: `crates/network/src/sse.rs`, shim `crates/js/src/dom.rs:8193`, pump wired into the shell tick at `crates/shell/src/main.rs:12241`), so the run produced three new bugs instead of `assert_implements` noise. **(a) [BUG-362](../../bugs/BUG-362-FIXED.md) — the dominant cause, 44 of 61 ids TIMEOUT (~7 of the 8 minutes)**: the constructor never resolves a relative URL against the document base (`dom.rs:8194` stores `String(url || '')` verbatim and hands it to `_lumen_sse_connect`, `v8_runtime.rs:2646`, which parses it as absolute), so every `new EventSource("resources/message.py")` — i.e. almost every test in the category — fails with `missing scheme` and the connection never opens; the `url` attribute likewise returns the raw string instead of the serialized absolute URL. Fourth independent site of the BUG-346/BUG-347/BUG-359 family. **(b) [BUG-363](../../bugs/BUG-363-FIXED.md)** — the interface does not follow its WebIDL binding on seven counts (constants only on the interface object, not the prototype, hence `source.CONNECTING === undefined`; callable without `new`; not an `EventTarget`; writable `url`/`readyState`; own-property event handlers; no `SyntaxError` on an invalid URL; `readyState` set to `CLOSED` synchronously in the constructor instead of staying `CONNECTING`); most of the 34 executed FAIL subtests land here. **(c) [BUG-364](../../bugs/BUG-364-FIXED.md)** — all 14 `dedicated-worker/`/`shared-worker/` ids TIMEOUT because `new Worker("script.js")` with an external URL silently substitutes a comment for the script body (`worker.rs:688`, only `data:`/`blob:lumen/` supported): the script is never fetched and no `error` event is fired. Only 2 subtests pass, and one of the two passing tests is a **false positive worth recording**: `eventsource-url.any.html` asserts only `source.url.substr(-url.length) === url`, which an unresolved relative string satisfies trivially — a fix for BUG-362 must be verified against `eventsource-constructor-empty-url.any.html` instead. Also observed but not filed: the cross-origin tests reference WPT's alternate hostnames (`{{domains[…]}}` → `xn--lve-6lad.127.0.0.1`), which do not resolve without the upstream hosts-file entries — an environment/survey gap, not an engine defect. See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/eventsource/`, 95 файлов: 33 корневых `.any.js`, 12 корневых `.window.js`, 2 корневых `.htm`, `dedicated-worker/` — 7 `.htm` + 9 скриптов воркеров + `.any.js` + `.worker.js`, `shared-worker/` — 7 `.htm` + 7 скриптов воркеров, `resources/` — 9 `wptserve`-обработчиков на Python + 2 `.event_stream`-фикстуры + 2 `.htm`-фикстуры, `META.yml`/`WEB_FEATURES.yml`/`README.md`, плюс `LICENSE-WPT.md`), в скоупе (⬜, Server-Sent Events — `EventSource`, формат `text/event-stream`, переподключение и `Last-Event-ID`). **Внекатегорийных зависимостей нет вовсе** — единственные внешние `src=` это уже вендоренные `/resources/testharness.js`+`testharnessreport.js`; `<meta name=variant>` не используется, `.https.`-тестов нет, `testdriver.js` не упоминается ни в одном файле — 61 файл-кандидат дал ровно 61 id (собственный glob `run_report.py` отбирает только оконный `.any.html`, поэтому `.any.js` не раскрываются в `.any.worker.html`). Прогон `run_report.py --all --root eventsource --recursive` — **8 мин 1 с**, **16/61 harness OK, 2/100 сабтестов**. **Первая категория бэклога, чьи отказы — дефекты движка, а не гэпы исполнителя:** `EventSource` в Lumen действительно реализован (настоящий SSE-стек `crates/network/src/sse.rs`, шим `crates/js/src/dom.rs:8193`, насос подключён к тику шелла `crates/shell/src/main.rs:12241`), поэтому вместо шума `assert_implements` прогон дал три новых бага. **(а) [BUG-362](../../bugs/BUG-362-FIXED.md) — доминирующая причина, 44 из 61 id в TIMEOUT (~7 из 8 минут прогона)**: конструктор не резолвит относительный URL относительно базы документа — `dom.rs:8194` сохраняет аргумент дословно (с фолбэком на пустую строку вместо честной стрингификации) и передаёт в `_lumen_sse_connect` (`v8_runtime.rs:2646`), который парсит строку как абсолютный URL, — поэтому каждый `new EventSource("resources/message.py")`, то есть почти каждый тест категории, падает с `[JS SSE] connect error: … missing scheme` и соединение не открывается никогда; вторая половина того же дефекта — атрибут `url` возвращает переданную строку вместо сериализованного абсолютного URL (`new EventSource("")` → `""` вместо `location.href`, на чём напрямую падает `eventsource-constructor-empty-url.any.html`). Четвёртый независимый сайт семейства BUG-346/BUG-347/BUG-359. **(б) [BUG-363](../../bugs/BUG-363-FIXED.md)** — интерфейс не соответствует своему WebIDL-биндингу по семи пунктам (константы только на объекте интерфейса, не на прототипе, отсюда `source.CONNECTING === undefined`; вызывается без `new`; не наследует `EventTarget`; `url`/`readyState` записываемые; обработчики событий — собственные свойства инстанса; невалидный URL не бросает `SyntaxError`; `readyState` синхронно ставится в `CLOSED` прямо в конструкторе вместо `CONNECTING`); сюда приходится большинство из 34 выполнившихся FAIL-сабтестов. Показательна первая строка `eventsource-close.window.html`: `assert_equals(source.readyState, source.CONNECTING)` → `expected (undefined) undefined but got (number) 2` — одна строка ловит сразу оба пункта. **(в) [BUG-364](../../bugs/BUG-364-FIXED.md)** — все 14 id `dedicated-worker/`/`shared-worker/` в TIMEOUT: `new Worker("script.js")` с внешним URL молча подставляет комментарий вместо тела скрипта (`worker.rs:688`, поддержаны только `data:`/`blob:lumen/`) — скрипт не запрашивается по сети (в логе прогона нет ни одной загрузки `*-worker/*.js` при загруженных `.htm`), событие `error` не бросается. Прошли ровно 2 сабтеста, и один из двух зелёных тестов — **ложноположительный, это стоит зафиксировать**: `eventsource-url.any.html` проверяет только `source.url.substr(-url.length) === url`, то есть что `url` оканчивается на переданный относительный путь, — нерезолвленная строка проходит эту проверку тривиально, поэтому фикс BUG-362 надо верифицировать на `eventsource-constructor-empty-url.any.html`, а не на нём. Второй зелёный, `eventsource-prototype.any.html`, проверяет лишь расширяемость прототипа и `assert_own_property(self, "EventSource")`. Замечено, но не заведено: кросс-ориджин-тесты обращаются к альтернативным хостам WPT (`{{domains[…]}}` → `xn--lve-6lad.127.0.0.1`), которые не резолвятся без апстримовых записей в hosts-файле — гэп окружения/обследования, не дефект движка
