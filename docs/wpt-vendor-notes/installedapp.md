# WPT vendor notes — `installedapp`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-05 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-installedapp`, `docs/wpt-status.md`), scope 🚫 (out of scope, OS integration). Same pinned commit, `git sparse-checkout add` at the same commit hash, 5 files (`META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` copied from the sibling `idle-detection` category, 2 test files, one shared `resources/iframe.html`). Both `.https.` files, no `variant` hits, no `testdriver.js`. `run_report.py --all --root installedapp --recursive` completed in ~2:15 (2 selected ids): **0/2 harness OK**. `installedapp.https.window.html` TIMEOUT — its second subtest awaits an `<iframe>`'s `load` event after setting `iframe.src = 'resources/iframe.html'`, reproducing already-open [BUG-480](../bugs/BUG-480-OPEN.md) (`<iframe>` has no separate browsing context, `load` never fires). `idlharness.https.window.html` TIMEOUT — same un-vendored `/resources/WebIDLParser.js`+`/resources/idlharness.js` gap as `input-device-capabilities`. A `--mcp-live-port` live probe confirmed `navigator.getInstalledRelatedApps` is entirely absent (`typeof` → `"undefined"`) — expected for a 🚫-scope category, not a bug — but probing the shared `navigator` container per the WPT-VENDOR "probe one level up" convention surfaced a new finding: [BUG-624](../bugs/BUG-624-OPEN.md) (`window.Navigator` doesn't exist as a global constructor at all — `navigator` is a bare object literal with every member as a writable/enumerable own-instance data property, stronger than the already-documented BUG-366 instance-vs-prototype class since there is no interface object to fix a prototype on). See `docs/wpt-status.md` for details.

Вендорена целиком 2026-08-05 (коммит `35be3b44`, `tests/wpt/installedapp/`, 5 файлов: `META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` скопирован из соседней `idle-detection`, `installedapp.https.window.js`, `idlharness.https.window.js`, `resources/iframe.html`), скоуп 🚫 (ОС-интеграция), вендорена по стоящему пользовательскому решению включать 🚫-категории. `run_report.py --all --root installedapp --recursive` — ~2:15, 2 отобранных id, оба `.https.`: **0/2 harness OK**. `installedapp.https.window.html` TIMEOUT — второй сабтест ждёт `iframe.onload` после `iframe.src = 'resources/iframe.html'`, воспроизводит [BUG-480](../bugs/BUG-480-OPEN.md) (`<iframe>` без отдельного browsing context, `load` не эмитится). `idlharness.https.window.html` TIMEOUT — невендоренные `/resources/WebIDLParser.js`+`/resources/idlharness.js`, тот же класс гэпа, что `input-device-capabilities`.
