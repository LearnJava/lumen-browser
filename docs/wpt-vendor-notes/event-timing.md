# WPT vendor notes — `event-timing`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-28 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-event-timing`, `docs/wpt-status.md`), in-scope (⬜, Event Timing API — `PerformanceEventTiming`, the `event`/`first-input` entry types, `performance.eventCounts`/`interactionCount`). Same pinned commit, `git sparse-checkout add` at the same commit hash, 78 files (69 root `.html` including one `-manual` and two `.tentative.`, `idlharness.any.js`, `idlharness.window.js`, `supported-types.window.js`, `resources/` — `event-timing-test-utils.js`+`crossiframe-childframe.html`+`slow-image.py`, `META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md`). Out-of-category helpers not vendored: `/resources/testdriver.js`+`testdriver-vendor.js` (referenced by 67 of the 69 test files) and `/resources/testdriver-actions.js` (42 files), plus `/resources/WebIDLParser.js`+`/resources/idlharness.js` for the two `idlharness.*` files — same documented survey gap as `accname`/`audio-session`. No `<meta name=variant>` and no `.https.` tests at all, so 69 candidate files gave exactly 71 selected ids and `run_report.py --all --root event-timing --recursive` completed in **40 s** — the cheapest multi-test category in this backlog so far. **The most testdriver-bound category vendored to date: 67 of 71 ids SKIP** (`Executor does not support testdriver.js` — Event Timing measures input-processing latency by definition, so nearly every test synthesizes a click/tap/keypress via `test_driver.click`/`Actions`), 2 TIMEOUT (`idlharness.any.html`, `idlharness.window.html` — `idl_test is not defined` from the un-vendored WebIDLParser pair, same pattern as `audio-session`/`entries-api`), and exactly 2 ids executed: 2/71 harness OK, 0/2 subtests. Both executing tests are feature-detection tests and both fail on the already-filed BUG-354 — `supported-types.window.html` fails `assert_implements(window.PerformanceEventTiming)` (the interface does not exist), and `supported-types-consistent-with-self.html` catches the inconsistency head-on: `PerformanceObserver.supportedEntryTypes` advertises `event`/`first-input` while `'PerformanceEventTiming' in self` is `false`. Second category after `element-timing` to land on that same hardcoded list; no new BUG-NNN filed. See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/event-timing/`, 78 файлов: 69 корневых `.html` (в т.ч. один `-manual` и два `.tentative.`), `idlharness.any.js`, `idlharness.window.js`, `supported-types.window.js`, `resources/` — `event-timing-test-utils.js`+`crossiframe-childframe.html`+`slow-image.py`, `META.yml`/`WEB_FEATURES.yml`, плюс `LICENSE-WPT.md`), в скоупе (⬜, Event Timing API — `PerformanceEventTiming`, типы записей `event`/`first-input`, `performance.eventCounts`/`interactionCount`). Невендоренные внекатегорийные зависимости: `/resources/testdriver.js`+`testdriver-vendor.js` (67 из 69 тестовых файлов) и `/resources/testdriver-actions.js` (42 файла), плюс `/resources/WebIDLParser.js`+`/resources/idlharness.js` для обоих `idlharness.*` — та же методология survey-gap, что `accname`/`audio-session`. `<meta name=variant>` не используется, `.https.`-тестов нет вовсе — 69 файлов-кандидатов дали ровно 71 id, и `run_report.py --all --root event-timing --recursive` уложился в **40 с**, самый быстрый многотестовый прогон бэклога. Результат — **2/71 harness OK, 0/2 сабтестов**. Категория рекордно завязана на testdriver: **67 из 71 id — SKIP** (`Executor does not support testdriver.js`; Event Timing по определению меряет задержку обработки реального ввода, поэтому почти каждый тест синтезирует клик/тап/клавишу через `test_driver.click`/`Actions` — 94%, самая высокая абсолютная цифра по бэклогу после `accname` (19 id, 100%) и `attribution-reporting` (19 из 24)); 2 TIMEOUT — `idlharness.any.html` и `idlharness.window.html` (404 на невендоренные `/resources/WebIDLParser.js`+`idlharness.js` → `idl_test is not defined`, тот же паттерн, что `audio-session`/`entries-api`/`element-timing`). Реально выполнились ровно два теста, оба feature-detection, оба падают на уже заведённом [BUG-354](../../bugs/BUG-354-FIXED.md): `supported-types.window.html` — FAIL на `assert_implements(window.PerformanceEventTiming, 'Event Timing is not supported.')`; `supported-types-consistent-with-self.html` — FAIL `assert_equals: expected false but got true`, то есть тест ловит само рассогласование напрямую: `PerformanceObserver.supportedEntryTypes` рекламирует `event`/`first-input`, а `'PerformanceEventTiming' in self` === false. Вторая категория после `element-timing`, упирающаяся в тот же захардкоженный список `crates/js/src/dom.rs:11067`; в BUG-354 дописано это подтверждение. Проба `--dump-layout` вне WPT: сам Event Timing не реализован ни в каком виде — `PerformanceEventTiming`/`EventCounts` `undefined`, `performance.eventCounts`/`performance.interactionCount` `undefined`, при этом `PerformanceObserver.observe({entryTypes:['event']})` не бросает и молча ничего не доставляет (вторая половина BUG-354).
