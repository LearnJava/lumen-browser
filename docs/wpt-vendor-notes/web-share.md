# WPT vendor notes — `web-share`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-09 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-web-share`, `docs/wpt-status.md`), scope ⬜ (candidate — Web Share API has a Phase 1 stub, `navigator.share`/`navigator.canShare` always reject/return `false`, `crates/js/src/dom.rs:13350-13354`). Same pinned commit, `git sparse-checkout add` at the same commit hash, `LICENSE-WPT.md` copied from the sibling `web-nfc` category, 27 files (`META.yml`, `WEB_FEATURES.yml`, `resources/`, 22 of 27 root test files `.https.`/`.http.`, most `-manual` and excluded by `run_report.py`'s own selection). No `variant` hits; 9 of 27 files pull `testdriver.js`. `run_report.py --all --root web-share --recursive` selected 15 ids: **3/15 harness OK, 2/6 subtests**. 12 TIMEOUT on the standard TLS `UnknownIssuer` gap ([BUG-657](../../bugs/BUG-657-OPEN.md)); the 3 non-`.https.` ids that ran each FAILed one subtest and each poisoned the next queued `.https.` id's result (`AssertionError: Got results from <prev>, expected <next>` — reconfirmation of already-open [BUG-380](../../bugs/BUG-380-FIXED.md)). Findings: (1) `canShare-insecure.http.html` and `share-securecontext.http.html` both FAIL `assert_false(navigator has attribute 'share'/'canShare')` — `navigator.share`/`.canShare` are exposed unconditionally with no `[SecureContext]` gate at all, live probe confirmed `typeof navigator.share === 'function'` even on a `file:` page; same root cause as `web-locks`/`web-nfc`, reconfirmation of already-open [BUG-399](../../bugs/BUG-399-FIXED.md) (`window.isSecureContext` hardcoded `true`). (2) `feature-policy-listed.tentative.html` FAILs `features()`/`allowedFeatures() includes 'web-share'` — expected, matching the `encrypted-media` precedent from [BUG-361](../../bugs/BUG-361-FIXED.md)'s fix: `_ppSupported` deliberately excludes unimplemented features, and Web Share is a Phase 1 stub (`NotSupportedError`), not a real implementation — correct, honest failure, not a bug. No new bug filed this pass. See `docs/wpt-status.md` for the full breakdown.

## Прогон и находки (`docs/wpt-status.md`)

Web Share API, Phase 1 стаб (`navigator.share`/`.canShare` всегда rejected/`false`, `crates/js/src/dom.rs:13350-13354`). Вендорена целиком 2026-08-09 (пин `35be3b44`, `tests/wpt/web-share/`, 27 файлов, `LICENSE-WPT.md` скопирован из `web-nfc`). 22 из 27 корневых тестов `.https.`/`.http.`, большинство `-manual` исключены отбором `run_report.py`; 9 файлов тянут `testdriver.js`, variant-хитов нет. `run_report.py --all --root web-share --recursive` отобрал 15 id: **3/15 harness OK, 2/6 сабтестов**. 12 TIMEOUT на TLS-гэпе `UnknownIssuer` ([BUG-657](../bugs/BUG-657-OPEN.md)); каждый из 3 исполнившихся не-`.https.`-тестов «отравил» следующий id в очереди (`Got results from <prev>, expected <next>`) — переподтверждение уже открытого [BUG-380](../bugs/BUG-380-FIXED.md). Находки: (1) `canShare-insecure.http.html`/`share-securecontext.http.html` FAIL `assert_false(navigator has attribute 'share'/'canShare')` — обе функции доступны без гейта по секьюрность-контексту (живая проба: `typeof navigator.share === 'function'` даже на `file:`-странице) — переподтверждение уже открытого [BUG-399](../bugs/BUG-399-FIXED.md) (`window.isSecureContext` захардкожен `true`). (2) `feature-policy-listed.tentative.html` FAIL `features()/allowedFeatures() includes 'web-share'` — ожидаемо, тот же паттерн, что `encrypted-media` в [BUG-361](../bugs/BUG-361-FIXED.md): `_ppSupported` намеренно не включает нереализованные фичи, Web Share — Phase 1 заглушка, честный отказ, не баг. Новый номер бага не заводился. **2026-08-10 (P3): [BUG-380](../bugs/BUG-380-FIXED.md) закрыт, корпус перепрогнан** — отравлений (`Got results from <prev>`) больше нет, исполнившиеся тесты дают прежние 3/15 harness OK, 2/6 сабтестов; 12 `.https.` на TLS-гэпе теперь числятся `ERROR` (`document was never replaced ... still at <href>`) за ~2 с вместо `TIMEOUT` — при сверке с этой заметкой учитывать смену статуса.
