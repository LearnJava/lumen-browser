# WPT vendor notes — `encrypted-media`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-28 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-encrypted-media`, `docs/wpt-status.md`), in-scope (⬜, Encrypted Media Extensions — `navigator.requestMediaKeySystemAccess`/`MediaKeys`/`MediaKeySession` on top of `MediaSource`). Same pinned commit, `git sparse-checkout` at the same commit hash, 173 files (96 `.https.` root tests — the generated `clearkey-*`/`drm-*` pairs, one scenario × two key systems; `scripts/` — 39 shared test bodies; `util/` — 5 helpers; `polyfill/` — 5 browser polyfills; `content/` — 10 encrypted MP4 fixtures + `content-metadata.js`; `resources/` — 4 popup pages for the persistent-license rounds; `META.yml`/`WEB_FEATURES.yml`/`README.md`). **No out-of-category dependencies at all** — the only external `src=` references are the already-vendored `/resources/testharness.js`+`testharnessreport.js`, and no file uses `<meta name=variant>`, so 99 selected files produced exactly 99 ids with no expansion. `run_report.py --all --root encrypted-media --recursive` completed in **57:32**: **2/99 harness OK, 0/6 subtests**. 96 of the 99 ids are `.https.`-only and hit the same HTTPS-port gap as `WebCryptoAPI`/`ai`/`bluetooth` (95 TIMEOUT `invalid url: invalid port: "None"` + 1 ERROR on `idlharness.https.html`, the session-reuse artifact seen in `accelerometer`/`beacon`) — roughly 56 of the 57 minutes. Exactly 3 non-https tests executed, each surfacing a distinct cause: `media-element-event-handler-attributes.html` (0/4) → new BUG-360 (HTML event-handler content attributes never compile into handlers, and the live dispatch paths ignore the `on<type>` IDL property; the same test also exposed the missing named-access-on-Window mechanism); `encrypted-media-supported-by-permissions-policy.tentative.html` (0/1) → new BUG-361 (`document.permissionsPolicy.features()` returns the header-declared policy keys instead of the UA-supported feature set — the third category on that same line after `accelerometer`/`ambient-light`); `missing-sinf.html` (0/1) → already-filed BUG-347, new manifestation on a path-absolute `fetch()` URL. EME itself is unimplemented in Lumen (`navigator.requestMediaKeySystemAccess`/`MediaKeys`/`MediaSource` all `undefined`), so even with an HTTPS port the 96 `.https.` tests would fail on `assert_implements`. See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/encrypted-media/`, 173 файла: 96 `.https.`-тестов в корне (`clearkey-*`/`drm-*` — генерируемые пары «один сценарий × два key system»), `scripts/` — 39 общих тел тестов, `util/` — 5 хелперов (`utils.js`, `testmediasource.js`, `clearkey-messagehandler.js`, `drm-messagehandler.js`, `utf8.js`), `polyfill/` — 5 браузерных полифилов, `content/` — 10 зашифрованных MP4-фикстур + `content-metadata.js`, `resources/` — 4 popup-страницы для persistent-license-раундов, `META.yml`/`WEB_FEATURES.yml`/`README.md`; плюс `LICENSE-WPT.md`), в скоупе (⬜, Encrypted Media Extensions — `navigator.requestMediaKeySystemAccess`/`MediaKeys`/`MediaKeySession` поверх `MediaSource`). **Внекатегорийных зависимостей нет вовсе** — единственные внешние `src=` это уже вендоренные `/resources/testharness.js`+`testharnessreport.js`; `<meta name=variant>` не используется ни в одном файле, поэтому 99 отобранных файлов дали ровно 99 id без раскрытия. Прогон `run_report.py --all --root encrypted-media --recursive` — **57 мин 32 с**, **2/99 harness OK, 0/6 сабтестов**. Категория почти целиком упирается в известный гэп исполнителя: **96 из 99 id — `.https.`-only** (95 TIMEOUT `invalid url: invalid port: "None"` + 1 ERROR на `idlharness.https.html` — результат вернулся помеченным URL предыдущего теста, тот же session-reuse-артефакт, что в `accelerometer`/`beacon`), это ~56 из 57 минут прогона. До выполнения дошли ровно 3 не-HTTPS теста, и каждый вскрыл свою причину. **(а) `media-element-event-handler-attributes.html` (0/4) → новый [BUG-360](../../bugs/BUG-360-FIXED.md)**: event-handler-атрибуты HTML не работают вовсе — `onclick="…"`/`onencrypted="…"` (и из парсера, и через `setAttribute`) хранятся как обычный атрибут и никогда не компилируются в обработчик; вдобавок все три живых пути диспатча (`_lumen_dispatch`, `_lumen_dispatch_bubble`, `_lumen_dispatch_rich`, `crates/js/src/dom.rs:3813/3831/3869`) читают только реестр `addEventListener`, так что и присвоенный вручную `el.onclick = fn` молчит — при том что нужный блок в шиме уже написан для не-DOM таргетов (`dom.rs:3391`). Тем же тестом вскрыт соседний гэп — **named access on the Window object** (`id="testElement"` не даёт `window.testElement`), именно на нём упал первый сабтест (`ReferenceError: testElement is not defined`). **(б) `encrypted-media-supported-by-permissions-policy.tentative.html` (0/1) → новый [BUG-361](../../bugs/BUG-361-FIXED.md)**: `document.permissionsPolicy.features()` возвращает ключи политики из HTTP-заголовка вместо списка поддерживаемых движком фич, на странице без заголовка — всегда `[]`; третья категория бэклога на одной и той же строке `permissions_policy.rs:47` после `accelerometer` и `ambient-light`, где причина записывалась без root cause. **(в) `missing-sinf.html` (0/1)** — `fetch("/encrypted-media/content/audio_aac-lc_128k_enc_dashinit.mp4")` падает `network error` при том, что файл вендорен: это уже заведённый [BUG-347](../../bugs/BUG-347-FIXED.md) (`fetch()` не резолвит URL относительно базы документа — `HttpClient::fetch_sync` зовёт `Url::parse` без base, `crates/network/src/lib.rs:3668`), новое проявление — на **path-absolute** URL, где симптом маскируется под сетевую ошибку вместо `invalid url: missing scheme`. Отдельно зафиксировано: сам EME не реализован ни в каком виде — проба `--dump-layout` даёт `undefined` для `navigator.requestMediaKeySystemAccess`, `MediaKeys` и `MediaSource`, — поэтому даже с починенным HTTPS-портом 96 `.https.`-тестов провалились бы на `assert_implements`; ни один из трёх новых/подтверждённых багов к EME отношения не имеет. Побочно замечено при пробах: `HTMLElement.click()` на живом элементе отсутствует (`b.click is not a function`) — отдельного бага не заводилось, ни один тест категории на это не упал
