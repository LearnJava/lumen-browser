# WPT vendor notes — `custom-elements`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-07-26 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-custom-elements`, `docs/wpt-status.md`), in-scope (⬜, Custom Elements — already partially implemented in Lumen as a single global `customElements` registry, `crates/js/src/dom.rs`). Same pinned commit, `git sparse-checkout` at the same commit hash, 208 files (`META.yml`, `WEB_FEATURES.yml`, `form-associated/`, `htmlconstructor/`, `parser/`, `reactions/` (+ `customized-builtins/`, `resources/`), `registries/`, `resources/`, `state/`, `upgrading/`). Out-of-category helpers not vendored: `/common/gc.js`, `/common/object-association.js`, `/html/semantics/forms/form-submission-0/resources/targetted-form.js`, `/images/{green-1x1,green,yellow}.png`, `/resources/testdriver{,-actions,-vendor}.js`, same documented survey gap as `FileAPI`/`ai`. `run_report.py --all --root custom-elements --recursive` selected 176 ids and completed fully (~14:05): 95/176 harness OK, 366/3447 subtests passed, 58 TIMEOUT, 5 SKIP (`Executor does not support testdriver.js`), 1 ERROR (`WebSocket connection closed`, session-restart artifact). Two new engine bugs found and filed — both broad, not WPT-specific: [BUG-346](../../bugs/BUG-346-OPEN.md) (`Url::resolve()` doesn't collapse `.`/`..` dot-segments — a documented, intentional gap; `<script src="../x.js">` resolves to the literal `.../a/../x.js` and 404s; surfaced via `reactions/`+`reactions/customized-builtins/`, ~95 of the run's results), [BUG-347](../../bugs/BUG-347-OPEN.md) (`fetch()` never resolves relative URLs against the document base at all — `missing scheme`; the same symptom had already surfaced without a root cause in `browsing-topics`/`client-hints`/`connection-allowlist`/`cors`, root-caused here). Separately: the entire `registries/` subdirectory (22 files, scoped custom element registries — a newer part of the spec) fails on `CustomElementRegistry is not defined` — a whole unimplemented feature, expected on a first pass, not filed as its own BUG-NNN (same pattern as `container-timing`/`compute-pressure`). The remaining failures are ordinary first-pass reactions/upgrade-semantics gaps. See `docs/wpt-status.md` for details.
