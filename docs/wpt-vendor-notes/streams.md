Test category, added 2026-08-06 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-streams`, `docs/wpt-status.md`), scope ⬜ (candidate). No `variant` hits, no `testdriver.js` references, only 3 `.https.` files — self-contained aside from `/common/gc.js` (not vendored, same documented survey gap as `FileAPI`/`custom-elements`/`js`) and its own `../resources/*.js` relative imports, which hit the already-open dot-segment bug below. `run_report.py --all --root streams --recursive` completed in 5:50 (88 selected ids): **55/88 harness OK, 154/1076 subtests**. Dominant signal (~200 FAIL, `recordingReadableStream`/`recordingWritableStream`/`delay`/`readableStreamToArray is not defined`) reconfirms [BUG-346](../../bugs/BUG-346-FIXED.md) (`Url::resolve()` doesn't collapse `..`-segments — `streams/piping/../resources/recording-streams.js` 404s even though the file is vendored at `streams/resources/recording-streams.js`). Missing `byobRequest`, and `pull()`/`flush()` never being re-invoked after the first call, match the engine's own documented Phase 0 design (`crates/js/src/dom.rs:5630-5634`: "synchronous-friendly model … async pull callbacks are not re-invoked") — not a bug. New finding — [BUG-684](../../bugs/BUG-684-OPEN.md): `ReadableStream`/`WritableStream`/`TransformStream` are plain ES5 constructors with no `new.target` guard, so calling any of them without `new` silently succeeds and leaks the constructor's fields onto `globalThis` (`TransformStream()` leaks `globalThis.readable`/`globalThis.writable`); same defect class as [BUG-629](../../bugs/BUG-629-OPEN.md)/[BUG-374](../../bugs/BUG-374-FIXED.md)/[BUG-672](../../bugs/BUG-672-OPEN.md)/[BUG-681](../../bugs/BUG-681-OPEN.md). Separately, `ReadableStream.prototype[Symbol.asyncIterator]`/`.values()` are missing entirely (WHATWG Streams §4.1), explaining the run's `s[Symbol.asyncIterator] is not a function` cluster. Confirmed live via `--mcp-live-port`. See `docs/wpt-status.md` for the full breakdown.

Прогон `run_report.py --all --root streams --recursive` (5:50, 88 отобранных id): **55/88 harness OK, 154/1076 сабтестов**. Доминирующий сигнал (~200 FAIL, `recordingReadableStream`/`recordingWritableStream`/`delay`/`readableStreamToArray is not defined`) — переподтверждение [BUG-346](../../bugs/BUG-346-FIXED.md) (`Url::resolve()` не схлопывает `..`-сегменты: `streams/piping/../resources/recording-streams.js` 404-ит, хотя файл реально вендорен по `streams/resources/recording-streams.js`). Отсутствие `byobRequest` и повторных вызовов `pull()`/`flush()` соответствует собственному doc-комментарию модуля (`crates/js/src/dom.rs:5630-5634`, «synchronous-friendly model», Phase 0) — не баг. Новая находка — [BUG-684](../../bugs/BUG-684-OPEN.md): `ReadableStream`/`WritableStream`/`TransformStream` — обычные ES5-конструкторы без `new.target`-гварда, вызов без `new` молча биндит `this` на `globalThis` и утекает поля конструктора как одноимённые глобалы (`TransformStream()` — худший случай, утекают `globalThis.readable`/`globalThis.writable`); тот же класс, что BUG-629/374/672/681. Отдельно: `ReadableStream.prototype[Symbol.asyncIterator]`/`.values()` отсутствуют целиком (WHATWG Streams §4.1), объясняя кластер `s[Symbol.asyncIterator] is not a function` в самом прогоне.
