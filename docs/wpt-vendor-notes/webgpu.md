# WPT vendor notes — `webgpu`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-09 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-webgpu`, `docs/wpt-status.md`), scope 🚫 — but not for the reason the roadmap note used to give ("no GPU compute pipeline"): `crates/js/src/webgpu.rs` genuinely implements WebGPU up through Stage 3 (real `wgpu::Buffer`/`Texture`/`RenderPipeline`/`ComputePipeline`, canvas present) behind the `webgpu` Cargo feature, which `lumen-shell` does not currently enable — the default V8 build keeps `navigator.gpu` a pure in-memory Phase 0 shim. Same pinned commit, `git sparse-checkout add` at the same commit hash, `LICENSE-WPT.md` copied from the sibling `webgl` category, 4 files (`LICENSE.txt`, `META.yml`, `README.md`, `WEB_FEATURES.yml` — no test files at all). The upstream `webgpu/` directory is intentionally empty: its own `README.md` explains the WebGPU CTS is generated from TypeScript sources in a separate `gpuweb/cts` repository and vendored ("pinned") directly by each browser rather than exported into web-platform-tests. `run_report.py --all --root webgpu --recursive` correctly reports `no tests selected` (0 files, 0 ids) — no run to execute. Following the `eyedropper`/`webauthn` precedent that an empty or out-of-scope category is not automatically finding-free, a live probe (`--mcp-live-port`) of `navigator.gpu` found [BUG-712](../../bugs/BUG-712-OPEN.md): `navigator.gpu` is a plain object literal (`_gpu = {...}` at `webgpu.rs:821`) with no backing `GPU` interface — `globalThis.GPU` is `undefined` anywhere in the shim (confirmed by grep), so `navigator.gpu instanceof GPU` throws `ReferenceError` and `navigator.gpu.constructor.name === 'Object'` instead of `'GPU'`. Same defect class as [BUG-711](../../bugs/BUG-711-OPEN.md) (WebGL context has no prototype identity either) but on WebGPU's own entry point — every *other* interface in the same file (`GPUAdapter`, `GPUDevice`, `GPUCanvasContext`, etc.) is correctly built as a `function Ctor(){}` + `Ctor.prototype`, confirmed live (`canvas.getContext('webgpu') instanceof GPUCanvasContext === true`). One new bug number. See `docs/wpt-status.md` for the full breakdown.

## Прогон и находки (`docs/wpt-status.md`)

Скоуп 🚫 не по причине пустого движка — `crates/js/src/webgpu.rs` реализует WebGPU Stage 3 поверх `wgpu`, но не активен без Cargo-фичи `webgpu`, которую `lumen-shell` пока не подключает (дефолтная V8-сборка держит `navigator.gpu` Phase-0-шимом). Вендорена целиком 2026-08-09: апстримная директория `webgpu/` в WPT намеренно пуста (CTS живёт отдельно как `gpuweb/cts`, не входит в web-platform-tests). `run_report.py --all --root webgpu --recursive` — `no tests selected` (0/0), как и ожидалось. Живая проба (`--mcp-live-port`, тот же приём, что у `eyedropper`/`webauthn` — «пустой прогон не значит отсутствие находки») нашла [BUG-712](../bugs/BUG-712-OPEN.md): `navigator.gpu` — голый объектный литерал без интерфейса `GPU` (`globalThis.GPU === undefined`, `instanceof` бросает `ReferenceError`), тот же класс дефекта, что [BUG-711](../bugs/BUG-711-OPEN.md) у WebGL; все остальные интерфейсы файла (`GPUAdapter`/`GPUDevice`/`GPUCanvasContext`) корректно constructor/prototype-based
