# WPT vendor notes — `jpegxl`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-05 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-jpegxl`, `docs/wpt-status.md`), scope ⬜ (candidate). Same pinned commit, `git sparse-checkout add` at the same commit hash, 85 files (`META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` copied from the sibling `encoding` category, 62 test files split roughly two-thirds reftest (33 pairs) and one-third testharness, one `resources/` dir of `.jxl`/`.png` fixtures + shared `helpers.js`/`canvas-decode-paths-reftest.js`/`jpegxl-reftest.css`). No `variant` hits, no `testdriver.js`, 3 `.https.` files. `run_report.py --all --root jpegxl --recursive` completed in ~2 min (13 selected testharness ids — the 33 reftest pairs are `Unsupported test type reftest`, excluded from the id count): **2/13 harness OK, 0/11 subtests passed**. All failures trace to already-known causes: `crates/engine/image/src/jxl.rs::decode_jxl` is a documented Phase-0 stub (always `Err`), explaining the TIMEOUT wall on every fixture-decode test (`alpha-vardct.html`, `html-img.html`, `html-input-image.html`, `lossless-jpeg-transcode.html`, `modular-lossy.html`, `svg-image-element.html`, `wide-gamut-*.html`); `html-preload-image.html` FAIL reconfirms [BUG-485](../bugs/BUG-485-FIXED.md)/[BUG-565](../bugs/BUG-565-FIXED.md) (`document.head` is `undefined`, throws on `.appendChild`); the two `.https.` ids ERROR/TIMEOUT on the standard self-signed-cert TLS gap, with one exhibiting the [BUG-380](../bugs/BUG-380-OPEN.md) browsing-context-reuse contamination pattern (`AssertionError: Got results from X, expected Y`). Investigating why decode failures TIMEOUT instead of failing fast surfaced a new, high-blast-radius bug, confirmed with a live `--mcp-live-port` probe using a **valid, correctly-decoding PNG** (not JXL) to rule out a format-specific cause: [BUG-630](../bugs/BUG-630-OPEN.md) — `<img>` never fires `load` or `error` for any image format, and `HTMLImageElement`'s entire decoded-state IDL surface (`complete`/`naturalWidth`/`naturalHeight`/`onload`/`onerror`) is absent from both the instance and the whole prototype chain; the engine's three decode call sites (`crates/shell/src/main.rs::decode_image` + lazy-load + background-image) log-and-drop both the `Ok` and `Err` branches with no event dispatch. Any WPT test that awaits an image's `load`/`error` event — the standard idiom — hangs to the outer wptrunner timeout regardless of the tested feature. See `docs/wpt-status.md` for details.

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-08-05 (коммит `35be3b44`, `tests/wpt/jpegxl/`, 85 файлов: `META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` скопирован из соседней `encoding`, 62 тестовых файла — 33 reftest-пары + testharness-остаток, `resources/` с фикстурами `.jxl`/`.png` + `helpers.js`/`canvas-decode-paths-reftest.js`/`jpegxl-reftest.css`), скоуп ⬜ (кандидат). `run_report.py --all --root jpegxl --recursive` — ~2 мин, 13 отобранных testharness-id (33 reftest-пары дают `Unsupported test type reftest`, в счёт не идут): **2/13 harness OK, 0/11 сабтестов**. Все провалы объясняются уже известным: `crates/engine/image/src/jxl.rs::decode_jxl` — задокументированная Phase-0 заглушка (всегда `Err`), отсюда TIMEOUT на всех fixture-decode тестах; `html-preload-image.html` FAIL переподтверждает [BUG-485](../bugs/BUG-485-FIXED.md)/[BUG-565](../bugs/BUG-565-FIXED.md) (`document.head` отсутствует); два `.https.`-id ERROR/TIMEOUT на стандартном TLS-гэпе тестового сертификата, один — с контаминацией по классу [BUG-380](../bugs/BUG-380-OPEN.md) (`AssertionError: Got results from X, expected Y`). Разбор, почему провал декодирования даёт TIMEOUT, а не быстрый FAIL, вскрыл новый баг с большим радиусом поражения — живой пробой (`--mcp-live-port`) на **валидном, корректно декодируемом PNG** (не JXL — чтобы исключить формато-специфичную причину) подтверждён **[BUG-630](../bugs/BUG-630-OPEN.md)**: `<img>` вообще не эмитит ни `load`, ни `error`, а весь IDL-набор состояния декодирования (`complete`/`naturalWidth`/`naturalHeight`/`onload`/`onerror`) отсутствует и на инстансе, и во всей цепочке прототипов `HTMLImageElement`; движковые точки декодирования (`crates/shell/src/main.rs::decode_image` + lazy-load + background-image) логируют и молча роняют обе ветки (`Ok`/`Err`) без диспатча событий. Любой WPT-тест, ожидающий `load`/`error` у `<img>` — стандартная идиома — зависает до внешнего таймаута wptrunner независимо от корректности тестируемой фичи.
