# WPT vendor notes — `graphics-aam`

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/graphics-aam/`, 7 файлов: `META.yml`, 6 `*-manual.html` — ATTAcomm-тесты для ролей `graphics-document`/`graphics-object`/`graphics-symbol` на HTML- и SVG-элементах, `LICENSE-WPT.md` — `WEB_FEATURES.yml` у категории нет), скоуп ⬜ (кандидат), тот же формат ручных ATTAcomm-тестов, что уже вендоренные `core-aam`/`dpub-aam`. Внекатегорийные хелперы `/wai-aria/scripts/ATTAcomm.js`+`manual.css` не довендорены — категория `wai-aria` сама ещё не вендорена, та же методология, что `core-aam`/`dpub-aam`. `run_report.py --all --root graphics-aam --recursive` — `no tests selected`: `all_vendored_test_ids()` исключает файл по `-manual` в имени, здесь это 100% категории, ожидаемо для manual/ATTAcomm-набора, не разрыв. По правилу «пробуй даже без сигнала» — прямая Rust-проба на `lumen_a11y::build_ax_tree` (временный тест в `crates/engine/a11y/tests/cases/ax_tree.rs`, удалён после подтверждения — `git diff` на файл пуст): [BUG-398](../bugs/BUG-398-FIXED.md) — три роли модуля Graphics ARIA (`https://w3c.github.io/graphics-aria/`) отсутствуют в `AXRole::parse` (`crates/engine/a11y/src/roles.rs`) целиком, откатываются к `AXRole::Generic` наравне с реально невалидными значениями роли (accessible name через `aria-label` при этом считается верно — теряется только семантика роли), воспроизведено на обоих тестовых узлах пробы (`role="graphics-document"` и вложенный `role="graphics-object"`).
