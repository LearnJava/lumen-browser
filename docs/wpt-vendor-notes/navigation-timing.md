# WPT vendor notes — `navigation-timing`

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-08-05 (коммит `35be3b44`, `tests/wpt/navigation-timing/`, 82 файла: `META.yml`, `WEB_FEATURES.yml`, `LICENSE-WPT.md` скопирован из соседней `navigation-api`, `nav2-*`/`test-*` корневые тестовые файлы, `resources/`). Прогон `run_report.py --all --root navigation-timing --recursive` (~8 мин, 59 отобранных id): **12/58 harness OK, 4/36 сабтестов passed (11%)**. Чтение `crates/shell/src/main.rs::deliver_nav_timing` подтвердило причину: `PerformanceNavigationTiming`-запись строится с `detail_json = null`, поэтому объект содержит только `entryType`/`name`/`startTime`/`duration` — ни одного специфичного поля (`connectEnd`/`redirectCount`/`type`/`transferSize` и т.д. — все `undefined`), в отличие от соседнего `_lumen_record_resource_timing`, который такие поля строит. Доминирующая причина 5 из 6 файлов, где harness завершился без TIMEOUT/ERROR. Заведён [BUG-640](../bugs/BUG-640-OPEN.md). Остальные 46/58 — уже известные гэпы: TLS `UnknownIssuer` на `.https.`-тестах, cross-origin/iframe многооконная навигация (класс BUG-480, `nav2-test-redirect-*`/`test-timing-*redirect*`/`nav2-test-navigate-iframe.html` зависают TIMEOUT в ожидании второго origin/окна), и невендоренный категория-внешний `/common/dispatcher/dispatcher.js` (`RemoteContext`, тот же класс, что `/common/security-features/...` у `mixed-content`) — новых багов на эти классы не заведено
