# WPT vendor notes — `svg`

## Vendoring (`tests/wpt/VENDOR.md`)

Test category, added 2026-08-06 by the WPT-VENDOR backlog (`ROADMAP.md` `WPT-VENDOR-svg`, `docs/wpt-status.md`), scope ⬜ (candidate). Same pinned commit, `git sparse-checkout add` at the same commit hash, 2149 files (`animations/`, `as-image/`, `coordinate-systems/`, `embedded/`, `extensibility/`, `fonts/`, `geometry/`, `import/`, `interact/`, `layout/`, `linking/`, `painting/`, `path/`, `pservers/`, `crashtests/`, plus root `historical.html`/`idlharness.window.js`/`sniffing-content-type.html`); one category-local helper missing from the already-vendored shared `tests/wpt/resources/` — `/resources/SVGAnimationTestCase-testharness.js` (182 references, used by nearly every `animations/` file) — was missing and vendored alongside it in this pass. Out-of-category helpers not vendored: `/common/reftest-wait.js`+`/common/rendering-utils.js` (same documented survey gap as `streams`' `/common/gc.js`); `/css/support/*-testcommon.js` were already vendored by earlier `css/` categories, no gap there. No `variant` hits, 6 `testdriver.js` files, 11 `.https.` files — all cheap by the usual predictors, and the run bore that out. `run_report.py --all --root svg --recursive --processes=4` completed in 4:12 (861 selected ids): **421/472 harness OK, 397/2068 subtests** — an unusually high harness-OK ratio for this backlog, the profile of a substantially-implemented category (like `fetch`), not a blanket-absence wall. New finding — [BUG-685](../../bugs/BUG-685-OPEN.md): the HTML parser never implements HTML LS §13.2.6.5 foreign content (confirmed: `crates/engine/html-parser/src/tree_builder.rs:1879` builds every parsed element with `QualName::html(name)` unconditionally, zero `namespace`-aware branches anywhere in the crate) — every element parsed from literal `<svg>…</svg>` markup gets `namespaceURI` = XHTML and lands on plain `HTMLElement.prototype`, never reaching the real, unit-tested `SVG*Element` DOM in `crates/js/src/svg.rs` (`getBBox()`, `getTotalLength()`, `pauseAnimations()`/`setCurrentTime()`, `baseVal`/`animVal`, etc.), which is wired only through a `document.createElementNS` monkey-patch. Confirmed live via `--mcp-port` (`document.createElementNS(svgNS,'rect') instanceof SVGRectElement` → `true`; the same tag written as literal markup → `namespaceURI: xhtml`, `ctorName: "HTMLElement"`, `tagName: "RECT"`). Explains nearly the entire run's error volume: 260× `reading 'baseVal'`, ~230× SMIL timeline methods (`pauseAnimations`/`setCurrentTime`/`beginElement`/…), ~130× `getBBox`, 38× `valueAsString`, ~45× path-geometry methods (`getTotalLength`/`getPointAtLength`/`isPointInFill`/`isPointInStroke`), ~10× text-content-element char queries. 90× `document.elementFromPoint is not a function` — reconfirmation of already-open [BUG-464](../../bugs/BUG-464-OPEN.md)/[BUG-477](../../bugs/BUG-477-OPEN.md)/[BUG-580](../../bugs/BUG-580-OPEN.md), not part of this bug. 135× `ReferenceError: svg is not defined` not fully investigated — plausibly correct behavior (a page-level `let svg = …` binding is invisible to inline SMIL event-handler attributes like `onbegin="svg…"` per the HTML LS "handler content attribute" scoping algorithm), flagged in the bug for whoever picks up the fix rather than filed as a second bug. One new bug number. See `docs/wpt-status.md` for the full breakdown.
