# WPT vendor notes — `fonts`

## Прогон и находки (`docs/wpt-status.md`)

Вендорена целиком 2026-07-28 (коммит `35be3b44`, `tests/wpt/fonts/`, 205 файлов + `LICENSE-WPT.md`), скоуп ⬜ (кандидат). **Это не тестовая категория, а разделяемый ресурсный каталог**: `README.md` внутри прямо говорит — «содержит только вспомогательные файлы шрифтов, используемые другими тестами; тесты CSS Fonts см. `/css-fonts`» — и это подтверждается: ни одного `.html`/`.js`-файла нет, только `.woff`/`.woff2`/`.ttf`/`.otf`/`.css`/`.md`/`.yml`/лицензии (Ahem, CSSTest, Lato, GentiumPlus, noto-семейство и др.). `run_report.py --all --root fonts --recursive` — **`no tests selected`**, id = 0, harness запускать нечего. Проба «уровнем выше» (методология `fedcm`/`fenced-frame`): собрана страница с `@font-face { src: url("Ahem.ttf") }` и `font-size: 100px`, `--dump-layout` дал ширину `#p` для `"hello"` **225.83px** вместо ожидаемых 500px (Ahem — моноширинный тестовый шрифт, глиф = квадрат в 1em) — то есть в headless-снимке текст всё ещё в fallback-шрифте (Inter). Это не баг: по коду (`crates/shell/src/main.rs` вокруг `parse_and_layout`/`load_font_faces`, PH3-19) `url()`-источники `@font-face` асинхронные по дизайну — `local()` резолвится синхронно, а `url()` остаётся в `Loading` и догружается фоновым потоком, событие `FontLoaded` обрабатывается в `about_to_wait` живого event-loop'а с последующим relayout (FOUT). Однослотовые headless-пути (`--dump-layout`/`--screenshot`/`--print-to-pdf`/`--trace-nav`) используют `parse_and_layout` напрямую и не крутят `about_to_wait`, поэтому принципиально не могут дождаться `FontLoaded` — это ожидаемое ограничение инструмента, а не дефект `@font-face`, отдельного бага не заводилось. Других находок нет: категория безобидна для WPT-бэклога и своей ценности исчерпывается тем, что она — зависимость `css-fonts` (пока не вендорена).
