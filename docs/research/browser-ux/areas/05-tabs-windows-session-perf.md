# Вкладки, окна, сессии, запуск, воспринимаемая производительность

Приложение к UX-исследованию. В области 32 находки. 10 из них исправлены после проверки фактов, в тексте приведены исправленные версии. Пометка «(не проверено)» стоит у утверждений, которые не удалось подтвердить источником. В документе ChatGPT 16 находок отсутствуют, 16 упомянуты общими словами, и ни одна не описана конкретно (с числами, клавишами, порогами).

Ограничения: Reddit инструментам недоступен; issues.chromium.org без JS не показывает число звёзд; часть доменов не загрузилась. Числа Firefox и Chromium сверены по исходникам (`firefox.js`, `StaticPrefList.yaml`, `tab_container_impl.cc`, `accelerator_table.cc` и др.).

## Главное в области

1. **Правильное поведение браузеры находили годами, и это готовый каталог.** Firefox заморозил ширину вкладок при закрытии через 3 года после бага (2008 → Firefox 5). Защита от Ctrl+Q появилась примерно через 20 лет (баг 52821 → Firefox 87). Chrome удалил Ctrl+Shift+Q в 2018 году. Safari 15 откатили через месяц. Ctrl+Tab в Firefox меняли дважды (63 → 89, миграцию чинили в 97). Отключение звука кликом и выключатель hover cards в Chrome то убирали, то возвращали. Прокрутку полосы вкладок в Chrome 144 удалили. Lumen может сразу взять итоговые решения и пропустить эти ошибки.
2. **Сильнее всего злит смена привычного поведения, а не отсутствие функции.** Сюда относятся новое значение по умолчанию, перенесённая кнопка, миграция настроек, которая молча переворачивает выбор. Правило: новые значения по умолчанию действуют только для новых профилей, явный выбор пользователя миграция не трогает, функцию не удалять без замены.
3. **Надёжность сессии — вопрос безопасности, и она определяет политику предупреждений.** Люди откладывают обновления, чтобы не потерять сотни вкладок или приватные окна. Если восстановление гарантировано, «Закрыть N вкладок?» становится шумом. Предупреждать нужно только о том, что не вернётся: приватные окна, несохранённый ввод, активные загрузки.
4. **Аудитория бимодальна.** Медиана — 2–4 вкладки, но громкий хвост держит сотни и тысячи и голосует: вертикальные вкладки и группы — первые места на Mozilla Connect. Интерфейс по умолчанию рассчитывать на 2–15 вкладок, архитектуру — на 500–3000: ленивое восстановление, размер и запись сессии, никакой работы O(N) на кадр.
5. **Экономию памяти не видно, потерю состояния видно сразу.** Выгрузка и ленивая загрузка вкладок требуют поддержки движка: прокрутку, формы и историю нужно восстанавливать так же, как при восстановлении сессии. Вкладки с несохранённым вводом, звуком, WebRTC и загрузками выгружать нельзя.
6. **Для собственного движка и UI главный риск — платформенные мелочи, которые браузеры на Chromium получают бесплатно.** Это сочетания клавиш по виртуальному коду (ЙЦУКЕН), зарезервированные сочетания, Snap Layouts, RegisterApplicationRestart и WM_QUERYENDSESSION, зона перетаскивания окна, EcoQoS только для фона. Воспринимаемая скорость важнее измеренной: скелет окна при запуске даёт обратную связь до 15 с раньше, последний сохранённый кадр при переключении вкладки скрывает задержку отрисовки.

## Находки

### Полоса вкладок: геометрия и работа мышью

**Быстрое закрытие подряд: ширина вкладок заморожена, пока курсор над полосой** · массово · высокая · у ChatGPT: нет
- Боль: человек закрывает 5–10 вкладок подряд кликами по ×. Если после каждого закрытия вкладки расширяются, × уезжает из-под курсора, легко закрыть не ту. Функцию не просят, но регрессию замечают сразу: Opera 82 — «very irritating», в Firefox это три года было частой жалобой в Mozilla Input.
- Как должно быть: режим включается только при закрытии мышью (клик по × или средний клик). При закрытии с клавиатуры (Ctrl+W) или из кода раскладка пересчитывается сразу. Пока режим активен, вкладки раскладываются по замороженной доступной ширине (в Chrome это правый край последней вкладки до закрытия). Вкладки справа сдвигаются влево с прежней шириной, и × следующей вкладки оказывается под курсором. Если закрыта крайняя правая вкладка, доступная ширина не меняется: оставшиеся расширяются так, что × новой последней снова под курсором, но не шире максимальной ширины вкладки. Режим снимается, когда курсор уходит из зоны полосы с запасом (Chrome: `kTabStripAnimationVSlop` = 40 px по вертикали, `kTabStripAnimationHSlop` = 60 px по горизонтали), а также при добавлении вкладки, сужении окна или когда осталась одна вкладка. Открытое контекстное меню вкладки откладывает снятие. Возврат к нормальной ширине анимирован. Уход курсора определять по mousemove с проверкой зоны: mouseout при быстром движении теряется. Средний клик по вкладке, которая уже анимирует закрытие, закрывает ту, что оказалась под курсором. Снимать режим по таймеру нельзя.
- Кто делает лучше / хуже: эталон — Chrome («rapid closure mode» в design doc полосы вкладок). Edge, Vivaldi и Яндекс наследуют это от Chromium. Firefox догнал в версии 5 (2011), баг заведён в 2008. Opera 82.0.4227.23 сломала поведение регрессией. У Chrome есть открытый с 11.2024 баг 380282508: в полноэкранном режиме вкладки расширяются, хотя курсор над полосой.
- Источники: https://bugzilla.mozilla.org/show_bug.cgi?id=465086 (37 голосов, 92 в CC, 6 дублей) · https://chromium.googlesource.com/chromium/src/+/refs/heads/main/chrome/browser/ui/views/tabs/tab_container_impl.cc · https://forums.opera.com/topic/53115/tab-strip-change-size-when-i-close-a-tab

**Активная вкладка должна читаться однозначно (урок Safari 15)** · массово · высокая · у ChatGPT: нет
- Боль: в Safari 15 вкладки выглядели как кнопки, затенение инвертировалось (активная темнее), при двух вкладках одного сайта активную приходилось угадывать. Gruber: «they look like buttons». Тред на Reddit набрал около 1000 апвоутов (число не проверено). Apple откатила дизайн в 15.1. Компактный режим в macOS 26 убрали и после жалоб вернули.
- Как должно быть: активная вкладка сливается с тулбаром — тот же фон, без нижней границы. Контраст между активной и неактивной не ниже 3:1 (WCAG 1.4.11) в светлой, тёмной, приватной и высококонтрастной темах. Активность передаётся не только цветом, но и формой (слияние с тулбаром). Полосу по умолчанию не перекрашивать в цвет сайта. Активная должна отличаться даже от вкладки того же сайта с той же favicon.
- Кто делает лучше / хуже: Chrome, Firefox и Edge используют модель «вкладка слита с тулбаром». Safari 15 — хрестоматийный провал.
- Источники: https://daringfireball.net/2021/10/the_tragedy_of_safari_15_quote_unquote_tabs · https://appleinsider.com/articles/21/10/27/apple-releases-safari-151-for-macos-big-sur-and-catalina-with-traditional-tab-design · https://www.technobezz.com/news/apple-restores-compact-tab-bar-in-safari-after-user-complaints

**Кнопка × и минимальная ширина вкладки: пороги скрытия и защита от промаха** · массово · средняя · у ChatGPT: нет
- Боль: на узких вкладках люди попадают по × вместо выбора вкладки. Обратная жалоба: на неактивных вкладках нет ×, и закрыть вкладку, не переключаясь на неё, нельзя.
- Как должно быть: Chrome скрывает × на неактивных вкладках при ширине содержимого меньше 68 DIP (в touch-режиме — 100 DIP) с комментарием «too easy to hit on accident». Активная вкладка × не теряет: её минимальная ширина — ширина × плюс два отступа. Неактивные сжимаются до `kInteriorWidth` = 16 DIP, остаётся одна favicon. В Firefox `browser.tabs.tabMinWidth` = 76 px, а × на неактивных видна при ширине от 140 px (`browser.tabs.tabClipWidth`). Рекомендация: показывать × на всех вкладках, пока помещаются favicon, несколько символов заголовка и ×. Ниже порога × остаётся на активной и появляется по наведению на остальных, причём при любой ширине окна. Зона нажатия × не меньше 16×16 px, с зазором от зоны выбора. Средний клик закрывает вкладку при любой ширине. У закреплённых вкладок × нет.
- Кто делает лучше / хуже: в Chrome пороги продуманы. Firefox скрывает × на неактивных раньше (порог 140 px). В Brave на macOS при узком окне × не появлялась по наведению на неактивную вкладку, хотя места для favicon и × хватало; исправлено в Brave 1.29 (07.2021).
- Источники: https://chromium.googlesource.com/chromium/src/+/97b1abc3e66086a8a54d60818a686cf3ca81e961/chrome/browser/ui/views/tabs/tab.h · https://github.com/brave/brave-browser/issues/13946 · https://support.mozilla.org/en-US/questions/1247607

**Полоса вкладок как заголовок окна: зона перетаскивания, двойной клик, Snap Layouts** · часто · средняя · у ChatGPT: нет
- Боль: при большом числе вкладок окно не за что схватить: в Vivaldi над вкладками остаётся 1 px, Firefox 89 (Proton) убрал опцию Drag Space (`browser.tabs.extraDragSpace`). Двойной клик по полосе в разных браузерах то открывает вкладку, то разворачивает окно.
- Как должно быть: 1) справа от кнопки «+» всегда остаётся зона перетаскивания около 40–60 px, даже при переполнении; 2) у неразвёрнутого окна над вкладками есть несколько пикселей для захвата, у развёрнутого вкладки прижаты к верхнему краю экрана; 3) двойной клик по пустому заголовку разворачивает и восстанавливает окно, а двойной или средний клик по пустому месту полосы открывает вкладку — настраивается, с разделением зон, как в Opera 12; 4) Windows 11: при наведении на кнопку «Развернуть» показываются Snap Layouts, для этого WM_NCHITTEST над кнопкой возвращает HTMAXBUTTON (не проверено); 5) Win+стрелки и прилипание к краям работают как у нативных окон; 6) правый клик по пустому месту полосы везде открывает одно и то же меню.
- Кто делает лучше / хуже: у Chrome на Windows системные жесты работают нативно. Firefox убрал Drag Space. Vivaldi при полосе сверху по двойному клику разворачивает окно.
- Источники: https://forum.vivaldi.net/topic/37861/more-window-drag-space-above-tabs · https://www.ghacks.net/2021/04/12/firefoxs-drag-space-customize-option-will-be-removed-for-most-users/ · https://forum.vivaldi.net/topic/24367/double-click-tab-bar-to-open-new-tab

**Индикатор звука на вкладке и отключение звука одним кликом** · часто · средняя · у ChatGPT: вскользь
- Боль: «откуда играет звук и почему нельзя просто кликнуть по динамику?». Chrome 71 (2018) убрал отключение звука кликом по иконке, пользователи массово ставят расширения. В 2022 году функцию вернули только за флагом (`enable-tab-audio-muting` есть в `flag-metadata.json` и сейчас). Chrome глушит сайт, а не вкладку.
- Как должно быть: иконка звука — это кнопка. Клик отключает звук этой вкладки (не всего сайта) и не активирует её. Зона нажатия не меньше 16×16 px. Ctrl+M отключает звук активной вкладки. Три состояния: «играет», «звук выключен», «автовоспроизведение заблокировано». После окончания звука индикатор держится ещё 1–2 с, чтобы не мигать между треками. Свёрнутые группы и свёрнутая вертикальная панель показывают суммарный индикатор. В списке вкладок есть фильтр «со звуком». В контекстном меню — отдельные пункты «звук вкладки» и «звук сайта».
- Кто делает лучше / хуже: Firefox, Edge, Opera и Safari по умолчанию отключают звук кликом по иконке. В Chrome — правый клик → «Отключить звук сайта», клик по иконке работает только за флагом.
- Источники: https://techdows.com/2018/10/chrome-tab-audio-muting-ui-control-flag-removed.html · https://www.ghacks.net/2018/03/18/the-complete-google-chrome-audio-muting-guide/ · https://winaero.com/google-is-again-testing-tab-muting-in-the-chrome-browser/

**Карточки при наведении на вкладку: задержка, мерцание, перекрытие** · часто · низкая · у ChatGPT: нет
- Боль: hover cards в Chrome 78 крупные, вспыхивают, когда мышь проходит по полосе, и закрывают адресную строку. Возможность отключить их убрали в 2021 году и вернули в 2023-м. Показ памяти в карточке замедлил её появление.
- Как должно быть: задержка первой карточки зависит от ширины вкладки. В Chrome она 300 мс для самых узких, к стандартной ширине растёт логарифмически до 800 мс, а для вкладок полной ширины добавляется ещё 500 мс, то есть до примерно 1,3 с. Если курсор вернулся на полосу в пределах 300 мс после ухода, следующая карточка показывается без задержки. Карточка скрывается при клике, перетаскивании, вводе с клавиатуры и уходе курсора. Подсказки адресной строки она не перекрывает. В карточке полный заголовок и домен. Превью и память включаются отдельными переключателями; саму карточку можно заменить системной подсказкой.
- Кто делает лучше / хуже: в Chrome есть превью и память, отключение то убирали, то возвращали. Firefox: `browser.tabs.hoverPreview.enabled` = true, `showThumbnails` = true. В Edge превью опционально.
- Источники: `chrome/browser/ui/views/tabs/hovercard/tab_hover_card_controller.cc` (`kMinimumTriggerDelay` = 300 мс, `kMaximumTriggerDelay` = 800 мс) · https://9to5google.com/2019/11/06/how-to-disable-tab-hover-cards-chrome-78/ · https://www.askvg.com/disable-remove-memory-usage-from-tab-hover-cards-in-chrome/

### Много вкладок: переполнение, поиск, дубликаты

**Сколько вкладок держат пользователи: бимодальная аудитория** · массово · средняя · у ChatGPT: вскользь
- Боль: большинство держит мало вкладок, но громче всех те, у кого их сотни. На Хабре пишут «503 вкладки», «3000 тормозит», в Яндексе — «несколько сотен вкладок». Именно они голосуют за вертикальные вкладки и группы.
- Как должно быть: в Firefox Test Pilot 2010 года (27 000 участников) медиана средней загрузки — 2,38 вкладки, у четверти — от 3,59. У половины участников максимум меньше 8 вкладок, у четверти бывало 11 и больше, рекорд — 1 103. Данным 16 лет. Интерфейс по умолчанию рассчитывать на 2–15 вкладок, инфраструктуру — на 500–3000: размер и частота записи сессии, ленивая загрузка, поиск, никакой работы O(N) на каждый кадр. Тестовые профили: 3, 20, 100, 500 и 2000 вкладок.
- Кто делает лучше / хуже: Firefox выдерживает больше всего вкладок. Chrome на сотнях вкладок упирается в иконки и загрузку всех вкладок при старте.
- Источники: https://slate.com/human-interest/2010/12/a-new-data-set-from-firefox-reveals-our-browsing-habits.html (27 000 участников) · https://dubroy.com/blog/how-many-tabs-do-people-use-now-with-real-data/ · https://habr.com/ru/articles/538294/

**Переполнение полосы: сжатие до иконок или прокрутка** · часто · высокая · у ChatGPT: вскользь
- Боль: в Chrome после ~20 вкладок видны только иконки, вкладки одного сайта неотличимы, правые пропадают. Флаг `#scrollable-tabstrip` существовал с Chrome 75 (04.06.2019) и был удалён в Chrome 144 (13.01.2026); это задело и Brave 1.86.139. Цитата человека с нарушениями моторики: «tiny tabs just do not work». Google обещал новую прокрутку к H1 2026. У прокрутки Firefox тоже есть противники (HN: «feature I hate the most»).
- Как должно быть: гибрид. Вкладки сжимаются, пока заголовок читаем (favicon + 6–8 символов, около 76–100 px), дальше полоса прокручивается горизонтально. Колесо мыши над полосой прокручивает вкладки, а не переключает их. Стрелки или градиент по краям показывают, что за краем есть вкладки. При любом переключении (Ctrl+Tab, Ctrl+9, поиск) активная вкладка прокручивается в видимую область, новая — тоже. Закреплённые вкладки не прокручиваются. Кнопка «Список всех вкладок» открывает вертикальное меню с отметкой активной вкладки и индикаторами звука. Минимальная ширина вкладки настраивается, в том числе ради доступности.
- Кто делает лучше / хуже: лучше всех Firefox: минимальная ширина, прокрутка, «List all tabs». Chrome сжимает вкладки до 16 DIP, прокрутки после 144 нет. Edge и Vivaldi дают выход через вертикальные вкладки.
- Источники: https://issues.chromium.org/issues/475853506 (Accepted; 478527840 закрыт как его дубликат) · https://tabsprompt.com/blog/chrome-tab-scrolling-removed · https://piunikaweb.com/2026/01/19/chrome-brave-tab-scrolling-removed-chromium-144/

**Поиск по открытым вкладкам** · часто · средняя · у ChatGPT: вскользь
- Боль: на Хабре пишут: «в хроме с 70–100 вкладками найти нужное просто нереально». В 2026 году Chrome перенёс кнопку поиска влево, к закреплённым вкладкам. Люди промахиваются, а вернуть выбор места Google отказался.
- Как должно быть: поиск вызывается с клавиатуры — Ctrl+Shift+A, как в Chrome на Windows и Linux. Ищет по заголовку и URL с нечётким совпадением, во всех окнах, включая недавно закрытые вкладки. Enter переключает на вкладку и её окно, из строки результата вкладку можно закрыть. Адресная строка предлагает «Перейти на вкладку» (префикс `%` в Firefox, `@tabs` в Chrome). Кнопку поиска не ставить рядом с частыми целями клика, её положение настраивается.
- Кто делает лучше / хуже: в Chrome лучший поиск с клавиатуры, но кнопка стоит неудачно. Firefox — «List all tabs», префикс `%`, Firefox View. Vivaldi — Quick Commands.

- Как должно быть: есть единый стек закрытого — вкладки, окна и группы. Вкладка возвращается в то же окно на тот же индекс вместе с историей назад/вперёд, прокруткой, полями форм, закреплением, группой и масштабом. Повторные нажатия идут глубже по стеку (Firefox: `max_tabs_undo` = 25, `max_windows_undo` = 5; закрытые вкладки сохраняются между сессиями, `persist_closed_tabs_between_sessions` = true). Если сессия не восстановилась автоматически, Ctrl+Shift+T после запуска возвращает её целиком. Массовое закрытие («Закрыть другие вкладки») отменяется одним действием. В меню «История» есть «Восстановить окно (N вкладок)». Вкладки приватного окна восстанавливаются, только пока это окно открыто.
- Кто делает лучше / хуже: образец задал Chrome. Firefox лучше всех восстанавливает формы. Пользователи Яндекса жалуются, что после второго перезапуска закрытое уже не вернуть (не проверено).
- Источники: http://googlemac.blogspot.com/2011/06/q-i-didnt-mean-to-do-that.html · https://yandex.ru/support/browser/ru/troubleshooting/troubleshooting · https://otvet.mail.ru/question/239533941

**Случайный выход: Ctrl+Q рядом с Ctrl+W, ⌘Q рядом с ⌘W и ⌘Tab** · часто · критично · у ChatGPT: нет
- Боль: «хотел закрыть вкладку — закрылся весь браузер». Баг Firefox 52821 «too easy to hit CTRL+Q instead of CTRL+W» прожил около 20 лет (2000 → Firefox 87). На HN это назвали «one of the biggest UI failures».
- Как должно быть: на Windows у браузера нет одноаккордного сочетания выхода. Chrome удалил Ctrl+Shift+Q в конце 2018 года и предлагает Alt+F, X; в `accelerator_table.cc` сочетания для `IDC_EXIT` нет. Alt+F4 закрывает только текущее окно. На macOS по ⌘Q появляется оверлей «Удерживайте ⌘Q для выхода». В Chrome удержание — 1,5 с (`kShowDuration` = 1500 мс), опция включена по умолчанию. События после отпускания поглощаются, иначе KeyUp закроет следующее приложение. Firefox 87 добавил `browser.quitShortcut.disabled`. В Firefox 94 появилось отдельное предупреждение при выходе по сочетанию: `warnOnQuitShortcut` включён на macOS и Linux и выключен на Windows. Если выход всё-таки произошёл, следующий запуск обязан вернуть сессию, а Ctrl+Shift+T — всю сессию целиком.
- Кто делает лучше / хуже: лучше всех Chrome: hold-to-quit на Mac есть с 2011 года (тогда включался вручную), на Windows сочетания выхода нет. Firefox показывает диалог. В Safari защиты нет, её продают сторонние утилиты. Утверждение, что в Яндексе Ctrl+Shift+Q закрывает браузер, указанной справкой не подтверждено (не проверено).
- Источники: https://bugzilla.mozilla.org/show_bug.cgi?id=52821 (86 голосов, 126 в CC, 19 дублей) · https://www.ghacks.net/2018/10/22/google-retires-ctrl-shift-q-in-chrome-to-exit-web-browser/ · http://googlemac.blogspot.com/2011/06/q-i-didnt-mean-to-do-that.html

**Предупреждения при закрытии окна и выходе — только там, где восстановление не спасёт** · часто · высокая · у ChatGPT: нет
- Боль: жалобы идут в обе стороны. Одних раздражает «Закрыть N вкладок?». Другие теряют всё без предупреждения: когда Firefox не предупреждал при включённом восстановлении сессии, это назвали «completely daft», ведь состояние страниц всё равно теряется.
- Как должно быть: предупреждать только о том, что не вернётся при восстановлении: 1) приватные окна, с указанием числа вкладок; 2) несохранённый ввод (beforeunload при sticky activation или изменённые поля форм); 3) активные загрузки и выгрузки. Закрытие окна со многими вкладками можно не подтверждать, если окно гарантированно возвращается через Ctrl+Shift+T и «Недавно закрытые → Восстановить окно». К закрытию сочетанием клавиш требования строже, чем к закрытию через меню или кнопку. В диалоге есть «Больше не спрашивать». Настройки разных предупреждений не перекрывают друг друга: в Firefox баг 1726736 вызвал регрессию 1732446, дубль — 1732422.
- Кто делает лучше / хуже: Firefox самый настраиваемый (`warnOnClose` = false, `warnOnCloseOtherTabs` = true, `warnOnQuit` = true), но настройки конфликтовали. Chrome почти не предупреждает и полагается на восстановление. В Edge начиная с 104 есть политика AskBeforeCloseEnabled; по умолчанию окно закрывается без подтверждения.
- Источники: https://support.mozilla.org/en-US/kb/how-configure-close-tab-warnings-firefox · https://bugzilla.mozilla.org/show_bug.cgi?id=1732446 · https://learn.microsoft.com/en-us/DeployEdge/microsoft-edge-browser-policies/askbeforecloseenabled

**Перезапуск для обновления: приватные окна и страх потерять вкладки** · часто · высокая · у ChatGPT: вскользь
- Боль: перезапуск для обновления в Chrome безвозвратно закрывает окна инкогнито (справка: «Your Incognito windows won't reopen when Chrome restarts»). Люди откладывают перезапуск и остаются уязвимыми к zero-day (Forbes, 04.2026).
- Как должно быть: обновление применяется при следующем естественном закрытии браузера. Кнопка перезапуска заранее называет последствия: «Будут закрыты приватные окна: 2 (7 вкладок)». Есть вариант «Перезапустить, когда я закрою браузер». После перезапуска сессия восстанавливается полностью, независимо от настройки стартовой страницы. Напоминания немодальные.
- Кто делает лучше / хуже: Chrome показывает индикатор «Relaunch to update», «Not now» откладывает обновление до следующего перезапуска, но инкогнито при перезапуске теряется. Firefox восстанавливает сессию после перезапуска. Пользователи Яндекса боятся обновлений.
- Источники: https://support.google.com/chrome/answer/95414 · https://www.forbes.com/sites/zakdoffman/2026/04/04/if-you-see-this-message-in-google-chrome-you-are-now-at-risk/

### Запуск, память, отзывчивость, фоновые вкладки

**Память: репутация «ест RAM» и прозрачность расхода** · массово · высокая · у ChatGPT: вскользь
- Боль: «3 вкладки — 913 МБ». Пользователи смотрят на сумму в Диспетчере задач Windows. В Windows 11 22H2 режим эффективности, включённый для Edge, вызывал лаги.
- Как должно быть: встроенный диспетчер задач (Shift+Esc) показывает память, CPU и сеть по каждой вкладке и расширению и позволяет завершить процесс; после этого вкладка показывает страницу с кнопкой перезагрузки. В Диспетчере задач Windows процессы понятно подписаны. EcoQoS применяется только к фоновым вкладкам, не к интерфейсу и не к активной вкладке. Предупреждение о высоком расходе памяти предлагает конкретное действие. Ориентир Tom's Guide: при 20 вкладках Chrome — 1,8 ГБ, Firefox — 1,6, Edge — 1,4; при 60 вкладках Edge — 2,9, Chrome — 3,7, Firefox — 3,9.
- Кто делает лучше / хуже: в Chrome есть Shift+Esc и память в карточке вкладки, в Firefox — about:processes. Edge выигрывает за счёт усыпления вкладок.
- Источники: https://www.tomsguide.com/uk/news/chrome-firefox-edge-ram-comparison · https://learn.microsoft.com/en-us/answers/questions/1184305/how-to-turn-off-efficiency-mode-for-edge · https://techcrunch.com/2022/12/08/chrome-gets-memory-and-energy-saver-modes

**Отзывчивость интерфейса при тяжёлой странице и переключении вкладок** · часто · критично · у ChatGPT: вскользь
- Боль: тяжёлая страница подвешивает весь браузер: вкладку не закрыть, адрес не ввести. При переключении вкладки — белый экран или спиннер. Модальное «скрипт не отвечает» блокирует всё окно.
- Как должно быть: 1) полоса вкладок, адресная строка и Ctrl+W реагируют в пределах кадра, не позже 100 мс (RAIL). Зависшую вкладку можно закрыть всегда. 2) При переключении сразу показывается последний сохранённый кадр вкладки. Прогрев при наведении (Firefox tab warming: `warmup.maxTabs` = 3, `unloadDelayMs` = 2000) не меняет `visibilityState` и не запускает медиа: в Firefox 57 исправляли баг 1394455, где прогрев снимал блокировку медиа. Спиннер — только если кадр не готов через сотни миллисекунд. 3) Зависание страницы показывается немодальной плашкой на её вкладке («Остановить» / «Подождать»). 4) Разбор и раскладка страницы не блокируют поток интерфейса.
- Кто делает лучше / хуже: Chrome — процессы и диалог «Страница не отвечает». Firefox — e10s/Fission, немодальная плашка, прогрев вкладок.
- Источники: https://bugzilla.mozilla.org/show_bug.cgi?id=1394455

**Воспринимаемая скорость запуска: сначала окно, потом движок** · часто · высокая · у ChatGPT: нет
- Боль: нажал на иконку — ничего не происходит, нажимаешь снова и снова. На слабом компьютере Firefox 19 секунд не подавал признаков запуска.
- Как должно быть: сразу после клика показывается скелет окна, ещё до загрузки движка. Размер, позиция, монитор, тема и состав тулбаров берутся из прошлой сессии (Firefox хранит их в реестре, `browser.startup.preXulSkeletonUI` — только Windows). Элементы рисуются серыми неинтерактивными плашками, потом окно бесшовно заменяется настоящим. На слабых системах обратная связь появляется до 15 с раньше. Повторный запуск передаёт команду уже работающему процессу, без диалога о заблокированном профиле. Метрики: время до первого кадра окна и время до готовности адресной строки к вводу.
- Кто делает лучше / хуже: Firefox с версии 92 показывает skeleton UI на Windows. Chrome, Edge и Яндекс держат фоновые процессы (не проверено).
- Источники: https://blog.mozilla.org/performance/2021/08/05/performance-in-progress/ · https://www.ghacks.net/2021/01/25/firefox-nightly-uses-a-new-skeleton-ui-on-start-on-windows/

**Ленивая загрузка вкладок при старте** · часто · высокая · у ChatGPT: нет
- Боль: при 50–500 вкладках Chrome при запуске загружает их все: старт тормозит, фоновые вкладки играют видео. В Firefox закреплённые вкладки загружаются сразу.
- Как должно быть: сразу загружается только активная вкладка каждого окна. Остальные показывают заголовок и favicon из сессии и загружаются по клику (Firefox `restore_on_demand` = true, ленивые вкладки с версии 55). Закреплённые вкладки грузятся в фоне не больше 3 параллельно (Firefox `MAX_CONCURRENT_TAB_RESTORES` = 3, `restore_pinned_tabs_on_demand` = false), и это можно отключить. Фоновые вкладки не начинают звук до первого показа (`media.block-autoplay-until-in-foreground` = true). При нехватке памяти фоновая загрузка останавливается.
- Кто делает лучше / хуже: лучше всех Firefox. Chrome загружает всё, ограничение было только в экспериментальных флагах `#infinite-session-restore` и `#page-almost-idle`. В Slimjet есть отдельная опция.
- Источники: https://bugzilla.mozilla.org/show_bug.cgi?id=1345090 · https://www.ghacks.net/2018/12/07/chrome-session-restore-improve/ · https://www.slimjet.com/en/no-load-background-tabs-at-startup.php

**Выгрузка и усыпление вкладок без потери пользовательского состояния** · часто · высокая · у ChatGPT: вскользь
- Боль: возвращаешься на вкладку, а она перезагрузилась: пропали текст в форме, прокрутка, состояние SPA, иногда выкидывает на страницу входа. «I don't like it refreshing the pages».
- Как должно быть: 1) не выгружать вкладки, где менялись поля форм или contenteditable, идёт загрузка или выгрузка файла, играет медиа или PiP, активен WebRTC или демонстрация экрана, а также недавно активные. Закреплённые выгружаются в последнюю очередь. 2) При возврате страница перезагружается без событий unload и видит `document.wasDiscarded` (Chrome 108). Движок восстанавливает прокрутку и формы так же, как при восстановлении сессии. 3) Выгруженные вкладки визуально отмечены: в Edge — блёклые, в Firefox 140 — серая иконка, в Chrome — кольцо вокруг иконки неактивной вкладки. 4) Есть список исключений. 5) Таймауты: Edge — 2 ч по умолчанию (5 мин в режиме эффективности — не проверено). Chrome Memory Saver выгружает по таймеру через 6 / 4 / 2 ч в зависимости от уровня (Moderate / Balanced / Maximum), выгрузка при нехватке памяти — отдельный механизм. Firefox выгружает только при критически низкой памяти (`unloadOnLowMemory` на Windows и macOS). 6) Вкладку можно выгрузить вручную, есть служебная страница со списком (about:unloads, chrome://discards).
- Кто делает лучше / хуже: Edge — самый агрессивный (−37% CPU, −32% памяти). У Chrome есть chrome://discards. Firefox — самый осторожный и прозрачный: в 93 выгрузка только при низкой памяти, в 140 — ручная «Unload Tab».
- Источники: https://developer.chrome.com/blog/memory-and-energy-saver-mode · https://hacks.mozilla.org/2021/10/tab-unloading-in-firefox-93/ · https://www.techradar.com/news/one-of-the-best-microsoft-edge-features-is-now-even-more-useful

**Фоновые вкладки и батарея ноутбука** · часто · средняя · у ChatGPT: вскользь
- Боль: ноутбук быстро разряжается и шумит из-за фоновых вкладок. Safari ценят за экономию батареи.
- Как должно быть: таймеры скрытых вкладок срабатывают не чаще раза в секунду. Intensive throttling в Chrome 88 включается, если вкладка скрыта больше 5 мин, тихая не меньше 30 с, не использует WebRTC и цепочка таймеров не короче 5 (chain count ≥ 5). Тогда таймеры будят её раз в минуту. rAF в скрытых вкладках не вызывается (не проверено). Режим энергосбережения снижает частоту обновления экрана и фоновую работу и отмечен иконкой; конкретные 30 fps и порог заряда 20% не проверены. Вкладки со звуком, видеоконференциями (WebRTC) и загрузками не замедляются. Анимации интерфейса учитывают `prefers-reduced-motion`.
- Кто делает лучше / хуже: у Chrome — Energy Saver, у Edge — режим эффективности. Safari — лучший по батарее на macOS.
- Источники: https://developer.chrome.com/blog/timer-throttling-in-chrome-88 · https://support.google.com/chrome/answer/12929150

**Диалоги фоновых вкладок и кража фокуса** · часто · средняя · у ChatGPT: вскользь
- Боль: `alert()` из фоновой вкладки перебрасывает пользователя на неё прямо во время набора текста. Или диалог висит незаметно, и кажется, что страница не работает.
- Как должно быть: диалоги и запросы разрешений из фоновой вкладки не переключают вкладку и не активируют окно. Диалог показывается, когда пользователь сам перейдёт на вкладку (Chrome 64: «window.alert() no longer brings a background tab to the foreground»). На вкладке появляется индикатор «требует внимания», кнопка на панели задач Windows может мигать через FlashWindowEx (не проверено). Диалог модален только в пределах своей вкладки, вкладку с открытым диалогом можно закрыть по ×. `window.focus()` без активации пользователем игнорируется (не проверено).
- Кто делает лучше / хуже: Chrome — начиная с версии 64. Firefox, по имеющимся данным, тоже перешёл к диалогам, модальным для вкладки (не проверено).
- Источники: https://developer.chrome.com/blog/new-in-chrome-64

## Анти-цели области

- Не менять поведение по умолчанию у существующих пользователей. Миграция настроек не переворачивает явный выбор (Firefox 1701542, 1746804). Функцию не убирать без замены (прокрутка полосы в Chrome 144, Drag Space в Firefox 89) и не переключать её туда-обратно (выключатель hover cards в Chrome, отключение звука кликом).
- Не делать одноаккордный выход (Ctrl+Q, Ctrl+Shift+Q) на Windows. На macOS не выходить по одиночному ⌘Q без удержания.
- Не спрашивать «Закрыть N вкладок?», если всё восстанавливается. Не закрывать молча то, что не восстановится: приватные окна, несохранённый ввод, активные загрузки. Не перезапускать для обновления с тихой потерей приватных окон.
- Не перезаписывать сохранённую сессию пустой, не писать её неатомарно, не восстанавливать только последнее окно, не терять группы.
- Не загружать все вкладки при старте и не начинать звук в вкладке, которую пользователь ещё не видел.
- Не выгружать вкладки с изменёнными формами, звуком, WebRTC, загрузками. Не терять прокрутку и формы при возврате к выгруженной вкладке.
- Не сопоставлять сочетания клавиш по введённому символу: на ЙЦУКЕН это ломает всё управление.
- Не давать странице перехватывать Ctrl+W, Ctrl+T, Ctrl+Tab, Ctrl+Shift+T вне полноэкранного режима.
- Не переключать вкладку и не активировать окно по `alert()` или запросу разрешения из фона. Не делать диалог страницы модальным для всего окна.
- Не блокировать интерфейс работой страницы: зависшую вкладку можно закрыть всегда, без модального «скрипт не отвечает».
- Не сжимать вкладки до одной иконки без альтернативы (прокрутка, список всех вкладок). Не переключать вкладки колесом над полосой.
- Не пересчитывать ширину вкладок сразу после закрытия мышью и не снимать заморозку по таймеру.
- Не делать вкладки похожими на кнопки и не перекрашивать полосу в цвет сайта по умолчанию (урок Safari 15).
- Не делать разворот вертикальной панели по наведению поведением по умолчанию, не двигать кнопку «+».
- Не ставить кнопки (поиск вкладок и др.) рядом с частыми целями клика и не убирать возможность перенести их.
- Не переключать молча на уже открытую вкладку при открытии дубля: только предложение в адресной строке.
- Не применять EcoQoS и троттлинг к интерфейсу, активной вкладке, вкладкам со звуком и видеоконференциям.
- Не делать работу O(N) по числу вкладок на каждый кадр: у части пользователей 500–3000 вкладок.
