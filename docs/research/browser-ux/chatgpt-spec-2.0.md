# Lumen Browser — UX-спецификация 2.0 от ЧатГПТ.

> Статус: проект требований, не аудит текущей реализации. Аудитория: универсальный браузер для всех. Версия: 2026-10-11.

## 1. Назначение и критерии качества

Lumen должен обеспечивать предсказуемое, доступное, быстрое и безопасное взаимодействие с вебом. Приоритет — непрерывность работы пользователя, а не визуальные эффекты.

**Семь принципов:** предсказуемость; обратная связь; контроль и отмена; низкая когнитивная нагрузка; доверие и приватность; непрерывность; совместимость со стандартами и ожиданиями платформы.

**Разграничение ответственности:** `ENGINE` — HTML/CSS/DOM/input/layout/paint; `CHROME` — собственный UI браузера; `PLATFORM` — интеграция с ОС; `SITE` — поведение, контролируемое веб-сайтом. Не обещать средствами браузера то, что определяется кодом сайта.

**Приоритеты:** P0 — без этого сценарий ненадёжен или опасен; P1 — значительное удобство; P2 — необязательная функция. Статусы: draft / specified / implemented / tested / blocked. Исходный реестр не подтверждает реализацию.

## 5. Что добавлено по материалу Qwen

Отдельные темы для проработки: энергопотребление и выгрузка вкладок; доверие к разрешениям; passkeys/OTP; изоляция cookie и профилей; безопасные загрузки; offline и диагностические ошибки; reader mode; мультимедиа и PiP; screen reader; мобильная эргономика (как будущий отдельный профиль требований); синхронизация; расширения и управление их доступами; новая вкладка без навязанных сервисов.

Некоторые утверждения Qwen — рекомендации, не универсальные нормы: не фиксировать частоту мигания caret; не навязывать стили ссылок сайтам; не обещать pause/resume без поддержки сервера; не придумывать причину запроса геолокации; не хранить чувствительные поля форм; не предполагать, что browser контролирует все ошибки сайтов.

## 6. План проверки и трассируемость

Для каждого требования добавить поля: `standard_ref`, `component`, `platform`, `preconditions`, `steps`, `expected`, `negative_cases`, `automation`, `owner`, `status`, `evidence`.

**Источники нормативных требований для последующей сверки:** HTML Living Standard, CSS specifications, UI Events, Selection API, Pointer Events, Clipboard API, WebDriver/WPT, WCAG 2.2, ARIA Authoring Practices, платформенные Human Interface Guidelines. Ссылки и применимость к конкретному пункту пока не верифицированы.

**Метрики:** процент успешных задач, время до результата, число повторных действий, задержка ввода, время переключения вкладок, плавность прокрутки, частота крашей, успех восстановления, использование памяти и батареи, доступность клавиатурой и экранным диктором.

## 7. Очередность внедрения

1. P0 ENGINE: текст/IME/selection/focus/hit testing/scroll/navigation.
2. P0 CHROME: вкладки, адресная строка, ошибки, загрузки, восстановление, разрешения.
3. P0 безопасность и доступность на всех уровнях.
4. P1: поиск вкладок, reader mode, профили, PiP, энергосбережение.
5. P2: расширенные жесты, визуальные эффекты, необязательные ассистенты.
