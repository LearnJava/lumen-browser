# AV1: скорость декодирования 1080p (UX-VIDEO-AV1)

Замер к решению ADR-035 п.2: хватает ли портируемого `rav1d` без ассемблера для воспроизведения
1080p в реальном времени и включать ли `asm` (nasm в сборке).

## Как мерили

- Машина разработчика: Intel Core i5-10210U (4 ядра / 8 потоков, 1,6 ГГц базовая), Windows 10. Машина
  общая — параллельно идут сборки других сессий, поэтому приведены лучшие из нескольких запусков.
- Ролик: ffmpeg 9 + SVT-AV1 (`-preset 8 -b:v 4M -g 120`), синтетический `mandelbrot` 1920×1080,
  30 кадр/с, 10 с, 300 кадров, 4:2:0 8 бит, ~5,6 МБ (≈4,5 Мбит/с — типичный битрейт 1080p).
  Дополнительно тяжёлый вариант `-crf 32` (16 Мбит/с). Ролики в репозиторий не кладутся (20 МБ).
- Инструмент: `cargo run --release -p lumen-av1 --example bench -- ролик.mp4 [потоков]` — демуксер
  `lumen-media-demux` → `lumen_av1::Decoder` → `Picture::to_rgba8_into` для каждого кадра.
  «Потоков» 0 — по числу логических ядер (8).
- Сборка с asm: `nasm` 2.16.03 в `PATH`, `--features asm`.

## Результат

| Сборка | Потоков | Декодирование, 300 кадров | YUV→RGBA, на кадр | Всего | Скорость |
|---|---|---|---|---|---|
| без asm (по умолчанию) | 8 | 9,5–10,7 с | 3,8–4,4 мс | 10,7–12,0 с | **0,83–0,93×** реального времени |
| без asm | 1 | 27,4 с | 8,9 мс | 30,1 с | 0,33× |
| **с asm** | 8 | 1,6–1,8 с | 3,9–4,9 мс | 2,8–3,1 с | **3,2–3,6×** |
| с asm | 4 | 1,8 с | 3,9 мс | 3,0 с | 3,3× |
| с asm | 1 | 3,2 с | 4,0 мс | 4,4 с | 2,25× |
| с asm, ролик 16 Мбит/с | 8 | 2,2 с | 4,2 мс | 3,5 с | 2,85× |

Без asm на 8 потоках декодирование (без учёта RGBA) идёт со скоростью ≈ 1,0× — на грани, любая
фоновая нагрузка (JS, композитор, аудио) роняет кадры. С asm запас в 3 раза даже на одном потоке.

## Решение

- **Релизные сборки включают `asm`**: `cargo build --release -p lumen-shell --features av1-asm`
  (фича шелла → `lumen-image/av1-asm` → `lumen-av1/asm` → `rav1d/asm`). На x86 нужен `nasm` в `PATH`
  на машине сборки; на ARM64 asm-ядра собирает ассемблер тулчейна.
- **В default фича выключена**: `cargo build` и CI-сборки без nasm остаются рабочими, AVIF и видео
  тогда идут портируемым путём (корректно, но ≈ 3,5× медленнее). Для AVIF-картинок разница
  незаметна, для видео 1080p — нужна.
- Аппаратный AV1 через ОС (`COMPAT-MEDIA-OSDEC-*`) остаётся быстрым путём там, где он есть;
  asm-rav1d — программный запас на всех платформах.
- Проверено: тесты `lumen-av1` (17, побитовое совпадение кадров с ffmpeg/libdav1d) проходят и с
  `--features asm`.

## Конвертация YUV→RGBA

Таблицы вкладов отсчётов (по одной на значение 8/10/12 бит) + сложение, общая цветность считается
раз на пару пикселей, строки делятся между потоками для кадров ≥ 256 Кпикс. 1080p: ≈ 4 мс/кадр на
8 потоках, ≈ 9 мс/кадр на одном. Для воспроизведения это не бутылочное горлышко; позже кадры уйдут
на GPU как YUV (`Picture::planes` отдаёт плоскости без копирования формата).
