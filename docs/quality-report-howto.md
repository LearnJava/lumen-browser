# Сводный отчёт качества — как запускать и читать

`python scripts/quality_report.py` сводит свежий и предыдущий полный прогон WPT (`docs/wpt/runs/*.json`),
свежий полный прогон `graphic_tests/results/*.json` и предыдущий **того же режима съёмки** (см. ниже) и открытые баги `BUGS.md` в
[`quality-report.md`](quality-report.md) и пишет срез истории `docs/quality/runs/<stamp>.json`
(только если данные изменились — повторный запуск ничего не меняет). `--check` — только итоговая строка
в stdout, без записи.

- **Когда:** после мержа нового `--run-json` прогона WPT или полного `graphic_tests/run.py`; коммитить
  отчёт и новый срез вместе с прогоном.
- **Что читать первым:** строку «Итог» (тренд и число просадок), затем «Просадки с прошлого отчёта» —
  регрессии WPT по категориям, рост CRASH/TIMEOUT/ERROR/FAIL, тесты graphic_tests, ушедшие из PASS.
- **Счётчики:** PASS/FAIL дают только reftest и crashtest, testharness — OK + доля сабтестов;
  UNSUPPORTED (тип без исполнителя), SKIPPED и NOT-RUN в числитель не входят. Дельта багов — к прошлому
  срезу; нет второго прогона — `n/a`. Свод «тест → баг» для топ-5: `tests/wpt/metadata/**/*.ini`,
  WPT-пути в незакрытых строках `ROADMAP.md` с колонкой `bugs`, таблицы [`wpt-status.md`](wpt-status.md).
- **Пара прогонов graphic_tests (TEST-12).** Режим прогона выводится из поля `capture` каждого теста:
  `ipc` (все по IPC, `run.py --ipc`), `gdigrab` (все через gdigrab), `default` (смесь по `GPU_CAPTURE`,
  обычный `run.py`), `legacy` (прогон до TEST-9, поля нет). Предыдущий прогон — последний более
  ранний *полный* прогон **того же режима**; нет такого — Δ graphic_tests `n/a`, а под таблицей
  «Источники» написана причина. Тест, у которого способ съёмки в двух прогонах разный, не попадает
  в «Сменившие статус» и в просадки, а идёт отдельной строкой «Сменился способ съёмки». В «Источниках»
  у прогона пометка «не в main» (коммит не предок `origin/main`, проверка `git merge-base
  --is-ancestor`; без git пометка пропускается) и/или «WIP» (тема коммита начинается с `WIP`):
  числа такого прогона предварительные. HTML-страница сервера показывает те же пометки — она
  рендерит этот же markdown.
- **Разброс, а не просадки.** Два прогона WPT одного коммита код не сравнивают: их разница уходит в
  раздел «Разброс прогонов» и в число просадок не входит (мера шума окружения). Составной снимок
  (исходные отчёты + перепрогон части шардов: «с поддоменами», «с попапами») пишет в JSON
  `"derived_from": "<исходный снимок>.json"`, и исходник из пары выпадает — свежий прогон сравнивается
  с прошлым прогоном, а не со своей же версией «как снято». Предупреждения под
  «Источниками»: прогоны WPT и graphic_tests разнесены больше чем на 7 дней (то же — хвостом строки
  «Итог» и плиткой на HTML-странице), у прогонов WPT разные параметры раннера (`processes`,
  `parallel_shards`, `batch_small`, …). Колонка «Отставание от main» — сколько коммитов `origin/main`
  прогон не видел (в срез не пишется). FAIL ↔ DEBTOR в «Сменивших статус» — переклассификация
  храповика, не исправление и не поломка.
- Тесты скрипта: `python scripts/test_quality_report.py`; страницы-дашборда —
  `python scripts/test_quality_report_server.py`.

## Кнопка «Обновить» в браузере

`python scripts/quality_report_server.py` поднимает страницу отчёта на `http://127.0.0.1:8740/`
и сам открывает её в браузере по умолчанию (`--no-open` — не открывать, порт — `--port`):
отчёт в HTML, кнопка «Обновить отчёт» запускает `quality_report.py`
(~2 мин на текущих данных) и перечитывает страницу; относительные ссылки (`bugs/BUG-NNN`,
`wpt-status.md`) открываются как страницы. Кнопка тестов не запускает: без нового прогона
WPT или graphic_tests цифры и Δ те же. Сверху — блок «Что изменилось» (какие прогоны
сравниваются, предупреждения из «Источников», сдвиг статусов WPT; «Стало лучше» — до 5
категорий WPT с ростом pass rate по весу «тестов × Δ п.п.» плюс тесты graphic_tests, ставшие
PASS; «Стало хуже» — первые 5 строк «Просадок» со ссылкой на раздел), под ним дашборд:
полосы pass rate по подсистемам с меткой прошлого значения (зелёный кусок — прирост,
бледно-красный — потеря) и цветной Δ, плитки итогов с цветной Δ (для багов рост — красный).
Всё берётся из таблиц самого отчёта, под каждым
разделом — пояснение простым языком для неспециалиста. Сервер слушает только localhost, отдаёт только `.md`
внутри репозитория и ничего не пишет сверх самого генератора. Markdown-файл остаётся
каноническим; обновлённый отчёт и срез по-прежнему коммитятся вместе с прогоном.
